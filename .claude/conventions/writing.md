# 문서 작성 컨벤션

**AI에게 문서를 맡길 때 적용하는 규칙이다.** 사람이 직접 쓸 때도 같은 기준으로 본다.

`CLAUDE.md`의 "기획 문서 정합성"이 **문서끼리 어긋나지 않게** 하는 규칙이라면, 여기는 **한 문서를 사람이 읽을 수 있게** 하는 규칙이다.

## 1. 사람이 읽는 글로 쓴다

2026-08-24에 셋이 합의했다.

> 지민: "FRD나 문서 쓸 때 너무 AI스럽다고 해야 하나? 가독성이 떨어져서. **FRD 본래 문서만으로도 인간이 읽기 편하게 유지되어야 한다**고 생각해서"
> 지응: "인정인정. 나도 느꼈어"

**전체를 다 읽은 사람만 이해할 수 있는 글은 안 된다.** 처음 보는 사람이 그 문단만 읽어도 무슨 말인지 알아야 한다.

| | |
|---|---|
| 전 | 애플이 앱에게 알려주지 않는다. 거부 여부를 알려주면 그 자체로 건강 정보가 새기 때문이다. 앱이 보는 것은 "기록이 안 온다" 뿐이고, 거부한 것인지 진짜로 기록이 없는 것인지 구분할 수 없다 |
| 후 | HealthKit은 사용자의 읽기 권한의 거부 여부를 앱에 알려주지 않는다. 권한을 거부한 경우와 권한은 있지만 기록이 없는 경우가 똑같이 0건으로 조회된다 |

**줄 수를 줄이는 것이 목표가 아니다.** 내용을 쉽게 파악할 수 있게 하는 것이 목표다. 그것만 되면 길어도 된다.

## 2. 긴 줄표를 쓰지 않는다

`—`(em dash)는 **AI가 쓴 티가 난다.** `-`, `( )`, `:`로 바꾼다.

## 3. 조사한 것에는 검증할 수 있는 출처를 단다

2026-08-25에 합의했다.

> 지민: "기술 조사 같이 외부 자료 토대로 뽑아내는 글은 검증할 수 있는 링크를 달라고 해야 신뢰도가 높아집니다. **실제로 AI가 존재하지 않는 출처를 만들거나, 실제 존재하는 글을 엉뚱한 주장에 붙이는 문제도 있어서**"
> 지응: "다음번엔 출처 넣을게"

외부 자료를 근거로 쓴 문단에는 **원문 링크**를 단다. 링크를 못 찾으면 "출처를 못 찾았다"고 적는다. **찾은 척하지 않는다.**

## 4. 모르는 것은 모른다고 적는다

확인되지 않은 것은 `[확인 필요]`로 남긴다. 추측으로 메우지 않는다.

**누가 무슨 말을 했는지 적을 때는 실제로 한 말만 적는다.** 맥락으로 짐작한 것은 짐작이라고 밝힌다.

## 자주 나오는 AI 티

위 규칙을 어기는 구체적인 형태들이다. 고칠 때 이것부터 본다.

| | 예 |
|---|---|
| 번역투 | "~를 통해", "~에 있어서", "그/그녀" 남용 |
| 기계적 나열 | "첫째, 둘째, 셋째", 뜻 없이 이어지는 불릿 |
| 맺음말 상투구 | "결론적으로", "시사하는 바가 크다" |
| 같은 리듬 | 문장 길이가 다 비슷해서 밋밋함 |
| 얼버무림 | "~할 수 있을 것으로 보인다" |
| 접속사 남발 | 문단마다 "또한", "따라서"로 시작 |
| 형식명사 | "~하는 것이다", "~할 필요가 있다" |
| 장식 과다 | 볼드가 너무 많아서 어디가 중요한지 안 보임 |

> 분류는 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)(MIT)의 것을 참고해 추렸다. 그 플러그인을 따로 설치해서 써도 된다.

## 고칠 때

**내용은 건드리지 않는다.** 사실, 수치, 고유명사, 인용은 그대로 둔다. 문체만 고친다.

**많이 고쳤다 싶으면 멈추고 확인받는다.** 문체만 다듬으랬는데 내용까지 바뀌는 일이 잦다.
