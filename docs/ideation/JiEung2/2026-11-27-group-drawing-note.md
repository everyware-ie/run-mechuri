# 합동 그리기: 칸을 나눠 한 장을 함께 채우기

*2026-11-27 · JiEung2 · 개인 노트이며 팀 결정이 아님*

11/20 회의에서 크루는 보류하고 "여러 사람이 한꺼번에 그리는 기능"으로 바꿔 진행하기로 했다. 구체화는 지응 담당이다([결정문](../../decisions/2026-11-20-crew-hold-login-required.md)). 이 노트는 그 구체화의 첫 정리다.

## 1. 처음 떠올린 모양

회의에서는 "셋로그 형태"라고만 불렀다. 문서에는 셋로그가 무엇인지 적혀 있지 않다. 아래는 지응이 설명한 모양이다.

- 한 장을 4칸으로 나눈다
- 칸마다 가운데에 `+` 버튼이 있다
- 크루원이 거기에 자기가 뛴 기록을 올린다
- 기준 기간은 이번 주 기록으로 한다. 오늘 기록으로 해도 상관없다고 처음에는 생각했다

[MVP PRD §10 로드맵](../../specs/prd/running-drawing-mvp.md)의 그룹 드로잉("같은 날 함께 뛴 사람들의 기록을 하나의 경로 그림 파일에 모아")과 가까운 방향이다.

## 2. 대화에서 정한 것

지응이 직접 정한 것만 적는다.

| 질문 | 정한 것 |
|---|---|
| 기록은 어디서 오나 | 앱에서 측정한 기록과 건강 앱에서 가져온 기록 모두 |
| 기준 기간 | 이번 주로 시안을 그렸다. 처음에는 오늘 기록이어도 상관없다고 했다 |
| 칸 배치 | 2×2, 세로 4행, 가로 4열 세 가지를 모두 지원. 합동 그리기를 만들 때 고른다 |
| 출력 크기 | 기존 경로 그림과 같다(9:16, 1080×1920) |
| 기록을 올린 뒤 | 4칸이 다 차기 전에는 바꿀 수 있고, 다 차면 바꿀 수 없다 |
| 내 칸을 언제 채우나 | 만들면서 채우지 않는다. 만든 뒤에 `+`로 올린다. 지금 안 뛰었어도 만들 수 있게 하려는 이유다 |
| 칸에 보일 이름 | 닉네임이 아니라 올릴 때마다 입력한다 |
| 배경 | 칸 주인이 칸마다 고른다 |
| 칸보다 큰 사진 | 칸 비율에 맞춰 늘이거나 줄이지 않는다. 칸 크기만큼만 보이게 하고 어느 부분이 보일지만 고른다 |
| 사진 배경 | 다른 사람 폰에서도 보여야 하므로 서버에 올린다 |
| 서버 | 지민이 로그인 작업을 하고 있어서 그 뒤에 한다 |

## 3. 시안을 그리며 제안하고 지응이 이어 간 것

아래는 정한 것이 아니다. 시안을 그리면서 같이 나온 제안이다. 팀에 가져가기 전에 확인이 필요하다.

- **크루 없이 간다.** 지응은 처음에 "크루를 만든 뒤 같은 크루 안에서 만들면 어떠냐"고 물었다. 크루를 다시 들이면 11/20에 보류한 가입, 내보내기, 크루장 넘기기가 같이 돌아와서, 크루 없이 초대 링크로 칸을 채우는 쪽으로 그렸다. 만든 사람에게 특별한 권한을 주지 않는다. 이 구조를 지응이 명시적으로 승인한 것은 아니다.
- **지난주 멤버로 다시 만들기.** 크루의 장점인 "매주 같은 사람들과"를 크루 없이 얻는 방법으로 나왔다. 멤버만 미리 초대하고 기록은 각자 올려야 한다. 후속 후보다
- **배치는 만들 때 정한다.** 처음에는 영상을 만드는 사람이 고르는 쪽을 제안했으나, 장 상세 화면이 배치마다 달라지기를 원해서 만들 때 정하는 쪽으로 바꿨다. 한 칸이라도 채워지면 바꿀 수 없다는 규칙은 제안이다
- **마감 뒤.** 마감은 그 주 토요일 자정이다. 빈 칸이 있어도 영상은 만들 수 있고, 서버에 올린 좌표와 사진은 마감 뒤 일정 기간이 지나면 지운다는 안이다. 기간은 정하지 않았다

## 4. 검토하고 접은 것

- **가로 4열을 왼쪽부터 차례로 재생하기.** 이어달리기 같은 이야기는 좋지만 영상 길이가 칸 수만큼 늘어난다. 기본은 동시 재생으로 하고 순차 재생은 후속 후보로 남긴다
- **경로가 가장 크게 그려지는 배치.** 1080×1920에서 정사각에 가까운 경로가 한 변 최대 얼마까지 그려지는지 계산했다. 가로 4열 270, 세로 4행 480, 2×2 540이다. 실제 경로의 가로세로 비율에 따라 달라지는 추정치다
- **기본 이미지 6장만 쓰기.** 사용자 사진을 서버에 올리지 않아도 되는 가장 단순한 길이었다. 지응이 사진을 서버에 올리기로 해서 접었다

## 5. 남은 질문

[2026-11-27 회의 안건](2026-11-27-meeting-agenda.md)에 정리했다. 가장 큰 것은 사용자가 올린 사진을 다른 사용자가 보게 되는 점이다. App Store 심사 가이드라인 1.2(걸러내기, 신고, 차단, 연락처 공개)가 적용될 수 있어서 크루 시안에서는 사진 기반 기능을 첫 버전에서 뺐다. 심사 판단은 확정하지 못했다 `[확인 필요]`.
