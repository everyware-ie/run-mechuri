# 2주차 업무 분배 제안 (8/19~8/25)

*2026-08-19 · phs00 · [2026-08-18 결정](../../decisions/2026-08-18-native-ios-and-mvp-scope.md)의 후속 · 일정 근거: [PRD §13](../../specs/prd/running-drawing-mvp.md)*

> **성격: 제안이지 결정이 아니다.** 08-18 회의에서 업무 분배를 시작했고 작업자 미정이 3건 남았다. 이 문서는 phs00이 정리한 안이며, 팀 합의로 확정한다.
> `[확인 필요]` 로 표시한 두 가지(회의 날짜, 관통 기준)는 특히 먼저 정해야 한다.

## 왜 이 순서인가

제약 셋이 순서를 거의 강제한다.

1. **8/25까지 코어 루프 관통**이 마감선이다. 여기가 밀리면 9/1 베타 심사가 밀리고, **베타가 유일한 심사 관문**이라 9/22가 함께 흔들린다 (9/22 출시는 TestFlight 공개 링크로 정의됐다)
2. **스택이 없으면 아무도 코드를 못 쓴다.** 리서치 → 셋이 모여 결정 → 그 다음이 셋업이다. **리서치와 결정 사이에 텀이 생긴다**
3. **서버 작업이 없어 백엔드 2명이 둘 다 iOS를 한다.** 팀에 앱 경험자가 없어 학습 곡선이 일정 안에 들어온다

## 결정 회의 전까지 (8/19~8/20)

| 담당 | 작업 |

| **JiEung2** | 기술 스택 리서치 (내보내기·렌더링 각도) / 드로잉 기능 테스트 / **HealthKit·GPX 구분 정리** |

### 스택 리서치를 둘 다 하는 이유

같은 것을 두 번 하자는 게 아니라 **보는 각도가 다르다.**

- **JiEung2**: mp4 내보내기 경로가 스택을 가른다. AVFoundation(Swift) vs RN에서의 대안. 렌더링 성능
- **jminkkk**: HealthKit 접근, 인스타 공유 API, 스토어 제출 관점. RN이면 공통부를 웹으로 빼는 구조(나이키런)가 성립하는지

산출물은 각자 `docs/ideation/<닉네임>/`에 노트 하나. **회의 전에 서로 읽는다.**

### 드로잉 기능 테스트에 붙는 조건

**합성 좌표가 아니라 실제 러닝 데이터로 한다.** [PRD §12](../../specs/prd/running-drawing-mvp.md)에 "실제 GPX가 목업만큼 예쁘지 않다"가 2주차 판정 리스크로 잡혀 있다. 렌더링 완성도가 "우와"의 유일한 레버이므로, 여기서 안 예쁘다는 게 드러나면 **스택보다 훨씬 큰 문제**다. 지금 알면 대응할 시간이 있다.

## 텀 구간에 무엇을 하나

리서치가 끝나고 결정이 나기까지 비는 구간이다. **스택과 무관한 작업만 골랐다.**

| 담당 | 텀에 할 것 | 왜 스택과 무관한가 |
|---|---|---|
| jminkkk | **디자인 요소 셋업** | 산출물이 **코드가 아니라 토큰·스펙·목업**이면 스택을 안 가린다. 결정 후 그대로 코드로 옮겨진다 |
| jminkkk | **계정 등록** | 승인 대기가 붙어 일찍 시작할수록 좋다 |
| JiEung2 | **실제 데이터 샘플 확보 + 경로 다듬기 로직 검증** | 순수 좌표 계산이라 언어를 안 가린다 |
| phs00 | 배경 이미지 선정, FRD | 문서 작업 |

**디자인 셋업이 텀을 메우는 게 아니라, 텀에 할 수 있는 실질 작업이라서 여기 있는 것이다.** 조건은 하나, 산출물이 코드가 아닐 것.

### 디자인 시스템은 FRD를 다 기다리지 않는다

| 부분 | 필요한 선행 | 언제 |
|---|---|---|
| 기반 토큰 (색·타이포·간격·다크 모드) | 없음 | 지금 |
| 핵심 컴포넌트 (버튼·선택 카드·슬라이더·시트) | PRD §6 코어 루프면 충분 | 지금 |
| 화면별 상세 레이아웃 | FRD | FRD 나오는 대로 |

화면이 다섯뿐이다(기록 선택 → 배경 선택 → 프리셋 선택 → 미리보기·편집 → 공유). FRD가 더하는 것은 각 화면의 규칙과 수치이지 컴포넌트 목록이 아니다.

**다만 이 제품에서 디자인의 승부처는 UI 크롬이 아니라 렌더링 결과물이다.** PRD P2가 "렌더링 완성도가 우와를 만드는 유일한 레버"라고 못박았고, 사용자가 인스타에 올리는 것은 우리 UI가 아니라 그 클립이다. **디자인 시스템은 결과물을 방해하지 않을 만큼만 만들고**, 힘은 미리보기·편집 화면에 몰아주는 편이 낫다. 5주 일정에서 디자인 시스템 과투자가 가장 흔한 실패 경로다.

## 08-18 분배에서 빠져 있던 것 둘

### 1. Apple Developer 계정 등록 (jminkkk)

역산표상 **8/18 착수**였고 승인 대기가 붙는다. 9/1 베타 심사의 선행 조건이라 늦어지면 마감선이 직접 흔들린다.

### 2. HealthKit / GPX 구분 (JiEung2)

**FRD를 막고 있는 유일한 항목이다.** 진입 화면이 여기서 갈린다. 스택 리서치의 데이터 각도에 딸려 나오거나, 8/20 회의에서 스택과 같이 닫는 것이 자연스럽다.

안 닫히면 FRD는 진입 화면을 비운 채 나머지만 쓰게 된다. 못 쓰는 것은 아니지만 반쪽이다.
