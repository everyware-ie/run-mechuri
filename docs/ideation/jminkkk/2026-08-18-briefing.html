둘의 차이

베타 심사 (TestFlight)정식 심사 (App Store)
무엇을 보나기본 보안·심사 지침 위반 여부훨씬 엄격. 앱 완성도 · 가이드라인 준수 · 로그인 계정 정보 · 데모 기능
범위버전의 첫 빌드만. 이후 수정 빌드는 빠르게 통과제출할 때마다
기간수 시간 ~ 1~3일90%가 24시간 이내(전체 평균). 신규 앱 최초 제출은 2~5일
리젝 시재제출수정 + 재제출 2~3일
  • 정식 심사가 훨씬 엄격합니다. 베타를 통과했다고 정식이 통과되지 않습니다.
  • 정식은 앱 완성도를 봅니다. 미완성 빌드를 정식에 내면 리젝 사유가 됩니다.
  • 우리는 신규 계정 + 신규 앱 + 최초 제출이라 가장 느린 조건입니다. 그래서 정식 심사를 24시간이 아니라 2~5일로 잡았습니다.
  • 신속 심사는 Apple 재량이라 계획 전제로 못 씁니다.

미확인 — "같은 버전의 이후 빌드는 심사가 없을 수도 있다(might not)"에서, 어떤 빌드가 다시 걸리는지 조건은 공개돼 있지 않습니다.

판단 1

웹이 아니라 네이티브

데이터 확보 방식웹으로 되나
GPX 업로드가능
HealthKit불가 — 네이티브 전용 API
직접 GPS 트래킹불가 — 백그라운드 위치가 웹에서 끊김
  • 세 방식 중 둘에서 웹이 탈락합니다.
  • 남은 GPX 업로드에서도 인스타 공유 API가 네이티브 전용이라, 웹은 "파일 다운로드 → 사진앱 → 인스타 업로드"가 됩니다.
  • 네이티브로 시작하면 데이터 방식 셋이 다 열려 있습니다. 웹으로 시작하면 GPX로 고정되고 나중에 HealthKit을 쓰려면 재작성입니다.
  • 팀 3명 전원 아이폰 사용 — 확인됨. iOS 전용으로 가도 실사용(9/9~14)에 문제 없습니다.
뒤집힐 조건

데이터 방식이 GPX로 확정 + Web Share API로 공유 마찰이 해소되면 웹이 다시 후보입니다. 후자는 30분이면 검증되는데 아직 못 했습니다.

미결

스택 — Swift인가 Expo인가

평가
SwiftHealthKit·위치 1급 지원. mp4 인코딩이 AVFoundation + Core Animation으로 표준 경로
Expo / RNJS에 익숙하면 빠를 수 있음. mp4 인코딩 경로 불확실 — ffmpeg-kit 지원 종료 후 대체 미확인
하이브리드웹뷰에 렌더링을 두면 mp4를 어디서 만들지가 걸림. 6주에는 부적합
결정 불가

mp4 인코딩 경로가 정해지면 스택이 따라옵니다. JiEung2 트랙이 MediaRecorder / ffmpeg.wasm / 서버 ffmpeg 중 무엇이 되는지 판정 중이고, 그 결과가 이 질문의 답입니다.

필요한 것—파일 올려둘 곳만 (S3·GitHub Pages). API·DB·서버 프로그램 전부 없음

이미지를 S3에 올려두고 앱이 URL로 불러오는 것과 같은 구조입니다. 이미지 대신 설정값 파일일 뿐입니다.
단, 심사 없이 바꿀 수 있는 건 색상·두께·크기 같은 값뿐입니다. 새 렌더링 방식이나 새 레이어는 코드 변경이라 여전히 심사입니다.
