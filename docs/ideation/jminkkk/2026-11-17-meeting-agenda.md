## 1. 크루원에게 보여 줄 기록의 범위 (10분)

### 배경

- Runary의 기록은 두 군데서 옴
  - **Runary 측정 기록**: Runary로 직접 뛴 기록. 기기에만 있어서 앱을 지우면 사라짐
  - **건강 앱 기록**: 애플워치 운동 앱 등 다른 앱으로 뛰고 건강 앱에서 불러온 기록. 원본이 건강 앱에 남아 있음
- [로그인 PRD](../../specs/prd/account-login.md)는 서버 백업 대상을 **Runary 측정 기록만**으로 정함
  - 건강 앱 기록은 원본이 남아 있어 백업이 필요 없음
- 그런데 크루원끼리 경로를 보려면 그 기록이 서버에 있어야 함
  - Runary 측정 기록만 올리면, 다른 앱으로 뛰는 사람은 크루에 보여 줄 기록이 없음

### 선택지

| | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | Runary 측정 기록만 공유 | 백업한 기록을 그대로 쓰므로 추가 작업 없음 | 다른 앱으로 뛰는 크루원은 참여 불가 |
| B | 건강 앱 기록도 전부 자동으로 서버에 올려 공유 | 어떤 앱으로 뛰든 크루에 보임 | 다른 앱 데이터까지 서버에 쌓임. 개인정보 처리방침 범위가 커짐 |
| C | 두 출처 모두 가능. 단, 사용자가 공유할 기록을 직접 고를 때만 올림 | 다른 앱 사용자도 참여 가능. 올리는 기록을 사용자가 통제 | "공유할 기록 고르기" 화면이 하나 늘어남 |

### 같이 볼 것

- 크루원에게 경로를 보여 줄 때 집·회사 위치를 어떻게 할지 ([11/10 결정](../../decisions/2026-11-10-third-sprint-crew-diary.md)에서 미정). 어느 선택지든 경로가 그대로 보이면 생기는 문제
- 현수의 크루 화면 디자인(경로 조회)에 "공유할 기록 고르기"가 들어가는지

### 정할 것

- A, B, C 중 무엇으로 갈지
- 정해지면 크루 PRD에 반영. B나 C면 [로그인 PRD](../../specs/prd/account-login.md) §4 기록 백업과 개인정보 처리방침 범위도 함께 고침

## 2. 로그인 필수 여부 (10분)

### 배경

- [로그인 PRD](../../specs/prd/account-login.md)는 로그인을 **선택(잠정)** 으로 둠
- 필수로 할지는 Apple·카카오 연동을 끝낸 뒤 정하기로 함
  - 연동, 가입, 백업, 탈퇴 코드는 어느 쪽이든 같음
  - 달라지는 것은 입구뿐: 필수면 첫 실행 때 로그인 화면, 선택이면 크루 진입과 내 계정 화면

### 선택지

| | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 선택 (지금 문서) | 기존 사용자가 업데이트 뒤에도 그대로 씀. 심사 위험 낮음 | 로그인하지 않은 사용자는 백업을 못 받고 앱을 지우면 기록이 사라짐 |
| B | 필수 | 모든 사용자의 기록이 백업됨. 크루로 이어지기 쉬움 | 첫 실행에서 이탈할 수 있음. 계정이 핵심이 아닌 앱이 로그인을 강제하면 반려될 수 있음([App Review Guidelines 5.1.1](https://developer.apple.com/app-store/review/guidelines/#data-collection-and-storage)) |

### 정할 것

- 지금 정할지, 연동이 끝난 뒤 다시 볼지
- B로 가면 [로그인 FRD](../../specs/frd/account-login.md) §2 로그인 입구와 PRD §3 언제 로그인을 묻나를 고침

## 3. 이메일을 받지 않기로 함 (5분, 선조치 후보고)

로그인 작업을 막지 않으려고 지민이 먼저 정하고 문서에 반영함. 괜찮은지 확인받고 싶음

### 정한 것

- Apple·카카오 로그인에서 이메일을 받지 않음. 로그인 식별자와 닉네임만 받음
- 반영한 곳: [로그인 PRD](../../specs/prd/account-login.md) §4 계정에 무엇이 남나, [로그인 FRD](../../specs/frd/account-login.md) §3-3 받는 정보

### 이유

- 지금 이메일을 쓸 곳이 없음. 동일인 확인은 로그인 식별자로 충분
- 쓰지 않는 개인정보를 받으면 처리방침과 App Store 개인정보 표시에 적을 항목만 늘어남
- 카카오는 동의항목을 하나도 설정하지 않아도 되어서, 비즈 앱 전환과 검수가 필요 없어짐

### 나중에 필요해지면

- 앱 안에서 이메일을 직접 입력받음. 로그인 수단과 상관없이 모든 사용자에게 받을 수 있음
- Apple 로그인으로 받는 방법은 기존 사용자에게는 못 씀. Apple은 가입 뒤에 이메일 범위를 늘릴 수 없음
- 받기로 하면 수집 목적, Apple 중계 이메일 발신 도메인 등록, 마케팅이면 수신 동의, 처리방침 개정이 따라옴

### 확인할 것

- 이대로 가도 되는지
- 공지·마케팅 메일처럼 곧 이메일을 쓸 계획이 있는지. 있다면 Apple 쪽만이라도 지금 받는 게 나음

## 4. 로그인을 Google 대신 카카오로 바꿈 (5분, 선조치 후보고)

[11/10 결정](../../decisions/2026-11-10-third-sprint-crew-diary.md)에서 지민에게 판단을 맡긴 것. 확인 결과에 따라 바꾸고 결정문에 개정으로 남김

### 11/10에 정한 것

- "카카오 대신 Google로 감. 카카오에 사업자가 꼭 필요한지는 확실하지 않음. 지민이 진행하면서 판단"
- Google로 간 이유는 카카오에 사업자가 필요할 수 있다는 것뿐이었음

### 확인한 것

- 카카오 로그인은 사업자 없이 쓸 수 있음. 비즈 앱이 아니어도 됨([카카오 앱 설정 문서](https://developers.kakao.com/docs/latest/ko/app-setting/app))
- 이메일을 받지 않기로 해서(§3) 동의항목도 하나도 필요 없음. 비즈 앱 전환과 검수도 필요 없음([카카오 로그인 활용 문서](https://developers.kakao.com/docs/latest/ko/kakaologin/utilize))
- 지응이 사업자 없이 진행해 본 경험이 있다고 한 것과 맞음

### 그래서 바꾼 것

- 로그인은 **Apple과 카카오**. Google은 넣지 않음
- 반영한 곳: [결정문 2026-11-17 개정](../../decisions/2026-11-10-third-sprint-crew-diary.md), [로그인 PRD](../../specs/prd/account-login.md) §2 범위

### 확인할 것

- 이대로 가도 되는지
- Google도 함께 넣자는 의견이 있는지. 넣으면 로그인 수단이 셋이 되어 SDK, 서버 검증, 탈퇴 처리가 하나씩 늘어남


---

## 5. 닉네임 영문은 소문자만 (공유)

논의할 안건은 아니고 알리는 것. 2026-11-20 지민이 정하고 [로그인 FRD](../../specs/frd/account-login.md) §4 닉네임에 반영함

- 닉네임의 영문은 소문자만 씀. 대문자를 입력하면 바로 소문자로 바뀜
- 이유: 닉네임은 중복이 안 되는데, `runner`와 `Runner`를 같이 허용하면 같은 사람인지 다른 사람인지 헷갈림
- 크루 화면 디자인(현수)에서 닉네임을 보여 줄 때 참고
