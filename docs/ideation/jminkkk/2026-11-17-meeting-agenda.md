## 1. 크루원에게 보여 줄 기록의 범위 (10분)

### 배경

- Runary의 기록은 두 군데서 옴
  - **Runary 측정 기록**: Runary로 직접 뛴 기록. 기기에만 있어서 앱을 지우면 사라짐
  - **건강 앱 기록**: 애플워치 운동 앱 등 다른 앱으로 뛰고 건강 앱에서 불러온 기록. 원본이 건강 앱에 남아 있음
- [로그인 PRD](../../specs/prd/account-login.md)는 서버 백업 대상을 **Runary 측정 기록만**으로 정함
  - 건강 앱 기록은 원본이 남아 있어 백업이 필요 없음
- 그런데 크루원끼리 경로를 보려면 그 기록이 서버에 있어야 함
  - Runary 측정 기록만 올리면, 다른 앱으로 뛰는 사람은 크루에 보여 줄 기록이 없음

### 선택지

| | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | Runary 측정 기록만 공유 | 백업한 기록을 그대로 쓰므로 추가 작업 없음 | 다른 앱으로 뛰는 크루원은 참여 불가 |
| B | 건강 앱 기록도 전부 자동으로 서버에 올려 공유 | 어떤 앱으로 뛰든 크루에 보임 | 다른 앱 데이터까지 서버에 쌓임. 개인정보 처리방침 범위가 커짐 |
| C | 두 출처 모두 가능. 단, 사용자가 공유할 기록을 직접 고를 때만 올림 | 다른 앱 사용자도 참여 가능. 올리는 기록을 사용자가 통제 | "공유할 기록 고르기" 화면이 하나 늘어남 |

### 같이 볼 것

- 크루원에게 경로를 보여 줄 때 집·회사 위치를 어떻게 할지 ([11/10 결정](../../decisions/2026-11-10-third-sprint-crew-diary.md)에서 미정). 어느 선택지든 경로가 그대로 보이면 생기는 문제
- 현수의 크루 화면 디자인(경로 조회)에 "공유할 기록 고르기"가 들어가는지

### 정할 것

- A, B, C 중 무엇으로 갈지
- 정해지면 크루 PRD에 반영. B나 C면 [로그인 PRD](../../specs/prd/account-login.md) §4 기록 백업과 개인정보 처리방침 범위도 함께 고침
