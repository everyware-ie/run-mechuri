# 2026-10-06 회의 제안: 쓰는 사람이 어디서 빠지는지 보자

*2026-10-06 · jminkkk · 개인 제안이고 팀 결정이 아니다*

- 공개 링크를 연 지 2주가 됐다
- 반응은 카톡과 스레드로 들어온다
- **앱을 연 사람이 결과물까지 가는지는 아무도 모른다**

## 왜 해야 하나

- **고칠 곳을 말로 정하고 있다**
  - 생성이 느리다는 말이 나와서 장면을 둘씩 동시에 그리기로 했다 ([9/29 결정](../../decisions/2026-09-29-export-parallel-rendering.md))
  - 시안을 보고 편집 화면을 바꾸기로 했다 ([10/4 결정](../../decisions/2026-10-04-story-style-editor.md))
  - 둘 다 틀렸다는 뜻은 아니다. 사용자가 실제로 그 지점에서 막히는지는 확인하지 않았다
- **확인하려던 질문에 아직 답이 없다**
  - [PRD](../../specs/prd/running-drawing-mvp.md) §5 검증 항목: "직접 측정하지 않더라도 공유를 목적으로 예쁜 경로 그림 결과물을 얻고 싶어하는 니즈가 있는지"
  - 지금 근거는 지인 몇 명의 반응뿐이다
  - 앱을 깔고 조용히 안 쓴 사람은 반응을 남기지 않아서 보이지 않는다
- **다듬는 단계라 순서가 중요하다**
  - [9/8 결정](../../decisions/2026-09-08-scope-and-roles.md)으로 두 사람이 성능 개선 리서치를 맡았다
  - 근거가 없으면 눈에 띄는 것부터 고치게 된다
- **다음 기능을 고를 근거가 없다**
  - PRD §10 로드맵의 그룹 드로잉은 서버와 계정이 필요한 큰 작업이다
  - 혼자 만든 결과물을 공유하는 사람이 얼마나 되는지 모르면 투자할지 판단할 수 없다
- **요약**
  - 지금 보이는 것: "누가 뭐라고 했다"
  - 보여야 하는 것: "몇 명이 어디까지 갔다"

## 제안하는 활동

- 넷은 순서대로 걸려 있다
- **1. 행동 로그를 남긴다**
  - 이게 없으면 2와 4를 못 한다
- **2. 단계별로 어디서 빠지는지 본다**
  - 핵심 흐름이 끝까지 돈다. 다음에 고칠 곳을 정할 근거가 필요하다
- **3. 들어온 반응을 나눠 적는다**
  - 반응을 레포에 모으기로 이미 정했다. 나눌 기준만 더하면 된다
- **4. 지표를 한두 개 정한다**
  - 성능 개선이 효과가 있었는지 잴 기준이 없다

---

## 1. 행동 로그를 남긴다

- **앱에는 지금 분석 도구가 없다**
  - `frontend/package.json`에 분석 SDK가 없다
  - 코드에도 이벤트를 보내는 곳이 없다 (2026-10-06 확인)
- **이벤트는 2의 단계를 볼 만큼만 잡는다**
  - 앱 열기: 홈에 들어왔을 때
  - 기록 선택: 러닝 기록을 하나 골랐을 때
  - 편집 진입: 편집 화면이 열렸을 때
  - 생성 완료: 영상이 다 만들어졌을 때
  - 공유: 인스타 스토리로 넘기거나 저장했을 때
- **도구를 고르기 전에 정할 것**
  - 처리방침에 사용 기록 수집을 추가해야 한다. 어디까지 고쳐야 하는지는 `[확인 필요]`
  - 고친 처리방침이 심사에 영향을 주는지 `[확인 필요]`
  - 도구는 아직 고르지 않았다. 회의에서 하자고 하면 후보를 비교한다

## 2. 단계별로 어디서 빠지는지 본다

- **흐름:** 앱 열기 → 기록 선택 → 편집 진입 → 생성 완료 → 공유
- **가장 많이 빠지는 칸이 다음에 고칠 곳이다**
  - 지금은 생성이 느리다는 말이 많아서 그쪽을 고치고 있다
  - 실제로 그 칸에서 가장 많이 빠지는지는 아직 모른다
- **지금 사용자 수로는 숫자가 흔들린다**
  - 몇 명이 빠졌는지만 보고, 비율로 판단하지 않는다

## 3. 들어온 반응을 나눠 적는다

- **지금:** [QA 기록](../../ops/qa-log.md)과 [9/29 결정](../../decisions/2026-09-29-weekly-content-and-reactions.md)으로 반응을 레포에 모은다
- **제안:** 두 칸을 더한다
  - 종류: 버그 / 불편 / 바라는 것 / 칭찬
  - 처리: 바로 고침 / 정해야 함 / 안 함
- **목적:** 같은 말이 몇 번 나왔는지 보이게 한다
  - 지금은 한 번 나온 말과 다섯 번 나온 말이 똑같이 한 줄이다

## 4. 지표를 한두 개 정한다

- **생성 완료율** (편집 진입 대비 생성 완료)
  - 만들다 그만두는지 알 수 있다
  - 성능 개선이 효과가 있었는지 알 수 있다
- **주간 공유 수**
  - [PRD](../../specs/prd/running-drawing-mvp.md) §5 검증 질문에 가장 가까운 숫자다
- **목표 수치는 아직 정하지 않는다**
  - 처음 2주 동안 재 본 다음에 정한다

## 이번에 하지 않는 것

- **코호트·재방문 분석, A/B 테스트**
  - 사용자가 몇십 명 쌓인 뒤. 지금은 숫자가 의미 없다
- **유입 경로별 성과** (스레드·카톡·지인)
  - 유입 출처를 추적할 수단이 생긴 뒤
- **리포트 자동화**
  - 손으로 낸 리포트를 세 번쯤 반복한 뒤

- 남긴다면 누가 맡을지, 처리방침은 누가 고칠지
- 3의 두 칸을 QA 기록에 바로 더할지
