# 시안과 FRD가 부딪치면 FRD를 따른다, 기본 배경 3장 확정, 설정 화면 제외

> 구현이 시작되고 처음으로 **스펙과 디자인이 실제로 부딪친** 회의다.
> 배경과 논의 과정: [2026-09-01 회의 종합](../meetings/2026-09-01/synthesis.md)

## 결정

### 1. 시안과 FRD가 부딪치면 FRD를 따른다

**디자인 시안을 코드로 옮기다 충돌이 잦았다.** 시안이 말하는 것과 FRD가 말하는 것이 달라서, 충돌마다 사람이 확인하고 하나씩 판단해야 했다. 그만큼 느려진다.

**FRD가 기준이다.**

#### 다만 FRD가 항상 옳다는 뜻은 아니다

**FRD대로 만들었더니 불편하거나 이상하면 이슈로 올려 FRD를 고친 뒤 진행한다.**

이 단서가 결정의 절반이다. 없으면 "문서가 그러니까 어쩔 수 없다"가 되어 제품이 나빠진다. **바꾸지 말자는 것이 아니라 조용히 갈라지지 말자는 것이다.** 구현이 스펙을 말없이 앞지르면 나중에 어느 쪽이 맞는지 알 수 없게 된다.

[CLAUDE.md의 정합성 규칙](../../CLAUDE.md) 2번("스펙이 조용히 제품 정의를 바꾸지 못하게 한다")을 시안 쪽으로 넓힌 것이다.

#### 왜 시안이 아니라 FRD인가

| | |
|---|---|
| FRD는 **팀이 확정한 것**이다 | 2026-08-25 회의에서 일곱 개를 함께 `approved`로 올렸다 |
| 시안은 **한 사람의 산출물**이다 | 좋은 제안이지만 팀 승인 절차를 거치지 않았다 |
| 훅이 FRD를 강제한다 | `approved`가 아니면 PR이 막힌다. 시안에는 그런 장치가 없다 |

### 2. 기본 배경 3장을 확정한다

배경 10장 중 셋을 골랐다.

| | 파일 |
|---|---|
| 아침 | `아침-1-빛없음.png` |
| 점심 | `점심-3-맑은한낮.png` |
| 저녁 | `저녁-3-맑은노을.png` |

**세 시간대에서 하나씩이고, 셋 다 빛을 얹지 않은 가장 담백한 쪽이다.** [배경 선택 FRD](../specs/frd/background-selection.md) §2-1이 정한 3장 규격을 그대로 채운다. 그 문서의 `[확인 필요]`("기본 이미지 3장의 실제 소재와 출처")가 이 결정으로 닫힌다.

**나머지 일곱 장은 버리지 않는다.** 레포에 남기고 나중에 늘릴 때 쓴다.

### 3. 설정 화면은 이번 범위에서 뺀다

jminkkk 시안 S9에 있었고 목업 구현 6단계 중 마지막이었다. **그런데 FRD 어디에도 없다.**

결정 1을 그대로 적용한 첫 사례다. 시안에 있다는 것만으로는 구현 근거가 되지 않는다.

### 4. 편집 화면이 느린 것은 1차 MVP에서 감수한다

**완성된 mp4는 속도가 괜찮은데 편집 과정이 굉장히 느리다.** Swift로 그렸을 때 너무 느려서 미리보기를 JS로 바꿨고, 원인은 "움직이는 것"으로 추측하고 있다.

**지금은 고치지 않는다.** 1차 MVP의 타겟 사용자가 팀 셋이고, 부분을 빠르게 만드는 것보다 **끝까지 도는 완성본**을 만드는 것이 먼저다. (phs00 판단)

**감수하는 것이지 문제가 없다는 뜻은 아니다.** 외부 사용자가 들어오는 시점에 다시 본다. [PRD §12 리스크와 폴백](../specs/prd/running-drawing-mvp.md)에 남겼다.

### 5. 08-18 미해결 4건을 닫는다

백엔드 인력 배치, 재방문 유인, "예쁘다"의 기준 육안 합의, PRD 단독 결정 승인.

**세 번의 회의를 지나면서 계속 미뤄졌다.** 더 끌지 않고 닫는다. 각 항목의 상태는 [2026-08-18 결정문](2026-08-18-native-ios-and-mvp-scope.md)에 개정으로 붙였다.

### 6. 제품명은 "메추리런"으로 두고 계속 본다

빌드에 그렇게 넣었다. 대안으로 "런메추리"가 나왔다.

**확정이 아니다.** TestFlight 단계까지는 이름을 꽤 쉽게 바꿀 수 있어서 그전까지 계속 아이디에이션한다.

## 9/1 목표는 절반 달성이다

결정은 아니지만 이 회의의 가장 중요한 사실이다.

| 9/1 목표 | 상태 |
|---|---|
| TestFlight 1차 빌드 | **달성.** 셋이 각자 아이폰에 설치해 쓰고 있다 |
| 베타 심사 통과 | **미착수** |

**지금 하고 있는 것은 내부 테스트다.** 셋 다 App Store Connect 팀 멤버라 심사 없이 설치된다. **9/22 출시 정의인 "TestFlight 공개 링크"는 외부 테스트 기능이라 베타 심사를 반드시 통과해야 한다.**

**일정을 재조정하지 않았다.** 역산표의 9/8 기능 동결과 9/22 출시는 그대로다.

## 확정하지 않은 것

1. **베타 심사 제출 시점.** 9/22가 여기에 걸려 있다
2. **일정 재조정.** 9/1이 절반만 달성됐는데 역산표는 그대로다
3. **인스타 스토리 공유.** 브릿지 셋 중 마지막이고 MVP 필수인데 미착수다
4. **배경 나머지 3건.** 파일이냐 코드냐, 배경별 선 색, 팀 문양 확산
5. **가민·코로스 확인.** 누가 언제 볼지 정하지 않았다
