# 심사가 막히면 출시일을 미룬다, 각인 가독성이 최우선, 편집 화면 손질

> 출시 엿새 전 회의다. **실사용이 왜 한 건도 없었는지가 드러났고, 그것이 작업 순서를 바꿨다.**
> 배경과 논의 과정: [2026-09-16 회의 종합](../meetings/2026-09-16/synthesis.md)

## 1. 각인 가독성이 최우선 작업이다

**W5 실사용 주간에 아무도 결과물을 올리지 않았다.** 일정이 없어서가 아니었다.

> 퀄리티를 높이고 올리고 싶다. **화질이 안 좋다. 각인이 흐리게 보이고 안 이쁨.**
> 또렷한 검정, 또렷한 회색으로 **좀 더 또렷하게**.
> **뒤에 배경까지 하면 각인 글씨가 잘 안 보임**

**만든 사람들이 자기 결과물을 내놓기를 주저했다.**

### 왜 이것이 순위를 바꾸나

**공유가 이 제품의 목적이다.** PRD §5는 이번 라운드에서 "직접 측정하지 않더라도 **공유를 목적으로** 예쁜 드로잉 결과물을 얻고 싶어하는 니즈가 있는지"를 검증한다고 했다.

**만든 사람도 안 올리는 결과물로는 그 검증을 할 수 없다.**

### 한 번 놓쳤던 신호다

> 지응 2026-09-14: "뭔가 **글씨가 빛나는 효과가 있어서 그런지** 살짝 화질이 안 좋아 보인다고 해야 되나"

[QA 기록](../ops/qa-log.md)에서 "나중에 볼 것"으로 분류했었다. **그 판단이 틀렸다.**

### 무엇을 보나

| | |
|---|---|
| 또렷함 | 지금은 흐리게 보인다. **또렷한 검정과 또렷한 회색**을 쓴다 |
| 사진 배경 위 | **가장 심한 곳이다.** 배경이 있으면 글씨가 묻힌다 |
| 빛 효과 | 글로우·그림자가 화질을 떨어뜨려 보이게 하는지 함께 본다 |

구체적인 값은 [경로 렌더링 FRD](../specs/frd/route-rendering.md)에서 다루고, 실제 값은 실기기에서 보며 정한다.

## 2. 9/22는 유지하되 막히면 미룬다

**베타 심사는 우리가 통제할 수 없는 구간이다.**

> 출시일을 미룰 수밖에. **사유 고치고 다시 신청하고 반복**

| | |
|---|---|
| 목표 | **9/22 그대로** |
| 막히면 | **미루는 것을 허용한다.** 리젝 사유를 고쳐 재신청하고 반복한다 |

**출시 정의는 건드리지 않는다.** 날짜만 움직인다.

## 3. 출시 = 공개 링크를 열고 스레드와 지인에게 공유한다

PRD §1의 정의(**"출시" = TestFlight 공개 링크**)를 그대로 유지한다.

| | |
|---|---|
| **공개 링크** | 연다. 이것이 출시다 |
| **어디에 공유하나** | **스레드**와 **지인**. 내려받아 쓸 수 있게 한다 |
| **외부 테스터** | **모집하지 않는다.** 링크를 닫는다는 뜻이 아니다 |

지인은 다섯이다. 준익, 수미, 준민, 규영, 준호.

**"외부 테스터를 안 받는다"와 "공개 링크를 연다"가 부딪쳐 보이지만 다른 층이다.** 링크는 열려 있고 우리가 모집을 하지 않을 뿐이다.

## 4. 편집 화면

### 4-1. 장소 각인은 빠뜨린 것이었다 (A안)

장소가 안 나오던 네 프리셋(**코너·레일·스탯바·원라인**)에 **전부 장소를 넣는다.**

**[경로 렌더링 §6 프리셋이 정하는 것은 자리뿐이다](../specs/frd/route-rendering.md)가 그대로 유지된다.** 프리셋은 자리만 정하고 무엇을 보일지는 사용자가 정한다.

### 4-2. 각인 터치 영역을 줄이고, 드로잉 영역을 보이게 한다

> **각인 터치 영역을 조금 더 최소화.** 실제 영역에 가깝게.
> 예: **코너의 터치 영역이 가장 큰 사각형**인데 **드로잉을 선택하는 과정이 불편함**
> 편집의 **드로잉 영역도 터치 영역을 점선으로 표기**한다. 각인처럼

**각인을 감추자는 안은 채택되지 않았다.** 감추면 "보이는데 안 만져진다"가 "모르던 게 나왔다"로 옮겨갈 뿐이다.

대신 **만질 수 있는 자리를 눈에 보이게** 한다.

### 4-3. 간결 프리셋을 뺀다

**일곱에서 여섯이 된다.** 원라인과 비슷하다는 이유다.

원라인은 **문구 크기를 줄이고 위치를 살짝 내린다.** 지금 너무 크게 나온다.

### 4-4. 도구와 안내

| | |
|---|---|
| **스토리 안전 영역** | **기능을 뺀다** |
| **재생 버튼** | **이름을 붙인다.** 초기화 버튼처럼 |
| **각인 초기화** | **새로 넣는다.** 탭마다 그 탭의 것만 초기화한다 |
| 제스처 안내 | `[확인 필요]` **토스트로 띄우는 것을 검토한다.** 확정이 아니다 |

**스토리 안전 영역을 빼는 것은 [결과물 편집 FRD §1 화면 구조](../specs/frd/result-editing.md)의 개정이다.** 2026-09-11에 "재생·스토리 안전 영역 버튼을 하단 도구 패널의 탭 옆에 둔다"고 정했던 것이 사라진다.

### 4-5. 빈 화면 문구는 기획안대로

경로가 없는 기록을 목록에서 빼면서 생기는 세 번째 빈 화면에, **걸러낸 기록 수를 보여주는 문구**를 둔다.

## 5. 화면에 쓰는 말을 바꾼다

| 어디 | 전 | 후 |
|---|---|---|
| 단계 탭 | 드로잉 | **경로** |
| 단계 탭 | 각인 | **러닝 데이터** |
| 각인 안의 탭 | 넣을 것 | **항목** |
| 대시보드 | 내가 만든 것 | **MY RUNARY** |

**문서도 함께 바꾼다.** 화면에서 바뀐 말은 문서에도 반영하는 것이 팀의 기준이다. (2026-09-16 phs00)

### 별도 작업으로 분리한다

**문서 155곳, 구현 노트까지 300곳이 넘는다.** 절 제목 셋(`§7 각인과 문구`, `§7 각인과 한 줄 문구`, `§6-1 기본 드로잉`)과 그것을 참조하는 곳까지 함께 고쳐야 한다.

**회의 결과 문서화와 섞으면 기계적 치환에 묻혀 검토가 불가능해진다.** 그래서 나눈다.

### 문서에서는 셋으로 나눠 쓴다

**문서에서 "경로"는 137번 쓰이고 거의 전부 GPS 경로를 뜻한다.** 드로잉을 그냥 "경로"로 바꾸면 한 말이 두 뜻이 된다. [용어집](../../.claude/domain/glossary.md)이 **"같은 말을 두 뜻으로 쓰는 것이 가장 흔한 어긋남"**이라고 적어둔 경우다.

특히 이런 문장이 무너진다.

> 경로는 시간순 좌표열이고 **드로잉은 그 위를 따라가는 애니메이션**이다

한 문장 안에 GPS 경로와 그 위의 그림이 나란히 있고 **서로 다른 것**이다.

**그래서 셋으로 나눈다.** 전부 "경로"로 시작해 일관되고 GPS 경로와도 섞이지 않는다.

| 무엇 | 말 |
|---|---|
| 화면 라벨 | **경로** |
| 문서에서 **그 탭**을 가리킬 때 | **경로 탭** |
| 문서에서 **그 그림**을 가리킬 때 | **경로 그림** |

**용어집은 이 PR에서 먼저 고쳤다.** 용어를 바꾸면 용어집부터 고치는 것이 규칙이기 때문이다. 나머지 문서의 치환은 별도 작업이다.

## 7. 확인만 하고 넘어간 것

**실기기에서 묻던 네 건이 전부 해결된 것으로 확인됐다.** 결과물이 잘리는 것, 다시 편집하면 이상하게 뜨는 것, 저장한 것과 편집 화면의 위치가 다른 것, 화면에서 각인을 눌러 고르는 것.

**앱 안 처리방침 링크**는 기능 추가 1순위로 넣는다.

회의에서 "TestFlight에서는 필요 없고 정식 출시 때 필요한 항목"이라는 이야기가 나왔다. **경험적 추론이라고 밝히고 말한 것이라 그대로 적어 둔다.** 넣기로 정했으므로 이 추론이 맞든 틀리든 결과는 같다.
