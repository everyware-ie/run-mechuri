# 2차 스프린트는 정식 등재부터, 측정은 안정성 먼저

> 배경과 논의: [2026-10-06 회의 종합](../meetings/2026-10-06/synthesis.md)

## 1. 2차 스프린트

- 기간은 10/6부터 **11/17(화)까지 6주**다
- 지금 버전으로 먼저 App Store에 정식 등재하고, 사용하면서 그룹 기능을 넣는다
- 측정 기능은 안정성을 먼저 잡는다. 서버가 필요한 작업은 그 뒤에 한다

## 2. 정식 등재를 두 번에 나눈다

| 단계 | 언제 | 무엇 |
|---|---|---|
| 1차 | 10/13(화)까지 준비 | 측정 기능을 뺀 버전 |
| 2차 | 11/3 ~ 11/10(화) | 측정 기능을 넣어 다시 제출 |

정식 등재에 낼 빌드는 최신 빌드가 아니어도 된다. 어느 빌드를 냈는지 [배포 기록](../ops/build-and-dev-commands.md)에 따로 남긴다.

## 3. 목표

| 지표 | 목표 |
|---|---|
| App Store 다운로드 | 30회 |
| 스레드 팔로워 | 50명 |

## 4. 사용성 테스트는 하지 않는다

지민이 제안한 외부 러너 대상 UT와 인터뷰를 이야기했지만 하지 않기로 했다.

## 5. 측정 기능의 기준

회의 뒤 현수가 정했다 (2026-10-07 phs00).

- **최소 기준은 유명 러닝 앱과 같은 방식이다.** 나이키 런, 스트라바 같은 앱과 같은 방식으로 제공해서 측정에 기능적인 하자가 없게 한다. GPS가 끊긴 구간도 그 앱들의 처리 방식을 확인해서 맞춘다
- **심박은 건강 앱에서 불러온다.** 나이키 런처럼 애플 운동 같은 다른 운동 앱과 동시에 측정할 수 있게 한다
- **QA는 각자 달릴 때 틈틈이 한다**

## 정하지 않은 것

- 1차 정식 제출일
- 측정 기능의 공개 범위
- 유명 러닝 앱들이 GPS가 끊긴 구간을 실제로 어떻게 처리하는지 (조사가 필요하다)
- 지민 제안의 행동 로그 수집과 대표 지표

## 2026-10-07 구현 범위 보완

현수가 건강 앱 심박 불러오기와 권한 반복 요청 수정의 FRD 정리·구현을 승인했다. 건강 앱 불러오기를 기본으로 제공하고 기존 Runary 워치 직접 측정은 별도 선택으로 유지한다. 종료 후 동기화된 심박을 다시 불러오며 오래된 값은 현재 심박으로 표시하지 않는다. 공개 범위와 배포 일정은 이번 승인으로 바꾸지 않는다.

## 2026-10-07 사용자 정정: 건강 앱 읽기와 워치 표시

사용자가 심박은 다른 운동 앱에 영향을 주지 않는 건강 앱 읽기로 고정하고 방식 선택을 제거하도록 정정했다. 위 구현 범위 보완의 직접 측정 별도 선택은 이 정정으로 대체한다. 워치는 자체 운동을 시작하지 않고 아이폰 지표 표시·제어를 맡는다. 아이폰에서 시작한 러닝이 워치에 표시되지 않는 문제도 함께 수정한다. 자동 전면 실행과 상태 전달·설치를 구분하며, 운동 세션 시작 API로 다른 운동 앱을 방해하지 않는다.

## 2026-10-07 사용자 보완: 자동 상태 갱신과 워치 실행 검증

개발 앱의 현재 러닝 누락·종료 후 새 시작 반영 지연을 수정하고 정상 대기 화면의 다시 연결 버튼을 제거한다. 워치에서도 아이폰 GPS 러닝의 시작·재개를 요청하며 조건을 만족하면 같은 요청을 한 번만 반영한다. 빈 지표는 `-`로 표시한다. 사용자는 심박 미수신 테스트에서 Runary만 실행했다고 확인했다.

사용자가 건강 앱 방식을 유지하면서 워치 앱을 여는 경로를 확인하도록 요청했다. 앱 실행 요청과 운동 세션 생성이 별개임을 확인하고 내부 빌드에서 공개 API의 실행 요청만 검증한다. 자체 워치 운동·연속 심박 수집은 추가하지 않는다. Nike의 내부 API와 Runary 단독 실행의 20~30초 심박 수신은 확인되지 않았다. 세부 기준은 [내부 측정 FRD](../specs/frd/internal-run-tracking.md) §8-4 자동 상태 갱신과 워치에서 시작·§8-5 건강 앱 방식을 유지하는 워치 실행 검증에 둔다.


## 2026-10-08 사용자 승인: 워치 건강 저장소 직접 전달

워치 건강 저장소의 심박 읽기를 실기기에서 확인한 뒤 사용자가 직접 전달 수정안의 구현을 승인했다. 워치에서 읽은 건강 심박을 페어링된 아이폰의 같은 러닝 기록에 전달해 아이폰 건강 동기화 지연을 보완한다. 심박 출처는 건강 앱 방식으로 유지하고 다른 운동 세션을 제어하지 않는다. 자체 운동 세션은 별도 3분 실험으로 남으며 일반 러닝의 자동 시작에 합치지 않는다. [내부 측정 FRD](../specs/frd/internal-run-tracking.md) §8-7 워치 건강 저장소의 심박 직접 전달에 범위·중복·권한·검증 기준을 둔다.
