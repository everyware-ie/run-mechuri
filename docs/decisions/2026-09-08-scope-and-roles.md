# 배경 소재 두 가지를 MVP에 넣는다, 각인 표시 모드 개정, 역할 변경

> 기능 동결일에 내린 결정이다. **동결하면서 예외를 하나 뒀고, 역할을 다시 나눴다.**
> 배경과 논의 과정: [2026-09-08 회의 종합](../meetings/2026-09-08/synthesis.md)

## 결정

### 1. 갤러리에서 고르기와 그 자리에서 찍기를 이번 빌드에 넣는다

[배경 선택 FRD](../specs/frd/background-selection.md) §1이 배경을 다섯으로 나누고 **1번(기본 이미지)만 MVP**로 잡아뒀다. 나머지 넷은 "여유 시"였다.

**그중 둘이 올라온다.**

| # | 배경 | 전 | 후 |
|---|---|---|---|
| 1 | 우리가 제공하는 기본 이미지 | MVP | MVP |
| **2** | **갤러리에서 고른 사진** | 여유 시 | **MVP** |
| 3 | 갤러리에서 고른 영상 | 여유 시 | 여유 시 |
| **4** | **그 자리에서 찍은 사진** | 여유 시 | **MVP** |
| 5 | 그 자리에서 찍은 영상 | 여유 시 | 여유 시 |

**전원 동의했다.**

#### 왜 이 둘인가

**§1-1이 정한 붙이는 순서 그대로다.** 그 문서가 "여유가 조금만 생기면 무엇부터 할지"를 미리 정해뒀고, 지금이 그 시점이다.

**사진 위에서 드로잉이 어떻게 얹히는지를 가장 빨리, 가장 다양한 소재로 볼 수 있는 경로**이기 때문이다(§1-1). 기본 이미지 셋만으로는 그것을 알 수 없다. **W5 실사용이 내일 시작하므로 지금 들어가야 그 관찰이 가능하다.**

**영상은 그대로 둔다.** 길이 처리와 반복 재생이 붙어서 무게가 다르다.

#### 사진 권한이 붙는다

**갤러리에서 고르기는 권한이 필요 없다**(PHPicker). **그 자리에서 찍기는 카메라 권한**이 필요하고, 찍은 것을 갤러리에 남기려면 **사진 쓰기 권한**이 붙는다([내보내기·공유](../specs/frd/export-and-share.md) §4-3).

**사진 쓰기는 이미 결과물 저장에서 쓰고 있으므로 새로 늘어나는 것은 카메라 하나다.** 스토어 제출물에 usage description 문구가 하나 더 필요해진다.

### 2. 각인 표시 모드 선택을 없앤다

[경로 렌더링](../specs/frd/route-rendering.md) §7-2가 **항상 / 완성 후만 / 숨김** 셋을 사용자가 고르게 해뒀다. **시안에 그 UI가 없었고 구현에서도 뺐다. 문서를 구현에 맞춘다.**

**"항상" 하나로 고정한다.**

#### 잃는 것이 적다

| 없앤 모드 | 무엇이 대신하나 |
|---|---|
| 숨김 | **각인 항목을 다 끄면 같다**(§7-4). 항목이 여섯이라 하나씩 끌 수 있다 |
| 완성 후만 | §7-2 자신이 "3주차 반응 테스트에서 확인한다"고 열어둔 항목이었다 |

**편집 화면이 이미 붐빈다.** 프리셋, 크기·위치·회전, 다듬기 두 축, 각인 여섯, 문구까지 들어간다. 여기에 모드 선택을 더할 자리가 아니다.

#### 퍼널이 나뉘면 다시 본다

회의에서 **편집을 여러 단계로 나누자는 안**이 나왔다.

```
지금:  배경 설정 → 편집(프리셋·각인을 한 화면에서)
제안:  배경 설정 → 프리셋 설정 → 각인 설정 → 완료
```

참고: [토스 기술 블로그 - 퍼널](https://toss.tech/article/engineering-note-1). **편집 순서 자체를 고르게 하는 방향**도 함께 이야기됐다.

**각인이 자기 화면을 갖게 되면 자리가 생긴다.** 그때 표시 모드를 다시 넣을지 본다. **이 결정은 그때까지의 것이다.**

**구현하는 사람이 그 부분을 진행할 때 판단한다.** 지금 퍼널을 어떻게 나눌지까지 정하지 않는다.

### 3. 한글 폰트는 Pretendard

지금 폰트 셋(Space Grotesk, JetBrains Mono)에 **한글 글리프가 없다.** 각인 프리셋에서 이미 폴백이 걸리고 있었고, 한 줄 문구를 구현하려면 반드시 필요하다.

**해당 작업을 진행할 때 다시 검토한다.** 확정하되 못을 박지는 않는다.

### 4. 역할을 다시 나눈다

| 사람 | 전 | 후 |
|---|---|---|
| **phs00** | 홍보·마케팅, 기획 문서 | **+ 구현** |
| **jminkkk** | 디자인 | **성능 개선 리서치** |
| **JiEung2** | 개발 | **성능 개선 리서치** |

**phs00이 구현을 이어받는다.** 첫 작업은 편집 화면 상단의 재생 관련 버튼 글씨다.

**둘이 성능으로 옮기는 이유**는 핵심 플로우가 end-to-end로 돌기 시작했기 때문이다. 만드는 일에서 다듬는 일로 무게가 옮겨간다.

## 결정이 아니지만 기록해 둘 것

### 인스타 공유가 풀렸다

**세 번의 실기기 실패 원인은 Meta 앱이 '개발중' 상태였던 것이다.** '운영중'으로 돌리니 동작한다.

의심했던 `com.instagram.sharedSticker.backgroundVideo` 키 문제도, 계정 등록 문제도 아니었다. **[내보내기·공유 FRD](../specs/frd/export-and-share.md) §5의 우선순위를 그대로 둔다.** 안건에서 "MVP 필수의 무게를 다시 잡자"고 제안했던 것은 필요 없어졌다.

### 베타 심사를 9/10에 신청한다

**TestFlight에는 심사가 둘이고 지금까지 한 것은 내부 개발자 심사다.**

| | 대상 | |
|---|---|---|
| 내부 개발자 심사 | 애플 개발자 센터에 등록된 관리자만 | 간단하다. 2분쯤 |
| **베타 심사** | 공개 링크. 외부 테스터 최대 1만 명 | **9/22에 필요한 것** |

소요는 보통 하루, 늦으면 5일이다. **통과하는지부터 확인하려고 먼저 신청한다.**

`[확인 필요]` 신청 전 내부 점검이 필요하다. 앱 안에 "베타" 글씨가 들어가 있으면 안 되는 것 같은 항목들이다.

## 확정하지 않은 것

1. **퍼널 분리.** 방향만 나왔고 구현 시점에 판단한다
2. **첫 실행 연결 화면의 자리.** 아래 참고
3. **배경 나머지 3건.** 파일이냐 코드냐, 배경별 선 색, 팀 문양 확산
4. **가민·코로스 확인.** 세 번째 회의째 미정
5. **제품명.** 빌드에는 "메추리 런"이 들어갔지만 확정 선언은 없었다
6. **스트라바를 어떻게 볼지.** 제안만 나왔다

> **첫 실행 연결 화면이 FRD와 어긋나 있다.** 9/2~9/3에 만들어진 화면인데, [홈과 보관함](../specs/frd/home-and-library.md) §4-2가 **"첫 실행에만 나오고 사라지는 화면이면 그 역할을 못 한다"** 고 정해뒀다. 프리셋이 늘 때 알릴 자리로 써야 한다는 이유였다.
>
> **지금 정하지 않고 W5 실사용 뒤에 본다.** 내일부터 셋이 써보면 그 화면이 다시 필요한지가 드러난다. 지금 정하면 근거 없이 정하는 것이 된다. (phs00 판단)

## 2026-09-11 사진 배경 구현 시 보완

phs00이 갤러리·촬영 사진 구현을 요청하며 두 가지를 확인했다.

- 다시 열어서 구도를 바꿀 수 있도록 편집용 사진과 조정값을 앱 안에 보관한다. 사진 원본을 복사하지 않던 규칙은 사진에 한해 개정한다.
- 정확한 iCloud 다운로드 진행률은 사용자 경험상 유리하지만, MVP 단계와 공수를 고려해 이번에는 시스템 안내와 앱의 작업 안내·취소를 사용한다. 정확한 진행률은 후속 개선 대상으로 문서화한다.

정본은 [배경 선택 §4 사진 처리·§6 불러오기와 대기](../specs/frd/background-selection.md), 구현 및 후속 항목은 [사진 배경 구현 노트](../product/features/photo-backgrounds.md)에 둔다.
