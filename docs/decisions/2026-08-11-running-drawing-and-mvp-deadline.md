# 러닝 주제를 "러닝 드로잉"으로 확정, MVP 출시 9/22

> 이 결정은 kill-betting과 함께 논의된 **통합 회의**에서 나왔다. 회의 종합 전문은 허브에 있고(위 `related_meeting`), 이 문서는 그중 **러닝 제품에 효력을 갖는 부분만** 옮긴 것이다.
>
> 허브 링크는 private repo라 GitHub 로그인 상태에서만 열린다. **이 레포 안에서 러닝의 결정을 확인하려면 이 문서가 1차 근거다.**

## 배경

관련 회의: [2026-08-11 통합 회의 종합](https://github.com/everyware-ie/mechuri-docs/blob/main/meetings/2026-08-11/synthesis.md) (허브, private)

08-04 회의에서 다음 발산 주제를 "공유하고 싶은 기능"으로 좁힌 뒤([topics/concept-candidates.md](../topics/concept-candidates.md)), 각자 `docs/ideation/<닉네임>/`에 고도화한 결과를 08-11에 종합했다.

## 선택지

발산된 후보는 다섯이었다.

- **그룹 기능** - 같은 날 뛴 각자 경로를 이미지화, 또는 미리 그릴 그림을 골라 챌린지 형식으로 완성
- **러닝 기록** - 뛰다가 발견한 것을 사진으로 기록
- **경로 공유** - 인스타에 올린 코스를 앱에서 가져와 네비게이션으로 안내
- **속도별 색 변화** - 내 전 기록과 비교
- **드로잉** - 뛴 코스로 그린 그림

## 결정

### 1. 주제: 러닝 드로잉

- **"잘 그려지면 된다"가 최우선이다.** 지도와 달린 거리를 바탕으로 예쁘게 그려지는 것.
- 그룹 드로잉까지를 시야에 둔다.
- **AI 이미지 생성은 현 단계에서 도입하지 않는다.** 회의록에 "AI를 활용해 귀여운 이미지를 만들어주는"이라고 적힌 항목은 발산 중 나온 아이디어이며 도입 대상이 아니다(phs00 확인). 따라서 **렌더링 완성도가 "우와"를 만드는 유일한 레버**다.

### 2. 일정

| 항목 | 날짜 |
|---|---|
| MVP 출시 목표일 | **2026-09-22(화)** |
| 팀 목표 검증 기간 | ~2026-09-29(화) |

추석 연휴 9/24~27에 지인 영입을 노린다. 출시가 밀리면 검증 기회 자체가 줄어든다.

역산 6주: W1 조사와 결정 / W2 코어 루프 관통 / W3 퀄리티 집중 / W4 공유 흐름, 기능 추가는 여기서 끊음 / W5 실사용 / W6 버그와 배포.

### 3. 프로덕트 목표: 정성 목표로 확정

여러 정량 후보(사용 횟수 n회, 주 1회 이상 사용, 해피케이스 완주 등)를 놓고 논의한 끝에 정성 목표로 확정했다.

> **우리가 서비스를 써서 인스타 스토리에 처음 올렸을 때, 주변인에게 "우와" "이거 뭐야?" 소리를 1회 이상 듣기**

### 4. 기준이 되는 결과물

[JiEung2 목업(08-04)](../ideation/JiEung2/2026-08-04-route-overlay-mockup.html)이 정의하는 형태 - 러닝 영상 위에 경로가 살아 움직이는 9:16 세로 클립이며 정적 이미지가 아니다.

## 이 회의에서 확정하지 않은 것

MVP 범위는 **추천안까지만** 나왔고 1주차 조사 후 확정하기로 했다. 1주차 종료 시 확정할 항목은 다섯이다.

1. 배포 형태 (웹 / iOS 앱 / 웹 먼저 후 앱)
2. 데이터 확보 방식 (GPX 업로드 / HealthKit / 자체 트래킹)
3. 기술 스택
4. MVP 프리셋 개수
5. 출력물이 움직이는 클립이어야 하는지, 정지 이미지도 허용인지

현재 상태는 [PRD §11](../specs/prd/running-drawing-mvp.md)에서 추적한다.
