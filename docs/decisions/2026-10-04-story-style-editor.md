# 편집 화면을 인스타 스토리 편집처럼 바꾼다

> **status: `decided`. 현수가 2026-10-04에 바로 확정했다.** 원래는 지민이나 지응이 PR을 보고 동의한 뒤 확정할 생각이었다. 편집 FRD를 바꾸는 결정은 쓴 사람 혼자 확정하지 않는 것이 규칙이라([FRD 목록](../specs/frd/README.md) "누가 `approved`로 올리나") **이번은 그 예외다.** 시안을 만든 지민의 제안을 받아 정리한 것이고, 개발을 바로 시작하려고 현수가 확정했다.
>
> **지민과 지응은 [PR #77](https://github.com/everyware-ie/run-mechuri/pull/77)에서 내용을 볼 수 있다.** 이의가 있으면 이 문서에 개정으로 덧붙이고 FRD를 함께 고친다.

## 무엇을 정했나

**편집 화면을 인스타 스토리 편집처럼 바꾼다.** 평소에는 화면 전체가 결과물이고, 오른쪽의 도구 버튼을 누를 때만 그 도구의 시트가 아래에서 올라온다. 지금처럼 경로 → 러닝 데이터 순서로 단계를 밟지 않는다.

함께 바뀌는 것이 셋 있다.

- **한 줄 문구를 러닝 데이터에서 떼어 따로 옮긴다**
- **손그림과 내 스타일을 새로 넣는다**
- **세 단계로 나눠 만든다.** 단계마다 PR과 TestFlight 확인을 거친다

## 어디서 나왔나

| 날짜 | |
|---|---|
| 10/1 | 지민이 카톡에서 제안했다 |
| 10/3 | 지민이 [시안](../ideation/jminkkk/2026-10-03-change-editing-page.html)을 올렸다 |
| 10/4 | 현수가 시안을 편집 FRD와 비교하고, 부딪치거나 비어 있는 13가지를 정했다 |

> 지민: "지금은 2개 퍼널을 차례로 선택해서 편집하는데 아예 인스타처럼 우측 상단에 컴포넌트별로 버튼을 누르면 편집할 수 있는 화면이 뜨도록"
> 현수: "저거 디자인 작업 완료되면 PR 날리고 머지해줘"

([QA 기록](../ops/qa-log.md) 2026-10-03 "카톡에서만 정하고 넘어간 것")

**시안은 참고용이다.** 인스타 편집 기능을 참고해 만든 디자인이라 모든 UI를 그대로 맞출 필요가 없다(2026-10-04 현수). 시안과 FRD가 부딪치면 FRD를 따른다는 [2026-09-01 결정](2026-09-01-frd-over-mockup.md)도 그대로다. 그래서 아래 13가지는 시안을 출발점으로 삼되 지금 앱과 FRD에 맞춰 정했다.

## 시안을 보고 정한 13가지

### 시안에 안 보이는 기존 기능

| # | 무엇 | 정한 것 |
|---|---|---|
| 1 | 다듬기 슬라이더 둘 | **경로 시트에 둔다.** 프리셋 아래 |
| 2 | 재생 버튼 | **실기기로 시험하고 정한다.** 지금 앱은 평소에 멈춰 있고 버튼을 눌러야 한 번 그린다. 9/2에 반복 재생 중 조작이 느려서 그렇게 바꿨다. 1단계에서 반복 재생을 다시 시험해, 조작이 느려지지 않으면 버튼을 없애고 느려지면 지금처럼 둔다 |
| 3 | 도구별 초기화 | **남긴다.** 새로 생기는 전체 되돌리기와 함께 둔다. 경로 그림을 한참 만진 뒤 처음으로 돌아가려고 되돌리기를 수십 번 누를 수는 없다 |
| 4 | 크기 조절 | **화면 왼쪽에 세로 크기 슬라이더를 둔다.** 경로·러닝 데이터·문구 시트를 열면 나온다. 핀치와 같은 값을 쓴다. 시안의 그리기 화면에 있는 굵기 슬라이더에서 가져온 생각이다 |
| 5 | 안전 영역 가이드 | **없앤다.** 9/16에 켜고 끄는 버튼을 없앤 뒤로 앱에서는 이미 안 보였다. 문서에만 남아 있던 것을 지운다 |

### 시안과 FRD가 부딪치는 것

| # | 무엇 | 정한 것 |
|---|---|---|
| 6 | 러닝 데이터 프리셋 | **지금 여섯 개를 유지한다.** 시안의 "한 줄, 큰 숫자, 세로, 띠"는 자리를 채운 이름으로 본다 |
| 7 | 화면에서 탭하면 | **시안대로 간다.** 손가락이 닿은 것을 바로 끌고 키운다. 러닝 데이터를 탭하면 다음 프리셋으로 바뀌고, 문구를 탭하면 다시 쓴다. 편집 대상을 고르는 층은 없어진다 |
| 8 | 경로 프리셋 이름 | **"기본 경로 그림"을 쓴다.** 시안의 "기본 드로잉"은 9/16에 바꾸기 전 이름이다 |
| 9 | 배경 시트와 구도 조정 | **배경 선택 단계는 남긴다.** 편집의 배경 시트에서 기본 배경은 바로 바뀌고, 갤러리를 고르면 배경 선택 화면으로 가서 구도를 잡고 돌아온다 |

### 새로 생기는 것

| # | 무엇 | 정한 것 |
|---|---|---|
| 10 | 편집 화면의 "보관함에 저장"과 나가기 확인 | **둘 다 두지 않는다.** 결과 영상은 마지막 편집값으로 한 번에 만드는 것이라 편집 도중에는 받을 수 없다. 지금처럼 공유 단계에서 만들고 보관함에 넣는다. 편집값은 바뀔 때마다 "이어서 만들기"로 저장되므로 ✕는 확인 없이 홈으로 간다 |
| 11 | 경로 색 | **정해 둔 팔레트에서 고르고, 빛나는 마감은 우리가 늘 입힌다.** 원래 MVP는 "프리셋마다 3~5가지"였다. PRD §10의 "색은 사용자가 고르고 마감은 우리가 한다"로 한 걸음 간다 |
| 12 | 글자 색 | **러닝 데이터 시트에서 흰색과 검정 중에 고른다.** 문구에도 같이 적용된다. 10/1 카톡에서 셋이 "흰검으로 일단 해보자"고 정한 것을 시안의 폰트 자리에 넣는다 |
| 13 | 구현 순서 | **세 단계로 나눈다.** 아래 "단계" |

## 단계

| 단계 | 범위 |
|---|---|
| 1 | **화면 구조.** 도구 버튼과 시트(배경, 경로, 러닝 데이터, 문구), 문구 분리, 러닝 데이터를 끌어서 숨기기, 전체 되돌리기, 왼쪽 크기 슬라이더, 재생 시험 |
| 2 | **스타일.** 경로 선 색과 두께, 러닝 데이터 폰트, 글자 색 |
| 3 | **새 도구.** 손그림, 내 스타일 |

**단계마다 PR을 따로 올리고 TestFlight에서 확인한다.** 한 번에 만들면 PR이 너무 커지고 무엇이 문제인지 찾기 어렵다.

3단계의 손그림과 내 스타일은 이번에 큰 규칙만 정했다. 결과물에 언제 보이는지, 무엇을 담는지 같은 세부는 3단계를 시작할 때 정한다.

## 개정

### 2026-10-04: 단계별 QA와 묶음 배포

현수가 배포는 나중에 변경사항을 모아 한꺼번에 진행하고, 1단계 QA를 한 번에 마무리한 뒤 다음 작업으로 2단계에 착수하도록 요청했다.

**단계별 PR과 핵심 QA는 유지하고 TestFlight 배포는 단계 사이의 착수 조건에서 뺀다.** 개발용 앱에서 1단계 핵심 QA를 마치면 2단계에 착수한다. 확인하지 않은 항목을 통과했다고 기록하지 않으며, 배포 전 확인과 다음 단계 착수를 막는 오류를 구분해 남긴다. 2단계와 3단계의 기능 범위는 바꾸지 않는다.

처음 정한 단계별 TestFlight 확인 순서의 개정이다. [결과물 편집 FRD](../specs/frd/result-editing.md) §9 우선순위와 1단계 인계 노트를 함께 맞춘다. 제품 정의와 단계별 기능 범위는 같아 PRD의 우선순위 표는 유지한다.

### 2026-10-04: 1단계 완료본은 먼저 내부 배포한다

핵심 QA를 마친 뒤 현수가 “아 그냥 1차본 배포까지하고 다음 편집 2단계 작업하는 게 좋겠어요”라고 요청했다. 이번에는 **1단계 완료본과 누적 수정사항을 내부 TestFlight에 먼저 배포한 뒤 2단계를 진행한다.** 단계별 PR·핵심 QA와 기능 범위는 유지한다. 공개 링크 변경은 기존처럼 지민에게 인계하며, 이후 단계의 배포 시점은 별도 요청에 따른다.

이전 묶음 배포 요청을 이번 1단계 완료본에 한해 보완한다. [결과물 편집 FRD](../specs/frd/result-editing.md) §9 우선순위와 [배포 기록](../ops/build-and-dev-commands.md#2026-10-04-스토리형-편집-1단계-배포-10027)에 반영한다.

### 2026-10-04: 러닝 데이터를 탭하면 선택한다 (7번)

1단계를 실기기에서 써 보니 **"항목을 누르면 선택되는 게 아니라 다른 프리셋으로 바뀐다"**는 지적이 나왔다(현수). 누르면 고른다는 기대와 어긋났다.

**러닝 데이터를 탭하면 러닝 데이터 시트가 열리며 선택된다.** 프리셋은 시트에서 결과를 보며 고른다. 문구를 탭하면 문구 시트가 열리는 것과 같은 방식이다.

같은 날 **"경로는 눌러도 선택이 안 된다"**는 지적도 나왔다. 경로 그림도 그 영역(점선 상자) 안을 탭하면 경로 시트가 열리며 선택된다. 빈 곳을 탭하면 열린 시트를 닫는다.

이어서 **"러닝 데이터를 선택했는데 경로가 움직인다"**는 지적이 나왔다. 선택은 생겼는데 끌기는 손가락이 닿은 곳만 봤기 때문이다. **글자를 직접 짚지 않은 끌기는 선택된 대상을 움직인다.** 다른 글자를 직접 짚으면 그 글자가 잡힌다. 선택된 것이 없으면 경로 그림이 움직인다. 이 규칙은 `frontend/src/lib/edit-gesture.ts`에 모으고 조합별 테스트를 붙였다.

그 뒤 **"아무것도 선택되지 않은 상태에서 경로의 선택 범위가 너무 크다"**는 지적이 나왔다. 선택된 것이 없으면 경로 그림 영역(점선 상자) 안을 끌 때만 경로 그림이 움직이게 좁혔다. 빈 곳은 아무것도 움직이지 않는다. 7번의 나머지(손가락이 닿은 것을 바로 끌고 키운다, 고르는 층이 없다)는 그대로다.

[결과물 편집 FRD](../specs/frd/result-editing.md) §4-1 손댄 것을 만진다, §7 러닝 데이터와 문구를 함께 고쳤다.

### 2026-10-04: 문구를 러닝 데이터 프리셋에서 완전히 뗀다

1단계에서는 문구를 옮기고 키우는 것만 러닝 데이터와 따로 하고, 처음 자리·크기·글꼴은 러닝 데이터 프리셋을 따르게 했다. 지금까지 만든 결과물의 모습을 지키려는 것이었다. 써 보니 인스타 형식으로 바꿨으니 문구도 **시안대로 프리셋에 묶이지 않은 자유 문구**여야 한다는 의견이 나왔다(현수).

| | 정한 것 |
|---|---|
| 처음 자리 | 화면 가운데. 인스타에서 글자를 넣을 때의 기본 자리와 같다 |
| 정렬 | 가운데 |
| 이미 만든 결과물 | 보관함에서는 원래 모습 그대로다. 다시 편집하면 문구를 원래 자리·크기 근처에 두고 글꼴만 문구 글꼴로 바꾼다 |

러닝 데이터 프리셋은 문구 자리를 비워 두지 않는다. [경로 렌더링 FRD](../specs/frd/route-rendering.md) §6 프리셋, §7-6 한 줄 문구와 [결과물 편집 FRD](../specs/frd/result-editing.md) §7을 고쳤다.

### 2026-10-04: 문구는 인스타처럼 화면에 바로 쓰고 여러 개 넣는다

문구 시트의 입력창에서 쓰는 방식을 써 보고 현수가 바꾸자고 했다.

> 현수: "문구를 넣을 때 팝업같은 게 뜨는 데 인스타에선 그냥 화면에 바로 들어갑니다. 마찬가지로 인스타와 동일하게 특정한 위치에 화면에 바로 문구를 쓰고 문구도 여러 개를 등록할 수 있게 적용해주세요. 여러개면 러닝 데이터를 선택하고 드래그로 삭제하듯 그렇게 삭제하는 기능도 추가되어야겠죠"

| | 정한 것 |
|---|---|
| 쓰는 곳 | 시트 없이 화면에서 바로. 화면이 어두워지고 가운데에서 결과물과 같은 글꼴·크기로 쓴다. 왼쪽 슬라이더로 크기를 바꾼다 |
| 개수 | 여러 개. 처음 정한 "문구는 하나만 둔다"(시안의 "1개만")를 뒤집는다 |
| 고쳐 쓰기 | 문구를 탭하면 그 자리에서 고쳐 쓴다 |
| 지우기 | 끌어서 아래 휴지통에 놓는다. 러닝 데이터는 같은 자리에서 숨는다 |

[결과물 편집 FRD](../specs/frd/result-editing.md) §1 화면 구조, §4-1 손댄 것을 만진다, §7 러닝 데이터와 문구, §7-2 끌어서 숨기기와 지우기와 [경로 렌더링 FRD](../specs/frd/route-rendering.md) §7-6 한 줄 문구를 고쳤다.

이어서 현수가 두 가지를 더 정했다. **문구를 쓸 때 화면을 어둡게 하지 않는다**("굳이 화면 디밍효과를 넣지 않아도 될 것 같고"). **시트는 아래로 끌어 내려서도 닫는다**.

### 2026-10-04: 실수로 숨기거나 지우지 않게 한다

현수가 "위치를 움직이다가 사라지게 만드는 경우가 꽤 있을 것 같다"고 했다. 숨기기 자리가 결과물 안에 있고 시트가 아래쪽을 가렸기 때문이다. 네 가지를 함께 넣는다.

- 숨기기·지우기 자리를 결과물 밖, 맨 아래 띠로 옮긴다
- 끄는 동안 시트를 아래로 치운다
- 그 자리에 들어가면 진동한다
- 숨기거나 지운 직후 되돌리기 안내를 띄운다

### 2026-10-04: 3단계 착수 정책 확정

현수가 그리기와 내 스타일 구현을 요청하고 착수 질문에 답했다. 손그림은 펜·형광·네온·획 지우개, 굵기·색·획별 되돌리기를 제공한다. 영상 처음부터 경로 위·러닝 데이터와 문구 아래에 보이며, 수정은 그리기 도구에서 한다. 별도의 이동·확대와 그려지는 애니메이션은 이번 범위에 넣지 않는다.

내 스타일에는 배경·프리셋·색·두께·러닝 데이터 항목·폰트와 **다듬기 값도 저장**한다. 이름을 붙여 기기 안에 최대 20개 저장·적용·삭제한다. 사진·영상 사본은 저장하지 않고 그 스타일을 적용할 때 현재 배경을 유지한다. 위치·크기·문구·손그림은 제외한다. 새로 만들기에 자동 적용하지 않는다. [편집 FRD](../specs/frd/result-editing.md) §11·§12와 경로 렌더링의 합성 규칙에 반영한다.


## 2026-10-04 추가 개정: 손그림 획 편집

현수가 그린 항목을 선택해 위치·크기·펜 종류·색을 바꾸고 싶다는 요청을 했고, FRD와 추천안을 확인한 뒤 구현을 승인했다. 기존의 별도 이동·확대 제외 제한을 해제한다. 손을 떼기 전까지 그린 선 한 획씩 편집 화면에서 선택한다. 획의 이동·크기·붓·색·굵기·삭제와 되돌리기를 제공하고, 여러 획 묶기는 제외한다. [편집 FRD](../specs/frd/result-editing.md) §11-1 획 선택과 수정과 PRD에 반영한다.
