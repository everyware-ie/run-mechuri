# 편집 화면을 인스타 스토리 편집처럼 바꾼다

> **status: `decided`. 현수가 2026-10-04에 바로 확정했다.** 원래는 지민이나 지응이 PR을 보고 동의한 뒤 확정할 생각이었다. 편집 FRD를 바꾸는 결정은 쓴 사람 혼자 확정하지 않는 것이 규칙이라([FRD 목록](../specs/frd/README.md) "누가 `approved`로 올리나") **이번은 그 예외다.** 시안을 만든 지민의 제안을 받아 정리한 것이고, 개발을 바로 시작하려고 현수가 확정했다.
>
> **지민과 지응은 [PR #77](https://github.com/everyware-ie/run-mechuri/pull/77)에서 내용을 볼 수 있다.** 이의가 있으면 이 문서에 개정으로 덧붙이고 FRD를 함께 고친다.

## 무엇을 정했나

**편집 화면을 인스타 스토리 편집처럼 바꾼다.** 평소에는 화면 전체가 결과물이고, 오른쪽의 도구 버튼을 누를 때만 그 도구의 시트가 아래에서 올라온다. 지금처럼 경로 → 러닝 데이터 순서로 단계를 밟지 않는다.

함께 바뀌는 것이 셋 있다.

- **한 줄 문구를 러닝 데이터에서 떼어 따로 옮긴다**
- **손그림과 내 스타일을 새로 넣는다**
- **세 단계로 나눠 만든다.** 단계마다 PR과 TestFlight 확인을 거친다

## 어디서 나왔나

| 날짜 | |
|---|---|
| 10/1 | 지민이 카톡에서 제안했다 |
| 10/3 | 지민이 [시안](../ideation/jminkkk/2026-10-03-change-editing-page.html)을 올렸다 |
| 10/4 | 현수가 시안을 편집 FRD와 비교하고, 부딪치거나 비어 있는 13가지를 정했다 |

> 지민: "지금은 2개 퍼널을 차례로 선택해서 편집하는데 아예 인스타처럼 우측 상단에 컴포넌트별로 버튼을 누르면 편집할 수 있는 화면이 뜨도록"
> 현수: "저거 디자인 작업 완료되면 PR 날리고 머지해줘"

([QA 기록](../ops/qa-log.md) 2026-10-03 "카톡에서만 정하고 넘어간 것")

**시안은 참고용이다.** 인스타 편집 기능을 참고해 만든 디자인이라 모든 UI를 그대로 맞출 필요가 없다(2026-10-04 현수). 시안과 FRD가 부딪치면 FRD를 따른다는 [2026-09-01 결정](2026-09-01-frd-over-mockup.md)도 그대로다. 그래서 아래 13가지는 시안을 출발점으로 삼되 지금 앱과 FRD에 맞춰 정했다.

## 시안을 보고 정한 13가지

### 시안에 안 보이는 기존 기능

| # | 무엇 | 정한 것 |
|---|---|---|
| 1 | 다듬기 슬라이더 둘 | **경로 시트에 둔다.** 프리셋 아래 |
| 2 | 재생 버튼 | **실기기로 시험하고 정한다.** 지금 앱은 평소에 멈춰 있고 버튼을 눌러야 한 번 그린다. 9/2에 반복 재생 중 조작이 느려서 그렇게 바꿨다. 1단계에서 반복 재생을 다시 시험해, 조작이 느려지지 않으면 버튼을 없애고 느려지면 지금처럼 둔다 |
| 3 | 도구별 초기화 | **남긴다.** 새로 생기는 전체 되돌리기와 함께 둔다. 경로 그림을 한참 만진 뒤 처음으로 돌아가려고 되돌리기를 수십 번 누를 수는 없다 |
| 4 | 크기 조절 | **화면 왼쪽에 세로 크기 슬라이더를 둔다.** 경로·러닝 데이터·문구 시트를 열면 나온다. 핀치와 같은 값을 쓴다. 시안의 그리기 화면에 있는 굵기 슬라이더에서 가져온 생각이다 |
| 5 | 안전 영역 가이드 | **없앤다.** 9/16에 켜고 끄는 버튼을 없앤 뒤로 앱에서는 이미 안 보였다. 문서에만 남아 있던 것을 지운다 |

### 시안과 FRD가 부딪치는 것

| # | 무엇 | 정한 것 |
|---|---|---|
| 6 | 러닝 데이터 프리셋 | **지금 여섯 개를 유지한다.** 시안의 "한 줄, 큰 숫자, 세로, 띠"는 자리를 채운 이름으로 본다 |
| 7 | 화면에서 탭하면 | **시안대로 간다.** 손가락이 닿은 것을 바로 끌고 키운다. 러닝 데이터를 탭하면 다음 프리셋으로 바뀌고, 문구를 탭하면 다시 쓴다. 편집 대상을 고르는 층은 없어진다 |
| 8 | 경로 프리셋 이름 | **"기본 경로 그림"을 쓴다.** 시안의 "기본 드로잉"은 9/16에 바꾸기 전 이름이다 |
| 9 | 배경 시트와 구도 조정 | **배경 선택 단계는 남긴다.** 편집의 배경 시트에서 기본 배경은 바로 바뀌고, 갤러리를 고르면 배경 선택 화면으로 가서 구도를 잡고 돌아온다 |

### 새로 생기는 것

| # | 무엇 | 정한 것 |
|---|---|---|
| 10 | 편집 화면의 "보관함에 저장"과 나가기 확인 | **둘 다 두지 않는다.** 결과 영상은 마지막 편집값으로 한 번에 만드는 것이라 편집 도중에는 받을 수 없다. 지금처럼 공유 단계에서 만들고 보관함에 넣는다. 편집값은 바뀔 때마다 "이어서 만들기"로 저장되므로 ✕는 확인 없이 홈으로 간다 |
| 11 | 경로 색 | **정해 둔 팔레트에서 고르고, 빛나는 마감은 우리가 늘 입힌다.** 원래 MVP는 "프리셋마다 3~5가지"였다. PRD §10의 "색은 사용자가 고르고 마감은 우리가 한다"로 한 걸음 간다 |
| 12 | 글자 색 | **러닝 데이터 시트에서 흰색과 검정 중에 고른다.** 문구에도 같이 적용된다. 10/1 카톡에서 셋이 "흰검으로 일단 해보자"고 정한 것을 시안의 폰트 자리에 넣는다 |
| 13 | 구현 순서 | **세 단계로 나눈다.** 아래 "단계" |

## 단계

| 단계 | 범위 |
|---|---|
| 1 | **화면 구조.** 도구 버튼과 시트(배경, 경로, 러닝 데이터, 문구), 문구 분리, 러닝 데이터를 끌어서 숨기기, 전체 되돌리기, 왼쪽 크기 슬라이더, 재생 시험 |
| 2 | **스타일.** 경로 선 색과 두께, 러닝 데이터 폰트, 글자 색 |
| 3 | **새 도구.** 손그림, 내 스타일 |

**단계마다 PR을 따로 올리고 TestFlight에서 확인한다.** 한 번에 만들면 PR이 너무 커지고 무엇이 문제인지 찾기 어렵다.

3단계의 손그림과 내 스타일은 이번에 큰 규칙만 정했다. 결과물에 언제 보이는지, 무엇을 담는지 같은 세부는 3단계를 시작할 때 정한다.
