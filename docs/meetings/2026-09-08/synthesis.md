# 2026-09-08 회의 종합 - 인스타 공유 해결, 범위 확대, 역할 변경

**역할이 바뀐다. phs00이 구현에 참여하고, jminkkk과 JiEung2는 성능 개선 리서치로 간다.**

## 논의된 안건

### 1. 기능 동결 — 예외 하나를 둔다

**예정대로 동결하되 배경 소재 두 가지는 넣는다.**

| | |
|---|---|
| 갤러리에서 사진 고르기 | **이번 빌드에 포함** |
| 그 자리에서 찍기 | **이번 빌드에 포함** |

**전원 동의했다.** [배경 선택 FRD](../../specs/frd/background-selection.md) §1이 둘을 "여유 시"로 잡아뒀는데 MVP로 올라온다.

**나머지는 지금 구현된 것의 성능 개선에 집중한다.**

### 2. 인스타 공유 — 됐다

**원인은 Meta 앱의 상태였다.**

| | |
|---|---|
| 개발자 계정 | JiEung2 개인 페이스북 계정을 Meta 개발자 계정으로 등록 |
| 앱 등록 | Meta 개발자 센터에 앱을 등록하고 키 발급 |
| **막혔던 것** | **앱이 '개발중' 상태였다. '운영중'으로 돌리니 동작한다** |

세 번의 실패에서 의심했던 `backgroundVideo` 키 문제도, 계정 설정 문제도 아니었다.

**그래서 문서를 고칠 필요가 없어졌다.** 안건 §2-2가 "인스타 공유의 무게를 다시 잡자"고 제안했는데, 공유가 되므로 [내보내기·공유 FRD](../../specs/frd/export-and-share.md) §5의 우선순위를 그대로 둔다.

> 실기기에서 버그 넷을 순차로 잡았다. `outputPath` URI 파싱 → App ID 미등록 → `FacebookAppID`·URL 스킴 누락 → `source_application` 쿼리 누락. **검증 성공.**

### 3. 베타 심사 — 9/10 신청

**용어부터 정리됐다.** TestFlight에는 심사가 둘 있다.

| | 대상 | 심사 |
|---|---|---|
| **내부 개발자 심사** | 애플 개발자 센터에 등록된 관리자만 | 간단하다. 2분쯤 |
| **베타 심사** | 공개 링크로 외부 사용자까지. 최대 1만 명 | 이쪽이 9/22에 필요한 것 |

**지금까지 한 것은 내부 개발자 심사다.**

| | |
|---|---|
| 첫 신청 | **9/10 (수)** |
| 소요 | 보통 하루, 늦으면 5일 |
| 신청 전 | GPT로 한 번 훑고 진행 |

**통과하는지부터 확인한다.** 먼저 신청해서 결과를 보고 그다음을 정한다.

`[확인 필요]` **신청 전에 내부에서 볼 것들이 있다.** 예를 들어 앱 안에 "베타" 글씨가 들어가 있으면 안 된다.

### 4. 스레드 두 번째 글

**좋아요 4는 전부 외부였다.** phs00 본인 것은 없다.

| | 1번 글 (8/29) | 2번 글 |
|---|---|---|
| 무엇 | 질문만 | **결과물 이미지 3장** |
| 조회 | 796 | 192 |
| **외부 반응** | **1** | **5** |

**노출은 4분의 1로 줄었는데 외부 반응은 다섯 배가 됐다.** 반응률로는 스무 배가 넘는다.

**말로 묻는 것보다 물건을 보여주는 쪽이 낫다.** 1번 글의 유일한 반응이 "가민 코로스 둘다 기능이 있어"였던 것도 같은 이야기다. 말로만 설명하면 남들이 아는 것에 견주게 된다.

> 기록이 이쁘게 그려지네요 ㅋㅋ

**PRD §11이 검증하려던 문장에 처음으로 맞는 반응이 나왔다.**

**다음 글은 클립으로 간다.** 정지 이미지로도 이 정도면, 움직이는 것은 그것이 차별점이기 때문이다.

### 5. 각인 표시 모드 — FRD를 시안에 맞춘다

FRD는 **항상 / 완성 후만 / 숨김** 셋을 고르게 되어 있었는데 시안에 그 UI가 없어 구현에서 뺐다. **FRD를 시안에 맞춰 개정한다.**

#### 퍼널을 나누자는 이야기가 함께 나왔다

지금은 **배경 설정 → 편집(각인·프리셋을 한 화면에서)** 이다. 이걸 이렇게 나누자는 안이다.

```
배경 설정 → 프리셋 설정 → 각인 설정 → 완료
```

참고: [토스 기술 블로그 - 퍼널](https://toss.tech/article/engineering-note-1)

**편집 순서 자체를 고르게 하는 방향도 함께 이야기됐다.**

**퍼널이 나뉘면 각인 옵션을 어떻게 둘지 다시 볼 자리가 생긴다.** 지금 표시 모드를 없애는 것은 그때까지의 결정이다. **구현하는 사람이 그 부분을 진행할 때 고려한다.**

### 6. 한글 폰트 — Pretendard

**Pretendard로 확정한다.** 지금 폰트 셋(Space Grotesk, JetBrains Mono)에 한글 글리프가 없어서 문구와 각인 프리셋에서 폴백이 걸리고 있었다.

**해당 작업을 진행할 때 다시 한 번 검토한다.**

## 확정하지 않은 것

1. **퍼널 분리.** 방향만 나왔고 구현 시점에 판단한다
2. **첫 실행 연결 화면의 자리.** 아래 참고
3. **배경 나머지 3건.** 파일이냐 코드냐, 배경별 선 색, 팀 문양 확산
4. **가민·코로스 확인.** 세 번째 회의째 미정
5. **제품명.** 빌드에는 "메추리 런"이 들어갔지만 확정 선언은 없었다

> **첫 실행 연결 화면이 FRD와 어긋나 있다.** [홈과 보관함](../../specs/frd/home-and-library.md) §4-2가 "첫 실행에만 나오고 사라지는 화면이면 그 역할을 못 한다"고 정했는데, 구현은 첫 실행에만 뜨는 별도 화면이다. **지금 정하지 않고 W5 실사용 뒤에 본다.** 셋이 써보면 그 화면이 다시 필요한지가 드러난다. (phs00 판단)
