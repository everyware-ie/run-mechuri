## 요약

- 외부 러너 대상 사용성 테스트(UT)는 얘기했지만 하지 않기로 했다
- 목표는 App Store 다운로드 30회, 스레드 팔로워 50명이다

## 2. 2주 동안 바뀐 것

업데이트 노트로 공유했다.

- **편집 개편:** 큰 이견은 없었다. 지응이 개인적으로 느낀 불편은 QA로 남겼다(§6)
- **공개 링크 빌드:** 외부 테스터가 공개 링크로 받는 빌드를 몇 번으로 둘지는 팀 안에서 정한다

## 3. 러닝 측정 기능

현수가 10/6 출근길에 처음으로 야외에서 재 본 결과를 공유했다. 자세한 것은 [내부 측정 QA](../../ops/internal-run-tracking-qa.md) §11에 있다.

- GPS와 화면 잠금 중 수신은 괜찮았다
- 도착 직전 구간은 iOS가 메모리를 확보하려고 앱을 꺼서 빠졌다
- 워치 심박은 워치에서 한 번 더 눌러야 시작되는 걸 몰라서 처음엔 안 들어왔다

다음 스프린트 이야기에서 **측정 기능은 안정성이 먼저**라고 정했다. 안건에서 정할 것으로 올린 셋은 회의에서 다루지 못해 회의 뒤 현수가 정했다 (2026-10-07 phs00).

| 정할 것 | 정한 것 |
|---|---|
| 누가 언제 뛰어 볼지 | 각자 여유 있을 때 달리면서 틈틈이 재고 QA한다 |
| 심박 받는 방법 | 나이키 런처럼 운동 앱과 동시에 쓸 수 있게, 건강 앱에서 심박을 불러오는 방식을 넣는다 |
| GPS가 끊긴 구간 | 따로 정하지 않고 아래 기준을 따른다 |

**측정 기능의 최소 기준:** 나이키 런, 스트라바 같은 유명한 러닝 앱과 같은 방식으로 제공한다. 측정에 기능적인 하자가 없어야 한다. GPS가 끊긴 구간도 그 앱들이 어떻게 처리하는지 확인해서 맞춘다.

**권한을 계속 다시 묻는다.** 이미 허용했는데 러닝 기록을 새로 그릴 때, 측정 뒤 심박을 가져올 때 또 권한을 허용해야 한다. 현수가 Codex로 고친다. [QA 기록](../../ops/qa-log.md)에 남겼다.

## 4. 다음 스프린트

### 방향

- 지금 수준으로 먼저 정식 등재하고, 사용하면서 그룹 기능을 넣는다
- 측정 기능의 안정성을 먼저 잡고, 서버가 필요한 작업은 그 뒤에 한다

안건의 후보로 보면 C(정식 등재)를 먼저 하고, A(측정)를 안정화해 다음 제출에 넣고, B(그룹 드로잉)는 그 뒤다.

### 일정

| 언제 | 무엇 | 누가 |
|---|---|---|
| 10/8 (목) | 정식 등재에 필요한 자료 조사 | 지응. 조사가 끝나면 다음 사람이 이어 받는다 |
| 10/13 (화)까지 | 정식 등재 준비. 측정 기능을 뺀 버전 | 함께 |
| | App Store에 올릴 서비스 화면 소개 | 지민 |
| | 측정 기능을 뺀 빌드 올리기 | 현수 (예정) |
| 11/3 ~ 11/10 (화) | 측정 기능을 넣어 정식 등재 다시 제출 | 함께 |
| 11/17 (화) | 스프린트 끝 | |

**정식 등재에 낼 빌드는 최신 빌드가 아니어도 된다.** 어느 빌드를 냈는지 기록에 따로 남기면 된다. 그래서 측정이 들어간 내부 빌드는 계속 올리고, 정식 등재용은 측정을 뺀 일반 빌드로 따로 낸다.

### 목표

| 지표 | 목표 |
|---|---|
| App Store 다운로드 | 30회 |
| 스레드 팔로워 | 50명 |

둘 다 스프린트가 끝나는 11/17까지다.

## 5. 사용성 테스트

지민이 [초기 사용자 검증 제안](https://github.com/everyware-ie/run-mechuri/pull/107)을 가져왔다.

지금 버전을 그대로 내기엔 화면 구성이나 문구에서 놓친 게 있을 것 같다는 얘기가 나왔다. 그래서 우리를 모르는 외부 러너를 불러 UT와 인터뷰를 하는 방안을 이야기했다.

- 대상: 아이폰을 쓰고, 실외 러닝을 운동 앱으로 기록하고, 기록을 공유하고 싶은 사람
- 섭외 후보: 준익(현수), 준민(지응), 스레드 모집 글(지민), UT 품앗이 방

**결론은 UT를 하지 않기로 했다.** 지민 제안의 나머지(행동 로그 수집, 대표 지표, 피드백 분류)도 정하지 않았다.

## 6. QA

- **지응:** 처음 그릴 때 러닝 데이터 프리셋이 코너인데, 새 편집 화면의 버튼들이 가리는 느낌이다. 지응 개인의 느낌이라 바로 고치지 않는다. 작업자가 보고 고칠지, 고친다면 어떻게 할지 정한다
- **라벨 글씨 가독성:** 해야 한다. 담당은 정하지 않았다
