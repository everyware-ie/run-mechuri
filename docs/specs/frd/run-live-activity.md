# 러닝 잠금화면 현황

2026-10-19 대화에서 거리 중심의 아이콘 제어 시안을 확인한 뒤, 사용자가 “네 다음 구현작업 진행해 주세요”라고 요청해 내부 빌드 구현을 승인했다.

전체를 읽기 어렵다면 [제어](#3-제어)의 재개·종료와 [복구와 오류](#5-복구와-오류)를 먼저 확인한다. 재개는 잠금화면에서 바로 처리하며, 종료는 확인 후 저장한다. 저장 실패 때는 카드를 남기고 복구하도록 안내한다.

## 1. 적용 범위와 시작

내부 측정이 켜진 아이폰 빌드에서 제공한다. iOS 16.4 이상은 현황 표시와 앱 진입을, iOS 17 이상은 지원되는 Live Activity 제어를 사용한다. OS 버전이나 설정에 따라 제어를 제공할 수 없으면 앱의 같은 러닝으로 이동한다. 버전 분기 때문에 기존 앱의 최소 지원 버전을 올리지 않는다.

기록이 없는 GPS 준비 단계에는 표시하지 않는다. 아이폰 즉시 시작으로 기록이 생성됐으면 GPS 수신 전에도 시간과 거리 0을 표시한다. 실제 러닝 시작과 최초 저장이 성공하면 같은 기록 ID로 한 개만 만든다. 워치에서 요청해 아이폰 측정이 시작된 경우도 동일하다. 워치의 요청만 도착했거나 시작이 실패한 상태를 `러닝 중`으로 표시하지 않는다. 앱이 백그라운드에 있어 생성할 수 없으면 측정은 유지하고 전면 복귀 시 같은 기록으로 다시 연결한다.

표시 권한은 ActivityKit의 허용 상태로 판단한다. 일반 알림 권한을 추가 조건으로 삼지 않는다. 허용하지 않으면 앱 안에서 상태를 안내하며 측정 시작을 막지 않는다.

## 2. 표시하는 정보

| 위치 | 내용 | 기준 |
|---|---|---|
| 위 | Runary 이름과 측정 상태 | `러닝 중`, `일시정지 중`, `중단됨`, `저장 확인 필요`, `업데이트 확인`을 실제 상태에 맞게 표시 |
| 가운데 왼쪽 | 거리와 km | 누적 거리를 가장 크게 표시. km 두 자리 소수로 표기하며 큰 값에서도 단위를 자르지 않음 |
| 제어 영역 | 상태에 따른 제어 | 거리 오른쪽에 기본 제어와 `종료`를 고정. 기본 제어는 측정 중 `일시정지`, 일시정지 시 `재개`. 중단·저장 오류 시 `앱에서 확인` |
| 아래 왼쪽 | 시간 | `duration`을 사용. 일시정지·중단 시간은 제외하고 한 시간부터 시 단위를 포함 |
| 아래 가운데 | 평균 페이스와 /km | 기존 측정 엔진의 `averagePace`. 20m 미만이나 유효한 값이 없으면 `-` |
| 아래 오른쪽 | 심박 아이콘, 현재 심박과 bpm | 기존 엔진의 현재 심박만 사용. 미수신·일시정지·15초가 지난 샘플은 `-` |

하단 세 항목의 제목과 표시 묶음은 각각 왼쪽 정렬한다. 심박 아이콘도 유지하며 평균 심박으로 현재값을 대신하지 않는다. 현재 페이스·케이던스·지도·경로 좌표·장소명은 이 화면에 넣지 않는다. 상세한 센서 상태는 앱에서 확인한다.

일시정지 전후 거리 크기·지표 위치·버튼 위치와 크기를 바꾸지 않는다. 종료 버튼이 일시정지 후 새로 생기는 방식은 쓰지 않는다. 심박이 `-`로 바뀌어도 지표 열 너비를 유지한다. 이 배치는 사용자가 최종 시안에서 확인한 기준이다.

사용자의 후속 제안에 따라 일반 제어 버튼에는 문구 대신 일시정지·재생·네모 종료 아이콘만 표시한다. 위 표의 문구는 동작 이름이며 버튼의 접근성 이름으로 제공한다. 종료 확인 화면의 `돌아가기`와 `종료·저장`은 문구를 유지한다. 아이콘·색의 기준은 [디자인 문서](../../design/run-live-activity.md)에 둔다.

## 3. 제어

### 일시정지

버튼을 누르면 현재 기록 ID와 `running` 상태를 확인하고 기존 네이티브 일시정지를 한 번 실행한다. 시간·거리·GPS 수집과 워치 상태는 기존 측정 규칙을 따른다. 이미 일시정지됐거나 종료된 기록의 늦은 요청은 상태를 되돌리지 않는다.

### 재개

2026-10-19 사용자가 “시안처럼 즉시 재개”를 요청했다. iOS 17 이상에서 ▶를 누르면 앱 화면을 열지 않고 같은 일시정지 러닝을 재개한다. 현재 기록 ID와 상태 변경 세대를 대조하고, 위치 서비스·사용 중 위치 권한·정확한 위치와 해당 Live Activity의 활성 상태를 확인한다. 권한이 없거나 이미 중단·종료됐다면 성공으로 표시하지 않고 앱에서 확인하도록 안내한다.

재개 버튼을 처리한 시각부터 측정 시간을 다시 쌓고 기존 GPS 수집을 다시 시작한다. 이전 좌표를 시작점으로 재사용하지 않는다. 경로는 새 구간으로 열고 재개 이후의 새 GPS 샘플부터 반영하며, 일시정지 중 이동 거리는 연결하지 않는다. 위치를 기다리는 동안 거리와 심박을 만들어 넣지 않는다. 별도 센서·타이머·항상 위치 권한을 추가하지 않는다.

아이폰 최초 시작은 측정 FRD의 즉시 시작 규칙을 따른다. 워치 시작과 앱 안의 기존 재개는 GPS 준비 조건을 유지한다. 앱 강제 종료 뒤의 중단 복구는 즉시 재개 대상이 아니다. OS 인증이 필요한 경우 해당 흐름을 따르며 잠금 해제 없이 항상 제어된다고 안내하지 않는다. 이 동작은 실기기에서 잠금·장시간 일시정지 후 GPS 재수신까지 검증한다.

### 앱 진입과 종료

카드 본문을 누르면 같은 러닝 화면을 연다. 기록 ID를 확인해 이미 끝난 러닝의 카드로 새 러닝을 만들지 않는다. 오래된 카드에서는 현재 상태를 읽고 진행 중인 러닝 또는 해당 완료 기록으로 안내한다.

### 잠금화면에서 종료하고 저장

사용자가 잠금화면에서 바로 종료하는 방법을 요청해, 앱에서만 종료하던 최초 검토안을 보완한다. 후속 시안에서는 일시정지 뒤에 종료를 추가했으나 사용자가 전체 UX가 더 어색해졌다고 지적했다. 최종안은 iOS 17 이상에서 측정·일시정지 모두 `종료 → 종료·저장`으로 처리하며, 아이콘 시안 확인과 후속 구현 요청을 기준으로 착수한다.

`종료`를 누르면 Live Activity 내부를 `러닝을 종료할까요?` 확인 화면으로 바꾸고 현재 거리·시간, `돌아가기`와 `종료·저장`을 표시한다. 확인 화면을 연 것만으로 원본을 일시정지하거나 종료하지 않는다. 돌아가기는 확인 전 상태로 복귀한다. 실제 종료를 실행하는 버튼은 최초 종료 진입 버튼과 구분해 연속 탭이 곧바로 저장으로 이어지지 않도록 한다.

`종료·저장`을 누르면 같은 기록과 유효한 확인 요청을 대조하고 기존 네이티브 종료·저장을 한 번 실행한다. 앱 화면을 반드시 열어야 하는 흐름으로 만들지 않되 OS의 잠금 인증을 따른다. 확인 뒤 앱·워치에서 일시정지·재개했거나 다른 기록으로 바뀌면 이전 종료 확인 요청을 무효화한다. 연속 탭이나 지연된 요청이 새 러닝을 종료하지 않아야 한다.

저장 성공을 확인한 뒤 Live Activity를 제거한다. 저장이 실패하면 완료로 표시하거나 카드를 먼저 지우지 않는다. 원본을 보존하고 `저장 확인 필요`와 앱 진입을 제공한다. 카드만 지우는 동작은 원본 러닝 종료와 무관하다. iOS 16.4~16.x에서는 같은 기록을 앱에서 열어 기존 종료 확인·저장 흐름을 사용한다.

## 4. 갱신과 지연

React 화면의 폴링과 별개로 기존 네이티브 측정 상태에서 갱신한다. 별도 GPS·건강 조회·운동 세션이나 지속 실행용 타이머를 만들지 않는다. 표시를 위해 메모리에 전체 경로를 복제하지 않는다.

상태 변경은 바로 반영하고 일반 지표는 최대 5초에 한 번으로 합쳐 전달하는 것을 초기 설정으로 한다. 시간 표시는 시스템의 시간 표시 기능을 사용하며 매초 ActivityKit 갱신을 호출하지 않는다. OS가 갱신을 지연할 수 있으므로 초 단위 수신을 보장하지 않는다.

측정 중 스냅샷의 일반 갱신 확인 기준은 30초를 초기 설정으로 한다. 심박은 실제 측정 시각으로 15초 신선도 기준을 별도로 적용한다. 표시 데이터에 유효 시각을 포함하고, 더 이상 최신임을 확인할 수 없으면 현재 심박을 숨기고 `업데이트 확인`을 표시한다. 중단 가능성이 있는 동안 마지막 확인 시각 이후 시간을 계속 늘려 보이지 않는다. 이 값은 Apple의 보장 주기가 아니며 잠금·백그라운드 실측에서 검증한다.

시스템이나 사용자가 표시를 지워도 원본 측정은 종료하지 않는다. 사용자가 같은 러닝의 표시를 지운 뒤에는 반복 생성하지 않으며 다음 새 러닝부터 다시 생성할 수 있다. OS의 실행 시간 제한이 끝난 경우도 러닝의 종료와 구분한다.

## 5. 복구와 오류

| 상황 | 동작 |
|---|---|
| 표시 생성·갱신 실패 | 측정은 유지. 현재 화면에서 표시 불가를 알리고 전면 복귀 때 상태를 대조. 실패 때마다 권한 창이나 경고를 띄우지 않음 |
| 앱 강제 종료·재실행 | 기존 원본을 중단 상태로 복구하고 기존 카드와 대조. 종료 중 시간을 만들어 넣거나 자동으로 GPS를 재개하지 않음 |
| 중복·다른 기록의 카드 | 한 기록에 한 카드만 연결하고 현재 기록과 맞지 않는 이전 카드는 정리. 이전 요청으로 새 기록을 조작하지 않음 |
| 일시정지·재개 명령 실패 | 성공 상태를 먼저 표시하지 않음. 현재 상태와 앱 진입을 제공 |
| 심박만 미수신 | 거리·시간·평균 페이스와 측정은 유지. 심박 `-`가 건강 권한 거부라는 뜻은 아님 |
| 저장 실패·권한 철회 | 기존 엔진의 중단·오류 상태를 그대로 표시하고 앱에서 복구하도록 안내 |

## 6. 지원 기기와 보관 범위

아이폰 11 Pro처럼 Dynamic Island가 없는 기기도 잠금화면을 지원한다. 지원 기기에는 Dynamic Island의 compact·minimal·expanded 표현도 작성한다. 첫 구현의 작은 표현은 Runary 식별과 누적 거리, 펼친 표현은 잠금화면과 같은 지표·상태를 사용한다. 작은 표현의 세부 배치는 별도 시각 확인을 남기며 최초 시안만으로 픽셀 구성을 확정하지 않는다.

Live Activity에는 표시용 요약과 기록 연결 정보만 전달한다. 경로 좌표·개별 심박 원본·사진·영상·진단 로그는 포함하지 않는다. 원격 푸시·서버 전송·계정을 추가하지 않는다. 잠금 상태에서의 민감 정보 표시에는 시스템 개인정보 보호 설정을 적용하며, 시스템이 가리는 값을 우회하지 않는다.

위젯 확장과 필요한 빌드 설정은 내부 측정 프로필에만 추가한다. 일반 `production` 설정에서는 내부 측정과 새 확장 진입을 제외한 상태를 검사한다. 서명·설치는 별도 검증이며 이번 구현에서 인증서나 개발 기기를 새로 등록하지 않는다.

## 7. 검증

- 자동 검사: 값·단위·누락값, 시간 기준, 심박 만료, 상태 전환, 중복 생성·명령, 종료 확인 취소, 재개 후 이전 종료 요청 무효화, 저장 실패 시 카드 유지, 완료 후 오래된 요청과 일반/내부 빌드 분리.
- 시뮬레이터: iOS 16.4·17 이상 분기, 큰 글자, 한 시간 이상의 시간과 큰 거리, 잠금화면·Dynamic Island 표현.
- 실기기: 실제 GPS 시작 후 잠금, 다른 앱 전환, 일시정지, 잠금화면에서 즉시 재개와 새 GPS 수신, 워치 제어, 잠금화면에서 종료 확인·취소·저장, OS 인증, 저장 실패 복구, 표시 삭제와 설정 거부.
- 자원 사용: 기존 측정과 비교해 표시 추가의 메모리·배터리 영향을 확인. HTML 시안 확인이나 시뮬레이터 실행을 실기기 측정 성공으로 기록하지 않음.

## 8. 근거

- [기존 측정 FRD](internal-run-tracking.md): GPS 준비·재개, 시간과 평균 페이스 계산, 15초 심박 신선도, 저장과 중단 복구.
- [Apple Live Activities 설계](https://developer.apple.com/design/human-interface-guidelines/live-activities): 잠금화면과 Dynamic Island의 구성·크기.
- [ActivityKit 표시와 수명](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities): 생성·갱신·종료, 시스템 제한과 사용자의 표시 제거. 표시가 종료되는 것과 러닝 종료는 다름.
- [버튼과 App Intents](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities): iOS 17 이상의 상호작용과 잠금 인증, 앱 프로세스에서의 LiveActivityIntent 실행.
- [데이터 유효 시각](https://developer.apple.com/documentation/activitykit/activitycontent/staledate): 마지막 정보가 오래됐을 때의 상태 처리.

- [Apple 백그라운드 위치 안내](https://developer.apple.com/videos/play/wwdc2023/10180/): 활성 Live Activity가 있을 때 사용 중 권한의 백그라운드 위치 접근. 실제 수집과 재개는 호스트 앱이 수행한다.
