# 워치 운동 세션 연동

2026-10-26 사용자가 워치 운동 세션 연동과 건강 저장까지 구현을 승인했다. 현재 TestFlight 43번의 동작이나 구현 완료를 설명하지 않는다.

## 1. 사용자가 확인할 핵심

| 결정 | 추천안 |
|---|---|
| 워치 역할 | 아이폰 기록에 연결해 운동 중 심박과 화면을 제공한다. 아이폰을 소지하고 달린다. |
| 시작 | 처음 한 번 워치 연동을 켜고 권한을 확인한다. 이후 러닝 시작과 함께 자동 연결한다. 별도 운동 실험 버튼은 없앤다. |
| 다른 운동 앱 | 워치 운동은 동시에 하나만 실행되므로 병행을 보장하지 않는다. 첫 연결에서 이를 안내하며, 다른 운동 때문에 중단되면 자동으로 다시 시작하지 않는다. |
| 저장 | Runary에 먼저 저장하고, 쓰기 허용 시 건강 앱에도 Runary 운동으로 저장한다. 피트니스에서 확인하며 실패해도 원본을 보존한다. |
| 화면 | 거리 중심, 시간·평균 페이스·심박은 왼쪽 정렬. 하단은 일시정지/재개와 종료 아이콘이다. |
| 연결 실패 | 아이폰 측정은 계속한다. 워치는 마지막 확인 시점과 연결 상태를 표시하고 자동으로 상태를 다시 요청한다. |

## 2. 최초 연결과 권한

진행 중인 러닝이 없을 때 아이폰에서 워치 연동을 켤 수 있다. 안내는 “워치에서 심박을 측정하고 러닝 화면을 표시해요. 다른 워치 운동이 진행 중이면 종료될 수 있어요.”로 한다. `워치 연동 켜기`와 `나중에`를 제공한다. 사용자는 이후에도 워치 연동을 끌 수 있다.

워치에서 운동 세션에 필요한 권한과 심박 읽기를 요청한다. 이미 응답한 권한을 매번 다시 요청하지 않는다. 최초 OS 권한 안내는 사용자가 직접 완료해야 하며 자동 실행 성공으로 간주하지 않는다. 건강 읽기 허용 여부를 빈 조회 결과로 추측하지 않는다.

심박 권한을 거부하거나 워치를 연결하지 않아도 아이폰 시작·재개·종료·저장은 가능해야 한다. 설정을 켠 사실과 실제 워치 세션 실행 여부를 구분해 표시한다.

## 3. 시작과 제어

아이폰 `러닝 시작`은 현재처럼 시간을 즉시 기록하고 GPS 수신 이후 거리·경로를 추가한다. 워치 연결·권한 대기는 이 시작을 막지 않는다. 같은 러닝 식별자의 최신 상태를 받은 워치가 운동 세션을 한 번만 시작한다. 실행 요청 응답만으로 “워치 측정 중”을 표시하지 않고 실제 세션 콜백을 확인한다.

아이폰과 워치의 일시정지·재개는 같은 러닝에 적용한다. 워치에서 요청한 제어는 아이폰의 저장·반영 확인 전까지 `처리 중`으로 표시하며 중복 입력을 막는다. 워치 운동 세션은 확인된 상태를 따른다. 일시정지 구간을 거리와 시간에 합치지 않는다.

워치에서 최초 시작할 때 아이폰 위치 권한·실행 조건을 만족하지 못하면 `아이폰에서 시작 확인`으로 안내한다. 이번 단계에서 아이폰이 종료돼 있어도 워치만으로 새 GPS 기록을 만들겠다고 보장하지 않는다. 아이폰이 활성화된 경우 워치 요청도 GPS를 기다리지 않는 즉시 시작·재개 경로로 통일한다. 잠금 중 재개 가능 범위는 네이티브 검증 결과로 확정하며 실패 시 같은 기록을 보존한다.

종료 아이콘은 확인 화면을 연다. 연결된 경우 아이폰 종료 저장과 워치 세션 종료를 각각 확인한다. 아이폰 기록 저장이 끝났지만 워치 응답이 없으면 `기록 저장됨 · 워치 종료 확인 중`으로 구분한다. 이미 종료한 러닝을 늦은 메시지로 다시 시작하지 않는다.

## 4. 심박과 상태 전달

기존 워치 건강 저장소 읽기와 직접 전달을 우선 재사용한다. 센서에서 읽은 것처럼 합성한 수치나 이전 러닝의 심박을 넣지 않는다. 샘플 식별자 기반 중복 제거, 15초가 지난 현재 심박의 `-` 표시, 지연된 아이폰 건강 동기화 보완을 유지한다.

실행 중 세션의 수명은 SwiftUI 화면 활성화 여부와 분리한다. 손목을 내려 화면이 꺼져도 세션을 종료하지 않는다. 정상 실행 중에는 백그라운드 상태 전달과 재접속을 처리한다.

프로토콜에 러닝 ID, 상태 순서, 세션 상태와 오류 이유를 포함한다. 이전 러닝·이전 세션의 늦은 콜백은 현재 상태를 바꾸지 못해야 한다. 같은 요청을 반복 수신해도 세션과 기록을 중복 생성하지 않는다.

## 5. 연결 끊김과 충돌

10초 동안 최신 아이폰 상태를 확인하지 못하면 워치에 `연결 확인 중`과 마지막 확인 시점을 표시한다. 거리·시간을 무한히 추정해 늘리지 않는다. 재연결 버튼을 정상 측정 화면에 상시 배치하지 않는다.

첫 구현의 안전 기준은 마지막 유효 상태 후 30초에 워치 세션 일시정지, 2분에 워치 세션 종료다. 아이폰 러닝은 이 때문에 정지시키지 않는다. 이는 연결이 끊긴 채 워치 운동이 계속 남는 것을 막는 제안값이며 기기 QA 후 조정한다. 재연결하면 같은 러닝의 최신 상태를 확인하고 필요한 워치 세션만 복원한다.

연결이 끊긴 상태에서 워치의 종료를 확인하면 워치 세션은 즉시 종료한다. 아이폰에는 `종료 요청 전달 중` 상태를 유지하며 재연결 때 같은 러닝에만 요청한다. 종료 요청 시각 이후 수집분 처리와 저장 시각의 일치는 자동 회귀 검사로 검증해야 한다. 아이폰 저장 확인 전에는 전체 기록이 저장됐다고 표시하지 않는다.

다른 운동이 시작되어 Runary 세션이 종료되면 `워치 측정 중단`으로 표시한다. 아이폰 측정과 저장된 건강 심박 읽기는 계속하며 Runary 세션은 자동 재시작하지 않는다. 다른 운동이 끝난 뒤 사용자의 명시적 `워치 측정 다시 시작`으로만 재시도한다. 다른 앱의 운동 상태를 알아낼 수 있다고 가정하지 않는다.

앱 강제 종료·재실행은 정상 화면 잠금과 구분한다. 복구 가능한 활성 세션을 조회하고 같은 러닝 ID와 일치할 때만 연결한다. 아이폰의 중단 기록을 워치 때문에 자동 재개하지 않는다.

## 6. 화면 시안

거리 중심 구성 아래 시간·평균 페이스·심박을 둔다. 심박은 하트 아이콘과 bpm 단위를 함께 쓰고 세 지표 모두 왼쪽 정렬한다. 긴 상태 안내는 수치를 가리지 않는 하단 한 영역에 표시한다.

| 상태 | 상단 | 하단 동작 |
|---|---|---|
| 러닝 중 | 러닝 중 | 일시정지 아이콘, 종료 아이콘 |
| 일시정지 | 일시정지 | 재개 아이콘을 주황색으로 강조, 종료 아이콘 |
| 연결 지연 | 연결 확인 중 | 최신값이 아닌 지표 구분, 종료 요청 가능 |
| 다른 운동 충돌 | 워치 측정 중단 | 아이폰 러닝 계속 안내, 명시적 워치 재시작 |
| 권한 미완료 | 워치 연결 필요 | 권한 확인, 아이폰 러닝 계속 안내 |
| 종료 확인 | 러닝을 종료할까요? | 돌아가기, 종료 확인 |

아이콘 버튼은 최소 44pt 터치 영역과 VoiceOver 이름을 가진다. 디자인은 검토용 예시 수치를 사용하며 실제 센서 상태를 표현하는 시뮬레이션이 아니다.

## 7. 검증과 공개 전환

자동 검사는 중복 시작, 역순 상태, 다른 러닝 메시지, 연결 시간 초과, 충돌 후 자동 재시작 방지, 종료 요청 재전송, 늦은 콜백, 심박 중복·신선도를 확인한다. 아이폰·워치 전체 빌드와 공개/내부 설정 검사를 수행한다.

실기기에서는 다음을 짧게 검증한다. 기존 장거리 측정 성공을 다시 처음부터 검증하도록 요구하지 않는다.

1. Runary만 실행해 아이폰 시작 → 워치 세션 실행 → 새 심박 전달을 확인한다.
2. 손목 내리기·들기, 앱 목록으로 이동 후 내리기·들기를 각각 확인한다. 아이콘만 보이면 두 번째 항목은 미통과다.
3. 양쪽 일시정지·재개·종료, 연결 끊김 후 같은 러닝 복구, 종료 요청 전달을 확인한다.
4. 다른 운동과의 충돌은 사용자에게 알린 별도 QA에서 확인한다. 평소 사용 중인 운동을 임의로 중단하지 않는다.

자동 복귀가 OS 동작상 충족되지 않으면 구현 완료로 보고하거나 반복 실행 요청으로 앱을 강제로 열지 않는다. 관찰 결과와 대안을 제시해 출시 기준을 다시 정한다. 내부 검증이 끝난 뒤 공개 범위·개인정보 안내·스토어 설명을 개정한다.

## 8. 완료 기록의 건강 앱 저장

2026-10-26 사용자 요청으로 추가한 범위다. Apple 건강이 운동 데이터를 보관하고 피트니스가 연동된 운동을 보여주는 구조를 사용한다. 워치 연동 여부와 별개로 완료한 실제 Runary 러닝이 대상이다.

### 권한과 저장 대상

처음 기능을 켤 때 “완료한 러닝을 건강 앱에 저장해요. 피트니스에서도 확인할 수 있어요.”라고 안내하고 필요한 운동 쓰기 권한을 요청한다. 경로 등 부가 항목의 권한은 실제 저장 범위에 맞춘다. 기존 심박을 운동에 연결하기 위한 심박수 쓰기 권한도 요청한다. 심박 사본은 생성하지 않는다. 기존 설치에서 이 권한을 아직 요청하지 않았다면 사용자가 건강 저장을 다시 시도할 때 한 번 요청한다. 거부 후에는 설정 안내를 제공하며 자동으로 권한 창을 띄우지 않는다.\
거절하거나 나중에 철회해도 Runary 측정과 원본 저장은 계속한다. 매 러닝마다 권한 창을 반복해서 띄우지 않는다.

기능을 켠 뒤 완료하고 저장한 러닝부터 자동으로 전송한다. 샘플, 폐기한 측정, 진행 중인 기록, 다른 앱에서 가져온 기록은 제외한다. 기존 기록의 일괄 전송은 이번 범위에서 제외한다.

### 저장 데이터와 중복 방지

아이폰의 확정 기록을 기준으로 운동 종류, 시작·종료 시각, 일시정지를 제외한 운동 시간과 실제 측정 거리를 저장한다. 수집한 경로와 심박은 권한과 HealthKit의 연결 방식에 맞춰 반영한다.\
좌표가 없는 구간이나 심박을 만들어 넣지 않는다. 기존 건강 심박을 Runary가 새로 측정한 샘플처럼 복제하지 않는다. 칼로리와 활동 링 반영은 이번 완료 조건으로 약속하지 않는다.

최종 운동 저장 주체는 아이폰으로 통일한다. 워치 세션 종료가 별도의 운동 저장으로 이어지지 않게 해 한 러닝에 운동 한 건만 만든다. 러닝 ID와 건강 운동 ID의 연결, 항목별 저장 상태를 기기에 보관한다.\
같은 러닝의 재전송에는 동일한 동기화 식별자를 사용한다. 운동 저장 직후 앱이 종료된 경우와 운동은 저장됐으나 경로만 실패한 경우도 중복 생성 없이 복구해야 한다. HealthKit 동기화 식별자와 버전의 적용 방식은 구현 검증 항목으로 둔다.

기록 선택에서는 이 연결 정보로 Runary 원본과 건강에서 읽은 동일 운동을 한 항목으로 표시한다. 날짜와 거리만 비슷한 다른 앱 기록을 임의로 숨기지 않는다. Runary 원본이 없으면 읽기 권한으로 조회된 건강 기록은 계속 선택할 수 있다.

### 저장 결과와 재시도

Runary 원본 저장 완료와 건강 저장 결과는 별도로 표시한다. 아이폰 기록 상세에서 `건강 앱에 저장됨`, `건강 앱 저장 대기`, `건강 앱 저장 안 됨`을 구분한다. 부가 데이터만 실패하면 전체 완료로 표시하지 않는다.\
일시적인 실패는 앱에서 다시 처리할 수 있을 때 재시도하고, 사용자가 직접 다시 저장할 수도 있게 한다. 권한 거절은 자동 권한 요청으로 반복하지 않고 설정 안내를 제공한다. 기록 편집과 영상 제작은 건강 저장을 기다리지 않는다.

Runary 원본 삭제는 건강의 운동까지 자동 삭제하지 않는다. 삭제 안내에서 건강에 저장한 운동은 남는다고 알린다. 사용자가 건강에서 이미 삭제한 저장 완료 운동을 앱 재실행만으로 다시 만들지 않는다.

### 추가 검증과 남은 기술 확인

자동 검사에는 저장 재시도, 저장 직후 종료, 부분 실패, 권한 철회, 샘플 제외, 기록 선택 중복 제거를 포함한다. 실기기에서는 아이폰 단독 및 워치 연동 러닝을 각각 저장해 건강과 피트니스의 출처와 운동 건수를 확인한다. 일시정지한 운동 시간과 거리도 원본과 비교한다.

[확인 필요] 건강 경로에서 끊긴 구간을 잘못 잇지 않는 저장 방식과, 기존 심박 샘플을 복제하지 않고 운동에 연결했을 때 피트니스에 표시되는 범위를 네이티브 검증으로 확정한다. 지원하지 않는 항목은 완료로 보고하지 않고 기능정의서에 실제 범위를 반영한다.\
개인정보 처리방침, FAQ와 권한 설명의 기존 “읽기만 사용” 안내는 공개 배포 전에 함께 개정한다.

## 근거

- [Apple 타사 운동 앱 연동](https://support.apple.com/guide/iphone/sync-a-third-party-workout-app-iph392b962da/ios): 건강 및 피트니스 연동.
- [HealthKit 동기화 식별자](https://developer.apple.com/documentation/healthkit/hkmetadatakeysyncidentifier): 저장 재시도 시 동일 데이터 식별.
- [Apple 운동 세션](https://developer.apple.com/documentation/healthkit/hkworkoutsession): 워치의 단일 운동 세션과 충돌 처리.
- [백그라운드 세션](https://developer.apple.com/documentation/watchkit/enabling-background-sessions): 운동 처리 모드, 손목을 들었을 때 앱 표시와 크라운으로 나갔을 때 아이콘 표시.
- [기존 측정 FRD](internal-run-tracking.md): 기록의 기준, 복구, 저장소 심박 전달.

승인에 따라 기존 측정 PRD·FRD와 결정문에 이번 정책 개정을 함께 기록한다. 건강 저장에는 워치 운동 세션이 필수가 아니다.
