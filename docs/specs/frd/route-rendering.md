# 경로 렌더링 FRD

> **status: `draft`.** 팀 확인 후 `approved`로 올린다. **approved가 아니면 구현 근거가 아니다.**
> 근거: [PRD](../prd/running-drawing-mvp.md) · [2026-08-18 결정](../../decisions/2026-08-18-native-ios-and-mvp-scope.md)

## 0. 범위

**담는 것**: 정규화된 트랙이 들어와 9:16 클립이 나오기까지. 투영, 전처리, 애니메이션, 프리셋 스타일 정의, 각인, 배경 합성, 출력 규격.

**안 담는 것**

| 항목 | 어디로 |
|---|---|
| 사용자가 고르고 만지는 것 (프리셋 선택, 크기·위치·회전, 다듬기 세기, 각인 모드) | 결과물 편집 FRD |
| 배경을 어떻게 확보하나 | 배경 선택 FRD |
| 트랙을 어디서 가져오나 | 러닝 기록 선택 FRD |
| 색상값·타이포·간격의 실제 값 | 디자인 시스템 |

**이 문서는 렌더러가 무엇을 할 수 있는지를 정한다. 사용자가 무엇을 고를 수 있는지는 편집 FRD가 정한다.**

## 1. 원칙

| # | 원칙 | 출처 |
|---|---|---|
| R1 | **기본값으로 완성된 결과물이 먼저 나온다.** 편집은 그 위에서 바꾸는 것이지, 편집해야 완성되는 것이 아니다 | 2026-08-19 |
| R2 | **실제로 지나가지 않은 길이 보이면 안 된다.** 왜곡의 상한은 "이 그림을 보고 같은 길을 다시 뛸 수 있는가" | PRD §8 |
| R3 | 표현 요소는 전부 러닝 데이터에서 나온다. 예외는 배경 하나뿐 | PRD P1 |

## 2. 입력: 정규화된 트랙

데이터 출처(HealthKit / GPX)와 무관하게 아래 형태로 들어온 뒤에야 렌더러를 만난다.

| 필드 | 필수 | 비고 |
|---|---|---|
| 좌표열 (시각, 위도, 경도) | 필수 | 시간순 |
| 고도 | 선택 | MVP 프리셋 3개는 안 쓴다 |
| **심박** | **선택 (있으면 MVP에서도 읽는다)** | 아래 참고 |
| 총 거리 | 필수 | **각인에는 선 길이가 아니라 이 값을 쓴다** |
| 총 시간 | 필수 | |
| 평균 페이스 | 필수 | |

### 심박을 MVP에서 함께 읽는다

**HealthKit이 심박을 주면 MVP에서도 같이 읽어 트랙에 담는다.** 어차피 같은 워크아웃에서 나오는 데이터이고, bpm에 따른 페이스·거리·시간은 러너가 실제로 중요하게 보는 정보다. 나중에 쓰려고 그때 가서 데이터 경로를 다시 뚫는 것보다 지금 담아두는 편이 싸다. (2026-08-19)

**다만 심박은 있을 수도 없을 수도 있다.**

| 출처 | 심박 |
|---|---|
| HealthKit 워크아웃 | 대체로 있다 (시계나 밴드를 찼다면) |
| GPX 임포트 | 없는 경우가 많다 |

따라서 **심박에 의존하는 표현은 "있을 때만" 동작해야 한다.** 심박이 없다고 렌더링이 실패하거나 빈 자리가 남으면 안 된다.

- MVP 프리셋 3개는 심박을 쓰지 않는다. 없어도 결과물이 온전하다
- 각인에 심박을 넣을지는 §7의 `[확인 필요]`에서 다룬다
- 로드맵의 심박 맥동 프리셋은 이 데이터 위에 바로 얹힌다

`[확인 필요]` 트랙이 렌더링에 부적합한 경우의 하한. 좌표 수가 너무 적거나 총 거리가 지나치게 짧은 기록을 어디서 걸러낼지. 러닝 기록 선택 FRD와 나눠 정한다.

## 3. 전처리

### 3-1. 이상점 제거 (항상 적용)

명백히 잘못 찍힌 좌표는 **다듬기 세기와 무관하게 항상 제거한다.** 다듬기를 0으로 둬도 적용된다. 스타일이 아니라 오류 처리이기 때문이다.

### 3-2. 다듬기

**두 축이 있다.**

| 축 | 무엇을 |
|---|---|
| 직선 | GPS 노이즈로 지글거리는 직선 구간을 편다 |
| 코너 | 길모퉁이의 각을 다듬는다 |

- **직선은 시원하게, 코너는 실제 길모퉁이만큼.** 직선을 펴려고 코너를 뭉개지 않는다 (PRD §8)
- **슬라이더 범위 자체를 안전 구간으로 잡는다.** 사용자가 최대치까지 올려도 R2를 깨지 않는 범위여야 한다. 따라서 **경고나 차단 UI를 두지 않는다**
- 사용자 노출 방식(기본 한 축, 고급에서 두 축)은 결과물 편집 FRD가 정한다

`[확인 필요]` 안전 구간의 상한. [경로 보정 수준 비교 화면](../../ideation/phs00/2026-08-17-route-stylization-levels.html)에서 원본 대비 평균 이탈(m)을 보며 정한다. 잠정 기준은 **B~C 수준**(패널 순서: A 원본 / B 가벼운 정리 / C 양식화)이며, **이 값은 출발점이지 통과 기준이 아니다.** 드로잉 담당이 시도하면서 바뀔 수 있다.

### 3-3. 같은 구간을 여러 번 지날 때

**애니메이션은 기록된 순서를 그대로 따라간다.** 같은 길을 두 번 지났으면 그 구간 위를 두 번 지나간다. 왕복이든 같은 블록을 여러 바퀴 돈 것이든 마찬가지다. **이것이 기본 동작이고 항상 적용된다.** 별도 옵션이 아니다.

경로는 시간순 좌표열이고 드로잉은 그 위를 따라가는 애니메이션이므로, 이것은 특별한 처리가 아니라 자연스러운 결과다.

**다만 완성된 정지 화면에서는 겹친 선이 한 줄로 보인다.** 지나간 횟수는 그리는 동안에는 보이지만 최종 그림에는 남지 않는다.

#### 왕복 분리는 MVP에서 뺀다

겹친 구간을 **두 줄로 벌려** 나란히 보여주는 처리를 말한다. 정지 화면에서도 왕복이 읽히게 하는 방법이지만 넣지 않는다.

- **없는 선을 만들어내는 조작**이라 R2에 걸린다. 실제로 두 줄로 뛴 적이 없다
- 켤 때 사용자가 알 수 있게 하려면 안내 UI까지 필요하다
- 일정 대비 값어치가 약하다

`[확인 필요]` **겹쳐 지나간 구간을 더 밝게 또는 굵게 표시하는 안.** 선의 위치를 옮기지 않으므로 R2에 걸리지 않으면서, 정지 화면에도 "여기를 여러 번 지났다"가 남는다. 3주차에 실제 왕복 코스로 보고 판단한다.

## 4. 프레이밍

경로를 9:16 화면 어디에 얼마만 하게 앉힐지를 정한다. **값은 셋이다. 회전, 크기, 위치.**

**렌더러는 이 셋의 초기값을 정하고, 편집은 같은 셋을 사용자가 바꾼다.** 서로 다른 기능이 아니라 같은 값을 누가 정하느냐의 차이다.

| 값 | 렌더러의 초기값 |
|---|---|
| **회전** | **0도. 돌리지 않는다** |
| **크기** | 경로 전체가 여백 안에 들어오는 최대 크기 |
| **위치** | 화면 가운데 |

### 회전 0도가 무슨 뜻인가

**경로 그림을 세로 화면에 잘 들어맞게 하려고 돌리는 일을 하지 않는다는 뜻이다.**

실제 GPS 경로는 동서로 길게 뻗은 경우가 많다. 그런 경로를 9:16 세로 화면에 넣으면 좌우로는 꽉 차는데 위아래로는 납작해진다. 이때 **경로를 90도 눕히면 화면을 훨씬 크게 쓸 수 있는데, 그 자동 보정을 하지 않는다.**

좌표를 그대로 투영하므로 **결과적으로 북쪽이 위가 된다.** 지도와 같은 방향이고, 내가 뛴 길과 그림의 방향이 일치한다. R2("이 그림을 보고 같은 길을 다시 뛸 수 있는가")에 유리하다.

**대신 가로로 긴 경로는 세로 화면 가운데에 띠처럼 작게 남는다.** 위아래 여백은 배경 사진이 채우고 각인이 놓이므로 화면이 비지는 않는다. 다만 경로 자체를 크게 보고 싶은 사용자를 위해 **회전 편집이 실질적으로 필요한 옵션**이 된다. 자동으로 안 돌리는 대신 사용자가 직접 돌린다.

### 크기 (축척)

"축척"과 "크기"는 같은 것을 가리킨다. 경로를 몇 배로 확대해 그리느냐다. 렌더러는 **경로 전체가 여백 안에 들어오는 최대 크기**로 시작하고, 사용자는 편집에서 키우거나 줄인다. 키워서 경로 일부가 화면 밖으로 나가는 것도 허용한다.

**제안값** 경로 바깥 여백은 화면 짧은 축 기준 8%.

## 5. 애니메이션

### 5-1. 클립 길이: 거리와 무관하게 고정

5km든 20km든 같은 길이의 클립이 나온다. 긴 거리는 그만큼 빨리 그려진다.

**제안값**

| 구간 | 길이 |
|---|---|
| 그리기 | 9초 |
| 완성 후 정지 | 3초 |
| **합계** | **12초** |

15초를 넘기지 않는 것이 조건이다. 인스타 스토리가 15초 단위로 잘리기 때문이다. 정지 구간은 보는 사람이 모양을 알아볼 시간이자 캡처가 일어나는 자리다.

속도 조절은 편집에서 한다.

### 5-2. 시작 상태: 프리셋마다 다르다

경로 전체가 희미하게 미리 깔리는지, 빈 화면에서 시작하는지는 **프리셋 정의(§6)에 각각 명시한다.**

### 5-3. 끝: 완성 후 정지

그리기가 끝나면 완성된 경로가 화면에 남은 채로 정지 구간이 이어진다. 반복 재생하지 않는다.

## 6. 프리셋

**프리셋은 전부 하나의 렌더러다. 차이는 "경로 위 진행률을 어떻게 칠하느냐"뿐이다** (PRD §7). 따라서 아래 넷만 프리셋마다 다르다.

| 항목 | 무엇 |
|---|---|
| 시작 상태 | 그리기 전 화면 |
| 진행 표현 | 진행률에 따라 무엇이 어떻게 변하나 |
| 마무리 | 그리기가 끝나는 순간의 연출 |
| 기본 색 | 프리셋의 정체성 색 |

**MVP 기본은 셋이다.** 그 위의 연출 아이디어(폭죽, 줌 추적 등)는 PRD §7의 아이디어 풀에 있으며 이 문서 범위 밖이다.

### 6-1. 기본 드로잉 (기본값)

| 항목 | |
|---|---|
| 시작 상태 | **빈 화면.** 배경만 있다 |
| 진행 표현 | 경로가 처음부터 선으로 그려져 나간다. 그려진 부분은 남는다 |
| 마무리 | 별도 연출 없이 완성된 선이 남는다 |
| 기본 색 | `[확인 필요]` 디자인 시스템 |

가장 단순하고 어떤 코스에서도 성립한다. **앱을 처음 열었을 때의 기본값이다.**

### 6-2. 불빛 러너

| 항목 | |
|---|---|
| 시작 상태 | **빈 화면** |
| 진행 표현 | 빛이 경로를 달리고, 지나온 길에 잔광이 남는다 |
| 마무리 | **끝점에 닿는 순간 경로 전체가 밝아진다** |
| 기본 색 | `[확인 필요]` 디자인 시스템 |

원안은 "출발점에 닿는 순간"이었으나 **끝점으로 일반화했다.** 돌아오는 코스에서는 끝점이 곧 출발점이라 원래 의도가 그대로 살고, 편도 코스에서도 마무리 연출이 생긴다.

### 6-3. 구간 점등

| 항목 | |
|---|---|
| 시작 상태 | **경로 전체가 희미하게 깔린 채로 시작** |
| 진행 표현 | 구간이 하나씩 켜진다. 켜진 구간은 남는다 |
| 마무리 | 마지막 구간이 켜지면 전체가 켜진 상태 |
| 기본 색 | `[확인 필요]` 디자인 시스템 |

**구간 수는 거리에 따라 자동으로 조절한다.** km 고정이면 20km에서 20번이 되어 깜빡임처럼 보인다. 클립 길이가 고정이므로 점등 횟수가 일정해야 리듬이 산다.

**제안값** 점등 횟수 5~8회를 목표로, 구간 단위를 0.5 / 1 / 2 / 5km 중에서 자동 선택한다.

| 총 거리 | 구간 단위 | 횟수 |
|---|---|---|
| ~3km | 0.5km | 최대 6 |
| 3~8km | 1km | 3~8 |
| 8~16km | 2km | 4~8 |
| 16km~ | 5km | 4~ |

## 7. 각인

### 7-0. 무엇을 새기나

**넷을 기본으로 다 새긴다.** 항목별로 끄는 것은 편집에서 한다. (2026-08-19)

| 항목 | 진행에 따른 값 | 비고 |
|---|---|---|
| 거리 | 그려진 만큼 차오른다 | **선 길이가 아니라 기록된 거리**를 쓴다 |
| 시간 | 흐른다 | |
| 페이스 | 그 구간 값 | |
| **심박** | 그 시점 bpm | **데이터가 있을 때만.** 없으면 항목 자체가 빠진다 |

**심박이 없으면 빈 자리를 남기지 않는다.** 나머지 셋이 그 자리를 채운다. GPX로 가져온 기록에는 심박이 없는 경우가 많으므로 예외가 아니라 흔한 경우다(§2).

넷 다 시간축을 가지므로 §7-2의 카운트업이 일관되게 적용된다.

### 7-1. 표시 모드

| 모드 | 동작 |
|---|---|
| **항상** (**기본값**) | 그리는 동안에도 계속 보인다 |
| 완성 후만 | 그릴 때는 없고 정지 구간에 올라온다 |
| 숨김 | 전혀 나오지 않는다 |

기본값을 "항상"으로 둔 것은 **러너가 공유할 때 기록을 웬만하면 함께 올리기 때문**이다. 숫자가 없으면 러닝이라는 맥락이 안 읽힐 수 있다.

> **3주차 반응 테스트 확인 항목.** 그림만 보이는 구간이 없는 데다 항목이 넷이라 "숫자가 많아 정신없다"는 반응이 나올 수 있다. 그 경우 기본값(모드 또는 항목 구성)을 뒤집는다.

### 7-2. 값의 움직임

- **"항상" 모드에서는 진행에 따라 숫자가 올라간다.** 프리셋들이 이미 진행률을 따라가고 있으므로 같은 값을 숫자에 물린다
- **"완성 후만" 모드에서는 최종값만 나온다.** 페이스와 심박은 평균값
- **거리는 선 길이가 아니라 기록된 총 거리를 쓴다** (§2)

표현 방식(서식, 단위 표기 등)을 사용자가 고르는 것은 **로드맵**이다. MVP에서는 위 동작으로 고정한다.

### 7-3. 항목별 끄기

**어떤 항목을 새길지는 편집에서 고른다.** 넷 다 켜진 상태가 기본이고, 사용자가 필요 없는 것을 끈다. 우선순위는 여유 시다(PRD §7).

### 7-4. 배치

**두 영역을 피한다.**

1. **인스타 스토리 UI 안전 영역.** 상하단은 인스타 자체 UI에 가린다
2. **경로가 지나가는 영역.** "항상" 모드에서는 그리는 내내 화면에 떠 있으므로 경로와 겹치면 계속 거슬린다

`[확인 필요]` 안전 영역 수치. **제안값**은 상단 14%, 하단 20%다. 실제 기기에서 인스타를 띄워 확인해야 한다.

`[확인 필요]` **넷을 어떻게 늘어놓을지.** 한 줄인지 두 줄로 묶는지, 심박이 빠졌을 때 어떻게 재배치하는지. **제안**은 하단 안전 영역 위에 묶어 두는 것이고, 구체 레이아웃은 디자인 시스템에서 정한다.

## 8. 배경 합성

합성 순서는 아래에서 위로.

```
배경 (사진 또는 영상)
  ↓
경로 (프리셋 스타일)
  ↓
각인
```

- 배경이 영상일 때는 클립 길이(§5-1)에 맞춘다. 배경 영상이 더 짧거나 길 때의 처리는 **배경 선택 FRD**가 정한다
- **배경에서 선 색을 자동 추출하지 않는다** (PRD §5 제외). 대비는 선 굵기와 외곽선·그림자로 보완한다

`[확인 필요]` 선 굵기와 대비의 하한. **인스타 재압축으로 얇은 선이 뭉개지는지**를 3주차에 실측해 정한다 (PRD §12).
