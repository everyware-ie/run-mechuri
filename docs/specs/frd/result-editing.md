# 결과물 편집 FRD

> **status: `approved`.** 2026-08-25 회의에서 확정됐다. 구현 근거로 쓸 수 있다.
> 근거: [PRD](../prd/running-drawing-mvp.md) · [2026-08-18 결정](../../decisions/2026-08-18-native-ios-and-mvp-scope.md)

## 0. 범위

사용자가 결과물을 보며 고르고 만지는 전부를 정한다. 프리셋 선택, 드로잉 조작, 다듬기 세기, 각인과 문구, 미리보기가 여기 있다.

**[경로 렌더링](route-rendering.md)과의 경계가 이 문서의 뼈대다.** 렌더러는 초기값을 정하고, 편집은 같은 값을 사용자가 바꾼다. 서로 다른 기능이 아니라 같은 값을 누가 정하느냐의 차이다.

| 값 | 렌더러의 초기값 | 편집에서 |
|---|---|---|
| 프리셋 | 기본 드로잉 | 셋 중에서 고른다 |
| 회전 | 0도 | 돌린다 |
| 크기 | 화면에 맞춤 | 키우거나 줄인다 |
| 위치 | 가운데 | 옮긴다 |
| 다듬기 세기 | 기본값 | 조절한다 |
| 속도 | 12초 고정 | 조절한다 |
| 선 색 | 프리셋의 기본 색 | 바꾼다 |
| 각인 | 사용 가능한 항목 표시, 항상 | 프리셋·항목·문구·위치·크기를 조정한다 |

**배경의 확대·이동은 여기서 하지 않는다.** 배경 선택 화면 몫이다. 편집 화면에서 만지는 것은 드로잉과 각인뿐이다. 한 화면에서 배경과 드로잉을 동시에 만지면 사용자가 지금 무엇을 움직이는지 헷갈린다.

| 담지 않는 것 | 어디에 |
|---|---|
| 프리셋이 무엇을 어떻게 그리는지 | [경로 렌더링](route-rendering.md) §6 |
| 배경 소재를 고르고 9:16에 맞추는 것 | [배경 선택](background-selection.md) |
| 내보내기와 공유 | [내보내기·공유·저장](export-and-share.md) |

## 1. 화면 구조

> 편집 화면이 어디에 놓이고 무엇을 품는지 확인할 때 본다.

코어 루프는 네 단계다.

```
[러닝 기록 선택] → [배경 선택] → [편집] → [공유]
```

**편집 안에서 드로잉 → 각인 순서로 안내한다** (2026-09-11 사용자 확인). 하나의 전체 미리보기를 공유하며 도구만 바뀐다. 드로잉의 다음은 각인으로, 각인의 이전은 드로잉으로, 완료는 공유로 이동한다.

단계 탭으로 순서에 관계없이 이동할 수 있다. **상단 완료는 어느 단계에서도 사용할 수 있다.** 각인을 먼저 정한 뒤 드로잉 구도를 맞춘 사용자가 각인 단계를 다시 거칠 필요는 없다. 전환 시 편집값을 모두 유지하며 각인 변경만으로 드로잉을 자동 이동·축소하지 않는다.

단계 선택은 도구를 접어도 유지한다. 미리보기에는 배경·드로잉·각인을 항상 함께 표시하고, 도구가 전체 구도를 가리지 않게 한다.

**프리셋 목록만을 위한 화면은 따로 두지 않는다.** 각 단계에서 결과를 보며 고른다.

PRD P3이 "프리셋은 고르는 재미가 우선"이라고 했는데, 결과를 안 보고 이름만으로 고르면 재미가 나지 않는다. 목록에서 고르고 다음 화면에서 확인하는 구조는 마음에 안 들 때마다 뒤로 갔다 다시 와야 한다. 프리셋이 셋뿐이라 편집 화면 안에서 넘겨보는 것으로 충분하다.

**배경도 편집 화면에서 다시 열 수 있다.** 배경을 고른 뒤에야 드로잉과 안 어울린다는 것을 알게 되는 경우가 많다. 그때 뒤로 가는 대신 그 자리에서 바꾼다. 배경을 바꿔도 드로잉 편집값은 유지된다.

## 2. 미리보기

> 편집하는 동안 화면이 어떻게 움직이는지 정한다.

재생·스토리 안전 영역 버튼은 **하단 도구 패널의 드로잉·각인 탭 옆**에 둔다(2026-09-11 사용자 요청). 미리보기 위에 별도 조작 줄을 두지 않고, 패널을 접어도 두 버튼과 도구 열기는 사용할 수 있게 한다. 제스처 안내는 선택한 도구 내용 안에서 보여주며, 문구 입력 중에는 입력 안내를 우선한다. 미리보기는 남은 영역 안에 9:16 전체 구도를 유지한다.

도구 패널은 **기본 글자 크기에서 가능한 한 스크롤 없이 확인**할 수 있게 구성한다(2026-09-11 사용자 요청). 초기화는 드로잉 제스처 안내 옆에 **아이콘과 ‘초기화’ 문구를 함께 표시한 보조 칩 버튼**으로 제공하고, 프리셋과 두 다듬기 슬라이더를 함께 노출한다. 도구 내용에 맞춰 패널 높이를 필요한 만큼 조정하되 미리보기 공간을 보존하기 위해 상한을 둔다. 큰 글자·긴 항목·키보드 표시로 내용이 넘치면 패널 내부 스크롤로 모든 기능에 접근할 수 있게 한다.

### 2-1. 재생

| 상태 | 동작 |
|---|---|
| 평소 | 클립을 반복 재생한다 |
| 조작 중 (슬라이더를 잡고 있거나 제스처 중) | 그 시점에서 일시 정지한다 |
| 손을 떼면 | 그 시점부터 이어서 재생한다 |
| 프리셋을 바꾸면 | 처음부터 재생한다 |

**멈추는 이유는 움직이는 중에 무엇이 바뀌는지 보이지 않기 때문이다.** 특히 다듬기는 선 모양이 차이라 정지 상태여야 판단이 선다. 반대로 프리셋은 움직임이 차이여서(불빛이 달리는지, 구간이 켜지는지, 선이 그려지는지) 재생되어야 보인다. 그래서 평소에는 재생하고 손을 대면 멈춘다.

**완성된 상태로 건너뛰지 않는다.** 그리는 중에 손을 대면 갑자기 완성본이 튀어나오고, 손을 떼면 다시 빈 화면부터 시작한다. 한 번의 조작에 시각적 점프가 두 번 생긴다. 지금 보고 있던 그 화면이 그대로 멈추는 편이 자연스럽다.

프리셋 전환만 예외로 처음부터 재생한다. 연출 전체가 갈리므로 중간부터 보면 무엇이 달라졌는지 알 수 없다.

**어느 시점에서 멈출지는 사용자가 고른다.** 재생이 계속 돌고 있으므로, 선 전체를 보며 다듬기를 조절하고 싶으면 거의 다 그려졌을 때 손을 대면 된다. 재생 위치를 옮기는 UI를 따로 만들지 않는 이유가 이것이다.

### 2-2. 즉시 반영

모든 조작은 즉시 미리보기에 반영된다. 적용 버튼을 두지 않는다(PRD §7).

## 3. 프리셋 선택

> 셋 중 하나를 고르는 자리다.

기본값은 "기본 드로잉"이다. 고르면 즉시 미리보기가 그 프리셋으로 바뀌고 처음부터 재생된다.

**프리셋을 바꿔도 드로잉 조작값과 각인 설정은 유지된다.** 크기·위치·회전을 맞춰둔 것이 프리셋을 넘겨볼 때마다 초기화되면 비교가 안 된다.

> **"드로잉"과 "기본 드로잉"은 다른 말이다.** 드로잉은 결과물의 경로 그림을 가리키고, 프리셋 셋은 전부 그 드로잉을 그리는 방식이다. 그중 기본값의 이름이 "기본 드로잉"이다. 이 문서에서 "드로잉의 크기·위치"라고 할 때의 드로잉은 프리셋이 아니라 편집 대상이다.

`[확인 필요]` 고르는 방식. 가로로 넘기는 형태와 나란한 버튼 중 무엇이 나은지. 셋뿐이라 둘 다 성립한다. 디자인 시스템에서 정한다.

## 4. 편집 대상과 조작

> 손가락으로 무엇을 어떻게 만지는지 정한다.

### 4-1. 편집 대상 고르기

화면 위에 얹히는 것이 하나가 아니다. 드로잉과 각인이 함께 있고, 제스처는 하나의 대상에만 적용된다. **그러므로 지금 무엇을 만지고 있는지 고르는 층이 필요하다.** 편집툴의 레이어 선택과 같은 구조다.

| 대상 | 조작 |
|---|---|
| 드로잉 | 크기, 위치, 회전 |
| 각인 | 위치 |
| 배경 | 없음. 배경 선택 화면 몫이다(§0) |

기본 선택은 드로잉이다. 편집 화면에 들어오면 드로잉이 골라진 상태로 시작한다. 선택된 대상에만 제스처가 적용되므로, 각인을 고른 상태에서 끌면 각인이 움직이고 드로잉은 가만히 있다.

**화면에서 다른 대상을 단순 탭해서도 고를 수 있게 한다.** 선택하면 단계 탭과 도구도 함께 바뀐다. 드래그·핀치는 현재 선택한 단계의 대상에 적용하며, 손댄 위치만으로 드래그 도중 대상이 바뀌지 않는다.

**켜진 각인 항목은 하나의 묶음이다.** 거리·시간·페이스·날짜·장소·심박을 따로따로 배치하지 않는다. 개별 배치는 조작 대상을 늘리고, 각 항목의 안전 영역도 따로 고려해야 한다. 어떤 항목을 보일지는 끄고 켜는 것으로 정하고 배치는 묶음째 옮긴다. 개별 배치는 로드맵이다.

> **MVP 필수 구간에서는 이 층이 없어도 성립한다.** 각인 편집이 "여유 시"라서 그때까지는 만질 수 있는 대상이 드로잉 하나뿐이다. 대상 선택 UI는 각인 편집이 붙는 시점에 함께 등장한다.

### 4-2. 제스처

| 제스처 | 동작 |
|---|---|
| 끌기 | 위치 |
| 핀치 | 크기 |
| 두 손가락 비틀기 | 회전 |

**슬라이더를 쓰지 않는 이유는 사진 앱과 같은 조작이라 배울 것이 없기 때문이다.** 화면에서 슬라이더 세 개를 미리 줄이는 효과도 있다.

선택된 대상에만 적용된다(§4-1). 각인은 끌기로 위치, 핀치로 크기를 바꿀 수 있으며 회전은 지원하지 않는다.

### 4-3. 초기화

제스처만 두면 사용자가 이상하게 놓고 돌아오지 못하는 경우가 생긴다. 드로잉을 렌더러의 초기값(회전 0도, 화면에 맞춤, 가운데)으로 되돌리는 방법을 둔다.

**되돌리는 단위는 드로잉 조작뿐이다.** 프리셋과 각인 설정은 그대로 남는다. 한 번에 다 날아가면 되돌리기를 누르기가 무서워진다.

### 4-4. 범위

화면 밖으로 나가도록 옮기거나 키우는 것을 허용한다. 경로 일부만 크게 보여주는 것도 표현이다. 다만 **드로잉이 화면에서 완전히 사라지지는 않게 한다.** 되돌아올 방법이 초기화뿐이면 막다른 길이 된다.

크기의 상하한을 수치로 정하지 않는다. 위 두 줄이 실질적인 하한이고, 상한은 사용자가 판단할 몫이다. 너무 키우면 무엇인지 알아볼 수 없는 결과물이 나오지만 그건 미리보기에서 바로 보인다.

## 5. 다듬기 세기

> 선을 얼마나 매끄럽게 할지 조절하는 자리다.

**두 축이다. 직선과 코너 슬라이더 둘을 편집 화면에 바로 둔다.** 고급 설정으로 숨기지 않는다.

> **개정 (2026-09-07).** 원래는 "다듬기 세기" 한 축을 기본으로 주고 고급 설정을 열어야 둘로 나뉘는 구조였다. 복잡해질까 봐 그렇게 잡았는데, **실물을 만져보니 슬라이더 둘이 부담스럽지 않았다.**
>
> 오히려 축을 합치면 **직선만 펴고 싶은데 코너까지 뭉개지는 상황을 사용자가 풀 방법이 없어진다.** 둘은 실제로 다른 것을 만지고 있어서, 하나로 묶으면 조절이 아니라 타협이 된다.
>
> 근거는 [2026-09-01 결정](../../decisions/2026-09-01-frd-over-mockup.md)이 정한 절차다. FRD대로 만들었더니 이상하면 이슈로 올려 FRD를 고친 뒤 진행한다.

**슬라이더 범위 자체가 안전 구간이다.** 최대치까지 올려도 실제로 지나가지 않은 길이 보이지 않는다([경로 렌더링](route-rendering.md) §3-2). 그래서 경고나 차단 UI를 두지 않는다.

이 문서는 슬라이더 둘을 화면 어디에 어떻게 두는지 정하지 않는다. 제약 하나만 건다.

> **결과를 보면서 조절할 수 있어야 한다.** 별도 화면으로 빼서 미리보기가 안 보이게 하면 안 된다. 그 안에서 펼치기든 하단 버튼이든 무엇이든 좋다.

배치는 편집 화면 전체 구조가 나온 뒤에 정해진다. 다듬기만 따로 떼어 먼저 정하면 프리셋 선택·대상 선택·각인 설정이 같은 화면에서 자리를 다툴 때 어긋난다.

## 6. 속도와 색

> 둘 다 여유 시 항목이다(PRD §7).

### 6-1. 속도

그리기 구간의 길이를 조절한다. 클립 총 길이가 함께 바뀐다.

| 항목 | 값 |
|---|---|
| 기본 | 12초 (그리기 9 + 정지 3) |
| 상한 | **15초.** 인스타 스토리가 15초 단위로 잘린다. 넘기면 결과물이 두 장으로 쪼개진다 |
| 하한 | 8초 제안. 너무 빠르면 무엇을 그리는지 안 보인다 |

#### 배경 영상 길이와 어긋나지 않는다

속도를 바꾸면 클립 길이가 바뀌는데 배경 영상은 그와 무관하게 제 길이를 갖는다. **경우의 수를 따로 만들 필요가 없다.** [배경 선택](background-selection.md) §5-1의 규칙이 12초 고정이 아니라 "클립 길이" 기준이기 때문이다.

| 배경 영상 | 처리 |
|---|---|
| 클립보다 짧다 | 반복 재생 (3초 미만은 마지막 프레임 정지) |
| 클립보다 길다 | 앞에서부터 클립 길이만큼 |

속도를 낮춰 클립이 15초가 되면 12초짜리 배경은 3초를 반복하고, 20초짜리 배경은 앞 15초를 쓴다. 규칙은 그대로고 기준만 따라 움직인다.

속도를 바꿔서 배경에 반복 이음새가 새로 생길 수는 있다. 다만 미리보기에 즉시 반영되므로 사용자가 바로 본다. 마음에 안 들면 속도를 되돌리거나 마지막 프레임 정지로 바꾸면 된다.

### 6-2. 색

**색은 사용자가 고르고 마감은 우리가 고정한다.**

| 단계 | 무엇 |
|---|---|
| MVP (여유 시) | 프리셋마다 어울리는 3~5가지를 미리 골라 제공한다 |
| 로드맵 | 사용자가 색상을 자유롭게 고르고, 우리가 그 위에 마감 처리를 얹는다 |

가짓수를 3~5로 두는 것은 옵션이 많으면 고르는 일이 피로가 되기 때문이다. 프리셋이 셋뿐인 것과 같은 판단이다.

**로드맵 쪽이 이 항목의 최종 형태다.** 사용자가 고르는 것은 색상값이고, 그 위에 얹히는 발광·대비·굵기 같은 마감은 우리가 항상 적용한다. 어떤 색을 골라도 우리 결과물로 보이게 하려는 것이다. 자유도는 주되 품질은 우리가 잡는다.

이 구조가 되면 "배경과 안 맞는 색을 골라서 결과물이 나빠진다"는 걱정이 대부분 사라진다. 마감이 대비를 보장하기 때문이다.

## 7. 각인과 문구

> 여유 시 항목이다. 둘 다 결과물에 얹는 글자이고 위치 규칙(§7-1)을 함께 쓴다.

**각인** — 기록에서 나오는 숫자다.

| 항목 | 초기값 | 편집에서 |
|---|---|---|
| 항목 | 있는 것 다 (거리·시간·페이스·심박·날짜·장소) | 항목별로 끈다 |
| 위치 | **프리셋이 정한 자리** | 묶음째 옮긴다 |
| 크기 | 프리셋 기본값 | 묶음째 키우고 줄인다 |

**표시 모드를 고르지 않는다.** 각인은 그리는 내내 보인다([경로 렌더링](route-rendering.md) §7-2). 다 감추고 싶으면 항목을 전부 끄면 된다. (2026-09-08 개정)

**심박과 장소는 있을 때만 항목으로 나타난다.** 심박은 데이터가 없으면, 장소는 네트워크가 없으면 켜고 끌 대상 자체가 없다([경로 렌더링](route-rendering.md) §7-1).

**한 줄 문구** — 사용자가 직접 쓰는 말이다. 규칙은 [경로 렌더링](route-rendering.md) §7-6이 정본이고 여기서는 편집만 다룬다.

| 항목 | 초기값 | 편집에서 |
|---|---|---|
| 내용 | **비어 있다** | 쓴다. 입력은 3줄까지 |
| 위치 | **프리셋이 정한 자리** | 옮긴다 |
| 크기 | 프리셋 기본값 | 키우고 줄인다 |

**표시 모드가 없다.** 쓰면 보이고 비우면 안 보인다.

**비어 있을 때는 "문구 추가" 자리표시자가 편집 중에만 보인다.** 탭하면 입력창이 뜬다. 자리표시자는 결과물에 나오지 않는다. 안전 영역 가이드와 같은 방식이다(§7-1).

**입력이 3줄에서 막히는 것은 쓰는 동안뿐이다.** 다 쓴 뒤 크기를 키워 4줄이 되거나 옮겨서 잘리는 것은 막지 않는다. §7-1과 같은 태도다.

### 7-1. 위치는 막지 않고 알려준다

기본 위치만 제공하고 그 뒤는 사용자가 알아서 옮긴다. 놓을 수 있는 자리를 몇 개로 제한하지 않는다.

대신 **편집 중에 인스타 UI가 가리는 영역을 보여준다.** 화면 상하단의 안전 영역 밖을 가이드로 표시해서, "여기에 두면 인스타에서 가려진다"를 눈으로 알 수 있게 한다.

막지는 않는다. 사용자가 알고도 거기 두겠다면 그렇게 둔다. 가이드는 편집 중에만 보이고 결과물에는 나오지 않는다. 드로잉에도 같은 가이드가 쓰인다. 경로를 위로 끌어올리면 마찬가지로 가려지기 때문이다.

**막는 대신 알려주는 이유**는 무엇이 가려지는지 모르는 채로 자리를 제한당하면 왜 못 옮기는지 알 수 없기 때문이다. 보이면 사용자가 판단한다.

## 8. 편집 화면이 어떤 값에서 시작하나

이 문서가 정하는 것은 한 줄뿐이다.

> **같은 기록으로 새로 만들면 렌더러의 초기값에서 시작한다.** 지난번에 만든 결과물의 편집값을 이어받지 않는다.

이어받으면 "다른 프리셋으로 다시 만들기"가 지난 조작에 묶여버린다. 고르는 재미가 우선이므로(P3) 새로 만들 때는 깨끗한 기본값에서 시작한다. 지난 결과물을 다시 열어 고치는 경우는 물론 그때 값 그대로다.

나머지는 [홈과 보관함](home-and-library.md)이 정한다. 결과물과 편집값을 어떻게 보관할지, 복제를 둘지, 목록에서 무엇을 할 수 있는지는 보관 모델의 문제이지 편집 화면의 문제가 아니다.

## 9. 우선순위

| 항목 | 우선순위 |
|---|---|
| 프리셋 선택 | **MVP 필수** |
| 드로잉 크기·위치·회전 (제스처), 초기화 | **MVP 필수** |
| 미리보기 재생 규칙 | **MVP 필수** |
| 다듬기 세기 (직선·코너 두 축) | 여유 시 |
| 속도, 색 | 여유 시 |
| 각인 항목·위치 | 여유 시 |
| 편집 대상 선택 (레이어) | 각인 편집과 함께 |

**회전이 필수인 이유**는 렌더러가 자동으로 돌리지 않기 때문이다. 가로로 긴 경로는 세로 화면에서 띠처럼 작아지는데, 회전이 없으면 그 경우를 구제할 방법이 없다(PRD §7).
