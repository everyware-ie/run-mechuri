# 결과물 편집 FRD

> **status: `approved`.** 2026-08-25 회의에서 확정됐다. 구현 근거로 쓸 수 있다.
> 근거: [PRD](../prd/running-drawing-mvp.md) · [2026-08-18 결정](../../decisions/2026-08-18-native-ios-and-mvp-scope.md)

> **2026-10-04 개정: 편집 화면을 인스타 스토리 편집처럼 바꾼다.** 평소에는 화면 전체가 결과물이고, 도구는 누를 때만 올라온다. 한 줄 문구를 러닝 데이터에서 떼고, 손그림(§11)과 내 스타일(§12)을 더한다. 세 단계로 나눠 만든다(§9). 근거: [2026-10-04 결정](../../decisions/2026-10-04-story-style-editor.md)

## 0. 범위

사용자가 결과물을 보며 고르고 만지는 전부를 정한다. 프리셋 선택, 경로 그림 조작, 다듬기 세기, 선 색과 두께, 러닝 데이터와 문구, 손그림, 내 스타일, 미리보기가 여기 있다.

**[경로 렌더링](route-rendering.md)과의 경계가 이 문서의 뼈대다.** 렌더러는 초기값을 정하고, 편집은 같은 값을 사용자가 바꾼다. 서로 다른 기능이 아니라 같은 값을 누가 정하느냐의 차이다.

| 값 | 렌더러의 초기값 | 편집에서 |
|---|---|---|
| 프리셋 | 기본 경로 그림 | 셋 중에서 고른다 |
| 회전 | 0도 | 돌린다 |
| 크기 | 화면에 맞춤 | 키우거나 줄인다 |
| 위치 | 가운데 | 옮긴다 |
| 다듬기 세기 | 기본값 | 조절한다 |
| 속도 | 12초 고정 | 조절한다 |
| 선 색 | 프리셋의 기본 색 | 바꾼다 |
| 선 두께 | 프리셋의 기본 두께 | 바꾼다 |
| 러닝 데이터 | 사용 가능한 항목 표시, 항상 | 프리셋·항목·위치·크기·폰트·글자 색을 조정한다 |
| 한 줄 문구 | 비어 있다 | 쓰고, 러닝 데이터와 따로 옮기고 키운다 |

**배경의 확대·이동은 여기서 하지 않는다.** 배경 선택 화면 몫이다. 편집 화면에서 만지는 것은 경로 그림, 러닝 데이터, 한 줄 문구, 손그림이다. 한 화면에서 배경과 경로 그림을 동시에 만지면 사용자가 지금 무엇을 움직이는지 헷갈린다.

| 담지 않는 것 | 어디에 |
|---|---|
| 프리셋이 무엇을 어떻게 그리는지 | [경로 렌더링](route-rendering.md) §6 |
| 배경 소재를 고르고 9:16에 맞추는 것 | [배경 선택](background-selection.md) |
| 내보내기와 공유 | [내보내기·공유·저장](export-and-share.md) |

## 1. 화면 구조

> 편집 화면이 어디에 놓이고 무엇을 품는지 확인할 때 본다.

코어 루프는 네 단계다.

```
[러닝 기록 선택] → [배경 선택] → [편집] → [공유]
```

> **2026-10-04 개정.** 그전에는 편집 안에서 경로 → 러닝 데이터 순서로 단계를 안내하고, 하단 도구 패널을 접고 펼쳤다. 인스타 스토리 편집을 참고한 [시안](../../ideation/jminkkk/2026-10-03-change-editing-page.html)을 바탕으로 아래 구조로 바꾼다. 시안은 참고용이고 세부는 이 문서가 정한다([2026-10-04 결정](../../decisions/2026-10-04-story-style-editor.md)).

**평소에는 화면 전체가 결과물이다.** 9:16 미리보기를 화면 가득 보여 주고, 도구는 누를 때만 올라온다. 도구가 늘 화면을 차지하면 만든 것을 결과물 그대로 볼 수 없다.

화면에 늘 떠 있는 것은 셋이다.

| 자리 | 무엇 |
|---|---|
| 오른쪽 | 도구 버튼. 배경, 경로, 러닝 데이터, 문구, 그리기, 내 스타일 |
| 왼쪽 위 | 나가기(✕)와 되돌리기(↶) |
| 아래 | 완료. 누르면 공유 단계로 간다 |

**도구 버튼을 누르면 그 도구의 시트가 아래에서 올라온다.** 시트를 닫으면 다시 결과물만 보인다. 시트가 올라와 있는 동안에도 미리보기는 가려지지 않은 만큼 계속 보인다.

| 도구 | 시트에서 하는 것 |
|---|---|
| 배경 | 다른 배경으로 바꾼다(아래 "배경도 편집 화면에서 다시 열 수 있다") |
| 경로 | 프리셋(§3), 다듬기 세기(§5), 선 색과 두께(§6-2), 초기화 |
| 러닝 데이터 | 표시할 항목, 프리셋, 폰트와 글자 색(§7), 초기화 |
| 문구 | 한 줄 문구를 쓴다(§7) |
| 그리기 | 손그림 화면으로 들어간다(§11) |
| 내 스타일 | 지금 스타일을 저장하거나 저장한 것을 적용한다(§12) |

**도구 버튼에는 이름을 붙인다.** 아이콘만으로는 무엇을 하는 버튼인지 알기 어렵다는 지적이 있었다(2026-09-16).

**결과물은 완료 다음에 만든다.** 편집 화면에는 결과물을 따로 저장하는 버튼을 두지 않는다. 결과 영상은 마지막 편집값으로 한 번에 만드는 것이라, 편집 도중에 만들어 두면 값을 바꿀 때마다 다시 만들어야 한다. 그만큼 생성 시간과 배터리를 쓴다. 지금처럼 공유 단계에서 한 번 만들고 보관함에 넣는다([내보내기·공유·저장](export-and-share.md)).

**나가기는 확인 없이 홈으로 간다.** 편집값은 바뀔 때마다 "이어서 만들기"로 저장되어서 나가도 잃는 것이 없다([홈과 보관함](home-and-library.md) §3 만들다 만 것).

**프리셋 목록만을 위한 화면은 따로 두지 않는다.** 경로 시트와 러닝 데이터 시트에서 결과를 보며 고른다.

PRD P3이 "프리셋은 고르는 재미가 우선"이라고 했는데, 결과를 안 보고 이름만으로 고르면 재미가 나지 않는다. 목록에서 고르고 다음 화면에서 확인하는 구조는 마음에 안 들 때마다 뒤로 갔다 다시 와야 한다.

**배경도 편집 화면에서 다시 열 수 있다.** 배경을 고른 뒤에야 경로 그림과 안 어울린다는 것을 알게 되는 경우가 많다. 그때 뒤로 가는 대신 그 자리에서 바꾼다. 배경을 바꿔도 다른 편집값은 유지된다.

배경 시트에서 기본 배경은 누르면 바로 바뀐다. **갤러리를 고르면 배경 선택 화면으로 가서 구도를 잡고 돌아온다.** 확대·이동으로 구도를 잡는 일은 배경 선택 화면 몫이기 때문이다(§0).

`[확인 필요]` 시트의 높이, 그리고 시트가 미리보기를 얼마나 가려도 되는지. 1단계를 만들며 실기기에서 정한다.

## 2. 미리보기

> 편집하는 동안 화면이 어떻게 움직이는지 정한다.

**목표는 평소에 반복 재생하는 것이다(§2-1 재생).** 화면 전체가 결과물이 되면서 재생을 켜고 끄는 버튼을 둘 이유가 줄었다.

> **지금 앱은 평소에 완성된 모습으로 멈춰 있고, 재생 버튼을 눌러야 한 번 그린다.** 2026-09-02 실기기에서 반복 재생 중에 조작이 계속 느려서 그렇게 바꿨다. 그 뒤 미리보기 성능을 개선했으므로 다시 시험한다.
>
> `[확인 필요]` **스토리형 편집 1단계에서 실기기로 시험한다.** 반복 재생 중에도 조작이 느려지지 않으면 재생 버튼을 없앤다. 느려지면 지금처럼 멈춘 화면과 이름 붙은 재생 버튼을 남긴다(2026-10-04).

**초기화는 도구마다 따로 둔다**(2026-09-16). 경로 시트의 초기화는 경로 그림만, 러닝 데이터 시트의 초기화는 러닝 데이터만 처음 상태로 되돌린다. 왼쪽 위의 되돌리기와는 다르다(§4-3 되돌리기와 초기화).

> **스토리 안전 영역 버튼을 뺀다 (2026-09-16 개정).** 원래는 재생 버튼과 나란히 두기로 했다. **맞춰도 잘린다는 제보가 이어졌고**, 기능이 있어도 사용자가 믿고 쓸 수 없다면 자리만 차지한다. ([2026-09-16 결정](../../decisions/2026-09-16-release-and-editor-scope.md))
>
> **2026-10-04: 가이드도 뺀다.** 9/16에는 버튼만 없애고 가이드 자체는 남긴다고 적었지만, 그 뒤로 앱은 가이드를 보여 주지 않았다. 문서를 앱에 맞춘다. 러닝 데이터와 문구의 기본 위치가 인스타 UI에 가리는 곳을 피하는 규칙은 그대로다([경로 렌더링](route-rendering.md) §7-5 배치).

`[확인 필요]` **제스처 안내를 어디서 보여 줄지.** 지금은 도구 패널 안에 있는데, 패널이 없어지면 자리가 사라진다. 시트 안, 처음 한 번만 뜨는 안내, 토스트(2026-09-16에 나온 안) 중에서 1단계를 만들며 정한다. 문구 입력 중에는 입력 안내를 우선한다.

시트는 **기본 글자 크기에서 가능한 한 스크롤 없이 확인**할 수 있게 구성한다(2026-09-11 사용자 요청). 큰 글자·긴 항목·키보드 표시로 내용이 넘치면 시트 안에서 스크롤해 모든 기능에 접근할 수 있게 한다.

### 2-1. 재생

| 상태 | 동작 |
|---|---|
| 평소 | 클립을 반복 재생한다 |
| 조작 중 (슬라이더를 잡고 있거나 제스처 중) | 그 시점에서 일시 정지한다 |
| 손을 떼면 | 그 시점부터 이어서 재생한다 |
| 프리셋을 바꾸면 | 처음부터 재생한다 |

**멈추는 이유는 움직이는 중에 무엇이 바뀌는지 보이지 않기 때문이다.** 특히 다듬기는 선 모양이 차이라 정지 상태여야 판단이 선다. 반대로 프리셋은 움직임이 차이여서(불빛이 달리는지, 구간이 켜지는지, 선이 그려지는지) 재생되어야 보인다. 그래서 평소에는 재생하고 손을 대면 멈춘다.

**완성된 상태로 건너뛰지 않는다.** 그리는 중에 손을 대면 갑자기 완성본이 튀어나오고, 손을 떼면 다시 빈 화면부터 시작한다. 한 번의 조작에 시각적 점프가 두 번 생긴다. 지금 보고 있던 그 화면이 그대로 멈추는 편이 자연스럽다.

프리셋 전환만 예외로 처음부터 재생한다. 연출 전체가 갈리므로 중간부터 보면 무엇이 달라졌는지 알 수 없다.

**어느 시점에서 멈출지는 사용자가 고른다.** 재생이 계속 돌고 있으므로, 선 전체를 보며 다듬기를 조절하고 싶으면 거의 다 그려졌을 때 손을 대면 된다. 재생 위치를 옮기는 UI를 따로 만들지 않는 이유가 이것이다.

### 미리보기 숫자 카운트업 (2026-09-13 보완)

배경 선택과 편집 미리보기의 거리·시간은 **최종 영상과 같은 30fps 시간 간격**으로 갱신한다. 9초 그리기 구간을 270단계로 샘플링하고 시작은 0, 완성 후에는 최종값을 유지한다. 경로와 같은 진행률을 사용하며 제스처·화면 전환에 따른 일시 정지와 재생 초기화 규칙을 함께 따른다. 고정된 날짜·장소·라벨까지 매번 다시 그리거나 큰 그림자 처리 비용으로 경로 재생을 방해하지 않도록 한다. 이는 iOS MVP 구현 기준이며 실시간 재생의 모든 프레임을 모든 기기에서 보장한다는 뜻은 아니다.

구간 페이스도 같은 재생 진행률에서 갱신하고, 완성되면 최종 평균 페이스를 유지한다. 추정·신호 공백 보완 규칙은 [경로 렌더링 §7-3 값의 움직임](route-rendering.md)을 따른다. 구간별 계산은 기록 변경 시 한 번 수행해 숫자 갱신마다 GPS 좌표를 다시 순회하지 않는다.

### 미리보기 실행 범위 (2026-09-13 보완)

미리보기 재생은 해당 화면이 보이고 앱이 활성 상태일 때만 수행한다. 다음 화면으로 이동하거나 앱을 벗어나면 이전 미리보기의 반복 작업을 중단한다. 돌아왔을 때 편집값과 사용자의 재생 설정을 보존한다. 러닝 데이터 숫자 갱신 때문에 변경되지 않은 경로 캔버스를 다시 구성하지 않도록 한다. 고정된 러닝 데이터와 변화하는 숫자를 분리하고 필요한 영역만 갱신하되, 서체·가독성·위치·숫자 카운트업은 유지한다. GPS 신호 공백의 표현 정책은 [경로 렌더링 §3-4 신호가 끊긴 구간](route-rendering.md)의 별도 범위이며, 성능 개선만을 이유로 좌표를 임의로 삭제하지 않는다.

### 2-2. 즉시 반영

모든 조작은 즉시 미리보기에 반영된다. 적용 버튼을 두지 않는다(PRD §7).

## 3. 프리셋 선택

> 셋 중 하나를 고르는 자리다.

**경로 시트에서 고른다.** 기본값은 "기본 경로 그림"이다. 고르면 즉시 미리보기가 그 프리셋으로 바뀌고 처음부터 재생된다.

**프리셋을 바꿔도 경로 그림 조작값과 러닝 데이터 설정은 유지된다.** 크기·위치·회전을 맞춰둔 것이 프리셋을 넘겨볼 때마다 초기화되면 비교가 안 된다.

> **"경로 그림"과 "기본 경로 그림"은 다른 말이다.** 경로 그림은 결과물에 그려지는 경로의 그림을 가리키고, 프리셋 셋은 전부 그 경로 그림을 그리는 방식이다. 그중 기본값의 이름이 "기본 경로 그림"이다. 이 문서에서 "경로 그림의 크기·위치"라고 할 때의 경로 그림은 프리셋이 아니라 편집 대상을 말한다. **2026-09-16까지는 둘 다 "드로잉"이라 불렀다.**

**셋을 경로 시트에 나란히 둔다**(2026-10-04). 화면에 쓰는 이름은 위 셋 그대로다. 시안에 있던 "기본 드로잉"은 2026-09-16에 바꾸기 전 이름이다.

## 4. 편집 대상과 조작

> 손가락으로 무엇을 어떻게 만지는지 정한다.

### 4-1. 손댄 것을 만진다

> **2026-10-04 개정.** 그전에는 지금 무엇을 만질지 고르는 층(편집툴의 레이어 선택 같은 것)이 있었다. 대상을 고르면 단계 탭과 도구도 함께 바뀌었다. 스토리형 편집에서는 그 층을 없애고 손가락이 닿은 것을 바로 만진다.

화면 위에 얹히는 것은 경로 그림, 러닝 데이터, 한 줄 문구, 손그림이다. **손가락이 닿은 것을 만진다.** 따로 고르는 단계를 거치지 않는다.

| 대상 | 끌기 | 핀치·크기 슬라이더 | 비틀기 | 탭 |
|---|---|---|---|---|
| 경로 그림 | 위치 | 크기 | 회전 | 없음 |
| 러닝 데이터 | 위치 | 크기 | 없음 | 다음 프리셋으로 바꾼다 |
| 한 줄 문구 | 위치 | 크기 | 없음 | 다시 쓴다 |
| 손그림 | 그리기 화면에서만 만진다(§11) | | | |
| 배경 | 없음. 배경 선택 화면 몫이다(§0) | | | |

**한 번 잡은 대상은 손을 뗄 때까지 바뀌지 않는다.** 끌다가 다른 대상 위를 지나가도 처음 잡은 것이 움직인다.

**겹친 곳을 누르면 위에 있는 것을 잡는다.** 한 줄 문구와 러닝 데이터가 경로 그림보다 위다. 경로 그림은 화면을 넓게 차지해서, 아래에 두지 않으면 글자를 잡기 어렵다.

**러닝 데이터의 탭 판정 영역은 실제로 글자가 있는 자리에 가깝게 잡는다**(2026-09-16 실기기 피드백). 지금은 켜진 항목 전체를 감싸는 하나의 사각형이라, **항목을 네 귀퉁이에 흩어놓는 프리셋(코너)에서는 그 사각형이 화면 대부분을 덮는다.** 빈 곳을 눌러도 러닝 데이터가 잡히고 **경로 그림을 고르기가 불편해진다.**

2026-09-20 후속 QA: 항목 이름과 값은 한 영역으로 묶고, 강조값·날짜·문구와 다른 항목은 별도 영역으로 둔다. 항목이 가깝거나 장식 선으로 연결되어 있어도 빈 공간까지 하나의 큰 사각형으로 합치지 않는다. 글래스의 실제 카드 배경은 전체를 선택할 수 있다. 선택 점선과 탭 판정은 같은 영역을 사용하며, 어느 영역을 선택해도 러닝 데이터 전체가 함께 움직인다.

**만질 수 있는 자리는 점선으로 보여 준다**(2026-09-16). 되는 줄 몰라서 못 쓰는 문제를 감추는 것이 아니라 자리를 눈에 보이게 해서 푼다. 시트가 열려 있으면 그 도구의 대상에, 끌어 옮기는 동안에는 잡은 대상에 점선을 그린다. 평소에는 결과물만 보이도록 그리지 않는다.

**켜진 러닝 데이터 항목은 하나의 묶음이다.** 거리·시간·페이스·날짜·장소·심박을 따로따로 배치하지 않는다. 개별 배치는 조작 대상을 늘리고, 각 항목의 안전 영역도 따로 고려해야 한다. 어떤 항목을 보일지는 끄고 켜는 것으로 정하고 배치는 묶음째 옮긴다. 개별 배치는 로드맵이다.

**한 줄 문구는 러닝 데이터와 따로 움직인다**(2026-10-04). 그전에는 러닝 데이터 묶음과 함께 옮겼다. 자세한 것은 §7 러닝 데이터와 문구에 있다.

### 4-2. 제스처

| 제스처 | 동작 |
|---|---|
| 끌기 | 위치 |
| 핀치 | 크기 |
| 두 손가락 비틀기 | 회전 |

**경로 그림의 위치·크기·회전은 사진 앱처럼 제스처로 조절한다.** 화면에 조작별 슬라이더 세 개를 더하지 않는다.

손가락이 닿은 대상에 적용된다(§4-1 손댄 것을 만진다). 러닝 데이터와 한 줄 문구는 끌기로 위치, 핀치로 크기를 바꿀 수 있으며 회전은 지원하지 않는다. 러닝 데이터를 놓으면 마지막으로 표시된 위치에서 멈춘다. 관성이나 저장 시점의 위치 중복 적용으로 추가 이동했다가 돌아오지 않아야 한다(2026-09-20 QA).

**크기는 화면 왼쪽의 세로 슬라이더로도 조절한다**(2026-10-04). 경로·러닝 데이터·문구 시트를 열면 화면 왼쪽에 크기 슬라이더가 나오고, 그 도구의 대상 크기를 바꾼다. 시트를 닫으면 슬라이더도 사라진다. 손그림 화면의 굵기 슬라이더와 같은 자리다(§11).

- 핀치와 슬라이더는 같은 값을 쓴다. 범위도 같다
- 조절하는 동안 미리보기에 반영하고, 손을 떼면 편집값을 저장한다
- 크기만 바꾼다. 위치·프리셋·문구 내용·표시 항목은 그대로다
- 초기화하면 기본 크기로 돌아온다

> 2026-09-20에는 러닝 데이터의 프리셋·항목·문구 탭에 공통으로 크기 슬라이더를 두었다. 경로 그림과 문구도 같은 방식으로 조절할 수 있게 왼쪽 슬라이더 하나로 모은다.

### 4-3. 되돌리기와 초기화

**되돌리기(↶)는 편집 전체를 한 단계씩 되돌린다**(2026-10-04). 경로 그림을 옮긴 것, 러닝 데이터 프리셋을 바꾼 것, 문구를 고친 것, 배경을 바꾼 것이 모두 같은 순서로 쌓인다. 손을 뗄 때 한 단계가 된다. 끌어 옮기는 도중의 중간 값은 쌓지 않는다.

**초기화는 도구마다 따로 둔다.** 제스처만 두면 사용자가 이상하게 놓고 돌아오지 못하는 경우가 생긴다. 경로 시트의 초기화는 경로 그림을 렌더러의 초기값(회전 0도, 화면에 맞춤, 가운데)으로 되돌린다.

**되돌리는 단위는 그 도구의 대상뿐이다.** 경로 그림을 초기화해도 프리셋과 러닝 데이터 설정은 그대로 남는다. 한 번에 다 날아가면 초기화를 누르기가 무서워진다.

**둘 다 두는 이유가 있다.** 되돌리기만 있으면 경로 그림을 한참 만진 뒤 처음으로 돌아가려고 수십 번 눌러야 한다. 초기화만 있으면 방금 한 번 잘못 만진 것을 되돌릴 수 없다.

`[확인 필요]` 앱을 나갔다가 "이어서 만들기"로 돌아왔을 때도 되돌리기 기록이 남아 있어야 하는지. 1단계를 만들며 정한다.

### 4-4. 범위

화면 밖으로 나가도록 옮기거나 키우는 것을 허용한다. 경로 일부만 크게 보여주는 것도 표현이다. 다만 **경로 그림이 화면에서 완전히 사라지지는 않게 한다.** 되돌아올 방법이 초기화뿐이면 막다른 길이 된다.

크기의 상하한을 수치로 정하지 않는다. 위 두 줄이 실질적인 하한이고, 상한은 사용자가 판단할 몫이다. 너무 키우면 무엇인지 알아볼 수 없는 결과물이 나오지만 그건 미리보기에서 바로 보인다.

## 5. 다듬기 세기

> 선을 얼마나 매끄럽게 할지 조절하는 자리다.

**두 축이다. 직선과 코너 슬라이더 둘을 편집 화면에 바로 둔다.** 고급 설정으로 숨기지 않는다.

> **개정 (2026-09-07).** 원래는 "다듬기 세기" 한 축을 기본으로 주고 고급 설정을 열어야 둘로 나뉘는 구조였다. 복잡해질까 봐 그렇게 잡았는데, **실물을 만져보니 슬라이더 둘이 부담스럽지 않았다.**
>
> 오히려 축을 합치면 **직선만 펴고 싶은데 코너까지 뭉개지는 상황을 사용자가 풀 방법이 없어진다.** 둘은 실제로 다른 것을 만지고 있어서, 하나로 묶으면 조절이 아니라 타협이 된다.
>
> 근거는 [2026-09-01 결정](../../decisions/2026-09-01-frd-over-mockup.md)이 정한 절차다. FRD대로 만들었더니 이상하면 이슈로 올려 FRD를 고친 뒤 진행한다.

**슬라이더 범위 자체가 안전 구간이다.** 최대치까지 올려도 실제로 지나가지 않은 길이 보이지 않는다([경로 렌더링](route-rendering.md) §3-2). 그래서 경고나 차단 UI를 두지 않는다.

**경로 시트에 둔다**(2026-10-04). 프리셋 아래에 둔다. 시트가 올라와도 미리보기가 보이므로 아래 제약을 지킨다.

> **결과를 보면서 조절할 수 있어야 한다.** 별도 화면으로 빼서 미리보기가 안 보이게 하면 안 된다.

## 6. 속도와 색

> 속도는 여유 시 항목이다(PRD §7). 선 색과 두께는 스토리형 편집 2단계에서 만든다(§9 우선순위).

### 6-1. 속도

그리기 구간의 길이를 조절한다. 클립 총 길이가 함께 바뀐다.

| 항목 | 값 |
|---|---|
| 기본 | 12초 (그리기 9 + 정지 3) |
| 상한 | **15초.** 인스타 스토리가 15초 단위로 잘린다. 넘기면 결과물이 두 장으로 쪼개진다 |
| 하한 | 8초 제안. 너무 빠르면 무엇을 그리는지 안 보인다 |

#### 배경 영상 길이와 어긋나지 않는다

속도를 바꾸면 클립 길이가 바뀌는데 배경 영상은 그와 무관하게 제 길이를 갖는다. **경우의 수를 따로 만들 필요가 없다.** [배경 선택](background-selection.md) §5-1의 규칙이 12초 고정이 아니라 "클립 길이" 기준이기 때문이다.

| 배경 영상 | 처리 |
|---|---|
| 클립보다 짧다 | 반복 재생 (3초 미만은 마지막 프레임 정지) |
| 클립보다 길다 | 앞에서부터 클립 길이만큼 |

속도를 낮춰 클립이 15초가 되면 12초짜리 배경은 3초를 반복하고, 20초짜리 배경은 앞 15초를 쓴다. 규칙은 그대로고 기준만 따라 움직인다.

속도를 바꿔서 배경에 반복 이음새가 새로 생길 수는 있다. 다만 미리보기에 즉시 반영되므로 사용자가 바로 본다. 마음에 안 들면 속도를 되돌리거나 마지막 프레임 정지로 바꾸면 된다.

### 6-2. 선 색과 두께

**색은 사용자가 고르고 마감은 우리가 고정한다.** 경로 시트에서 고른다.

> **2026-10-04 개정: 정해 둔 팔레트에서 고른다.** 원래 MVP는 "프리셋마다 어울리는 3~5가지를 미리 골라 제공"이었다. 스토리형 편집 2단계에서 프리셋과 상관없는 팔레트 하나로 바꾸고, 발광·대비 같은 마감은 우리가 늘 입힌다. 아래 로드맵으로 한 걸음 간 것이다. 몇 가지 색을 둘지는 구현 노트에서 정한다.

| 단계 | 무엇 |
|---|---|
| 스토리형 편집 2단계 | 정해 둔 팔레트에서 고른다. 마감은 우리가 입힌다 |
| 로드맵 | 사용자가 색상을 자유롭게 고르고, 우리가 그 위에 마감 처리를 얹는다 |

가짓수를 적게 두는 것은 옵션이 많으면 고르는 일이 피로가 되기 때문이다. 프리셋이 셋뿐인 것과 같은 판단이다.

**로드맵 쪽이 이 항목의 최종 형태다.** 사용자가 고르는 것은 색상값이고, 그 위에 얹히는 발광·대비 같은 마감은 우리가 항상 적용한다. 어떤 색을 골라도 우리 결과물로 보이게 하려는 것이다. 자유도는 주되 품질은 우리가 잡는다.

이 구조가 되면 "배경과 안 맞는 색을 골라서 결과물이 나빠진다"는 걱정이 대부분 사라진다. 마감이 대비를 보장하기 때문이다.

**두께도 고른다**(2026-10-04). 경로 시트의 슬라이더로 조절한다. 너무 얇으면 사진 위에서 안 보이고 너무 두꺼우면 경로 모양이 뭉개지므로, 범위는 실기기에서 보며 구현 노트에 정한다.

**고른 색과 두께는 프리셋을 바꿔도 유지한다.** 프리셋을 넘겨볼 때마다 맞춰 둔 것이 돌아가면 비교가 안 된다(§3 프리셋 선택과 같은 이유). 사용자가 아직 고르지 않았으면 프리셋의 기본 색과 두께를 쓴다.

## 7. 러닝 데이터와 문구

> 둘 다 결과물에 얹는 글자이고 위치 규칙(§7-1)을 함께 쓴다. 폰트와 글자 색도 함께 쓴다(§7-3).

**러닝 데이터**: 기록에서 나오는 숫자다. 러닝 데이터 시트에서 항목, 프리셋, 폰트와 글자 색을 고른다.

**화면에서 러닝 데이터를 탭해도 다음 프리셋으로 바뀐다**(2026-10-04). 시트를 열지 않고 넘겨보며 고를 수 있다. 순서는 아래 목록 순서이고, 마지막 다음은 처음이다.

**프리셋 선택 목록은 코너 → 글래스 → 레일 → 스택 → 스탯바 → 원라인 순서로 노출한다** (2026-09-13 내부 QA 반영, 2026-09-16 개정). 앞의 세 개를 우선 노출하고, 나머지는 큰 거리 강조·통계 정렬·문구 강조·최소 표현 순으로 배치한 초기 가설이다. 실제 사용량에 따른 인기 순위는 아니다. 새 기록을 만들 때 선택 이력이 없으면 **코너**로 시작한다. 이후에는 사용자가 마지막으로 직접 선택한 러닝 데이터 프리셋을 기기에 저장해 앱을 다시 열어도 새 기록의 기본값으로 사용한다. ‘같은 기록으로 새로 만들기’에도 적용한다. 기억하는 것은 프리셋 종류뿐이며 문구·위치·크기·표시 항목 등은 새 기록의 기본값으로 시작한다. ‘다시 편집’과 ‘이어서 만들기’는 해당 결과물·초안의 저장값을 유지하고, 불러오는 것만으로 최근 선택을 바꾸지 않는다. (2026-09-13 후속 사용자 요청)

> **간결 프리셋을 뺀다 (2026-09-16 개정).** 일곱에서 여섯이 된다. **원라인과 비슷해서 고를 때 헷갈리고**, 둘 다 있을 이유가 약하다. 줄이면 우리가 다듬을 대상도 준다. ([2026-09-16 결정](../../decisions/2026-09-16-release-and-editor-scope.md))

**원라인은 문구가 너무 크게 나온다**(2026-09-16 실기기 피드백). 크기를 줄이고 자리를 조금 내린다.

| 항목 | 초기값 | 편집에서 |
|---|---|---|
| 항목 | 있는 것 다 (거리·시간·페이스·심박·날짜·장소) | 항목별로 끈다 |
| 위치 | **프리셋이 정한 자리** | 묶음째 옮긴다 |
| 크기 | 프리셋 기본값 | 묶음째 키우고 줄인다 |
| 폰트·글자 색 | 프리셋 기본값 | 고른다(§7-3) |

**표시 모드를 고르지 않는다.** 러닝 데이터는 그리는 내내 보인다([경로 렌더링](route-rendering.md) §7-2). 다 감추고 싶으면 숨기기 자리로 끌어다 놓는다(§7-2). (2026-09-08 개정, 2026-10-04 보완)

**심박과 장소는 있을 때만 항목으로 나타난다.** 심박은 데이터가 없으면, 장소는 네트워크가 없으면 켜고 끌 대상 자체가 없다([경로 렌더링](route-rendering.md) §7-1).

**한 줄 문구**: 사용자가 직접 쓰는 말이다. 규칙은 [경로 렌더링](route-rendering.md) §7-6이 정본이고 여기서는 편집만 다룬다.

> **2026-10-04 개정: 러닝 데이터에서 뗀다.** 그전에는 문구가 러닝 데이터 묶음의 일부라 함께 옮겼다. 스토리형 편집에서는 문구를 따로 끌어 옮기고 따로 키운다. 문구만 위로 올리고 숫자는 아래에 두는 식의 배치를 할 수 있게 된다.

| 항목 | 초기값 | 편집에서 |
|---|---|---|
| 내용 | **비어 있다** | 쓴다. 입력은 3줄까지 |
| 위치 | **프리셋이 정한 자리** | **러닝 데이터와 따로** 옮긴다 |
| 크기 | 프리셋 기본값 | 따로 키우고 줄인다 |
| 폰트·글자 색 | 러닝 데이터와 같다 | 러닝 데이터에서 바꾸면 같이 바뀐다(§7-3) |

**문구는 하나만 둔다.** 여러 개를 흩어 놓으면 결과물의 주인공이 경로에서 글로 넘어간다.

**표시 모드가 없다.** 쓰면 보이고 비우면 안 보인다.

**문구 도구를 누르거나 화면의 문구를 탭하면 입력이 열린다.** 비워 두고 완료하면 문구가 빠진다.

> **2026-10-04: "문구 추가" 자리표시자를 없앤다.** 그전에는 비어 있을 때 편집 중에만 보이는 자리표시자를 두고, 탭하면 입력창이 떴다. 이제 문구 도구가 그 입구 역할을 하고, 평소에는 화면에 결과물만 보이게 한다.

**입력이 3줄에서 막히는 것은 쓰는 동안뿐이다.** 다 쓴 뒤 크기를 키워 4줄이 되거나 옮겨서 잘리는 것은 막지 않는다. §7-1과 같은 태도다.

### 7-1. 위치는 막지 않는다

기본 위치만 제공하고 그 뒤는 사용자가 알아서 옮긴다. 놓을 수 있는 자리를 몇 개로 제한하지 않는다.

> **2026-10-04 개정: 인스타 UI가 가리는 영역을 보여 주던 가이드를 뺀다(§2 미리보기).** 원래는 편집 중에 화면 상하단의 안전 영역 밖을 가이드로 표시해 "여기에 두면 인스타에서 가려진다"를 알려 주기로 했다. 맞춰도 잘린다는 제보가 이어져 믿고 쓸 수 없었고, 2026-09-16 이후 앱에서는 보이지 않았다.

**기본 위치가 그 영역을 피하는 것으로 대신한다**([경로 렌더링](route-rendering.md) §7-5 배치). 사용자가 옮긴 뒤에는 미리보기를 보고 판단한다. 경로 그림도 같다.

**막지 않는 이유**는 무엇이 가려지는지 모르는 채로 자리를 제한당하면 왜 못 옮기는지 알 수 없기 때문이다.

### 7-2. 끌어서 숨기기

**러닝 데이터를 화면 아래의 숨기기 자리로 끌어다 놓으면 숨는다**(2026-10-04). 끌기 시작하면 숨기기 자리가 나타나고, 그 위에서 손을 떼면 러닝 데이터가 결과물에서 빠진다.

**러닝 데이터 도구를 다시 열면 돌아온다.** 숨기기 전의 위치·크기·프리셋·항목도 그대로 돌아온다. 항목을 전부 끄는 것과 결과는 같지만 켜 둔 항목 구성이 남는다.

`[확인 필요]` 한 줄 문구도 같은 방식으로 숨길지. 문구는 비우면 빠지므로 꼭 필요하지는 않다. 1단계를 만들며 정한다.

### 7-3. 폰트와 글자 색

> 스토리형 편집 2단계에서 만든다(§9 우선순위).

**러닝 데이터 시트에서 고르고, 한 줄 문구에도 같이 적용된다**(2026-10-04). 숫자와 문구의 글꼴이 따로 놀면 한 화면이 두 사람이 만든 것처럼 보인다.

| | 무엇 |
|---|---|
| 폰트 | 몇 가지 중에서 고른다. 고를 때 결과를 미리 보여 준다. 무엇을 넣을지는 구현 노트에서 정한다 |
| 글자 색 | **흰색과 검정 중에서 고른다** |

**글자 색은 흰색·검정으로 먼저 해 본다.** 밝은 배경에서 글자가 안 보인다는 제보에서 나왔고, 2026-10-01 카톡에서 셋이 정했다([QA 기록](../../ops/qa-log.md) 2026-10-03 "카톡에서만 정하고 넘어간 것"). 둘로 부족하면 그때 색을 더 연다.

고른 폰트와 글자 색은 러닝 데이터 프리셋을 바꿔도 유지한다. §6-2 선 색과 두께와 같은 이유다.

## 8. 편집 화면이 어떤 값에서 시작하나

새로 만들기와 다시 편집의 시작값을 구분한다.

> **같은 기록으로 새로 만들면 렌더러의 초기값에서 시작한다.** 지난번에 만든 결과물의 편집값을 이어받지 않는다. 러닝 데이터 프리셋 종류는 §7 러닝 데이터와 문구의 최근 선택 정책을 적용하며, 선택 이력이 없으면 코너다.

이어받으면 "다른 프리셋으로 다시 만들기"가 지난 조작에 묶여버린다. 고르는 재미가 우선이므로(P3) 새로 만들 때는 깨끗한 기본값에서 시작한다. 지난 결과물을 다시 열어 고치는 경우는 물론 그때 값 그대로다.

나머지는 [홈과 보관함](home-and-library.md)이 정한다. 결과물과 편집값을 어떻게 보관할지, 복제를 둘지, 목록에서 무엇을 할 수 있는지는 보관 모델의 문제이지 편집 화면의 문제가 아니다.

## 9. 우선순위

| 항목 | 우선순위 |
|---|---|
| 프리셋 선택 | **MVP 필수** |
| 경로 그림 크기·위치·회전 (제스처), 초기화 | **MVP 필수** |
| 미리보기 재생 규칙 | **MVP 필수** |
| 다듬기 세기 (직선·코너 두 축) | 여유 시 |
| 속도 | 여유 시 |
| 러닝 데이터 항목·위치 | 여유 시 |
| 스토리형 화면 구조: 도구와 시트, 한 줄 문구 분리, 끌어서 숨기기, 되돌리기, 왼쪽 크기 슬라이더 | **스토리형 편집 1단계** |
| 선 색과 두께, 폰트와 글자 색 | **스토리형 편집 2단계** |
| 손그림, 내 스타일 | **스토리형 편집 3단계** |

**회전이 필수인 이유**는 렌더러가 자동으로 돌리지 않기 때문이다. 가로로 긴 경로는 세로 화면에서 띠처럼 작아지는데, 회전이 없으면 그 경우를 구제할 방법이 없다(PRD §7).

**스토리형 편집은 단계마다 PR을 따로 올리고 TestFlight에서 확인한다**(2026-10-04). 한 번에 만들면 PR이 너무 커지고 무엇이 문제인지 찾기 어렵다. 1단계가 끝나기 전에는 2단계를 시작하지 않는다. 1단계에서 화면 구조가 바뀌면 2단계의 자리가 달라질 수 있기 때문이다.

## 11. 손그림

> 스토리형 편집 3단계에서 만든다. 이번에는 큰 규칙만 정하고 세부는 3단계를 시작할 때 정한다.

**화면에 손으로 그린 선을 결과물에 얹는다**(2026-10-04). 경로 옆에 화살표를 긋거나 그날의 기분을 낙서로 남기는 식이다.

**문서에서는 "손그림"이라 부른다.** 화면의 도구 이름은 "그리기"지만, 이 문서와 [경로 렌더링](route-rendering.md)에서 "그리기"는 경로가 그려지는 구간을 가리킨다. 같은 말을 두 뜻으로 쓰지 않으려고 문서의 이름을 따로 둔다.

**그리기 도구를 누르면 손그림 화면이 된다.** 다른 도구는 사라지고 화면 전체가 캔버스가 된다. 완료를 누르면 편집 화면으로 돌아온다.

| 자리 | 무엇 |
|---|---|
| 위 | 붓 종류. 펜, 형광, 네온, 지우개 같은 것. 무엇을 넣을지는 구현 노트에서 정한다 |
| 왼쪽 | 굵기 슬라이더. 편집 화면의 크기 슬라이더와 같은 자리다(§4-2) |
| 아래 | 색 |

손그림 화면 안의 되돌리기는 획 단위다. 편집 화면으로 돌아오면 손그림 전체가 편집 화면 되돌리기의 한 단계가 된다(§4-3).

`[확인 필요]` 3단계를 시작할 때 정한다.

- 결과물에서 손그림이 언제 보이는지. 처음부터 있는지, 경로처럼 그려지며 나타나는지
- 경로 그림, 러닝 데이터와 무엇이 위에 오는지. [경로 렌더링](route-rendering.md)에 합성 규칙을 함께 더한다
- 편집 화면에서 손그림을 옮기거나 키울 수 있는지

## 12. 내 스타일

> 스토리형 편집 3단계에서 만든다. 이번에는 큰 규칙만 정하고 세부는 3단계를 시작할 때 정한다.

**지금 스타일을 저장해 두고 다른 기록에 한 번에 적용한다**(2026-10-04). 매번 같은 프리셋과 색을 고르는 사람이 한 번에 끝낼 수 있게 한다.

| | 무엇 |
|---|---|
| 담는 것 | 배경, 경로 프리셋과 선 색·두께, 러닝 데이터 항목과 프리셋, 폰트와 글자 색 |
| 담지 않는 것 | 위치와 크기, 한 줄 문구, 손그림. 기록마다 다르기 때문이다 |

**새로 만들기의 시작값은 바뀌지 않는다.** 새 결과물은 여전히 렌더러의 초기값에서 시작하고(§8), 내 스타일은 사용자가 고를 때만 적용한다. 저절로 적용하면 "다른 프리셋으로 다시 만들기"가 지난 선택에 묶인다.

`[확인 필요]` 3단계를 시작할 때 정한다.

- 사진·영상 배경도 담는지. 담으면 편집용 사본을 여러 결과물이 함께 쓰게 되어 [배경 선택](background-selection.md)의 보관 규칙과 처리방침을 함께 봐야 한다
- 다듬기 세기를 담는지. 다듬기는 기록의 GPS 상태에 따라 알맞은 값이 달라서 스타일로 보기 어려울 수 있다
- 몇 개까지 저장하는지, 어디에 보관하는지
