# 결과물 편집 FRD

> **status: `draft`.** 팀 확인 후 `approved`로 올린다. **approved가 아니면 구현 근거가 아니다.**
> 근거: [PRD](../prd/running-drawing-mvp.md) · [2026-08-18 결정](../../decisions/2026-08-18-native-ios-and-mvp-scope.md)

## 0. 범위

**담는 것**: 사용자가 결과물을 보며 고르고 만지는 전부. 프리셋 선택, 드로잉 조작, 다듬기 세기, 각인, 미리보기.

**[경로 렌더링](route-rendering.md)과의 경계가 이 문서의 뼈대다.**

> **렌더러는 초기값을 정하고, 편집은 같은 값을 사용자가 바꾼다.** 서로 다른 기능이 아니라 같은 값을 누가 정하느냐의 차이다.

| 값 | 렌더러의 초기값 | 편집에서 |
|---|---|---|
| 프리셋 | 드로잉 | 셋 중에서 고른다 |
| 회전 | 0도 | 돌린다 |
| 크기 | 화면에 맞춤 | 키우거나 줄인다 |
| 위치 | 가운데 | 옮긴다 |
| 다듬기 세기 | 기본값 | 조절한다 |
| 속도 | 12초 고정 | 조절한다 |
| 선 색 | 프리셋의 기본 색 | 바꾼다 |
| 각인 | 넷 다 표시, 항상 | 항목과 모드를 고른다 |

**안 담는 것**

| 항목 | 어디로 |
|---|---|
| 프리셋이 무엇을 어떻게 그리는지 | [경로 렌더링](route-rendering.md) §6 |
| 배경 소재를 고르고 9:16에 맞추는 것 | [배경 선택](background-selection.md) |
| 내보내기와 공유 | 내보내기·공유·저장 |

**배경의 확대·이동은 여기서 하지 않는다.** 배경 선택 화면 몫이다. 편집 화면에서 만지는 것은 **드로잉과 각인**뿐이다. 한 화면에서 배경과 드로잉을 동시에 만지면 사용자가 지금 무엇을 움직이는지 헷갈린다.

## 1. 화면 구조

**코어 루프는 네 단계다.** (2026-08-19)

```
[러닝 기록 선택] → [배경 선택] → [편집] → [공유]
```

**프리셋 선택 화면을 따로 두지 않는다.** 편집 화면에서 결과를 보며 고른다.

### 왜 합치나

PRD P3이 "프리셋은 고르는 재미가 우선"이라고 했는데, **결과를 안 보고 이름만으로 고르면 재미가 나지 않는다.** 목록에서 고르고 다음 화면에서 확인하는 구조는 마음에 안 들 때마다 뒤로 갔다 다시 와야 한다. 프리셋이 셋뿐이라 편집 화면 안에서 넘겨보는 것으로 충분하다.

### 편집 화면에서 배경도 바꿀 수 있다

배경을 고른 뒤에야 이 배경이 드로잉과 안 어울린다는 것을 알게 되는 경우가 많다. 그때 뒤로 가는 대신 **편집 화면에서 배경 선택을 다시 열 수 있다.** 배경을 바꿔도 드로잉 편집값은 유지된다.

## 2. 미리보기

### 2-1. 재생

| 상태 | 동작 |
|---|---|
| 평소 | **12초 클립을 반복 재생한다** |
| 조작 중 (슬라이더를 잡고 있거나 제스처 중) | **그 시점에서 일시 정지한다** |
| 손을 떼면 | **그 시점부터 이어서 재생한다** |
| 프리셋을 바꾸면 | 처음부터 재생한다 |

**멈추는 이유**는 움직이는 중에는 무엇이 바뀌는지 보이지 않기 때문이다. 특히 다듬기는 선 모양이 차이라 정지 상태여야 판단이 선다. 반대로 프리셋은 움직임이 차이라(불빛이 달리는지, 구간이 켜지는지, 선이 그려지는지) 재생되어야 보인다. 그래서 평소에는 재생하고 손을 대면 멈춘다.

**완성된 상태로 건너뛰지 않는다.** 그리는 중에 손을 대면 갑자기 완성본이 튀어나오고 손을 떼면 다시 빈 화면부터 시작해서, 한 번의 조작에 시각적 점프가 두 번 생긴다. **지금 보고 있던 그 화면이 그대로 멈추는 것**이 자연스럽다. (2026-08-19)

프리셋 전환만 예외로 처음부터 재생한다. 연출 전체가 갈리므로 중간부터 보면 무엇이 달라졌는지 알 수 없다.

> **대가 하나.** 초반 시점에서 멈춘 채 다듬기를 조절하면 **아직 그려지지 않은 부분의 선 모양은 볼 수 없다.** 손을 떼면 이어서 재생되므로 곧 보이지만, 조절하는 순간에는 일부만 보고 판단하게 된다.
>
> 3주차에 실제로 걸림돌이 되면 **다듬기 조절 중에만 완성 상태로 보여주는 것**을 폴백으로 둔다. 지금은 점프 없는 쪽을 택한다.

### 2-2. 즉시 반영

모든 조작은 **즉시 미리보기에 반영된다.** 적용 버튼을 두지 않는다. (PRD §7)

## 3. 프리셋 선택

- 셋 중 하나를 고른다. **기본은 드로잉**
- 고르면 즉시 미리보기가 그 프리셋으로 바뀌고 처음부터 재생된다
- 프리셋을 바꿔도 **드로잉 조작값(크기·위치·회전)과 각인 설정은 유지된다.** 프리셋만 갈린다

`[확인 필요]` 고르는 방식. 가로로 넘기는 형태와 나란한 버튼 중 무엇이 나은지. 셋뿐이라 둘 다 성립한다. 디자인 시스템에서 정한다.

## 4. 드로잉 조작

### 4-1. 제스처

**손가락 제스처로 조작한다.** (2026-08-19)

| 제스처 | 동작 |
|---|---|
| 끌기 | 위치 |
| 핀치 | 크기 |
| 두 손가락 비틀기 | 회전 |

슬라이더를 쓰지 않는 이유는 **사진 앱과 같은 조작이라 배울 것이 없고**, 화면에서 슬라이더 세 개를 미리 줄일 수 있기 때문이다.

**대상은 드로잉뿐이다.** 배경은 이 제스처에 반응하지 않는다.

### 4-2. 초기화

**제스처만 두면 사용자가 이상하게 놓고 돌아오지 못하는 경우가 생긴다.** 드로잉을 렌더러의 초기값(회전 0도, 화면에 맞춤, 가운데)으로 되돌리는 방법을 둔다.

`[확인 필요]` 되돌리기 단위. 드로잉 조작만 되돌릴지, 편집 전체를 처음 상태로 되돌릴지. **제안**은 드로잉 조작만 되돌리는 것이다. 프리셋과 각인까지 한 번에 날아가면 되돌리기를 누르기가 무서워진다.

### 4-3. 범위

- 화면 밖으로 나가도록 옮기거나 키우는 것을 허용한다. 경로 일부만 크게 보여주는 것도 표현이다
- 다만 **드로잉이 화면에서 완전히 사라지지는 않게 한다.** 되돌아올 방법이 초기화뿐이면 막다른 길이 된다

`[확인 필요]` 크기의 상하한. 실제 경로로 보며 정한다.

## 5. 다듬기 세기

- **기본은 한 축이다.** "다듬기 세기" 슬라이더 하나
- **고급 설정에서 직선과 코너로 나뉜다.** 두 축을 따로 만진다
- **슬라이더 범위 자체가 안전 구간이다.** 최대치까지 올려도 "실제로 지나가지 않은 길"이 보이지 않는다([경로 렌더링](route-rendering.md) §3-2). 따라서 **경고나 차단 UI를 두지 않는다**

`[확인 필요]` 고급 설정을 여는 방법. **제안**은 슬라이더 옆의 펼치기다. 별도 화면으로 빼면 결과를 보며 조절할 수 없다.

## 6. 속도와 색

둘 다 **여유 시** 항목이다(PRD §7).

| 항목 | |
|---|---|
| 속도 | 그리기 구간의 길이를 조절한다. 클립 총 길이가 바뀐다 |
| 색 | 프리셋의 기본 색 대신 다른 색을 고른다 |

`[확인 필요]` 속도를 바꾸면 클립 총 길이가 15초를 넘을 수 있다. 인스타 스토리가 15초 단위로 잘리므로 **상한을 두는 것을 제안**한다.

`[확인 필요]` 색을 몇 가지로 줄지. 자유 선택은 배경과 안 맞는 결과물을 만들기 쉽다. **제안**은 프리셋마다 어울리는 몇 가지를 미리 고르는 것이다. 디자인 시스템과 함께 정한다.

## 7. 각인

**여유 시** 항목이다.

| 항목 | 초기값 | 편집에서 |
|---|---|---|
| 표시 모드 | 항상 | 항상 / 완성 후만 / 숨김 |
| 항목 | 거리·시간·페이스·심박 넷 다 | 항목별로 끈다 |
| 위치 | 규칙에 따른 자리 | 옮긴다 |

**심박은 데이터가 있을 때만 항목으로 나타난다.** 없는 기록에서는 켜고 끌 대상 자체가 없다([경로 렌더링](route-rendering.md) §7-0).

`[확인 필요]` 각인 위치를 얼마나 자유롭게 옮기게 할지. 자유롭게 두면 인스타 UI에 가리는 자리에 놓을 수 있다. **제안**은 안전 영역 안에서 몇 개의 자리 중 고르는 것이다.

## 8. 편집값의 수명

**같은 기록으로 다른 결과물을 다시 만들 수 있어야 한다**(PRD §6). 그때 편집값을 어떻게 다룰지 정한다.

- **결과물마다 편집값이 따로 남는다.** 하나를 고쳐도 다른 결과물이 바뀌지 않는다
- **보관함에서 지난 결과물을 열면 그때의 편집값 그대로 다시 편집할 수 있다**
- 같은 기록으로 **새로 만들면 렌더러의 초기값에서 시작한다.** 지난 편집값을 이어받지 않는다

세 번째가 중요하다. 이어받으면 "다른 프리셋으로 다시 만들기"가 지난 조작에 묶여버린다. 고르는 재미가 우선이므로 새로 만들 때는 깨끗한 기본값에서 시작한다.

**구체 규칙은 홈과 보관함 FRD에서 이어받는다.**

## 9. 우선순위

| 항목 | 우선순위 |
|---|---|
| 프리셋 선택 | **MVP 필수** |
| 드로잉 크기·위치·회전 (제스처), 초기화 | **MVP 필수** |
| 미리보기 재생 규칙 | **MVP 필수** |
| 다듬기 세기 (기본 한 축) | 여유 시 |
| 다듬기 고급 (직선·코너 분리) | 여유 시 |
| 속도, 색 | 여유 시 |
| 각인 모드·항목·위치 | 여유 시 |

**회전이 필수인 이유**는 렌더러가 자동으로 돌리지 않기 때문이다. 가로로 긴 경로는 세로 화면에서 띠처럼 작아지는데, 회전이 없으면 그 경우를 구제할 방법이 없다(PRD §7).
