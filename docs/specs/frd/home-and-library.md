# 홈과 보관함 FRD

> **status: `draft`.** 팀 확인 후 `approved`로 올린다. **approved가 아니면 구현 근거가 아니다.**
> 근거: [PRD](../prd/running-drawing-mvp.md)

## 0. 범위

**앱을 열었을 때 처음 보이는 화면**과 **만든 것이 쌓이는 자리**를 정한다. 둘은 같은 화면의 두 얼굴이다.

| 담는 것 | |
|---|---|
| 홈의 구조 | 무엇이 어떤 순서로 보이나 |
| 결과물 보관 | 만든 것을 어떻게 남기고 다시 쓰나 |
| 만들다 만 것 | 이어서 만들기 |
| 첫 실행 쇼케이스 | 보여줄 것이 없을 때, 그리고 그 뒤 |
| 복귀 위치 | 앱을 다시 열었을 때 어디로 가나 |

**안 담는 것**

| 항목 | 어디로 |
|---|---|
| 러닝 기록 목록과 선택 | 러닝 기록 선택 FRD |
| 편집 화면의 동작 | [결과물 편집](result-editing.md) |
| 권한·실패·대기의 공통 원칙 | [공통 규칙](common-rules.md) |

## 1. 홈은 결과물 목록이다

**보관의 단위는 "내가 만든 결과물"이다.** (2026-08-23)

러닝 기록 목록을 홈에 두지 않는다. HealthKit 기록은 수백 개일 수 있고, 그 안에 내가 만든 몇 개가 묻힌다. **내가 만든 것만 보이는 자리**가 있어야 다시 올 이유가 된다(PRD §6).

기록 목록은 **새로 만들기를 눌렀을 때** 열린다. 코어 루프의 첫 단계다.

```
[홈 = 결과물 목록] ──새로 만들기──▶ [기록 선택] → [배경 선택] → [편집] → [공유]
        │
        └──결과물 열기──▶ [보기 / 다시 만들기 / 공유 / 삭제]
```

### 1-1. 화면 구성

위에서 아래로 이렇게 쌓인다.

| 자리 | 무엇 | 언제 |
|---|---|---|
| 1 | **이어서 만들기** | 만들다 만 것이 있을 때만(§3) |
| 2 | **새로 만들기** | 항상 |
| 3 | **결과물 목록** | 만든 것이 있을 때 |
| 4 | **쇼케이스** | 보관함이 비었을 때는 이 자리를 채우고, 아니면 물러난다(§4) |

`[확인 필요]` 각 자리의 생김새와 정확한 배치. 디자인 시스템에서 정한다.

## 2. 결과물

### 2-1. 목록에 보여줄 것

| 항목 | |
|---|---|
| 썸네일 | 결과물의 한 장면 |
| 날짜 | 러닝을 한 날 (만든 날이 아니다) |
| 거리 | |
| 프리셋 | 어떤 연출로 만들었는지 |

**러닝한 날을 쓰는 이유**는 사용자가 "언제 뛴 것"으로 기억하기 때문이다. 만든 날짜는 며칠 뒤일 수 있다.

**정렬은 최신순**이다. 러닝한 날 기준으로 정렬한다.

**같은 기록으로 여러 개를 만들었어도 묶지 않고 나란히 둔다.** (2026-08-23) 만든 것이 몇 개 안 되는 시기에 묶음은 과하다.

### 2-2. 결과물에서 할 수 있는 것

| 동작 | |
|---|---|
| 보기 | 클립을 재생한다 |
| **공유** | 인스타 스토리로 보내거나 파일로 저장한다 |
| **다시 편집** | 그때의 편집값 그대로 열어 고친다 |
| **같은 기록으로 새로 만들기** | **렌더러의 초기값에서 시작한다**([결과물 편집](result-editing.md) §8) |
| 삭제 | 확인을 한 번 받는다 |

**"다시 편집"과 "같은 기록으로 새로 만들기"는 다르다.** 앞은 그 결과물을 고치는 것이고, 뒤는 같은 러닝으로 **새 결과물을 하나 더** 만드는 것이다. 뒤쪽이 P3(고르는 재미가 우선)을 지탱한다.

### 2-3. 무엇이 남나

**트랙 좌표를 앱이 복사해 보관한다**(PRD §6). 한 번 불러온 러닝은 우리 것이 된다.

| 남는 것 | |
|---|---|
| **트랙 좌표** | 출처가 HealthKit이든 나중의 GPX든 같은 자리에 |
| 완성된 결과물 파일 | |
| 어떤 배경인지(참조), 편집값 | |

**여기서 성질 하나가 나온다.**

> **원본 러닝 기록이 건강 앱에서 삭제돼도 결과물을 다시 편집하고 새로 만들 수 있다.** 그릴 재료를 우리가 갖고 있기 때문이다.

**참조가 약한 것은 배경 소재뿐이다.** 배경은 사용자 갤러리에 있어 우리가 복사하지 않는다. 사라지면 배경만 기본 이미지로 되돌리고 나머지는 유지한다(공통 규칙 §4-1).

## 3. 만들다 만 것

### 3-1. 맨 위에 하나

**만들다 만 것이 있으면 목록 맨 위에 "이어서 만들기"로 띄운다.** (2026-08-23)

- **여러 개면 가장 최근 것 하나만 맨 위에 온다.** 자리가 늘어나면 목록이 지저분해진다
- **나머지도 사라지지 않는다.** 목록 안에 미완성 표시를 달고 남는다. 앱이 임의로 버리지 않는다는 원칙 때문이다(공통 규칙 §4)

### 3-2. 맨 위 자리는 분리하고, 나머지는 목록 안에 둔다

**맨 위 "이어서 만들기"는 결과물 목록과 다른 자리다.** 돌아오자마자 눈에 들어와야 하는 것이라 목록에 묻히면 안 된다.

**나머지 미완성은 목록 안에 둔다.** (2026-08-23)

- **정렬은 목록과 같은 기준을 따른다.** 러닝한 날 최신순이다(§2-1). 미완성이라고 따로 위로 올리지 않는다
- **미완성 표시를 달아 사용자가 알 수 있게 한다.** 표시가 있으면 섞여 있어도 "이건 다 만든 건가"를 판단할 필요가 없다

정렬 기준을 따로 두지 않는 이유는, **사용자가 찾는 기준이 "언제 뛴 것"이지 "완성했는지"가 아니기 때문**이다. 완성 여부는 표시로 알면 된다.

## 4. 첫 실행 쇼케이스

### 4-1. 두 가지 역할

**미리 만들어둔 결과물 클립을 앱에 동봉해 보여준다**(PRD §6). 정지 이미지가 아니라 움직이는 것이어야 한다.

| 언제 | 역할 |
|---|---|
| **보관함이 비었을 때** | 무엇을 만들어 주는지 알리고 코어 루프로 이끈다. 빈 화면을 없앤다 |
| **결과물이 생긴 뒤** | 물러나되 **어딘가에서 항상 볼 수 있게 둔다** |

### 4-2. 왜 계속 볼 수 있어야 하나

**프리셋이 늘어날 때 알릴 자리가 된다.** (2026-08-23) 지금은 셋이지만 연출 아이디어 풀(PRD §7)에서 새 프리셋이 올라오면, **그것을 어디서 보여줄지가 필요하다.** 첫 실행에만 나오고 사라지는 화면이면 그 역할을 못 한다.

이 자리는 **재방문 유인과도 맞닿는다.** PRD가 재방문 유인을 기능이 아니라 검증 항목으로 내렸는데(§5), "새 프리셋이 생겼다"는 나중에 다시 올 이유가 될 수 있다. 지금 만들 것은 아니지만 **자리를 없애지 않는 것**이 값어치다.

### 4-3. 범위

**보관함이 빈 자리를 채우는 것이 먼저다.** 상시 접근은 그 다음이다. 둘 다 PRD §6에서 "여유 시"로 잡혀 있다.

`[확인 필요]` 결과물이 생긴 뒤 쇼케이스를 어디에 둘지. 목록 아래인지 별도 진입점인지. 디자인 시스템에서 정한다.

## 5. 복귀 위치

앱을 다시 열었을 때 어디로 가는지를 정한다(공통 규칙 §4-2에서 넘어온 항목).

| 떠나 있던 시간 | 어디로 |
|---|---|
| **짧으면** (제안 30분 이내) | **하던 화면으로 바로.** 인스타를 확인하거나 전화를 받은 경우다 |
| 그보다 오래면 | **홈으로.** 맨 위 "이어서 만들기"가 하던 것을 가리킨다 |

**오래된 뒤에 편집 화면으로 바로 떨어뜨리지 않는 이유**는, 무엇을 하던 중이었는지 모르는 채로 낯선 화면을 만나기 때문이다. 홈을 거치면 하던 것이 무엇인지 보이고, 이어서 할지 새로 시작할지 고를 수 있다.

**어느 쪽이든 하던 작업은 남아 있다.** 복귀 위치가 다를 뿐이다.

> **기준은 30분으로 두고 실사용에서 조정한다.** (2026-08-23) 머리로 정할 수 있는 값이 아니라 써 보며 맞추는 값이다. W5 실사용(9/9~9/15)이 판정 자리다.

## 6. `[확인 필요]` 모아보기

**열려 있는 `[확인 필요]`는 없다.** 아래 둘은 값을 정해두고 실사용에서 조정하는 항목이다.

| 항목 | 지금 값 | 언제 조정 |
|---|---|---|
| 복귀 기준 시간 | 30분 | W5 실사용 (§5) |
| 같은 기록의 결과물을 묶을지 | 묶지 않고 나란히 | 만든 것이 늘어난 뒤 (§2-1) |

### 디자인 시스템으로 넘긴 것

| 항목 | FRD가 건 제약 |
|---|---|
| 홈 네 자리의 생김새와 배치 | 위에서 아래 순서는 §1-1로 고정 |
| 결과물이 생긴 뒤 쇼케이스의 자리 | 항상 볼 수 있어야 한다(§4-2) |
| 미완성 표시의 생김새 | 목록에 섞여 있어도 구분돼야 한다(§3-2) |
