# 홈과 보관함 FRD

> **status: `approved`.** 2026-08-25 회의에서 확정됐다. 구현 근거로 쓸 수 있다.
> 근거: [PRD](../prd/running-drawing-mvp.md)

## 0. 범위

앱을 열었을 때 처음 보이는 화면과 만든 것이 쌓이는 자리를 정한다. **둘은 같은 화면의 두 얼굴이다.**

홈의 구조, 결과물 보관, 만들다 만 것 이어서 만들기, 첫 실행 쇼케이스, 복귀 위치가 여기 있다.

| 담지 않는 것 | 어디에 |
|---|---|
| 러닝 기록 목록과 선택 | [러닝 기록 선택](run-record-selection.md) |
| 편집 화면의 동작 | [결과물 편집](result-editing.md) |
| 권한·실패·대기의 공통 원칙 | [공통 규칙](common-rules.md) |

## 1. 홈은 결과물 목록이다

> 홈에 무엇이 보이는지 정한다.

보관의 단위는 "내가 만든 결과물"이다. 러닝 기록 목록을 홈에 두지 않는다.

**HealthKit 기록은 수백 개일 수 있고 그 안에 내가 만든 몇 개가 묻힌다.** 내가 만든 것만 보이는 자리가 있어야 다시 올 이유가 된다(PRD §6).

기록 목록은 새로 만들기를 눌렀을 때 열린다. 코어 루프의 첫 단계다.

```
[홈 = 결과물 목록] ──새로 만들기──▶ [기록 선택] → [배경 선택] → [편집] → [공유]
        │
        └──결과물 열기──▶ [보기 / 다시 만들기 / 공유 / 삭제]
```

### 1-1. 화면 구성

위에서 아래로 이렇게 쌓인다.

| 자리 | 무엇 | 언제 |
|---|---|---|
| 1 | 이어서 만들기 | 만들다 만 것이 있을 때만(§3) |
| 2 | 새로 만들기 | 항상 |
| 3 | 결과물 목록 | 만든 것이 있을 때 |
| 4 | 쇼케이스 | 보관함이 비었을 때는 이 자리를 채우고, 아니면 물러난다(§4) |

`[확인 필요]` 각 자리의 생김새와 정확한 배치. 디자인 시스템에서 정한다.

## 2. 결과물

> 만든 것을 목록에서 어떻게 보여주고 무엇을 할 수 있게 할지 정한다.

### 2-1. 목록에 보여줄 것

| 항목 | |
|---|---|
| 썸네일 | 결과물의 한 장면 |
| 날짜 | 러닝을 한 날 |
| 거리 | |
| 프리셋 | 어떤 연출로 만들었는지 |

**만든 날이 아니라 러닝한 날을 쓴다.** 사용자가 "언제 뛴 것"으로 기억하기 때문이다. 만든 날짜는 며칠 뒤일 수 있다.

정렬은 러닝한 날 기준 최신순이다.

같은 기록으로 여러 개를 만들었어도 묶지 않고 나란히 둔다. 만든 것이 몇 개 안 되는 시기에 묶음은 과하다.

### 2-2. 결과물에서 할 수 있는 것

| 동작 | |
|---|---|
| 보기 | 클립을 재생한다 |
| 공유 | 인스타 스토리로 보내거나 파일로 저장한다 |
| 다시 편집 | 그때의 편집값 그대로 열어 고친다 |
| 같은 기록으로 새로 만들기 | 렌더러의 초기값에서 시작한다 |
| 삭제 | 확인을 한 번 받는다 |

**"다시 편집"과 "같은 기록으로 새로 만들기"는 다르다.** 앞은 그 결과물을 고치는 것이고, 뒤는 같은 러닝으로 새 결과물을 하나 더 만드는 것이다. 뒤쪽이 P3(고르는 재미가 우선)을 지탱한다([결과물 편집](result-editing.md) §8).

### 2-3. 무엇이 남나

트랙 좌표를 앱이 복사해 보관한다(PRD §6). 한 번 불러온 러닝은 우리 것이 된다.

| 남는 것 | |
|---|---|
| 트랙 좌표 | 출처가 HealthKit이든 나중의 GPX든 같은 자리에 |
| 완성된 결과물 파일 | |
| 어떤 배경인지(참조), 편집값 | |

여기서 성질 하나가 나온다.

> **원본 러닝 기록이 건강 앱에서 삭제돼도 결과물을 다시 편집하고 새로 만들 수 있다.** 그릴 재료를 우리가 갖고 있기 때문이다.

참조가 약한 것은 배경 소재뿐이다. 배경은 사용자 갤러리에 있어 우리가 복사하지 않는다. 사라지면 배경만 기본 이미지로 되돌리고 나머지는 유지한다([공통 규칙](common-rules.md) §4-1).

## 3. 만들다 만 것

> 편집하다 만 작업을 어디에 어떻게 보여줄지 정한다.

### 3-1. 맨 위에 하나

만들다 만 것이 있으면 목록 맨 위에 "이어서 만들기"로 띄운다. 여러 개면 하나만 올라온다. 자리가 늘어나면 목록이 지저분해진다.

**올라오는 것은 마지막으로 편집한 것이다. 러닝한 날이 아니다.**

이 자리의 목적은 "하던 걸 잇는 것"이지 "최근에 뛴 걸 잇는 것"이 아니다. 3일 전에 뛴 것을 어제 편집하다 말고 한 달 전에 뛴 것을 오늘 편집하다 말았다면, **오늘 만지던 한 달 전 러닝**이 올라온다. §5의 복귀 동선이 이 자리를 가리키므로 기준이 같아야 한다.

### 3-2. 나머지 미완성은 보여주지 않는다 (2026-08-25 확정)

**화면에 보이는 미완성은 맨 위의 그 하나가 전부다.** 나머지는 결과물 목록에 나타나지 않는다.

회의에서 "편집하다 만 것 목록을 노출할 필요가 있나"가 나왔고, **최근 1건이면 충분하다**로 정리됐다. 만들다 만 것이 여러 개 쌓여 있는 상태가 사용자에게 부담이 되고, 실제로 다시 손대는 것은 마지막에 만지던 하나이기 때문이다.

**데이터는 남는다.** 앱이 임의로 버리지 않는다는 원칙은 그대로다([공통 규칙](common-rules.md) §4). 보관은 하되 목록에 세우지 않는 것이고, 새 것을 편집하다 말면 그것이 맨 위 자리를 넘겨받는다.

**결과물 목록은 완성된 것만 담는다.** 미완성 표시라는 개념 자체가 없어진다. 목록에 기준이 하나만 남으므로 정렬도 러닝한 날 최신순 하나다.

> **한 화면에 기준이 둘 공존한다.** 맨 위 배너는 마지막 편집 시각이고 목록은 러닝한 날이다. 목적이 다르기 때문이다. 목록은 "언제 뛴 것"을 찾는 자리고, 배너는 "뭐 하던 중이었지"에 답하는 자리다.

## 4. 첫 실행 쇼케이스

> 보여줄 결과물이 없을 때 그 자리를 무엇으로 채울지 정한다.

### 4-1. 두 가지 역할

미리 만들어둔 결과물 클립을 앱에 동봉해 보여준다(PRD §6). 정지 이미지가 아니라 움직이는 것이어야 한다.

| 언제 | 역할 |
|---|---|
| 보관함이 비었을 때 | 무엇을 만들어 주는지 알리고 코어 루프로 이끈다 |
| 결과물이 생긴 뒤 | 물러나되 어딘가에서 항상 볼 수 있게 둔다 |

### 4-2. 왜 계속 볼 수 있어야 하나

**프리셋이 늘어날 때 알릴 자리가 된다.** 지금은 셋이지만 연출 아이디어 풀(PRD §7)에서 새 프리셋이 올라오면 그것을 어디서 보여줄지가 필요하다. 첫 실행에만 나오고 사라지는 화면이면 그 역할을 못 한다.

이 자리는 재방문 유인과도 맞닿는다. PRD가 재방문 유인을 기능이 아니라 검증 항목으로 내렸는데(§5), "새 프리셋이 생겼다"는 나중에 다시 올 이유가 될 수 있다. 지금 만들 것은 아니지만 자리를 없애지 않는 것이 값어치다.

### 4-3. 범위

보관함이 빈 자리를 채우는 것이 먼저고, 상시 접근은 그 다음이다. 둘 다 PRD §6에서 "여유 시"로 잡혀 있다.

`[확인 필요]` 결과물이 생긴 뒤 쇼케이스를 어디에 둘지. 목록 아래인지 별도 진입점인지. 디자인 시스템에서 정한다.

## 5. 복귀 위치

> 앱을 다시 열었을 때 어디로 데려갈지 정한다([공통 규칙](common-rules.md) §4-2에서 넘어온 항목).

| 떠나 있던 시간 | 어디로 |
|---|---|
| 30분 이내 | 하던 화면으로 바로. 인스타를 확인하거나 전화를 받은 경우다 |
| 그보다 오래 | 홈으로. 맨 위 "이어서 만들기"가 하던 것을 가리킨다 |

**오래된 뒤에 편집 화면으로 바로 떨어뜨리지 않는 이유**는 무엇을 하던 중이었는지 모르는 채로 낯선 화면을 만나기 때문이다. 홈을 거치면 하던 것이 무엇인지 보이고, 이어서 할지 새로 시작할지 고를 수 있다.

어느 쪽이든 하던 작업은 남아 있다. 복귀 위치가 다를 뿐이다.

> 기준 30분은 실사용에서 조정한다. 머리로 정할 수 있는 값이 아니라 써 보며 맞추는 값이고, W5 실사용(9/9~9/15)이 판정 자리다.

## 6. 남은 확인 항목

열려 있는 `[확인 필요]`는 없다. 아래 둘은 값을 정해두고 실사용에서 조정하는 항목이다.

| 항목 | 지금 값 | 언제 조정 |
|---|---|---|
| 복귀 기준 시간 | 30분 | W5 실사용 (§5) |
| 같은 기록의 결과물을 묶을지 | 묶지 않고 나란히 | 만든 것이 늘어난 뒤 (§2-1) |

### 디자인 시스템으로 넘긴 것

| 항목 | FRD가 건 제약 |
|---|---|
| 홈 네 자리의 생김새와 배치 | 위에서 아래 순서는 §1-1로 고정 |
| 결과물이 생긴 뒤 쇼케이스의 자리 | 항상 볼 수 있어야 한다(§4-2) |
| 맨 위 "이어서 만들기"의 생김새 | 결과물 목록과 다른 자리로 읽혀야 한다(§3-2) |
