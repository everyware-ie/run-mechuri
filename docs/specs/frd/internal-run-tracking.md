# 자체 러닝 측정 내부 검증 FRD

2026-10-05 사용자가 FRD와 지표·실패 복구 추천안을 확인하고 구현 착수를 승인했다. 공개 제품이 아닌 내부 검증용이며 [PRD](../prd/internal-run-tracking.md)를 근거로 한다.

## 1. 진입과 화면

개발 빌드와 팀 내부 TestFlight 빌드의 홈 하단과 첫 실행 안내 하단에 `러닝 시작` 카드와 작은 `팀 테스트` 표시를 둔다. 진행 중인 기록은 `러닝으로 돌아가기`로 안내한다. 아이폰 단독 GPS 측정에는 건강 앱 연결을 먼저 요구하지 않는다. 워치 심박을 사용하면 Runary 워치 앱 설치와 필요한 건강 데이터 권한을 확인한다. 일반 공개 빌드에서는 버튼과 직접 주소 진입을 모두 막고, 위치 추적용 백그라운드 설정도 기본 제외한다. 실제 운동의 수집·보관은 시작 버튼 전에는 하지 않는다. 사용자가 연 내부 측정 준비 화면에서만 전면 GPS를 잠깐 준비하는 추천안은 §2 권한과 시작에 둔다.

```
홈 / 첫 실행 안내
  → 내부 측정 (측정 시작 + 이전 측정 목록)
    → GPS 준비 완료 후 시작
    → 측정 중 (거리·시간·페이스·케이던스·GPS 상태, 선택적 워치 연결·심박)
      → 종료 → 측정 상세 (경로 + 요약 + 진단)
    → 이전 기록 선택 → 측정 상세
```

원본 측정 기록과 완성한 결과물은 서로 다른 목록이다. 내부 측정 목록을 기존 결과물 목록에 섞지 않는다. 한 번에 측정 한 건만 허용한다. 진행 중인 것이 있으면 새 측정 대신 해당 기록으로 돌아간다. 측정 화면을 닫아도 측정이 계속되는지 명시하고, 측정 중임을 내부 진입점에서 알 수 있게 한다.

### 1-1. 실제 러닝을 위한 화면 구성 (2026-10-05 사용자 보완)

사용자는 내부용으로 사용하더라도 서비스하는 환경에 맞춘 UI를 요청했고, 첫 화면에서 측정하는 느낌이 약하다고 제보했다. 내부 접근 제한은 유지하며 화면의 중심을 진단이 아닌 운동 경험으로 바꾼다.

- 준비 화면: Runary의 어두운 배경·주황 강조색·Pretendard를 사용한다. 러닝 시작 안내, GPS 준비 상태, 선택적인 워치 연결을 보여주고 시작 동작을 하단에 고정한다. 이전 기록은 접어서 볼 수 있다.
- 측정 화면: 시간·거리·현재 페이스·심박을 같은 크기의 네 칸으로 읽기 쉽게 배치한다. 측정 중·일시정지·중단을 상태 표시로 구분한다. 평균 페이스·케이던스·걸음은 보조 정보이며 일시정지·재개·종료는 하단에서 계속 접근한다. 목록은 측정에 간섭하지 않도록 별도 접힘 영역에 둔다.
- 완료 기록: 실제 경로와 러닝 요약이 먼저 보인다. 메모와 진단은 필요할 때 펼친다. 좌표가 없으면 빈 커다란 경로 판 대신 간단한 안내를 보여준다. 진단 원본과 복사 기능은 제거하지 않는다.
- 큰 글자·작은 화면: 본문은 필요할 때 스크롤하고 하단 동작과 겹치지 않는다. 값·단위는 구분하며 센서 미수신과 GPS 준비·오류를 실제 상태대로 표시한다. 지도는 아래 §1-2 러닝 지도에 따라 표시하며 가짜 경로·센서 값을 보여주지 않는다.

### 1-2. 러닝 지도 (2026-10-05 사용자 승인)

사용자가 [지도 보완안](../../topics/2026-10-05-tracking-map-and-permissions.md)을 확인하고 지도 추가 작업을 요청했다. 준비·측정·완료와 이전 기록에 Apple 지도를 포함한다.

- 준비: GPS 준비 후 확보한 실제 위치를 표시한다. 위치가 없으면 준비 안내를 보여주고 임의의 장소를 현재 위치로 표시하지 않는다. 기존 준비 취소·30초 시간 초과를 유지한다.
- 측정: 현재 위치·출발점·채택된 GPS 경로를 표시하고 지도 아래 시간·거리·현재 페이스·심박을 같은 중요도로 배치한다. 하단 일시정지·재개·종료를 유지한다. 손으로 이동·확대하면 따라가기를 멈추고 현재 위치 버튼으로 복귀한다.
- 일시정지·중단: 마지막 실제 위치와 경로를 유지하고 새로운 위치를 수집하지 않는다. GPS 재확보 중 준비 위치를 보여줄 수 있지만 원래 경로와 연결하지 않는다. 지연된 위치는 최신 위치처럼 표시하지 않는다.
- 완료·이전 기록: 전체 채택 경로를 화면 안에 맞춰 보여준다. 좌표가 없으면 작은 안내를 보여준다. 완료 기록의 위치를 새로 수집하지 않는다.
- 경로: 구간별로 선을 분리해 일시정지·중단·확인된 누락 구간을 직선으로 연결하지 않는다. 길게 측정한 기록의 표시량을 줄여도 실제 원본·거리 계산은 바꾸지 않는다.
- 성능·실패: 기존 네이티브 수집 상태에서 새 좌표만 읽고 매초 전체 로그를 다시 읽지 않는다. 지도 자체 위치 수집을 켜지 않는다. 화면이 닫히거나 앱이 백그라운드로 가면 지도 갱신을 중지한다. 지도 배경 실패가 측정·저장·종료를 막지 않게 한다.

지도 배경은 Apple 지도 서비스의 네트워크 요청을 사용한다. 원본을 Runary 서버에 업로드하지 않는 보관 규칙과 구분해 화면에 짧게 안내한다. 내비게이션·코스 추천·위성 전환·오프라인 다운로드·워치 지도는 제외한다. 지도 추가가 GPS 정확도 개선을 뜻하지 않으며 야외 위치·배터리 실측은 별도다.

## 2. 권한과 시작

처음 `GPS 준비`를 눌렀을 때 사용 중 위치 접근을 요청한다. 이미 허용한 경우 내부 준비 화면에서 전면 GPS를 확보하고, 준비 완료 후 `시작`으로 운동을 기록한다. 위치 서비스를 사용할 수 없거나 권한을 거부하면 설명과 설정으로 가는 길을 제공한다. 위치·시각 저장과 백그라운드 측정을 설명하는 별도 시작 전 팝업은 두지 않는다. 최초 시스템 권한 설명과 내부 화면의 도움말·개인정보 안내에서 실제 수집 범위를 설명한다. 측정 중에는 측정 상태가 보이게 한다. 사용자의 요청 없이 시작하거나 단순 홈 진입으로 운동 수집을 시작하지 않는다. 내부 준비 화면의 일시적인 GPS 확보와 운동 기록 시작은 구분한다.

걸음 수·케이던스에는 동작 및 피트니스 권한을 해당 기능 사용 시 요청한다. 거부해도 GPS 측정을 막지 않고 해당 항목만 미측정으로 표시한다. Runary 워치 앱이 직접 심박을 수집하는 데 필요한 HealthKit 권한을 요청한다. 워치가 없거나 권한을 허용하지 않으면 심박은 미측정이며 아이폰 GPS 측정은 가능하다. 선택적인 병행 심박 읽기 실험에는 심박 읽기 권한을 사용한다. HealthKit 읽기 권한 거부와 데이터 부재를 조회 결과만으로 구분하지 않는다. 권한 문구의 기존 `위치를 추적하거나 저장하지 않습니다` 표현은 내부 측정 빌드에서 실제 동작에 맞게 수정해야 한다.

정확한 위치를 꺼 둔 상태에서는 내부 정확도 검증을 시작하지 않고 설정 안내를 제공한다. 항상 허용 권한은 첫 구현에 요청하지 않는다.

GPS 준비는 오래된 캐시 위치나 부정확한 첫 위치를 출발점으로 삼지 않기 위한 과정이다. 첫 위치 확보에는 몇 초가 걸릴 수 있다. [Apple 위치 수집 시작 안내](https://developer.apple.com/documentation/corelocation/cllocationmanager/startupdatinglocation()).

추천 흐름은 위치 권한을 이미 허용한 사용자가 내부 측정 화면을 열면 전면에서 GPS를 준비하고 `GPS 준비 중 → 준비 완료 → 시작`으로 보여주는 것이다. 최초 권한은 준비·측정을 하려는 동작에서 요청한다. 시작 버튼은 준비가 완료됐을 때 사용하며 버튼을 누른 시점을 실제 기록 시작으로 삼는다. 별도의 카운트다운은 첫 버전에 두지 않는다. 준비·취소·화면 이탈 시 원본 운동 기록을 남기지 않으며, 준비 시도 30초 후 재시도·취소를 제공한다. 준비 중 수집은 해당 전면 화면에서만 수행하고 화면 이탈·백그라운드 전환 때 중지한다. 마지막 유효 위치가 오래되면 준비 완료를 취소하고 재확보한다. 준비 버튼·실제 시작·GPS 확보 시각은 진단에서 구분한다. 실제 운동의 시작은 앱 전면에서만 허용한다.

### 2-1. 앱 권한 화면

2026-10-05 사용자는 서비스 권한을 모아 관리할 별도 화면을 요청했다. 내부 측정 화면에서 `앱 권한`으로 진입하고 기존 기능의 권한 안내에서도 같은 화면에 연결하는 구성을 추천한다. 실제 허용·철회는 OS에서 수행하며 앱에 허용 토글을 만들어 권한이 변경된 것처럼 보이지 않게 한다.

위치·정확한 위치, 동작 및 피트니스, 건강 기록 읽기·워치 심박/운동, 카메라, 사진 저장을 기능별로 안내한다. 각 항목에는 필요한 이유·앱이 확인 가능한 상태·OS 설정으로 가는 동작 또는 이동 경로를 둔다. 시스템 사진 선택만 사용하는 갤러리 가져오기는 별도 사진 읽기 권한이 필요 없는 방식임을 설명한다. 권한 상태와 센서 미지원은 구분한다.

HealthKit 읽기는 허용·거부 상태를 앱이 확정할 수 없으므로 `권한 확인 필요` 안내를 제공하고 수신 상태는 따로 보여준다. 권한을 거부했다고 단정하거나 권한 요청 완료를 허용 완료로 표시하지 않는다. OS 설정에서 돌아오면 확인 가능한 상태를 새로 읽는다. 중단된 러닝은 자동 재개하지 않고 사용자에게 재개 선택을 제공한다. [Apple HealthKit 권한 안내](https://developer.apple.com/documentation/healthkit/hkauthorizationstatus).

공개 MVP에 설정 화면이 없다는 [공통 규칙](common-rules.md) §2-1 기록이 하나도 없을 때와 구분한다. 이번 화면의 내부 범위와 기존 실패 안내 연결은 이번 내부 기능에 포함한다.

## 3. 측정 중

거리·측정 시간·현재/평균 페이스·걸음 수·현재/평균 케이던스와 GPS 상태를 보여준다. 워치 연동 시 현재 심박과 수신 상태도 보여주며 상세에 평균·최대 심박을 보관한다. 평균 페이스는 누적 거리와 측정 시간으로 계산한다. 측정 시간은 사용자가 일시정지한 시간과 확인된 기록 중단 시간을 제외한다. 일시적인 GPS 불량으로 경로만 누락된 때는 시간 측정을 유지한다. 횡단보도에서 기다리면 자동으로 멈추지 않으며, 거리 증가를 억제하고 시간은 유지한다. 자동 일시정지가 켜진 비교 앱과 시간·평균 페이스가 다를 수 있다.

거리가 지나치게 작거나 센서 값이 없으면 `—`를 표시한다. 현재 페이스는 최근 유효한 위치 구간을 평활화하고 정지·수신 부재·수신 시각을 함께 판단한다. 케이던스는 센서의 걸음 수·시각으로 측정하며 GPS 속도에서 추측하지 않는다. 최신 센서 값이 없는 때 직전 값을 현재값처럼 계속 유지하지 않는다. 산출 창·최신값 유효시간의 상세 추천은 §3-1 지표 계산 추천안에 두고 채택한 설정을 진단에 남긴다.

기존 네이티브 수집의 채택 좌표를 지도에 표시한다. 측정 상세에서는 저장된 실제 경로를 지도 안에 맞춘다. 지도 위 실시간 위치와 거리 계산은 별개이므로 지도 UI를 위치 수집의 조건으로 만들지 않는다.

수집은 네이티브 위치 모듈이 담당한다. JavaScript 타이머나 화면 마운트 상태에 수집·저장을 의존하지 않는다. 화면 잠금과 다른 앱 전환 때도 수집을 시도한다. 일시정지·종료에는 GPS를 중지해 불필요한 소모를 줄인다. 자동 일시정지는 없다.

수집한 위치는 좌표·시각·수평 정확도를 원본으로 남긴다. 오래된 위치·잘못된 정확도·역행 시각·명백한 점프를 거리 집계에서 제외하고, 제외한 사유와 수를 진단에 남긴다. 좌표가 뜸해지는 경우 마지막 수신 시각을 표시한다. 수집 주기를 정확히 1초로 보장하지 않는다.

초기 필터값은 정확도·배터리 측정으로 조정할 기술 출발점이다. 정확도 35m 초과, 비정상 좌표와 역행 시각은 제외한다. 시작 위치는 정확도 20m 이내이며 최근 15초 안의 위치를 요구한다. 이미 측정 중에 순서대로 묶여 전달된 위치는 수신 지연만으로 버리지 않고 위치의 측정 시각과 구간을 검토한다. 운동에서 불가능한 점프와 정지 중 흔들림은 별도 필터로 처리한다. 원본과 채택 경로를 함께 비교해야 한다.

### 3-1. 지표 계산 추천안

아래 수치와 계산은 2026-10-05 사용자 질문에 대한 추천안이다. Apple이 정한 통과 기준이나 실측 결과가 아니다. 원본과 계산 방식의 버전을 보관하고 야외 테스트에서 조정한다.

| 현재 심박 | 현재 기록의 워치에서 받은 최신 유효 샘플을 bpm으로 표시. 평균값으로 현재값을 대체하지 않음. 측정 시각으로 15초 초과면 `—`와 수신 지연, 초기 미수신이면 심박 대기 |

| 걸음 수 | 동작 센서에서 받은 측정 구간의 걸음 수. 수동 일시정지·중단 구간 제외. 거리로 추정하지 않음. 센서 일부 누락은 부분 수집으로 표시 |
| 현재 케이던스 | 센서가 제공한 초당 걸음 수 × 60을 spm으로 표시. 유효한 0은 0으로 표시하고 미수신은 `—`. 새 센서 업데이트가 10초 넘게 없으면 지연으로 표시 |
| 평균 케이던스 | 유효한 센서 관측 구간의 걸음 수 ÷ 해당 구간의 측정 분. 관측된 정지는 0걸음으로 포함, 수동 일시정지·센서 미관측 시간은 제외. 센서 누락이 있으면 전체 운동 평균으로 오인하지 않도록 부분 수집 표시 |
| 칼로리·고도·상승고도·구간별 기록 | 첫 검증 범위에서는 후속 후보로 유지. 임의 공식을 붙여 기본 지표처럼 제공하지 않음 |

신선도는 앱이 값을 받은 시각과 실제 측정 시각을 구분한다. GPS와 심박은 샘플 시각을 사용하고 동작 센서는 API의 관측 구간과 업데이트 시각을 함께 남긴다. 화면에 방금 도착했어도 예전 측정값이면 현재값에 쓰지 않는다. 늦게 도착한 실제 유효 샘플은 해당 과거 측정 구간에 반영할 수 있으며, 지연만으로 원본 전체를 버리지 않는다. 미래 시각·역행·중복·현재 기록 밖의 샘플은 따로 검사한다.

GPS 공백, 워치 연결 지연, 느슨한 착용·추위·움직임에 따른 심박 측정 실패, 동작 센서의 미지원·초기 미수신 등이 직전 값만 남는 상황이다. 화면 잠금·백그라운드 전환 자체를 실패로 단정하지 않고 실제 샘플의 나이와 수집 상태로 판단한다. [Apple 위치 업데이트](https://developer.apple.com/documentation/corelocation/cllocationmanagerdelegate/locationmanager(_:didupdatelocations:)), [Apple 심박 측정 조건](https://support.apple.com/en-ie/105002), [Apple 케이던스 데이터](https://developer.apple.com/documentation/coremotion/cmpedometerdata/currentcadence).

## 4. 일시정지·재개·종료

`일시정지`는 현재 기록을 저장하고 시간·거리 누적과 GPS를 멈춘다. `재개`는 전면에서 GPS 준비를 마친 뒤 사용자 버튼 시각부터 새 구간으로 측정한다. 워치에서 재개를 눌러도 같은 조건을 적용한다. 아이폰이 잠겨 있거나 GPS가 준비되지 않았다면 아이폰에서 준비하도록 안내하고 재개 성공으로 표시하지 않는다. 일시정지 구간의 이동을 거리나 경로에 더하지 않는다.

`종료`는 확인 후 기록을 확정하고 GPS를 멈춘다. 짧은 테스트도 기록으로 보관한다. 위치가 하나도 없는 기록은 그림을 만들 수 없다고 안내한다. 저장 실패 시 완료로 표시하지 않고 저장 대기 상태·마지막 확정 범위와 다시 시도를 제공한다. 상세는 §5-1 실패와 복구 추천안에 둔다.

### 4-1. 멈춤과 GPS 누락을 구분한다 (2026-10-05 보완)

`30초 무수신이면 새 구간` 규칙은 사용하지 않는다. 이동 거리 필터 때문에 같은 위치에 서 있는 동안 새 좌표가 오지 않을 수 있다. 횡단보도에서 기다린 뒤 정상적으로 다시 움직이는 것만으로 경로를 끊거나 기록을 중단하지 않는다. [Apple 거리 필터 안내](https://developer.apple.com/documentation/corelocation/cllocationmanager/distancefilter).

30초는 진단에서 검토할 공백의 표시 기준이다. 공백만으로 GPS 오류·정지·앱 종료를 단정하지 않는다. 전후 위치·정확도·걸음 변화·위치 서비스 오류·수집 상태를 함께 판단한다. 비슷한 위치의 전후 점만으로 그동안 완전히 정지했다고 확정하지 않는다. 한 바퀴 돌아 제자리로 온 경우도 가능하기 때문이다.

일시정지·종료 후 복구·확인된 수집 중단은 새 구간으로 시작한다. 실제로 이동했지만 중간 경로를 확보하지 못한 경우는 누락 구간으로 표시하고 임의의 직선이나 GPS 좌표로 채우지 않는다. 알 수 없는 구간의 거리를 정상 기록처럼 계산하지 않고 거리 누락 가능성을 상세에 표시한다. 원본은 남긴다. 필터 출발값을 달리한 정지·이동 공백 검사를 통해 조건을 확정한다.

기술 설정에서도 의도하지 않은 정지를 막는다. 첫 검증에서는 자동 위치 수집 일시정지를 끄고 사용자가 일시정지·종료할 때 수집을 중지하는 방식을 비교한다. 이 설정의 배터리 대가는 실측하며, 시스템이 실제 수집을 중단하면 진단에 남긴다.

## 5. 저장과 앱 종료 후 복구

기기 Documents 내부 전용 폴더에 기록별 식별자로 보관한다. 원본 위치·채택 여부·상태 변경은 덧붙이는 로그로 기록하고, 요약·진행 상태는 원자적으로 저장한다. 측정이 진행 중인 때 최대 5초마다 저장 확정을 시도하고 일시정지·종료·백그라운드 전환 때 즉시 확정한다. 배치 수신·OS 중단·저장 오류 때문에 이 간격이 보장되지 않을 수 있다. 마지막 저장 확정 시각을 진단에 표시한다.

화면 잠금 후에도 파일을 쓸 수 있는 보호 등급을 적용한다. 기기 재시작 후 최초 잠금 해제 전 접근은 보장하지 않는다. 좌표를 콘솔·분석 서버·오류 보고에 남기지 않는다. 내부 기록 폴더는 백업에서 제외한다.

재실행에서 완료되지 않은 기록을 복구한다. 잘린 마지막 로그 한 줄은 완전한 앞부분을 읽어 복구하고, 복구 과정에서 문제를 표시한다. 기록 전체를 조용히 삭제하지 않는다. 아이폰 단독 측정에서 복구된 기록은 `중단됨`으로 보여주고 `이어서 측정`과 `여기까지 저장`을 제공한다. 복구 기준은 저장된 시점이다. 앱 종료 중의 좌표나 시간을 추정하지 않는다. 아이폰 앱만 종료되고 워치 운동이 살아 있는 경우에는 같은 기록에 재연결하고 워치에 실제 보관된 심박을 병합하는 방식을 추천한다. 상세는 §5-1 실패와 복구 추천안에 둔다. 저장된 아이폰 상태만 보고 살아 있는 워치 운동을 중단 상태로 덮지 않는다.

앱이 살아 있는 상태의 화면 재열기·개발 화면 새로고침은 강제 종료와 구분한다. 이미 측정 중인 네이티브 상태에 다시 연결하고 새 기록을 만들지 않는다. OS 종료 원인을 알 수 없으므로 임의로 `강제 종료`라고 단정하지 않는다.

| 아이폰 앱 종료 | GPS는 마지막 확정 시점까지 복구. 살아 있는 워치 세션이 있으면 같은 기록에 재연결하고 실제 보관된 심박만 병합. 워치 심박이 있었다는 이유로 종료 중 아이폰 GPS가 있었다고 추정하지 않음 |
| 워치 앱 종료 | 활성 운동 복구 API를 우선 시도하고 실제 세션·자료 복구 여부를 확인. 복구되지 않은 구간은 미수집 표시. 재실행이 항상 가능한 것으로 보장하지 않음 |
| 손상된 마지막 로그 | 온전한 앞부분을 복구하고 손상·복구 범위를 안내. 복구 실패 시 원본을 보존하고 오류를 표시하며 자동 삭제하지 않음 |

재시도·앱 복구는 같은 기록과 작업 식별자로 수행한다. 이중 운동 시작·거리·걸음·심박의 중복 집계를 막는다. 저장 오류로 수집 중단이 결정되면 워치에도 종료/중단을 요청하고, 응답이 없으면 미확인 상태를 기록해 재연결 시 정리한다. 버퍼 시간·재시도 횟수는 제품 보장이 아니라 첫 기술 설정이며 실제 저장 실패 검사로 조정한다. [Apple 활성 워치 운동 복구](https://developer.apple.com/documentation/healthkit/hkhealthstore/recoveractiveworkoutsession(completion:)).

## 6. 측정 기록 목록과 상세

날짜 최신순으로 거리·운동 시간·상태를 보여준다. 상세에는 경로 미리보기, 거리, 운동 시간, 평균 페이스, 시작·마지막 저장 시각, 측정 구간 수를 보여준다. 완료·중단·일시정지를 구분한다.

진단에는 총 수신·채택·제외 좌표 수, 제외 사유, 수평 정확도 분포, 수신/좌표 시각 공백, 전면·백그라운드 수신 수, 걸음·케이던스 수신, 시작·종료 배터리 잔량·충전 여부, 기기·OS·앱 버전을 자동으로 남긴다. 배치 전달 간격과 실제 좌표 시각의 공백을 구분한다. 백그라운드라는 사실만으로 화면 잠금이라고 단정하지 않는다. 심박 값의 출처·측정/수신 시각·워치 연결 상태도 남긴다.

평소 러닝에서 Runary 단독 측정을 확인하고 다른 아이폰 앱과의 비교도 선택할 수 있다. 워치 운동 세션은 중복 시작하지 않는다. 종료 시 비교 앱 이름·거리·시간과 `문제 없음 / 끊김 / 거리 이상 / 기타`를 선택해 선택적으로 메모할 수 있게 한다. 양식 작성을 종료·보관의 조건으로 만들지 않는다. 기기·OS·진단을 사람이 다시 입력하게 하지 않는다. 비교 코스와 기준 거리는 정밀 검증 때만 적는다. 충전 중 배터리 측정은 비교에서 제외한다. 다른 앱 동시 실행 중의 잔량 변화만으로 Runary 단독 소모를 계산하지 않는다.

완료·중단된 기록은 확인 후 삭제할 수 있다. 워치에 보관된 동일 기록의 심박도 삭제 대상으로 전달한다. 워치가 오프라인이면 재연결 때 삭제하며, 삭제 표식으로 늦은 전송이 기록을 되살리지 않게 한다. 진행 중인 기록은 먼저 종료해야 한다. 삭제 실패 시 목록과 파일을 유지하고 다시 시도하게 한다. 첫 구현은 원본 진단 파일의 외부 전송과 기존 편집 연결을 포함하지 않는다. 사용자가 채택한 `진단 요약 복사`는 상세에 제공한다. 빌드·기기 모델/OS·거리·시간·GPS 공백/정확도·센서 지연·오류·배터리/충전 여부와 사용자가 적은 비교 앱·문제 유형을 읽기 쉬운 텍스트로 복사한다. 좌표·장소·개별 심박 원본·고유 기기 ID는 제외한다. 자동 전송하지 않으며 사용자가 카톡 등으로 공유할지 선택한다.

## 7. 검증과 공개 조건

[내부 검증 계획](../../ops/internal-run-tracking-qa.md)을 따른다. 잠금 상태의 실제 야외 이동과 배터리 소모는 사용자가 직접 운동해야 검증할 수 있다. 자동 검사·시뮬레이터·책상 위 실행을 대신 성공 증거로 쓰지 않는다. 검증 결과를 문서에 남기고 공개 여부를 따로 결정한다.

## 8. Runary 단독 측정과 워치 연동

워치를 사용할 때 다른 운동 앱 없이 Runary만으로 심박을 측정하고 볼 수 있는 기능을 제공하는 것이 첫 내부 버전의 완료 조건이다. 심박은 각 러닝 기록의 필수 수집 항목이 아니며 워치 연동 사용은 선택이다. Apple Watch를 착용하고 Runary 워치 앱 설치·권한을 갖춘 상태에서 자체 운동 세션이 센서를 수집한다. 아이폰에는 심박 센서가 없으므로 워치 없이 심박을 측정한다고 안내하지 않는다. [Apple 운동 세션 안내](https://developer.apple.com/documentation/healthkit/hkworkoutsession).

심박은 사용자가 유지하고자 하는 핵심 러닝 항목이다. 심박이 수집되면 현재·평균·최대 심박을 기록하고 현재 심박을 워치에서 쉽게 읽을 수 있게 하는 것을 요구 범위에 넣는다. 사용자 답변에 따라 시간·거리·현재 페이스·심박을 같은 크기의 네 칸으로 배치하며 글자 크기·대비·가독성을 비슷하게 유지한다. 심박만 크게 강조하지 않는다. 케이던스·평균 지표는 다음 화면에서도 같은 읽기 기준을 적용하는 구성을 추천한다. 시간·거리·현재/평균 페이스·케이던스와 함께 표시하고 워치와 아이폰의 일시정지·재개·종료 상태를 동기화한다. 목표 심박 범위 표시·진동 알림·항목별 사용자 배치는 첫 버전 밖의 후속 후보로 두는 추천안이다.

워치 미착용·연동 미사용·권한 미허용·심박 미수신은 아이폰 러닝의 시작·종료·저장을 막지 않는다. 워치 연결 대기를 심박 없는 아이폰 측정의 필수 단계로 만들지 않는다. 심박이 없으면 미측정으로 표시하고 값을 0으로 저장하거나 평균·최대 심박 계산에 포함하지 않는다. 일부 구간에서만 심박을 받았다면 실제 수집된 샘플만 보관하며 누락 구간을 임의로 채우지 않는다.

### 8-1. 기존 운동의 심박 읽기는 선택적인 비교 실험

사용자는 기본 워치 운동 앱과 Nike Run Club을 함께 사용하면 Nike에도 심박이 표시된다고 알렸다. Nike는 아이폰에서 실행하고 워치에서 심박을 확인하며, 아이폰에서 시작한 Nike가 워치에 잘 나타나지 않을 때가 있다고 추가 설명했다. 워치에서 보고 있는 앱과 Nike의 내부 수신 방식은 아직 확정하지 않았다. 병행 심박 읽기와 Runary 워치 화면을 여는 기능을 같은 기능으로 취급하지 않는다.

이 비교 실험을 수행할 때만 Runary 자체 워치 세션을 만들지 않고 HealthKit에 추가된 심박을 관찰한다. 실험의 성공은 Runary 단독 심박 측정의 완료를 뜻하지 않으며, 이 실험을 워치 앱 구현의 선행 조건으로 두지 않는다. 샘플의 측정 시각·아이폰 수신 시각·출처를 기록해 기존 값인지 새 값인지 구분한다. 중복 샘플과 현재 측정 시간 밖의 샘플은 통계에서 제외한다. 권한 거부·샘플 부재·잠금 중 접근 불가·워치 동기화 지연을 GPS 실패와 구분한다.

최신값만 현재 심박으로 표시하고 늦은 값에는 마지막 측정 시각 또는 지연 상태를 표시한다. 오래된 심박을 현재 심박이나 목표 구간 알림의 기준으로 쓰지 않는다. 잠금 후 수신과 다시 전면에 돌아왔을 때의 지연도 측정한다. 샘플의 나이와 수신 간격이 안정적인지는 아직 검증하지 않았다. 값이 보이는 것만으로 실시간 기능을 통과 처리하지 않는다.

### 8-2. Runary가 직접 워치 운동을 시작한다

Runary가 워치에서 직접 운동을 관리하고 지표를 보여주려면 별도 watchOS 앱과 운동 세션을 구성한다. 다른 워치 운동 앱의 화면에 Runary 정보를 삽입하거나 그 앱의 실시간 센서 전달을 보장하지 않는다. 워치 운동 세션은 동시에 하나만 실행할 수 있어, 병행 테스트에서는 기존 워치 앱의 운동을 유지하고 Runary는 아이폰 수집과 심박 읽기만 시도한다. Runary 워치 운동을 시작하는 테스트에서는 기존 워치 운동을 종료한다. 아이폰에서 워치 앱을 연 뒤 워치의 `워치 측정 시작`에서 확인을 받아 세션을 만든다. 다른 워치 운동을 몰래 종료시키지 않도록 자동으로 새 세션을 만들지 않는다. 이를 확인하지 않고 새 세션을 시작해 사용자의 기존 운동을 중단시키지 않는다.

아이폰에서 Runary 측정을 시작하면 Runary 워치 앱이 자체 운동 세션으로 심박을 수집하고 아이폰에 전달하는 흐름을 구현한다. GPS 작업과 나눠 진행하더라도 이 흐름의 검증 전에는 첫 내부 버전을 완료 처리하지 않는다. 거리·경로·시간은 아이폰, 심박은 워치를 기준으로 하는 추천안을 §9 사용자 선택과 확정한 기준에 둔다. 지원 OS와 건강 앱 운동 저장 여부는 착수 전 기술 검토로 정한다. 내부 기록이 기존 앱의 운동과 중복으로 건강 앱에 저장되지 않도록 확인한다. 두 기기의 거리를 합산하지 않는다. 워치가 없거나 연동을 끈 경우에도 아이폰 측정은 가능해야 한다.

### 8-3. 워치가 열리지 않거나 연결이 끊어질 때

아이폰에서 시작하는 사용 흐름을 지원한다. 워치 사용을 선택한 경우 연결·설치·권한 상태를 확인하고 워치 앱 열기를 요청한다. 열기 요청을 보냈다는 사실만으로 `연결됨`이나 `심박 측정 중`으로 표시하지 않는다. 실제 측정 상태 응답과 새로운 심박 수신을 따로 확인한다. [Apple의 기기 간 운동 연동 예제](https://developer.apple.com/videos/play/wwdc2023/10023/).

화면에는 `워치 연결 중`, `워치 응답 없음`, `심박 대기`, `심박 수신 지연`을 실제 상태에 맞게 구분해 표시한다. 응답이 없으면 `다시 연결`과 `워치에서 Runary 열기` 안내를 제공한다. 자동으로 여러 운동 세션을 시작하지 않고 같은 측정 식별자로 재시도한다. 첫 응답 대기는 10초를 초기값으로 추천한다. 아이폰 시작 시각·GPS 수집은 워치 응답을 기다려 늦추지 않는다. 시간 초과 뒤 응답 없음과 수동 재연결을 제공하며, 같은 기록 ID의 활성 세션이 있는지 확인하고 연결한다. 늦게 연결돼도 기존 아이폰 기록의 시간·거리를 초기화하지 않는다. 이 수치와 흐름은 실제 기기에서 검증한다.

워치 연결 실패로 아이폰의 측정 기록을 지우거나 새 기록으로 덮지 않는다. 아이폰 단독 측정에서는 GPS를 유지하고, 심박 수신이 중단된 구간을 명시한다. 첫 버전은 아이폰 GPS를 기준으로 하는 추천이며 연결 끊김 때 워치 GPS로 자동 전환하지 않는다. 재연결되면 기존 기록에 붙이고 심박의 측정 시각으로 중복을 제거한다. 두 기기의 거리·시간을 중복 집계하지 않는다. 연결 상태가 정상이어도 심박이 늦을 수 있으므로 마지막 심박 시각을 별도로 관리한다.

| 심박 전달 | 추천안 채택 | 15초 초과는 지연 표시. 워치 자체 수집과 아이폰 수신을 각각 검증. 옛값으로 현재 상태를 채우지 않음 |

### 9-1. 내부 설치 계획

개발 서버 없이 실행되는 내부 TestFlight 빌드에 아이폰 앱과 Runary 워치 앱을 함께 포함한다. 팀 내부 그룹에만 배정하고 일반 외부 테스터·공개 링크에 자동 배포하지 않는다. 기존 공개 TestFlight 빌드에는 내부 진입을 추가하지 않는다. 단순히 그룹 이름만 내부로 짓는 것과 App Store Connect 내부 테스터 등록은 구분한다. 팀원이 내부 테스터로 등록 가능한지 배포 전 확인한다. [Apple 내부 TestFlight 안내](https://developer.apple.com/help/app-store-connect/test-a-beta-version/add-internal-testers).

첫 구현의 지원 하한은 iOS 16.4와 watchOS 10.0이다. 아이폰 휴대가 필요하며 워치 단독 GPS 측정은 제외한다. 모든 기존 워치를 지원한다고 먼저 약속하지 않는다. 아이폰 GPS와 워치 화면·심박, 잠금 수집·기록 복구의 설치 후 확인을 마친 뒤 내부 운동 테스트용으로 배포한다. GPS 정확도·배터리의 야외 합격까지 배포 전에 완료했다고 가정하지 않는다. 첫 내부 배포 자체가 그 실측을 하기 위한 단계다.

기술 초기값은 구현 담당자가 이유와 변경 이력을 남기고 실측으로 조정한다. 사용자가 상세 추천안과 전체 FRD를 확인해 구현 착수를 승인했다. 구현·검증 상태는 [구현 노트](../../product/features/internal-run-tracking.md)에 남긴다. 승인 자체는 운동 실측이나 배포 완료를 뜻하지 않는다.

## 기술 근거

- [Apple: allowsBackgroundLocationUpdates](https://developer.apple.com/documentation/corelocation/cllocationmanager/allowsbackgroundlocationupdates): 전면에서 시작한 위치 수집을 백그라운드에서도 이어가는 설정.
- [Apple: 위치 권한 요청](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services): 사용 중 권한과 활성 위치 수집의 관계.
- [Apple: 표준 위치 수집](https://developer.apple.com/library/archive/documentation/UserExperience/Conceptual/LocationAwarenessPG/CoreLocation/CoreLocation.html): 좌표 시각·정확도 확인, 수집 시작·중지와 백그라운드 모드. 과거 문서이므로 최신 OS에서 실측한다.
- [Apple: 파일 보호 등급](https://support.apple.com/guide/security/data-protection-classes-secb010e978a/web): 최초 잠금 해제 이후 사용할 수 있는 보호 등급.
- [Apple: HKWorkoutSession](https://developer.apple.com/documentation/healthkit/hkworkoutsession): 운동 중 센서 수집과 워치의 단일 운동 세션 제한.
- [Apple: 기기 간 운동 연동](https://developer.apple.com/videos/play/wwdc2023/10023/): 워치 운동 세션과 아이폰의 상태·지표 동기화. 예제의 cycling cadence를 러닝 cadence로 혼용하지 않는다.
- [Apple: currentCadence](https://developer.apple.com/documentation/coremotion/cmpedometerdata/currentcadence): 초당 걸음 수와 미지원·미수신에서 값이 없는 경우.
- [Apple: HKAnchoredObjectQuery](https://developer.apple.com/documentation/healthkit/hkanchoredobjectquery): 저장소에 새로 들어오는 샘플의 관찰. 워치-아이폰 실시간 전달 주기를 보장하는 API가 아니다.
