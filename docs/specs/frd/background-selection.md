# 배경 선택 FRD

> **status: `draft`.** 팀 확인 후 `approved`로 올린다. **approved가 아니면 구현 근거가 아니다.**
> 근거: [PRD](../prd/running-drawing-mvp.md) · [2026-08-18 결정](../../decisions/2026-08-18-native-ios-and-mvp-scope.md)

## 0. 범위

**담는 것**: 배경으로 쓸 소재를 고르고, 9:16 화면에 맞추고, 렌더러에 넘기기까지.

**안 담는 것**

| 항목 | 어디로 |
|---|---|
| 배경 위에 경로를 얹는 합성 | [경로 렌더링](route-rendering.md) §8 |
| 드로잉의 크기·위치·회전 | 결과물 편집 |
| 사진·카메라 권한을 거부했을 때의 동작 | 공통 규칙 |
| 배경 이미지 파일 자체 (어떤 사진을 넣을지) | 이 문서 밖. §2-2 참고 |

**경계 하나를 명시한다. 배경을 화면에 맞추는 확대·이동은 이 화면에서 한다.** 결과물 편집의 크기·위치·회전은 **드로잉만** 대상이다. 한 화면에서 두 대상을 만지면 사용자가 지금 무엇을 움직이는지 헷갈린다.

## 1. 배경의 종류와 범위

| # | 배경 | 범위 |
|---|---|---|
| 1 | **우리가 제공하는 기본 이미지** | **MVP 기본** |
| 2 | 갤러리에서 고른 사진 | 여유 시 |
| 3 | 갤러리에서 고른 영상 | 여유 시 |
| 4 | 그 자리에서 찍은 사진 | 여유 시 |
| 5 | 그 자리에서 찍은 영상 | 여유 시 |

**MVP 기본 범위는 1번뿐이다.** 찍어둔 것이 없어도 결과물이 나와야 하기 때문이다.

### 1-1. 붙이는 순서

2~5번은 전부 "여유 시"인데, 여유가 조금만 생기면 순서가 필요하다. **위 번호 순서대로 붙인다.** (2026-08-19)

| 순서 | 왜 |
|---|---|
| 갤러리 사진 | 구현이 가장 가볍고 **권한이 필요 없다**(§3-3). 러닝 직후 찍어둔 사진이 이미 있는 경우가 가장 흔하다 |
| 갤러리 영상 | 소재 종류만 늘어난다. 선택 UI는 위와 같다 |
| 촬영 사진 | **여기서부터 카메라 권한**과 촬영 UI가 새로 필요하다 |
| 촬영 영상 | 위에 녹화 제어가 더해진다 |

**갤러리를 먼저 두는 이유**는 구현 무게 때문만이 아니다. 사진이나 영상 위에서 드로잉이 어떻게 얹히는지를 **가장 빨리, 가장 다양한 소재로 볼 수 있는 경로**이기 때문이다. 그 경험이 "우와"를 만드는 자리다(PRD §6).

## 2. 기본 이미지

### 2-1. 규격

| 항목 | 값 |
|---|---|
| 개수 | **3장** (PRD의 "2~3개" 중 위쪽) |
| 비율 | 9:16 |
| 해상도 | 1080 × 1920 이상 |
| 형식 | 정지 이미지. 기본 이미지에는 영상을 두지 않는다 |

**앱에 함께 넣어 배포한다.** 서버에서 내려받지 않는다. 오프라인에서도 결과물이 나와야 하고, MVP에 서버가 없다.

### 2-2. 어떤 사진을 넣을지는 이 문서가 정하지 않는다

**파일만 갈아끼우면 되는 영역이라 구현 이후에도 얼마든지 바꿀 수 있다.** 그래서 규격만 정하고 내용은 열어둔다. (2026-08-19 phs00 판단)

후보는 **직접 촬영**과 **AI 생성**이다. 어느 쪽이든 아래 둘은 확인해야 한다.

- **저작권과 상업 이용.** 앱스토어 심사에 걸리는 항목이다. 직접 촬영이면 깨끗하고, 그 외에는 출처와 라이선스를 기록해둔다
- **경로 오버레이가 죽지 않는가.** 예쁜 사진과 배경으로 좋은 사진은 다르다. 화면이 복잡하거나 밝은 영역이 흩어져 있으면 선이 묻힌다

> **PRD P2와 충돌하지 않는다.** P2("AI 이미지 생성은 현 단계에서 도입하지 않는다")는 **제품 기능으로서** 앱이 사용자에게 이미지를 만들어 주는 것을 말한다. 우리가 에셋 몇 장을 만들며 도구를 쓰는 것은 다른 층위다. 사용자에게 노출되는 것은 완성된 이미지 파일뿐이다.

`[확인 필요]` 기본 이미지 3장의 실제 소재와 출처. phs00 담당.

## 3. 사용자 소재 고르기

### 3-1. 갤러리에서 고르기

- 사진과 영상을 한 화면에서 고른다. 종류별로 화면을 나누지 않는다
- **최근 항목이 먼저 보인다.** 러닝 직후에 찍은 것을 쓰는 경우가 가장 흔하다

### 3-2. 그 자리에서 찍기

- 앱 안에서 카메라를 띄워 사진 또는 영상을 찍는다
- **찍은 소재를 갤러리에 남기지 않는다.** 그 결과물을 만드는 데만 쓰인다 (2026-08-19)

갤러리에 남기려면 **사진 쓰기 권한이 하나 더 필요하다.** 읽기 권한과 별개라 권한 요청이 늘어난다. 인앱 카메라를 쓰는 앱들도 대체로 안 남기는 쪽이 기본이고, 저장은 별도 설정이나 명시적인 저장 버튼으로 둔다.

> **결과물은 별개다.** 완성된 클립을 기기에 저장하는 경로는 내보내기·공유·저장 FRD에 있다. 여기서 말하는 것은 배경으로 쓴 원본 소재다.

### 3-3. 권한

**동작마다 필요한 권한이 다르다. 하나로 묶어 생각하면 안 된다.**

| 동작 | 권한 |
|---|---|
| **갤러리에서 고르기** | **없음.** `PHPickerViewController`를 쓰는 경우 |
| 그 자리에서 찍기 | 카메라 |
| (참고) 찍은 소재를 갤러리에 저장 | 사진 **쓰기**. §3-2에서 하지 않기로 했다 |

`PHPickerViewController`는 **앱 밖에서 도는 선택 화면**이라 사용자가 고른 항목만 앱으로 넘어온다. 앱이 갤러리 전체를 보는 것이 아니므로 권한 요청 자체가 없다. 옛 API(`UIImagePickerController`의 사진 라이브러리 소스, `PHPhotoLibrary` 직접 접근)를 쓰면 읽기 권한이 필요하다.

**이것이 §1-1에서 갤러리 고르기를 먼저 붙이기로 한 이유를 하나 더 만든다.** 권한을 하나도 묻지 않고 사용자 소재를 받을 수 있는 유일한 경로다.

`[확인 필요]` **기술 스택에 따라 달라질 수 있다.** RN이면 PHPicker를 감싼 라이브러리를 쓰는지, 옛 API로 떨어지는지 확인해야 한다. 권한이 하나 늘면 스토어 제출물에 usage description 문구가 하나 더 필요하다.

**거부했을 때의 동작은 공통 규칙 FRD에서 정한다.** 다만 원칙 하나는 여기서 못박는다.

> **배경 권한을 거부해도 제품은 성립한다.** 기본 이미지가 있기 때문이다. 권한 거부가 막다른 길이 되면 안 된다.

## 4. 사진 처리

### 4-1. 9:16에 맞추기

| 항목 | 규칙 |
|---|---|
| 초기 상태 | **화면을 가득 채운다.** 짧은 축을 기준으로 확대하고 넘치는 부분은 잘라낸다 |
| 사용자 조정 | 확대·축소와 이동으로 어느 부분을 쓸지 고른다 |
| 여백 | **남기지 않는다.** 배경에 빈 자리가 생기면 결과물이 미완성으로 보인다 |
| 해상도 | **하한을 두지 않는다** |

가로로 찍은 사진은 크게 잘린다. 그래도 여백을 남기는 것보다는 낫다고 본다.

**해상도가 낮은 사진을 막지 않는 이유**는, 뭉개지는지 아닌지를 **사용자가 미리보기에서 직접 보고 판단할 수 있기 때문**이다. 우리가 대신 막으면 쓸 만한 사진까지 거부당한다. (2026-08-19)

## 5. 영상 처리

### 5-1. 길이

클립 길이는 **12초 고정**이다([경로 렌더링](route-rendering.md) §5-1). 배경 영상이 그보다 짧거나 길 수 있다.

| 경우 | 처리 |
|---|---|
| 영상이 12초보다 **짧다** | **반복 재생**(기본). 끝까지 재생한 뒤 처음으로 돌아간다 |
| 영상이 12초보다 **길다** | **앞에서부터 12초**를 쓴다. 어느 구간을 쓸지 고르는 것은 로드맵이다 |

**클립 길이가 배경에 휘둘리지 않게 한다.** 배경이 3초든 3분이든 결과물은 12초다.

#### 마지막 프레임 정지 (선택)

**반복 재생 대신 마지막 프레임에서 멈추는 것을 고를 수 있다.** (2026-08-19)

- **기본은 반복 재생**이다
- 이음새가 눈에 띄는 영상에서는 정지가 낫다. 반대로 뒷부분이 정지 화면이면 어색할 수 있어 사용자가 고르게 한다
- 우선순위는 **여유 시**다. 배경 영상 자체가 여유 시 항목이므로 그 안에서 마지막에 붙는다

#### 짧은 영상은 자동으로 정지 전환

**3초 미만이면 반복 재생 대신 마지막 프레임 정지를 자동으로 적용한다.** (2026-08-19) 1초짜리를 열두 번 반복하면 깜빡임처럼 보인다. 거부당하는 경험을 만들지 않으면서 결과물도 지킨다.

#### 최대 길이는 제한하지 않는다

앞 12초만 쓰므로 긴 영상이라고 결과물이 나빠지지 않는다. 다만 불러오는 데 시간이 걸릴 수 있다. §6 참고.

#### 구간 고르기는 로드맵

**MVP에서는 앞에서부터 12초를 쓴다.** 나중에 **사용자가 영상의 어느 구간을 쓸지 직접 잘라 고를 수 있게 한다.** (2026-08-19) 배경으로 쓰고 싶은 장면이 영상 중간에 있는 경우가 흔하므로 값어치가 있다. 다만 트리밍 UI가 따로 필요해 MVP 일정에는 넣지 않는다.

### 5-2. 소리

**배경 영상의 소리를 넣지 않는다. 결과물은 무음이다.** (2026-08-19)

- **올리는 자리에서 소리가 필요 없다.** 스토리는 소리 없이 보는 경우가 많고, 릴스로 올릴 때는 인스타가 제공하는 음악을 얹는 것이 일반적이다. 우리가 소리를 실어 보내면 오히려 그 위에 음악을 얹기 어려워진다
- 러닝 중 찍은 영상은 바람 소리가 대부분이라 그대로 실으면 결과물이 나빠진다
- 소리를 다루려면 볼륨 조절과 미리듣기가 따라붙어 범위가 커진다

## 6. 불러오기와 대기

고른 소재가 곧바로 준비되지 않을 수 있다. **대기를 어떻게 보여줄지는 규칙으로 정한다.**

### 6-1. 왜 필요한가

두 경우다.

| 경우 | 얼마나 |
|---|---|
| 큰 영상을 읽고 잘라내기 | 대체로 짧다 |
| **원본이 iCloud에만 있어 내려받아야 함** | **네트워크에 따라 수십 초까지** |

두 번째가 실제로 더 자주 걸린다. 아이폰의 **"iPhone 저장 공간 최적화"** 를 켜두면(iCloud 사진 사용 시) 기기에는 가벼운 버전만 남고 원본은 iCloud에 있다. 저장 공간이 빠듯해질 때 오래되고 큰 항목부터 내보내진다.

- **러닝 직후 찍은 사진을 바로 쓰는 주 흐름에서는 드물다.** 최근 항목은 대개 기기에 원본이 있다
- **예전에 찍어둔 영상을 고르거나 저장 공간이 빠듯한 기기에서 걸린다.** iCloud 사진을 안 쓰면 해당 없다

**드물지만 걸리면 크게 걸린다.** 그래서 예외가 아니라 정상 경로로 다룬다.

### 6-2. 규칙

| 항목 | 값 |
|---|---|
| 대기 표시를 띄우는 임계값 | **0.3초** |
| 띄웠을 때 최소 유지 시간 | **0.5초** |
| 2초를 넘기면 | **진행률과 취소를 함께 보여준다** |

**2초 지점은 추가가 아니라 교체다.** 같은 자리에서 대기 표시가 진행률과 취소로 바뀐다. 두 개가 함께 뜨지 않는다.

시간대별로 사용자가 보는 것은 이렇다.

| 실제 소요 | 보이는 것 |
|---|---|
| 0.2초 | **아무것도 안 보인다.** 임계값 전에 끝났다 |
| 0.4초 | 0.3초에 표시 → **0.8초까지 유지**(최소 0.5초를 채운다). 실제보다 0.4초 더 기다린다 |
| 3초 | 0.3초에 표시 → 2초에 진행률·취소로 바뀜 → 끝나면 바로 사라진다 |

**두 번째 줄이 이 규칙의 대가다.** 깜빡임을 없애는 대신 애매한 구간에서 조금 더 기다리게 된다. 번쩍이는 것보다 낫다고 본다.

**바로 띄우지 않는 이유**는 빨리 끝나는 경우에 표시가 번쩍하고 사라지기 때문이다. 그게 아무것도 안 보여주는 것보다 나쁘다. 최소 유지 시간도 같은 이유다. 임계값을 막 넘겨 띄웠는데 곧바로 끝나면 역시 깜빡인다.

**2초를 넘기면 취소를 주는 이유**는 iCloud 내려받기가 얼마나 걸릴지 모르기 때문이다. 다른 소재를 고르고 싶은 사용자가 갇히면 안 된다. **취소하면 배경 선택 화면으로 돌아오고 앞선 선택은 유지된다.**

`[확인 필요]` 세 수치는 실제 기기에서 iCloud 소재를 불러보며 조정한다. 특히 2초가 적절한지는 실측이 필요하다.

## 7. 실패 경로

| 경우 | 동작 |
|---|---|
| 사진·영상 불러오기 실패 | 배경 선택 화면에 머무르고 알린다. 결과물 제작이 중단되지 않는다 |
| iCloud 내려받기 실패 (네트워크 없음 등) | 같다. 다른 소재를 고르거나 기본 이미지로 갈 수 있다 |
| 지원하지 않는 형식 | 고르는 시점에 걸러낸다. 고른 뒤에 실패를 알리지 않는다 |
| 권한 거부 | 기본 이미지로 계속할 수 있다(§3-3) |
