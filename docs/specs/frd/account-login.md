# Apple·카카오 로그인과 회원가입

- 2026-11-17 지민이 정한 추천안을 담은 초안에서 출발했다. 2026-11-20 지민이 승인해 `approved`로 올렸다. 팀 검토는 구현 PR에서 한다
- 근거: [로그인 PRD](../prd/account-login.md)
- 화면 시안: [계정 화면 시안](../../ideation/jminkkk/2026-11-20-account-login-screens.html) (2026-11-20). 문구와 상태는 이 FRD가 정본이다

## 1. 사용자가 확인할 핵심

| 결정 | 내용 |
|---|---|
| 로그인 | 선택 (잠정). 로그인하지 않아도 지금의 기능을 모두 씀. 필수 여부는 연동 후 결정([안건](../../ideation/jminkkk/2026-11-17-meeting-agenda.md) §2 로그인 필수 여부) |
| 로그인 수단 | Apple, 카카오 |
| 입구 | 크루 진입, 홈의 "내 계정" 화면 |
| 받는 정보 | 로그인 식별자, 닉네임. **이메일은 받지 않음** |
| 닉네임 | 2~10자, 중복 불가, 나중에 변경 가능 |
| 백업 대상 | **Runary 측정 기록만**. 건강 앱 기록, 편집 상태, 결과물(영상)은 올리지 않음 |
| 복원 | 같은 계정으로 로그인하면 내려받음. 기기에 이미 있는 기록은 건너뜀 |
| 탈퇴 | 서버의 계정과 기록 삭제. **기기 기록은 유지** |

건강 앱 기록을 크루원에게 보여 줄지는 회의에서 정함([안건](../../ideation/jminkkk/2026-11-17-meeting-agenda.md))

## 2. 로그인 입구

### 2-1. 내 계정 화면

- 홈(보관함) 상단 제품명 오른쪽에 "내 계정" 버튼
  - 사람 아이콘과 "내 계정" 글자를 함께 넣은 외곽선 버튼. 아이콘만 두면 로그인 입구인 줄 알기 어렵다
  - 홈에서 주황은 "이어서 만들기"가 쓰고 있어서 이 버튼에는 쓰지 않는다
  - 터치 높이 44pt 이상
- 로그인 전
  - 문구: "로그인하면 러닝 기록이 서버에 백업돼요. 앱을 지웠다 다시 깔아도 러닝 기록이 돌아와요."
    - "기록"만 쓰면 만든 영상까지 돌아온다고 읽힐 수 있어서 "러닝 기록"으로 쓴다. 영상과 편집 상태는 백업하지 않는다(§5-5 올리는 것)
  - 버튼: "로그인". 누르면 로그인 수단 선택(§3-1 로그인 수단 선택)으로 이동
- 로그인 후

| 항목 | 내용 |
|---|---|
| 닉네임 | 표시, 변경 가능(§4) |
| 로그인 수단 | Apple 또는 카카오 |
| 백업 상태 | 마지막 백업 시각(예: `11.20 13:02`), 아직 올라가지 않은 러닝 기록 수(§5-4 실패와 재시도) |
| 로그아웃 | §6 |
| 탈퇴 | §7. 다른 항목보다 덜 눈에 띄게 아래쪽에 둠 |

- 올라가지 않은 기록이 있으면 "백업되지 않은 러닝 기록 2건"을 보여 주고, 그 아래에 "인터넷에 연결되면 자동으로 백업해요."를 쓴다
  - "백업 대기"는 사용자가 무엇을 기다리는지 알기 어려워서 쓰지 않는다. §6 로그아웃의 경고 문구와 같은 말을 쓴다
  - 0건이면 두 줄 모두 숨긴다

### 2-2. 크루 진입

- 로그인하지 않은 사용자가 크루 기능에 들어가면 로그인 수단 선택(§3-1)을 띄움
- 문구: "크루는 로그인한 뒤에 쓸 수 있어요."
- 가입이나 로그인을 마치면 원래 가려던 크루 화면으로 이동
- 취소하면 크루에 들어가기 전 화면으로 돌아감

## 3. 가입과 로그인

### 3-1. 로그인 수단 선택

- 버튼 둘: "Apple로 계속하기", "카카오로 계속하기"
  - 두 버튼은 같은 크기로 나란히 또는 위아래로 둠
  - Apple 버튼은 Apple이 제공하는 기본 버튼을 씀
- 아래에 [서비스 이용약관](public-policy-links.md)과 개인정보 처리방침 링크
- 가입과 로그인을 따로 나누지 않음. 같은 버튼으로 시작하고 서버에 계정이 있는지로 갈림

### 3-2. 흐름

| 상황 | 동작 |
|---|---|
| 서버에 계정이 없음 | 닉네임 입력(§4) → 가입 완료 → 첫 백업(§5-1) |
| 서버에 계정이 있음 | 바로 로그인 → 복원(§5-3) |
| 가입 도중 닉네임을 입력하지 않고 앱을 닫음 | 가입 미완료. 다음 로그인 때 닉네임 입력부터 다시 |
| Apple 또는 카카오 화면에서 사용자가 취소 | 오류 안내 없이 로그인 수단 선택으로 돌아감 |
| 네트워크 없음, 서버 오류 | "로그인하지 못했어요. 다시 시도해 주세요." + 다시 시도 |

### 3-3. 받는 정보

- Apple: 이름과 이메일을 요청하지 않음. 로그인 식별자만 씀
- 카카오: 동의항목을 하나도 설정하지 않음. 회원번호만 씀
  - 회원번호는 동의 없이 기본 제공. 동의 화면에는 앱 연결 안내만 나옴([카카오 로그인 활용 문서](https://developers.kakao.com/docs/latest/ko/kakaologin/utilize))
  - 닉네임은 카카오 프로필에서 가져오지 않고 직접 입력받음

## 4. 닉네임

- 수치는 출발점. 현수의 크루 화면 디자인과 맞춰 조정함

| 규칙 | 내용 |
|---|---|
| 길이 | 2~10자 |
| 허용 문자 | 한글, 영문 소문자, 숫자. 공백과 특수문자는 불가 |
| 앞뒤 공백 | 자동으로 지움 |
| 영문 대문자 | 쓸 수 없음. 입력하면 바로 소문자로 바꿈 |
| 중복 | 불가 |
| 변경 | 내 계정 화면에서 언제든 가능. 같은 규칙 적용 |

- 영문은 소문자만 쓴다 (2026-11-20 확정)
  - `runner`와 `Runner`가 다른 사람인지 같은 사람인지 헷갈리지 않게 하기 위해서다
  - 막지 않고 바꿔 주는 이유: iOS 키보드는 첫 글자를 대문자로 올린다. 막으면 대부분의 사용자가 첫 글자부터 오류를 본다

- 가입 때 닉네임 화면의 문구
  - 제목: "닉네임을 정해 주세요"
  - 설명: "크루에서 다른 사람에게 보이는 이름이에요. 나중에 내 계정에서 바꿀 수 있어요."
  - 입력 칸 아래 도움말: "2~10자, 한글·영문 소문자·숫자"
  - 버튼: "완료"
- 가입 중 닉네임 화면의 왼쪽 위에 닫기 버튼을 둔다 (2026-11-20 확정)
  - 누르면 가입 미완료로 남기고, 로그인하지 않은 상태로 로그인하기 전 화면에 돌아간다
  - 앱을 닫았을 때와 같은 결과다. 다음 로그인 때 닉네임 입력부터 다시 한다(§3-2 흐름)
  - 로그인은 선택이라, 앱을 끄지 않고도 가입을 그만둘 수 있어야 한다
- 내 계정에서 바꿀 때는 같은 입력 칸과 도움말을 쓴다. 지금 닉네임과 같으면 완료를 막는다
- 규칙에 맞지 않으면 입력 칸 아래에 이유를 보여 주고 완료 버튼을 막음
  - 길이: "2~10자로 입력해 주세요"
  - 허용 문자: "한글, 영문 소문자, 숫자만 쓸 수 있어요"
  - 중복: "이미 쓰고 있는 닉네임이에요"
- 중복 확인은 완료 버튼을 누를 때 서버에서 함

## 5. 백업과 복원

### 5-1. 첫 가입 시 일괄 업로드

- 가입을 마치면 기기에 있는 Runary 측정 기록을 서버로 올림
- **아직 어떤 계정에도 올라가지 않은 기록만** 올림
  - 같은 기기에서 다른 계정으로 로그인했다가 로그아웃한 경우, 그 계정의 기록이 새 계정으로 섞이지 않게 하기 위함
- 진행 표시: "기록 백업 중 3/12"
- 업로드 중에도 앱의 다른 기능을 막지 않음
- 앱이 닫히면 다음 실행 때 남은 것부터 이어서 올림

### 5-2. 이후 새 기록

- 측정을 마치고 기록이 기기에 저장된 직후 올림
- 백업 실패가 기기 저장, 편집, 영상 만들기를 막지 않음
- 기기에서 기록을 지우면 서버에서도 지움

### 5-3. 복원

- 서버에 계정이 있는 상태로 로그인하면 서버의 기록을 내려받음
- 기록 ID가 같은 기록이 이미 기기에 있으면 건너뜀
- 진행 표시: "기록 불러오는 중 3/12"

### 5-4. 실패와 재시도

- 올리지 못한 기록은 대기 목록에 둠
- 다음 앱 실행, 네트워크 복구 때 자동으로 다시 올림
- 같은 기록을 여러 번 올려도 서버에 하나만 남음
- 내 계정 화면에 "백업되지 않은 러닝 기록 2건"처럼 보여 줌(§2-1 내 계정 화면)

### 5-5. 올리는 것

| 올림 | 올리지 않음 |
|---|---|
| 기록 원본: 좌표(정확도 포함), 시각, 거리, 시간, 페이스, 심박, 걸음 수, 케이던스 | 진단 정보: 배터리, GPS 공백, 센서 지연, 워치 연결 상태, 오류 |
| 기록 ID, 측정 시작·종료 시각 | 편집 상태, 결과물(영상), 배경 사진 |
| | 건강 앱에서 불러온 기록 |

- 진단 정보는 측정이 잘 됐는지 팀이 확인하려고 기기에 남기는 값. 기록 복원에 필요 없고 수집 항목을 줄이기 위해 올리지 않음([내부 측정 PRD](../prd/internal-run-tracking.md) §6 보관과 삭제)

## 6. 로그아웃

- 내 계정 화면에서 "로그아웃" → 확인
- 확인 창 제목: "로그아웃할까요?". 버튼은 "취소"와 "로그아웃"
- 백업 대기 중인 기록이 있으면 확인 창에 알림
  - "아직 백업되지 않은 러닝 기록 2건이 있어요. 로그아웃하면 백업되지 않아요."
- 확인 창에 "이 기기의 기록은 그대로 남아요."를 함께 쓴다
- 로그아웃하면
  - 서버와의 연결과 대기 중인 업로드를 멈춤
  - 기기 기록은 그대로 둠
  - 홈으로 돌아감

## 7. 탈퇴

### 7-1. 흐름

- 내 계정 화면에서 "탈퇴" → 확인 화면
- 확인 화면에 알릴 것
  - 서버에 백업한 기록과 계정이 지워지고 되돌릴 수 없음
  - 기기에 있는 기록은 남음
- 확인 화면의 문구
  - 제목: "탈퇴하기 전에 확인해 주세요"
  - 지워지는 것: "서버에 백업한 기록과 계정이 지워져요" / "닉네임도 함께 지워지고, 되돌릴 수 없어요."
  - 남는 것: "이 기기에 있는 기록은 남아요" / "로그인하지 않은 상태로 지금처럼 쓸 수 있어요."
  - 버튼: "탈퇴하기", "취소"
- 확인하면 아래를 처리하고 로그아웃 상태로 홈에 돌아감

### 7-2. 처리

| 대상 | 처리 | 근거 |
|---|---|---|
| 서버의 계정, 닉네임, 백업 기록 | 삭제 | [로그인 PRD](../prd/account-login.md) §5 로그아웃과 탈퇴 |
| Apple로 가입한 계정 | Apple 토큰 해지 요청 | [Apple 토큰 해지 문서](https://developer.apple.com/documentation/sign_in_with_apple/revoke_tokens) |
| 카카오로 가입한 계정 | 카카오 "연결 끊기" 요청 | [카카오 로그인 REST API 문서](https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api) |
| 기기 기록 | 유지 | |

- 네트워크가 없으면 탈퇴를 진행하지 않고 안내: "인터넷에 연결한 뒤 다시 시도해 주세요."
- 탈퇴한 뒤 같은 Apple·카카오 계정으로 다시 로그인하면 새 계정으로 가입함
- 크루에 가입한 상태로 탈퇴할 때의 처리는 크루 FRD에서 정함

## 8. 네트워크가 없을 때

- 로그인, 가입, 닉네임 변경, 탈퇴: 네트워크가 필요함. 안내 후 다시 시도
- 백업: 대기 목록에 두고 나중에 올림(§5-4)
- 그 외 기능: 지금처럼 오프라인에서 모두 동작([공통 규칙](common-rules.md) §8 오프라인)

## 9. 검증

- 로그인하지 않은 상태에서 기록 선택, 측정, 편집, 영상 만들기가 지금과 같음
- Apple, 카카오 각각으로 가입하고 닉네임을 정할 수 있음
- 닉네임 규칙(길이, 중복, 허용 문자)이 맞지 않으면 완료가 막힘
- 가입하면 기존 Runary 측정 기록이 서버에 올라감
- 비행기 모드에서 측정한 기록이 네트워크 복구 뒤 올라감
- 앱을 지웠다 다시 깔고 같은 계정으로 로그인하면 기록이 돌아옴. 중복이 생기지 않음
- 로그아웃 뒤 다른 계정으로 가입해도 이전 계정의 기록이 섞이지 않음
- 탈퇴하면 서버의 계정과 기록이 지워지고, 기기 기록은 남음
