# 샘플 기록으로 Runary 체험하기

2026-10-12 사용자에게 FRD를 제시한 뒤 경로 후보와 정식 앱 포함 여부를 설명했다. 사용자가 하트를 선택하고 로컬 미러링에서 먼저 확인하도록 요청했다. 이 범위로 구현하며 TestFlight 업로드는 로컬 확인 뒤에 진행한다.

## 왜 필요한가

실외 러닝 경로가 건강 앱에 없는 사용자와 심사자는 현재 앱의 편집·영상 생성 기능을 직접 확인하기 어렵다. 첫 화면의 샘플 애니메이션은 감상만 가능하다. 가상의 기록으로 실제 결과물을 만들어 볼 수 있게 한다.

## 제공 범위

- 모든 사용자에게 하트 모양의 샘플 기록 한 건을 제공한다. 첫 실행 안내, 홈, 기록 선택에서 진입한다.
- 건강 권한과 실제 러닝 기록 없이 배경 선택·편집·영상 생성·보관함 저장·기기 저장·공유를 사용한다.
- 샘플 기록으로 만든다는 사실을 알리고 실제 건강 기록과 구분한다.
- 건강 앱에는 샘플을 쓰지 않는다. 샘플의 장소를 찾기 위한 외부 위치 조회도 하지 않는다.
- 실제 러닝 기록 불러오기와 기존 결과물의 편집·보관 동작을 유지한다.

## 제출 범위

[10/6 정식 등재 결정](../../decisions/2026-10-06-second-sprint-app-store.md)의 1차 측정 제외 범위를 유지한다. 샘플 기능을 포함한 새 일반 `production` 빌드를 TestFlight에서 검증한다. 사용 가능한 빌드 번호와 개인정보 자료를 확정한 뒤 정식 심사 자료와 맞춘다.

## 성공 기준

건강 기록이 없거나 권한을 허용하지 않은 기기에서 샘플로 편집하고 실제 MP4를 생성·저장할 수 있다. 앱 재실행 뒤 샘플 초안을 이어 만들고 결과물을 다시 편집할 수 있다. 기존 건강 기록은 변경되지 않는다. 일반 제출 빌드에 측정 화면과 워치 진단이 노출되지 않는다.
