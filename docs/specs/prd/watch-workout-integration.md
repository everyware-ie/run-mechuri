# 일반 러닝과 워치 운동 세션 연결

## 1. 목적

2026-10-26 사용자는 짧은 야외 테스트에서 측정이 잘 되는 것 같다고 알렸다. 이어 워치 연동 완성, 화면 복귀 검증, 정식 출시 준비 순서로 진행하는 데 동의했다. 기존 5.41km 실측과 이번 사용자 확인을 유지하고, 새로 바뀌는 워치 동작을 집중 검증한다.

현재 제품은 저장된 건강 심박을 읽어 전달하지만 일반 러닝에 워치 운동 세션이 없다. Runary만 사용하는 러닝에서 연속 심박과 운동 중 화면 표시를 제공하려면 이 부분을 연결해야 한다.

## 2. 제안 범위

아이폰이 거리·경로·시간과 저장 기록의 기준이다. 워치는 같은 러닝에 연결한 운동 세션으로 심박 수집을 돕고 지표와 제어를 제공한다. 워치 단독 GPS 측정은 추가하지 않는다.

첫 연결에서 다른 워치 운동이 종료될 수 있음을 알리고 사용자가 Runary 워치 연동을 켠다. 이후에는 일반 러닝 시작에 연결한다. 워치 연동을 끄면 기존 건강 심박 읽기와 아이폰 측정은 유지한다. 매 러닝마다 심박 방식 선택을 요구하지 않는다.

2026-10-26 사용자가 Runary 측정 기록을 Apple 피트니스에서도 확인하고 싶다고 요청해 건강 앱 저장을 범위에 추가했다. 완료한 실제 러닝을 Runary에 먼저 보관하고, 사용자가 쓰기를 허용하면 HealthKit에 Runary 출처의 러닝 운동으로 저장한다. 워치 없이 아이폰만으로 측정한 기록도 대상이다.\
샘플 체험과 다른 앱에서 가져온 운동은 다시 쓰지 않는다. 기존 기록을 일괄 전송하지 않고, 이번 기능을 켠 뒤 완료한 기록부터 자동 저장한다.

건강 저장 실패가 Runary 기록 저장이나 편집을 막아서는 안 된다. 같은 러닝을 재시도하거나 건강에서 다시 읽어도 중복 운동과 중복 선택 항목을 만들지 않는다.\
건강과 피트니스의 운동 목록에서 Runary 기록을 확인하는 것을 완료 기준에 추가한다. 칼로리와 활동 링은 검증하지 않은 값이나 반영 효과를 약속하지 않는다. [Apple의 타사 운동 앱 연동 안내](https://support.apple.com/guide/iphone/sync-a-third-party-workout-app-iph392b962da/ios)를 근거로 한다.

## 3. 성공 기준

별도 실험 버튼 없이 시작·일시정지·재개·종료가 같은 러닝에 연결돼야 한다. 권한 거부·미착용·연결 끊김에서도 아이폰 기록을 보존한다. 오래된 심박과 거리·시간을 최신값처럼 보여주지 않는다.

손목을 들었을 때 측정 화면이 나타나는 것은 실제 워치에서 검증한다. 앱 목록이나 시계 화면으로 명시적으로 이동한 경우도 별도 확인하며, 아이콘 표시만으로 자동 복귀를 통과 처리하지 않는다. OS가 허용하지 않는 동작을 강제하는 방식으로 대체하지 않는다.

## 4. 기존 정책과 승인 범위

2026-10-26 사용자가 워치 운동 세션 연동과 건강 저장 구현을 승인했다. [내부 측정 PRD](internal-run-tracking.md)의 건강 읽기·다른 운동 비제어 정책과 다른 점은 자체 운동 세션과 완료 기록의 건강 저장을 허용한다는 것이다. [기존 결정](../../decisions/2026-10-06-second-sprint-app-store.md)의 정정 이력은 보존한다.

사용자는 [FRD](../frd/watch-workout-integration.md)를 확인하고 1·2번 구현 범위를 승인했다. 공개 빌드 전환과 개인정보 안내는 워치 검증 후 진행한다.
