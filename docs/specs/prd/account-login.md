# Apple·카카오 로그인과 회원가입

## 1. 왜 필요한가

- **크루 기능의 선행 조건**
  - 3차 스프린트(11/10 ~ 12/8)에서 크루 가입, 크루원끼리 경로 보기 개발
  - 다른 사람의 기록을 보려면 기록의 주인 식별 필요 → 계정 필요
  - 근거: [3차 스프린트 결정](../../decisions/2026-11-10-third-sprint-crew-diary.md)
- **앱 삭제 시 데이터 유실**
  - 현재 기록은 기기에만 보관. 앱 재설치 시 Runary 측정 기록 전부 삭제
  - 11/10 회의에서 지응이 실제로 겪음([회의 종합](../../meetings/2026-11-10/synthesis.md) §1 지난주 약속과 QA)
  - 로그인 사용자의 기록을 서버에 보관해 함께 해결

## 2. 범위

포함

- Apple 로그인, 카카오 로그인
- 첫 로그인 시 회원가입과 닉네임 입력
- 로그아웃, 앱 내 탈퇴
- 서버 백업, 재로그인 시 복원

제외

- Google 로그인: 회의에서 카카오가 안 될 때의 대안으로 정했던 것. 카카오가 사업자 없이 가능해서 넣지 않음([결정문 2026-11-17 개정](../../decisions/2026-11-10-third-sprint-crew-diary.md))
- 크루 가입, 크루원 경로 보기: 크루 PRD에서 다룸
- 서버 선정: Spring Boot(Java 21)로 정함. 구현 단계에서 정하기로 했던 것(2026-11-20, [구현 노트](../../product/features/account-login.md))
- 이메일·비밀번호 가입

## 3. 언제 로그인을 묻나

- **로그인은 선택 (잠정)**
  - 필수로 할지는 Apple·카카오 연동을 끝낸 뒤 결정([안건](../../ideation/jminkkk/2026-11-17-meeting-agenda.md) §2 로그인 필수 여부). 연동 코드는 어느 쪽이든 같고 입구만 달라짐
  - 비로그인 상태에서도 기록 선택, 측정, 편집, 영상 생성 모두 가능
  - 기존 사용자가 업데이트 후 막히지 않게 하기 위함
- **로그인 권유 지점 두 곳**

| 지점 | 이유 |
|---|---|
| 크루 기능 진입 시 | 계정 없이 크루 사용 불가 |
| 홈의 "내 계정" 화면 | 크루를 쓰지 않는 사용자도 백업 가능해야 함 |

- 내 계정 화면에 로그인, 백업 상태, 로그아웃, 탈퇴를 모음([FRD](../frd/account-login.md) §2 로그인 입구)

## 4. 계정에 무엇이 남나

### 가입 시 수집 항목

| 항목 | 출처 | 용도 |
|---|---|---|
| 로그인 식별자 | Apple 또는 카카오 | 동일인 확인 |
| 닉네임 | 사용자 직접 입력 | 크루 화면에서 서로를 부르는 이름 |

- **이메일은 받지 않음** (2026-11-19 확정)
  - 쓸 곳이 없음. 동일인 확인은 식별자로 충분하고, 쓰지 않는 개인정보는 받지 않음
  - 나중에 필요해지면 앱 안에서 직접 입력받음. Apple은 가입 뒤에 이메일 범위를 늘릴 수 없어서([Apple 포럼 답변](https://developer.apple.com/forums/thread/678930)) 로그인 수단으로 받는 방법은 기존 사용자에게 쓸 수 없음
  - 받기로 하면 수집 목적, Apple 중계 이메일 발신 도메인 등록, 카카오 비즈 앱 전환, 처리방침과 App Store 개인정보 표시 개정이 따라옴
- 닉네임은 가입 시 필수 입력. 2~10자, 중복 불가, 변경 가능([FRD](../frd/account-login.md) §4 닉네임)
- 닉네임 수치는 크루 화면 디자인(현수)과 맞춰 조정

### 기록 백업

- **첫 가입 시 1회 일괄 업로드**: 기존 사용자의 기기 기록 보존 목적
- **가입 이후 새 기록은 생성 시마다 업로드**
- **재로그인 시 서버 기록 복원**: 앱 재설치, 기기 변경 상황
- **백업 실패가 기기 기록과 편집을 막지 않음**: 실패한 기록은 이후 재시도

백업 대상

| 대상 | 업로드 | 이유 |
|---|---|---|
| Runary 측정 기록 | 함 | 앱 삭제 시 사라지는 데이터가 바로 이것 |
| 건강 앱에서 불러온 기록 | 안 함 | 건강 앱에 원본이 남아 재조회 가능. 크루원에게 보여 줄지는 회의에서 결정([안건](../../ideation/jminkkk/2026-11-17-meeting-agenda.md)) |
| 편집 상태(배경, 프리셋, 러닝 데이터 등) | 안 함 | 범위를 가장 작게 시작 |
| 결과물(영상) | 안 함 | 용량이 커서 저장 비용 발생 |

## 5. 로그아웃과 탈퇴

- **로그아웃**: 서버 연결만 해제. 기기 기록은 유지
- **앱 내 탈퇴 필수**
  - App Store가 계정 생성이 가능한 앱에 앱 내 계정 삭제 기능을 요구함
  - 근거: [App Review Guidelines 5.1.1(v)](https://developer.apple.com/app-store/review/guidelines/#data-collection-and-storage), [계정 삭제 안내](https://developer.apple.com/support/offering-account-deletion-in-your-app/)
- **탈퇴 시 서버의 계정 정보와 기록 삭제**
- 카카오로 가입한 사용자는 탈퇴 시 카카오 "연결 끊기"도 호출
- 탈퇴해도 기기 기록은 유지. 탈퇴 뒤에도 로그인 없이 앱을 계속 쓸 수 있음
- Apple로 가입한 사용자는 탈퇴 시 Apple 토큰 해지도 요청

## 6. 정책과 심사

- 현재 공개 문서는 모두 "로그인 없음, 기기에만 저장" 기준 → 로그인 도입 시 개정 필요

| 문서 | 바뀌는 것 |
|---|---|
| [개인정보 처리방침](https://runary.notion.site/privacy) | 수집 항목(식별자, 닉네임, 기록), 서버 보관, 탈퇴 시 삭제 |
| 서비스 이용약관 ([초안](../../ops/runary-terms-draft-2026-10-12.md)) | 회원가입과 탈퇴 |
| App Store 개인정보 표시 | 계정과 연결되는 수집 항목 |

- 이번 PRD에서는 개정하지 않음. 로그인 포함 빌드의 심사 제출 전에 개정
- 카카오 같은 외부 로그인을 넣으면 Apple 로그인도 함께 제공해야 함([App Review Guidelines 4.8](https://developer.apple.com/app-store/review/guidelines/#login-services)) → Apple 로그인 포함으로 충족

### 카카오 로그인 사전 조건

- **사업자 등록 불필요**: 카카오 로그인 자체는 비즈 앱이 아니어도 사용 가능
- **이메일은 비즈 앱 필요**: 사업자 없이 "개인 개발자 비즈 앱"으로 전환 가능. 이메일을 받지 않기로 해서 지금은 전환 불필요
  - 조건: 앱 소유자 카카오계정 본인인증, 카카오비즈니스 통합 서비스 약관 동의, 앱 아이콘 등록
  - 개인 개발자 비즈 앱으로 안 되는 것: 비즈니스 채널 연결, 카카오싱크. 이 PRD에서는 쓰지 않음
  - 근거: [카카오 앱 설정 문서](https://developers.kakao.com/docs/latest/ko/app-setting/app), [데브톡 안내](https://devtalk.kakao.com/t/how-can-i-switch-to-a-biz-app-if-i-do-not-have-any-business-registration-number/71983)
- **동의항목은 하나도 설정하지 않음** → 비즈 앱 전환, 검수 모두 불필요
  - 카카오 사용자 정보를 쓰지 않는 서비스는 동의항목을 설정하지 않아도 됨. 이때 동의 화면에는 앱 연결 안내만 나옴
  - 회원번호는 사용자 동의 없이 기본 제공
  - 근거: [카카오 로그인 활용 문서](https://developers.kakao.com/docs/latest/ko/kakaologin/utilize)

## 7. 기존 정책과의 관계

- 이 PRD가 기존 PRD 두 곳의 정책을 바꿈

| 문서 | 현재 내용 | 변경 |
|---|---|---|
| [내부 측정 PRD](internal-run-tracking.md) §6 보관과 삭제 | Runary 서버로 보내지 않음. 백업·동기화 미제공 | 로그인 사용자는 서버 백업 |
| [MVP PRD](running-drawing-mvp.md) §6 사용자 플로우 | 서버를 백업 용도로 먼저 두지 않음 | 서버를 크루와 함께 도입하고 백업에도 사용 |

- 이 PRD를 approved로 올릴 때 두 PRD도 같은 PR에서 개정

## 8. 성공 기준

- 비로그인 사용자가 지금과 똑같이 앱 사용 가능
- Apple, 카카오 중 하나로 가입하고 닉네임 설정 가능
- 가입 시 기기의 Runary 측정 기록이 서버에 업로드됨
- 앱 재설치 후 같은 계정으로 로그인하면 기록 복원
- 앱 내 탈퇴 가능. 탈퇴 시 서버의 계정과 기록 삭제
