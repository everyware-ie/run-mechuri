# Runary 크루 참여와 러닝 경로 보기

- 같은 크루의 멤버가 서로 달린 기록과 경로를 볼 수 있게 함
- 크루에 참여하면 그 뒤 완료한 러닝이 크루에 자동으로 올라가고 사용자는 보여 줄 항목만 고름(2026-11-16 현수 안)
- 경로는 Runary의 중심이므로 처음부터 끝까지 그대로 보여줌
- 처음 만난 사람과도 같은 크루에 들어갈 수 있으므로 지도로 보여 줄지와 지도 위 장소 이름을 숨길지는 공유하는 사람이 고르게 함
- 크루원이 서로의 기록을 보러 앱에 다시 들어오는지 확인함
- 11/10 회의에서 3차 스프린트 범위로 **크루 참여와 크루원 경로 보기**를 정함. 결정문에는 "크루 가입"으로 적혀 있고, 크루 쪽 문구는 2026-11-20 현수가 "참여"로 바꿈
- 11/14 답변에 따라 자동 공유와 두 가지 경로 보기를 초안에 반영함
- 11/16 현수가 경로는 빼거나 자르지 않기로 정함. 11/17에는 주변을 가리는 대신 지도 공유 여부와 장소 이름 숨기기를 고르게 바꿈([공유 범위와 장소 이름 숨기기](#공유-범위와-장소-이름-숨기기))
- 참여 방식은 아래 후보를 비교한 뒤 첫 버전 범위를 정함 ([3차 스프린트 결정](https://github.com/everyware-ie/run-mechuri/blob/main/docs/decisions/2026-11-10-third-sprint-crew-diary.md))

## 크루에 들어가는 방법

| 후보 | 사용자 흐름 | 시안에서 비교할 점 |
|---|---|---|
| 회원 검색 후 초대 | 크루원이 이메일이나 닉네임으로 가입된 회원을 찾아 초대함<br>상대가 초대를 확인하고 수락함 | 검색할 수 있는 정보, 동명이인 구분, 받은 초대에 들어가는 위치 |
| 친구 목록에서 초대 (친구 추가 기능 도입 시) | 크루원이 앱에서 이미 친구로 추가한 회원을 목록에서 골라 초대함<br>상대가 크루 초대를 확인하고 수락하면 참여함 | 이름이나 이메일을 다시 검색하지 않아도 되는 점, 친구 선택 화면과 받은 초대의 위치 |
| 초대 링크 | 크루원이 링크를 전달함<br>받은 사람은 크루 정보를 확인해 참여함 | 로그인 후 같은 초대로 돌아오는 흐름과 앱을 설치한 뒤 원래 링크를 다시 여는 흐름 |
| 앱에서 크루 찾기 | 참여하려는 사람이 앱에서 크루를 찾아 상세를 보고 참여함 | 모집 화면에 보여줄 정보, 크루별 즉시 참여와 승인 요청의 필요 여부 |

- 이미 친구인 사람을 초대할 때는 목록에서 바로 고를 수 있음
- 처음 연결하는 사람에게는 친구 추가 단계가 생기므로 회원 검색이나 초대 링크와 함께 비교함
- 친구 추가 기능을 도입할지 먼저 정함
  - 도입하면 크루 초대에 연결할 시점을 논의함
- 첫 버전에 어떤 참여 방식을 제공할지는 화면을 비교한 뒤 정함
- 회원가입과 로그인은 지민님 작업과 연결함

| 크루 자리 | 하단 네 번째 탭(2026-11-16 현수 제안)<br>회의에서 확인 |

| 참여 승인 | 크루 찾기로 들어올 때 바로 참여와 승인 후 참여 중 크루장이 크루마다 고름(2026-11-16 현수 안)<br>크루장은 크루 정보의 소개 탭에서 참여 방식을 바꾸고 참여 신청을 승인하거나 거절함<br>설정 화면은 따로 두지 않음<br>처리하지 않은 참여 신청이 있으면 크루장이 보는 크루 홈의 [>] 오른쪽 위에 건수 배지를 붙임<br>크루를 만든 사람이 크루장이 됨(2026-11-17 현수)<br>크루 찾기를 빼면 첫 버전에서 함께 빠짐 |
| 멤버 내보내기 | 크루장이 멤버를 내보내는 기능을 첫 버전에 넣음(2026-11-18 현수). 크루 찾기를 빼도 초대 링크는 다른 사람에게 전달될 수 있음<br>소개 탭의 멤버 줄에서 여는 멤버 명단에서 멤버마다 붙은 ⋯를 눌러 내보냄. 되돌리기 어려워 확인 창을 거침<br>크루장 넘기기도 같은 자리에 둠 |

## 첫 버전에서 빼려는 것

- 2026-11-18 현수 안. 회의에서 확인
- 아래 두 가지 모두 App Store 심사 가이드라인 1.2 때문에 뺌
- App Store 심사 가이드라인 1.2란
  - 애플이 앱스토어에 올릴 앱을 심사할 때 쓰는 기준([App Store Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)) 가운데 1절 "안전"의 "사용자가 만든 콘텐츠" 항목
  - 사용자가 만들어 다른 사용자가 볼 수 있는 글, 사진, 프로필 같은 것이 있는 앱에 적용됨
  - 그런 앱은 네 가지를 갖춰야 함
    1. 부적절한 내용이 올라오지 않게 거르는 장치
    2. 불쾌한 내용을 신고하고 제때 처리받는 수단
    3. 괴롭히는 사용자를 막는 차단
    4. 사용자가 개발자에게 연락할 수 있는 공개 연락처
  - 갖추지 않으면 심사에서 반려될 수 있음
  - Runary에서는 크루 이름과 소개, 닉네임, 공유한 러닝, 사진이 들어간 결과물이 여기에 해당할 수 있음

- 앱에서 크루 찾기(C2-D)
  - 처음 보는 사람끼리 만나는 통로라 네 가지를 첫 버전부터 갖춰야 함
  - 빼면 함께 빠지는 것: 크루 만들기의 공개 범위 단계, 참여 승인(C3), 크루장 소개 탭의 참여 방식과 참여 신청, 크루 찾기 위의 집계 한 줄
- 그린 결과물(사진을 배경으로 쓴 영상)을 크루에 공유하기와 사진을 크게 보여 주는 크루 홈(시안 C5-F)
  - 사용자가 고른 사진이 들어간 결과물을 다른 사용자에게 보여 주게 되므로 네 가지가 필요함
  - 첫 버전의 크루 공유는 기록 데이터(요약, 경로 모양, 지도)만 보냄
- 빼더라도 남는 것
  - 초대 링크로 들어온 크루원끼리도 크루 이름, 소개, 공유 기록이 보이고 링크는 다른 사람에게 전달될 수 있음
  - 그래서 나가기, 멤버 내보내기, 문의 연락처, 간단한 신고는 첫 버전에 두는 쪽으로 검토함 [확인 필요]

## 크루 만들기

- 2026-11-17 현수가 정함. 회의에서 확인
- 누구나 크루를 만들 수 있고 만든 사람이 크루장이 됨

- 들어가는 곳
  - 크루 탭이 비었을 때 "크루 만들기" 버튼을 크루 찾기보다 먼저 둠
  - 이미 크루가 있으면 크루 홈 제목의 ▾를 눌러 여는 내 크루 목록의 맨 위에 "새 크루 만들기"를 둠. 여러 크루를 허용할 때만 필요함
- 단계
  1. 크루 이름(필수, 20자까지)과 한 줄 소개(필수, 50자까지)를 적음
  2. 준비해 둔 표지 중에서 대표 이미지를 고름
  3. 공개 범위를 고름. 크루 찾기를 넣을 때만 있는 단계
  4. 내 공유 항목을 고름. 참여할 때와 같은 화면이고 버튼만 "크루 만들기"로 바뀜
  5. "크루 만들기"를 누르면 크루가 만들어지고 초대 시트가 바로 열림. 시트를 닫으면 빈 크루 홈이 보임
- 글자 수
  - 크루 홈 제목은 한 줄에 11자 안팎이 들어감. 두 줄까지 보이고 넘치면 말줄임하며 전체 이름은 소개 탭에서 보임
  - 한 줄 소개는 크루 홈에서 두 줄까지 보이고 넘치면 말줄임하며 소개 탭에서는 전부 보임
  - 크루 이름은 다른 크루와 겹쳐도 됨. 크루 찾기 결과에는 크루장 이름과 멤버 수를 함께 보여 구분함
- 대표 이미지
  - 사진 올리기는 첫 버전에서 뺌. 남이 올린 사진을 거르고 신고받는 일이 커지기 때문
- 공개 범위
  - 비공개: 초대받은 사람만 들어옴. 크루 찾기와 어떤 목록에도 보이지 않음. 기본값
  - 공개: 크루 찾기에 보이고 바로 참여와 승인 후 참여 중에서 고름
- 만든 뒤
  - 크루장이 크루 정보의 소개 탭에서 이름, 소개, 표지, 공개 범위를 고침
  - 크루장이 나가려면 다른 멤버에게 크루장을 넘겨야 함. 혼자 남았으면 나가면서 크루를 삭제하고 본인 기록은 개인 기록에 남음
- 이번 범위에서 뺀 것
  - 종료된 크루(운영을 멈춘 크루를 목록에 남겨 두기)
  - 사진 표지, 결과물 영상을 크루에 공유하기
- 크루 인원 상한과 한 사람이 만들 수 있는 크루 수는 기능정의서에서 정함

## 공유 범위와 장소 이름 숨기기

- 2026-11-16 현수가 정하고 2026-11-17 현수가 고침
- **경로 모양은 반드시 보여줌. 지도로 보여 줄지와 지도 위 장소 이름을 숨길지는 공유하는 사람이 고름**
- 11/16에는 출발점과 도착점 주변과 지정한 장소 주변을 가리기로 했음
- 11/17 현수가 장소를 지정해 가리는 것은 번거롭고 출발점과 도착점 주변만 가리는 것도 어색하다고 보아 뺌

- 기본 공유
  - 크루에 참여하면 같은 크루의 멤버에게 러닝 날짜, 전체 거리, 달린 시간, 평균 페이스, 지도 없는 전체 경로 모양을 보여줌
  - 경로 모양은 빼거나 자르지 않고 처음부터 끝까지 보여줌
  - 경로 모양 보기에는 지도, 실제 좌표, 장소 이름을 붙이지 않음
  - 평균 심박수는 값이 있고 심박 공유를 켠 경우에만 보여줌
  - 크루에 처음 들어갈 때 공유 항목 고르기에서 심박 공유를 켜 둔 채로 안내하고 사용자가 끌 수 있게 함(2026-11-17 현수 안)
  - 켜 둔 채로 안내하면 공유하는 비율이 크게 높을 것이라는 현수의 추정이며 아직 검증하지 않음
  - 출시 전 법률 확인에서 민감정보로 분류되거나 미리 켠 동의가 문제가 되면 꺼 둔 채로 안내함
  - 초 단위 심박 기록은 공유하지 않음
- 지도 보기
  - 지도 공유에 따로 동의하면 같은 경로를 지도 위에 처음부터 끝까지 그림
  - 지도로 공유할 때 장소 이름 숨기기를 고를 수 있음. 켜면 크루원의 지도에 가게와 건물 같은 장소 이름을 보여주지 않음
  - 길과 경로는 그대로 둠
  - 장소 이름 숨기기의 기본값은 시안에서 켬. 11/16에 구체적인 위치 정보는 기본으로 가리기로 한 뜻을 이음
  - 지금 쓰는 react-native-maps 1.27.2의 `showsPointsOfInterests`로 지도의 관심 장소(가게 등) 표시를 끌 수 있음. 길 이름은 남음
  - 근거: 2026-11-19 지인 사용 피드백. 측정을 마친 화면의 지도에 가게 이름과 위치가 보여 가릴 수 없냐는 의견([QA 기록 PR](https://github.com/everyware-ie/run-mechuri/pull/141))
  - 이 옵션은 크루원에게 보이는 지도에만 적용됨. 본인이 보는 측정 화면과 기록 상세의 지도는 QA 기록에서 따로 정함
  - 거리와 시간은 전체 러닝을 기준으로 표시함
  - 지도 공유에 동의하지 않았으면 경로 모양과 러닝 요약만 볼 수 있음 ([기록 열람 정책](running-drawing-mvp.md#9-기록-열람-정책))
  - 지도를 공유하지 않은 기록의 상세에는 경로 모양과 지도 사이 전환 탭을 두지 않음(2026-11-17 현수)
- 받아들인 한계
  - 장소 이름을 숨겨도 길은 보이므로 지도를 공유하면 달린 곳과 출발점을 알 수 있음
  - 위치를 알리고 싶지 않은 사람은 지도 공유를 끄고 경로 모양만 공유함
  - 정확한 경로를 보여주는 것을 더 중요하게 보고 이 점을 받아들임
  - 러너 대부분이 자기 기록이 정확하게 찍히는 것을 더 중요하게 여길 것이라는 현수의 추정에 따른 판단이며 아직 검증하지 않음
  - 지도 공유를 켤 때 달린 곳이 지도 위에 보인다고 안내함
- 크루원에게 가는 정보
  - 지도 공유를 켜지 않은 기록은 경로 모양을 그릴 정보만 보내고 실제 좌표는 보내지 않음
  - 지도 공유를 켠 기록은 지도에 경로를 그려야 하므로 경로 좌표가 크루원에게 전달됨
  - 서버 저장 항목과 개인정보 안내는 이 차이를 기준으로 정함
- 공유 범위 확인
  - 사용자는 참여 직후 크루원에게 어떻게 보이는지 미리 보고 보여 줄 항목을 고름
  - 설정에서 공유 항목을 바꿀 수 있음
  - 공개를 넓히는 변경(지도 켜기, 장소 이름 숨기기 끄기, 심박 켜기)은 바꾼 뒤 완료한 러닝부터 적용함(2026-11-17 현수)
  - 공개를 줄이는 변경은 이미 공유한 러닝에도 바로 적용함. 지도를 끄면 이미 크루원에게 보낸 좌표도 거둠
  - 지난 러닝은 본인 기록 상세에서 한 건씩 공유 항목을 바꾸거나 공유를 취소할 수 있음. 이 변경은 그 러닝에만 적용됨(2026-11-17 현수 안)
  - 자동 공유 자체는 끄지 않으며 공유를 멈추려면 크루를 나감(2026-11-16 현수 안에 따른 초안)
  - 원본 기록은 본인의 기록에 그대로 남음

## 시안으로 확인할 흐름

1. 참여 전 화면은 회원 검색 후 초대, 초대 링크, 앱에서 크루 찾기로 비교함
   - 친구 추가 기능을 도입하는 안에서는 친구 목록에서 초대하는 화면도 함께 비교함
2. 사용자는 크루에 참여한 뒤 공개 항목과 멤버에게 보일 모습을 확인하고 보여 줄 항목을 고름
3. 크루원이 러닝을 완료하면 크루 홈에 기록이 표시됨
4. 다른 크루원은 기록을 열어 러닝 요약과 경로 모양을 확인함
   - 기록을 공유한 사람이 지도 공유에 동의한 경우 지도 보기로 바꿔 같은 경로를 지도 위에서 봄
   - 장소 이름 숨기기를 켠 기록에는 가게와 건물 같은 장소 이름이 보이지 않음

- 첫 시안에서는 참여 방식별로 같은 크루 홈에 이르는 흐름을 비교함
- 참여할 때의 자동 공유 안내, 참여 직후의 빈 크루 홈, 기록 상세의 지도와 경로 모양 전환을 확인함
- 색, 글자, 버튼은 지민님의 시각 기준을 참고함 ([디자인 시스템 PR](https://github.com/everyware-ie/run-mechuri/pull/137))
- 시안: [크루 화면 시안](../../design/crew-screens.md) (2026-11-16, 2026-11-18 갱신). 웹에서 바로 보기: [시안 링크](https://claude.ai/artifact/NsdzMysnDufu5XyfdcnZ9E)

## 확인할 결과

- 팀원 두 사람이 각자 계정으로 첫 버전에서 채택한 참여 방식을 거쳐 같은 크루에 들어감
- 한 사람이 경로가 있는 러닝을 완료하면 상대가 크루 홈에서 러닝 요약과 경로 모양을 볼 수 있음
  - 참여 전 기록은 크루에 자동으로 올라가지 않음
  - 크루 밖의 계정이나 탈퇴한 계정은 공유 기록을 열 수 없음
- 경로 모양이 어느 보기에서나 처음부터 끝까지 그려지는지 확인함
  - 장소 이름 숨기기를 켠 기록에서 가게와 건물 같은 장소 이름이 보이지 않는지 확인함
  - 지도 공유를 켜지 않은 기록은 실제 좌표 없이 러닝 요약과 경로 모양만 전달되는지 확인함
  - 심박 공유를 켜지 않은 기록에는 평균 심박수가 표시되지 않음
- 공유 항목 고르기에서 심박 공유를 끄는 비율을 보고 기본값 효과를 확인함
- 공유를 취소했을 때 다른 멤버의 목록과 기존 상세 진입 경로에서 철회가 반영됨
  - 크루 요약의 사람 수와 합계에서도 빠지는지 확인함
  - 다시 공유하면 크루 홈과 요약에 다시 반영되는지 확인함
  - 개인의 러닝 원본은 계속 자기 기록에서 볼 수 있음
- 첫 사용 뒤 다음 러닝에서도 다시 공유하거나 크루 기록을 열어보는지 팀 테스트에서 확인함
