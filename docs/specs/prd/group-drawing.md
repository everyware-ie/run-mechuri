# 합동 그리기

2026-11-27 지응이 정리한 초안이다. 팀이 확정하지 않은 항목은 4절 표에 `[확인 필요]`로 남겼다.

## 1. 왜 만드나

Runary는 혼자 뛴 기록으로 경로 그림 영상을 만든다. 영상을 올리고 나면 다음 러닝 전까지 앱을 열 이유가 없다. 친구와 묶이면 다시 열 이유가 생긴다.

11/10 회의에서 3차 스프린트에 크루 참여와 크루원 경로 보기를 넣기로 했다. 11/20 회의에서 이 크루 기능을 보류하고 여러 사람이 한꺼번에 그리는 기능으로 바꿔 진행하기로 했다. 지민은 셋로그 방식이 더 좋을 것 같다고 했고, 현수처럼 잘 안 뛰는 사람에게 더 뛰게 만드는 동기 부여가 될 수 있다고 했다([결정문](../../decisions/2026-11-20-crew-hold-login-required.md), [회의 종합](../../meetings/2026-11-20/synthesis.md)).

[MVP PRD §10](running-drawing-mvp.md)은 이 기능을 바이럴 장치로 본다. 세 명이 같이 뛰면 세 명이 각자 영상을 올리기 때문이다.

## 2. 범위

한 판을 4칸으로 나눠서 칸마다 다른 사람이 자기 러닝을 올리고, 칸이 하나의 9:16 영상에 모인다.

| 만드는 것 | 내용 |
|---|---|
| 만들기 | 이번 주 기간과 칸 배치(2×2, 세로 4행, 가로 4열)를 정해 만든다. 만들 때는 내 칸을 채우지 않는다 |
| 초대 | 링크를 보내고, 받은 사람이 링크로 들어와 참여한다 |
| 칸 채우기 | 빈 칸의 `+`를 눌러 이번 주 기록 하나, 칸에 보일 이름, 칸 배경을 고른다 |
| 칸 바꾸기와 빼기 | 4칸이 다 차기 전에는 기록을 바꿀 수 있다. 내 칸은 언제든 뺄 수 있다 |
| 영상 만들기 | 칸이 다 차거나 마감되면 각자 폰에서 영상을 만들고 스토리로 올린다 |

기록은 앱에서 측정한 것과 건강 앱에서 가져온 것 모두 쓸 수 있다. 경로가 있는 기록만 목록에 나온다([기록 선택 FRD §2-2](../frd/run-record-selection.md)).\
영상 규격은 기존 경로 그림과 같다. 9:16, 1080×1920이다([경로 렌더링 FRD](../frd/route-rendering.md)).

## 3. 이번에 하지 않는 것

- 크루. 크루 가입, 크루 홈, 내보내기, 크루장 넘기기는 하지 않는다. 다시 꺼낼 때의 출발점은 [크루 PRD](crew.md)다
- 지난주 멤버로 다시 만들기
- 칸을 왼쪽부터 차례로 재생하는 이어달리기 모드
- 갤러리 영상 배경
- 크루원 러닝 알림과 응원

## 4. 정한 것과 정하지 않은 것

**2026-11-27 지응이 정했다.**

| 질문 | 정한 것 |
|---|---|
| 칸 수 | 4칸 |
| 기준 기간 | 이번 주. 일요일부터 토요일이다(다이어리와 같다). 처음에는 오늘 기록이어도 상관없다고 했고, 시안에서 이번 주로 그렸다 |
| 기록의 출처 | 앱 측정과 건강 앱 기록 모두 |
| 칸 배치 | 2×2, 세로 4행, 가로 4열 모두 지원하고 만들 때 고른다 |
| 내 칸을 언제 채우나 | 만든 뒤에 `+`로 올린다 |
| 기록을 바꿀 수 있나 | 4칸이 다 차기 전에는 바꿀 수 있고, 다 차면 바꿀 수 없다 |
| 칸에 보일 이름 | 올릴 때마다 입력한다. 닉네임이 아니다 |
| 배경 | 칸 주인이 칸마다 고른다. 기본 배경과 갤러리 사진 |
| 칸보다 큰 사진 | 늘이거나 줄이지 않고 칸 크기만큼만 보인다. 보일 부분의 중심을 고른다 |
| 사진을 어떻게 보여 주나 | 서버에 올려서 다른 사람 폰에서 보인다 |
| 서버 | 지민의 로그인 작업이 끝난 뒤에 한다 |

**시안을 그리며 가정한 것. 팀 확정이 필요하다.**

| 질문 | 시안의 가정 |
|---|---|
| 방장 | 두지 않는다. 각자 자기 칸만 관리한다 `[확인 필요]` |
| 배치 변경 | 한 칸이라도 채워지면 바꿀 수 없다 `[확인 필요]` |
| 마감 | 토요일 자정. 빈 칸이 있어도 영상은 만들 수 있다 `[확인 필요]` |
| 칸 위치 | 아무 `+`나 누르면 그 칸이 내 칸이다. 한 사람은 한 칸이다 `[확인 필요]` |
| 원본 삭제 | 올린 사본은 남고 내 칸 빼기를 따로 해야 지워진다 `[확인 필요]` |
| 재생 | 네 경로가 같은 시간에 함께 그려진다 |
| 서버 보관 | 마감 뒤 일정 기간이 지나면 사진과 좌표를 지운다. 기간은 정하지 않았다 `[확인 필요]` |

## 5. 위험과 선행 조건

**서버와 로그인.** 칸을 서로 보려면 서버와 계정이 필요하다. 로그인은 지민이 구현했고 서버는 아직 배포하지 않았다([지민 11/24 안건](../../ideation/jminkkk/2026-11-24-meeting-agenda.md)). 서버를 어디에 띄울지는 정하지 않았다.

**사용자가 올린 사진.** 다른 사용자가 보게 되므로 App Store 심사 가이드라인 1.2(걸러내기, 신고, 차단, 연락처 공개)가 적용될 수 있다. 심사 판단은 확정하지 못했다 `[확인 필요]`. 초대받은 사람끼리만 보는 비공개 판이라는 점이 완화 요인일 수 있다.

**개인정보.** 경로는 집 위치를 드러낼 수 있어서 [MVP PRD §9](running-drawing-mvp.md)는 경로 좌표를 별도 동의 없이 공개하지 않는다고 정했다. 합동 그리기는 사용자가 칸에 올리는 동작이 동의가 된다. 사진은 얼굴이나 집이 찍힐 수 있다. 처리방침과 App Store 개인정보 표시를 고쳐야 한다.

**렌더링 비용.** 칸 4개의 배경과 경로를 한 영상에 합성한다. 기존 12초 영상보다 비용이 늘어서 구현 전에 확인한다 `[확인 필요]`.

## 6. 성공 기준

- 4명이 한 판을 채워서 영상을 만들 수 있다
- 만든 사람이 그 자리에서 뛰지 않았어도 판을 만들 수 있다
- 합동 그리기로 만든 영상이 스토리로 올라간다

수치 목표는 정하지 않았다. 3차 스프린트 목표가 정해지면 맞춘다.
