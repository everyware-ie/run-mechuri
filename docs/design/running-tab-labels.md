# 하단 러닝 탭 이름 후보

2026-11-09 회의 검토안. 현재 명칭은 `러닝`이며 이 문서로 변경을 확정하지 않는다.

## 논의할 내용

11/3 회의에서 하단의 ‘러닝’이 측정 기능이라는 점이 잘 전달되지 않는다는 의견이 나왔다. 사용자는 이름 후보와 시안을 비교한 뒤 회의에서 정하자고 요청했다.

이번에 정할 것은 측정이 시작되지 않은 상태의 탭 이름이다. 기존 경로 아이콘, 주황색 선택 표시, 보관함과 준비 화면의 구성은 유지해 이름만 비교한다.

## 후보

| 이름 | 좋은 점 | 고려할 점 |
|---|---|---|
| 달리기 | 짧고 자연스러우며 어떤 활동을 하는 곳인지 알기 쉽다. 우선 추천 후보 | 직접 측정한다는 뜻은 준비 화면의 ‘러닝 시작’ 버튼과 함께 전달한다. |
| 러닝 측정 | 현재 이름에 기능 설명을 더해 목적이 가장 분명하다. 명확성을 우선할 때의 후보 | 다른 후보보다 길고 조금 기능적인 표현이다. |
| 러닝하기 | 직접 달리는 기능이라는 뜻을 자연스럽게 전달한다. | 준비 화면을 여는 탭이라는 점이 ‘러닝 시작’ 버튼과 함께 자연스럽게 읽히는지 비교한다. |
| 뛰러 가기 | 친근하고 가볍게 달리기를 권하는 느낌이다. | 다른 후보보다 캐주얼하므로 앱의 전체 말투와 어울리는지 비교한다. |
| 측정 | 짧고 행동 목적이 분명하다. | 무엇을 측정하는지는 Runary의 맥락으로 이해해야 한다. |
| 러닝 (현재) | 앱 안에서 쓰는 표현과 일관되고 사용자에게 익숙하다. 비교 기준 | 기존에 나온 ‘측정 기능으로 잘 안 읽힌다’는 의견을 해소하는지 판단해야 한다. |

‘러닝 시작’은 탭을 누르면 바로 측정이 시작될 것이라는 인상을 줄 수 있어 후보에서 제외했다. 실제로는 준비 화면의 시작 버튼을 한 번 더 눌러야 한다.
‘러닝 기록’은 과거 기록을 보는 메뉴처럼 읽힐 수 있어 이번 후보에 넣지 않았다.

## 시안에서 비교할 것

[회의용 HTML 시안](running-tab-labels.html)을 브라우저에서 열면 여섯 가지 이름을 바꿔 볼 수 있다. 파일 하나에 화면과 아이콘을 포함했으므로 별도 설치나 인터넷 연결이 필요 없다. 팀원에게는 이 HTML 파일을 그대로 전달하면 된다.

아래의 후보 선택 메뉴로 이름을 바꾸고, 시안 안의 하단 탭으로 보관함과 러닝 준비 화면을 오가며 비교한다. 시안의 시작 버튼은 예시 화면만 전환하며 실제 러닝을 측정하지 않는다.

- 보관함을 처음 봤을 때 어느 탭에서 직접 달리기를 기록하는지 알아볼 수 있는가.
- 준비 화면에 들어간 뒤 탭 이름과 ‘러닝 시작’ 버튼의 관계가 자연스러운가.
- 아이콘 아래에서 줄바꿈 없이 읽히고 `보관함`과 균형이 맞는가.

진행 중에는 기존처럼 `측정 중`, 일시정지하면 `일시정지`를 표시한다. 실제 측정 화면에서 하단 탭을 숨기는 규칙도 유지한다. 시안의 거리와 기록 수, 지도는 비교를 위한 예시이며 실측 자료가 아니다.

## 회의에서 정할 것

기존 후보에 사용자가 고른 `러닝하기`와 `뛰러 가기`를 추가해 비교하고 최종 이름을 정한다. 이름을 유지하는 선택도 가능하다. 확정한 뒤 [하단 탭 FRD](../specs/frd/home-running-tabs.md)를 개정하고 앱에 반영한다.

`러닝하기`와 `뛰러 가기`를 기존 시안에 추가했으며, 현재 이름을 포함한 여섯 가지 후보를 회의용 HTML에도 반영했다.

이번 작업은 문서와 비교 시안만 준비했다. 제품 코드와 승인된 FRD는 변경하지 않았다.

기존 네 가지 시안의 검토 결과: 로컬 미리보기에서 보관함과 준비 화면의 탭 전환, 시작 후 보관함의 `측정 중` 표시를 확인했다. 너비 320px에서도 `러닝 측정`이 줄바꿈이나 잘림 없이 표시됐다. 앱 실기기에 설치해 확인한 결과는 아니며, 문서 정합성 검사는 통과했다.

두 후보를 추가한 내보내기 파일은 후보 수와 화면 연결, 스크립트 문법, 외부 파일 참조 여부를 검사했다. 이번에는 브라우저 도구가 로컬 파일 열기를 제한해 내보낸 HTML의 화면 검증은 하지 못했다.
