# 경로 그림 프리셋 레퍼런스

2026-11-20 회의에서 본 검토용 보고서를, 11/26에 회의 의견을 반영해 고쳤다. 이 문서와 시안으로 프리셋 디자인을 확정하지 않는다.

3차 스프린트 디자인 보강의 1순위는 경로 그림 프리셋 세 가지(불빛 러너, 구간 점등, 기본 경로 그림)를 다듬는 일이다.\
그 근거가 될 레퍼런스를 찾고, 기법을 예시 경로에 적용한 움직이는 시안으로 만들었다. 프리셋 규칙의 정본은 [경로 그림 FRD](../specs/frd/route-rendering.md) §6 프리셋이다.

## 보는 법

웹에서 바로 보려면 [보고서 링크](https://claude.ai/artifact/6b1nh6bde6rqaEPjsWCb36)를 연다. 링크가 있는 사람은 누구나 볼 수 있고, 고칠 때마다 같은 주소에 새 버전이 올라간다.\
저장소에서는 [preset-references.html](preset-references.html)을 브라우저에서 연다. 글꼴(Pretendard)과 앱 화면 캡처가 파일 하나에 들어 있어서 인터넷에 연결하지 않아도 된다.

위쪽 막대에서 예시 배경(밤 사진, 낮 사진)과 선 색을 바꿀 수 있다.\
선 색은 앱의 기본 팔레트 여섯 가지(따뜻한 흰색, 오렌지, 민트, 하늘, 분홍, 보라)이고, 고르면 모든 예시가 그 색으로 바뀐다.

예시는 6초 그리기와 2.5초 정지로 줄였다. 실제 앱은 9초와 3초다.\
경로, 배경, 수치는 비교용 예시이고 실제 기록이 아니다.\
기법은 브라우저 캔버스로 흉내 낸 것이다. 실제 앱의 렌더러(미리보기와 영상)에서 같은 모양이 나오는지는 구현하며 확인해야 한다.

## 11/20 회의 의견 반영

회의 의견은 [11/20 회의 종합](../meetings/2026-11-20/synthesis.md) §3 경로 그림 프리셋에 있다. 회의에서 정한 것은 없고, 아래는 현수가 의견을 반영해 다듬은 것이다.

| 대상 | 회의 의견 | 바꾼 것 |
|---|---|---|
| 경로 색 | 좀 더 파스텔 톤을 유지 | 주변 빛도 고른 파스텔 색 그대로 쓴다. 따뜻한 흰색의 진한 주황 빛은 연한 살구색으로 바꿨다. 지금 앱 계산(`runnerLightColors`)과 달라진다 |
| retro web | retro web 스타일로 찾아보기 | 레퍼런스 세 개와 새 프리셋 시안 두 개(반짝이 커서, 픽셀 선)를 새 절로 넣었다 |
| 불빛 러너 A안 | 불빛 머리가 너무 큼, 밝기를 낮추면 좋겠음 | 머리의 원(점과 둥근 빛)을 아예 빼고, 꼬리의 가장 굵고 밝은 앞 끝이 머리 역할을 하게 했다(11/26 현수). 꼬리 굵기도 줄였다 |
| 불빛 러너 B안, C안 | 괜찮음, 새 프리셋으로 넣어도 될 듯 | 그대로 두고 "새 프리셋 후보"로 표시했다 |
| 구간 점등 A안 | km 동그라미가 눈알 같음. 바깥 테두리 없이 안쪽 동그라미와 글자만 | 바깥 고리와 켜질 때 퍼지던 고리를 빼고 점과 km 글자만 뒀다. 켜질 때는 점이 잠깐 커진다 |
| 구간 점등 B안 | 불빛이 따라가는 게 경박해 보임(지응은 괜찮다고 봄). 메추리 캐릭터가 달리면 어떤지 | B안은 그대로 두고 메추리 버전을 더했다 |
| 구간 점등 C안 | 구간을 나타낸다는 게 잘 안 보임 | 네온관을 구간마다 끊고 켜진 구간에 km 글자를 붙였다 |
| 기본 경로 그림 A안 | 의견 둘. 지금 선 모양에 굵기만 더하기, 또는 A안에서 출발점 동그라미만 없애기 | 두 안(A-1, A-2)을 나란히 그렸다 |
| 기본 경로 그림 B안, C안 | 별로. 기본은 기본으로 | 보고서에서 뺐다 |

### 불빛 러너의 주변 빛과 머리 비교 (11/26)

머리 원을 뺀 뒤, 첫 시안보다 불빛 느낌이 약해졌다는 현수 의견이 나왔다.\
하나씩만 바꿔 비교해 보니 그리는 중에는 머리를 뺀 것이, 마지막 정지 장면에서는 주변 빛을 파스텔로 바꾼 것이 불빛 느낌을 많이 깎았다. 빛처럼 보이는 건 하얗게 빛나는 중심과 진한 색으로 번지는 주변의 대비인데, 주변 빛이 파스텔이면 중심 색과 비슷해지기 때문이다.

그래서 보고서 1절 불빛 러너에 다섯 가지를 나란히 그렸다. 선의 중심 색과 꼬리는 첫 시안을 뺀 넷이 모두 같다.

| 안 | 주변 빛 | 머리 |
|---|---|---|
| 첫 시안 (참고) | 진하게 | 크게 |
| 지금 | 파스텔 | 없음 |
| 1번 | 진하게(지금 앱 계산 `runnerLightColors`와 같음) | 없음 |
| 2번 | 파스텔 | 테두리 없는 작은 빛 번짐 |
| 1+2번 | 진하게 | 테두리 없는 작은 빛 번짐 |

메추리 버전은 앱 하단 러닝 탭의 달리는 메추리 아이콘([running-quail-icon.tsx](../../frontend/src/components/running-quail-icon.tsx))을 그대로 쓰고 다리만 번갈아 움직이게 했다. 캐릭터를 새로 그리지 않았다.

## 프리셋별 시안

| 프리셋 | A안 레퍼런스 적용 | 더 해 본 시안 |
|---|---|---|
| 불빛 러너 | 가늘어지는 혜성 꼬리와 겹 빛. 머리에 원을 두지 않고 꼬리의 앞 끝이 머리 역할을 한다. 끝점에 닿으면 빛이 경로를 거꾸로 훑고 빛 고리가 한 번 퍼진다 | B안 불꽃 입자(머리에서 불티가 튀고 끝점에서 한 번 터진다), C안 발자국 잔광(선 대신 좌우 발자국이 찍히고 밟는 순간 번쩍였다가 은은하게 남는다). 둘 다 새 프리셋 후보 |
| 구간 점등 | 선이 끊기지 않고 흐르다가 km를 지나면 지나온 구간이 켜진다. 경계는 점과 km 글자로 표시한다 | B안 활주로 불빛(등이 차례로 켜지고 km를 넘으면 그 구간 위로 빛이 한 번 달린다), B안 메추리 버전(메추리가 달리며 등을 켜고 km마다 폴짝 뛴다), C안 네온 간판 켜기(구간마다 끊긴 네온관이 km를 넘으면 한 번 깜빡이며 켜진다) |
| 기본 경로 그림 | 흰 선 아래에 옅은 그림자를 깔고, 앞 끝은 펜 촉처럼 가늘게 한다. 출발점은 빈 원, 다 그리면 도착점을 찍는다 | A-1 지금 선 모양(고른 굵기)에 굵기만 더함, A-2 A안에서 출발점 동그라미만 뺌 |
| retro web (새 프리셋 후보) | 없음 | R1 반짝이 커서(머리는 옛날 화살표 커서, 지나간 자리에 팔레트 파스텔 반짝이가 떨어진다), R2 픽셀 선(경로를 큰 픽셀 칸에 맞춰 그리고 빛 번짐은 디더링 점무늬로) |

구간 점등 A안은 11/20 회의 전에 현수 의견으로 한 번 고쳤다.\
처음에는 FRD 표현대로 구간이 통째로 켜지게 그렸는데, 구간에서 구간으로 너무 빠르게 넘어가는 느낌이었다. 불빛 러너와 기본 경로 그림처럼 자연스럽게 흐르다가 도중에 켜지는 쪽이 낫다고 봤다.

## 정할 것

1. 불빛 러너의 주변 빛과 머리를 지금, 1번, 2번, 1+2번 중 무엇으로 할지(위 비교)
2. 경로 색: 주변 빛을 고른 파스텔 색 그대로 쓸지(이 보고서), 지금 앱처럼 채도를 올릴지. 이 보고서대로 가면 앱의 `runnerLightColors` 계산을 바꿔야 한다
3. 세 프리셋의 정체성 색. FRD의 기본 색은 셋 다 `[확인 필요]`로 남아 있다. 지금 앱은 셋 다 따뜻한 흰색이 기본이다
4. 불빛 러너 B안(불꽃 입자), C안(발자국 잔광)과 retro web 시안(반짝이 커서, 픽셀 선) 중 무엇을 새 프리셋으로 넣을지. 넣으면 [PRD](../specs/prd/running-drawing-mvp.md) §7 결과물의 형태와 경로 그림 FRD §6 프리셋에 프리셋을 더해야 한다
5. 구간 점등 B안을 불빛 버전과 메추리 버전 중 무엇으로 볼지. 메추리로 가면 캐릭터를 더 다듬을지
6. 구간 점등을 "흐르다가 켜짐"으로 바꾸면 경로 그림 FRD §6-3 구간 점등의 진행 표현("구간이 하나씩 켜진다")을 고쳐야 한다
7. 기본 경로 그림을 A-1과 A-2 중 무엇으로 할지
8. 마지막 정지 화면을 프리셋마다 다르게 보이게 할지. 캡처되는 자리이고 [QA 기록](../ops/qa-log.md)의 11/19 지인 피드백(정지 이미지 저장 요청)과 이어진다
9. 줌 추적(카메라)을 이번 디자인 보강 범위에 넣을지. PRD §7 결과물의 형태는 줌 추적을 1순위로 봤지만 아직 시도하지 않았다

## 확인 필요

- 빛 겹, 불티, 반짝이를 늘리면 영상을 만드는 시간이 늘 수 있다.\
  [내보내기 FRD](../specs/frd/export-and-share.md) §2-3 대기와 진행 표시에 따르면 9/13 측정에서 이미 약 40초(합성 입력)와 약 224초(실제 입력, 화면 잠금)가 걸렸다. 시안의 기법을 넣었을 때 얼마나 늘어나는지는 측정하지 않았다 `[확인 필요]`
- 픽셀 선은 흐림 대신 칸을 칠하므로 영상 렌더링이 가벼울 수 있다. 측정하지 않았다 `[확인 필요]`
- 메추리 버전은 아이콘 선 그림을 렌더러(미리보기와 영상)에서 그려야 한다. 캐릭터를 더 귀엽게 다듬을지는 정하지 않았다 `[확인 필요]`
- 네온 간판 켜기는 구간마다 한 번만 깜빡여서 1초에 3번 넘게 번쩍이지 않게 했다([W3C 기준](https://www.w3.org/WAI/WCAG21/Understanding/three-flashes-or-below-threshold.html)). 동작 줄이기를 켠 사용자에게 깜빡임을 뺄지는 정하지 않았다 `[확인 필요]`
