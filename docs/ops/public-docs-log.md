# 공개 안내 문서 변경 이력

노션에 올려 둔 **사용자용 안내**를 고칠 때마다 여기 남긴다. 무엇을 왜 고쳤는지와 그때의 앱 범위를 함께 적는다.

**왜 이 문서가 필요한가.** 앱 기능이 바뀌면 공개 안내도 따라가야 하는데, **고쳤다는 사실이 레포 밖에만 있으면 다음 사람이 모른다.** 2026-09-14에 실제로 그 일이 났다(아래 참고).

## 공개 페이지

| 페이지 | 주소 |
|---|---|
| 안내 허브 | https://phs00.notion.site/mechuri-run |
| 개인정보 처리방침 | **https://phs00.notion.site/privacy** (App Store Connect 제출용) |
| 자주 묻는 질문 | 허브에서 이동 |
| 공지사항 | 허브에서 이동 |

**제출용 주소는 로그인 없이 열려야 한다.** 만든 사람은 로그인돼 있어서 잘 보이지만 심사자는 못 볼 수 있다. 고칠 때마다 시크릿 창에서 확인한다.

## 2026-09-14 — 갤러리 사진과 카메라 촬영 반영

**고친 것**: 개인정보 처리방침, 자주 묻는 질문

### 왜

**공개 안내가 앱과 어긋나 있었다.** 두 문서 모두 "이 버전에는 갤러리 사진 선택과 카메라 촬영 기능이 없으며 이를 위한 권한을 요청하지 않는다"고 적혀 있었는데, **앱은 2026-09-11(PR #50)부터 둘 다 갖고 있다.** 빌드 14부터 나갔고 지금 TestFlight의 18번에도 있다.

심사자는 바이너리가 요구하는 권한과 처리방침을 대조한다. **앱은 카메라 권한을 요청하는데 처리방침은 요청하지 않는다고 말하는 상태였다.**

### 어쩌다 이렇게 됐나

| 날짜 | |
|---|---|
| 9/9 | **최초 제출 빌드는 기본 배경만 제공하기로 정했다.** 그 전제로 안내를 썼다([인계 문서](beta-2026-09-09/handoff.md)) |
| 9/9 | 그 결정과 체크리스트를 담은 PR #47이 **draft로 남아 머지되지 않았다** |
| 9/11 | PR #50으로 사진 배경과 카메라가 들어갔다 |
| 9/14 | 어긋남을 발견하고 고쳤다. PR #47도 함께 머지했다 |

**결정이 레포에 없으면 아무도 추적하지 못한다.** 이번에는 카톡이 아니라 머지 안 된 브랜치였다.

### 무엇을 고쳤나

**개인정보 처리방침**

| | |
|---|---|
| 적용 범위 | "기본 배경으로 만드는 최초 베타" → **"기본 배경과 사용자 사진으로 만드는 베타"** |
| §1 | "사진 앱에 결과물 저장" 절을 **"사진과 카메라"**로 교체. 고르기·찍기·저장 셋을 표로 나눴다 |
| §1 | **편집용 사진 사본을 앱에 보관한다**는 사실을 새로 적었다. 9/11에 들어간 동작인데 안내에 없었다 |
| §2 | 보관 표에 "배경으로 쓴 사진" 줄 추가 |
| §3 | 인스타 공유 배경이 기본 이미지이거나 **사용자가 고른 사진**일 수 있다고 고쳤다 |
| §5 | 권한 표에 **카메라** 줄 추가 |

**자주 묻는 질문**

- "내 사진이나 카메라로 배경을 만들 수 있나요" → **된다**로 교체
- "사진 권한은 왜 필요한가요" → **"사진이나 카메라 권한은 왜 필요한가요"**로 넓히고, 갤러리에서 고를 때는 앨범 접근 권한을 요청하지 않는다는 점을 밝혔다

### 시행일

**2026년 9월 10일을 그대로 두었다.** 사진 기능이 9/11에 들어갔지만 그때까지 내부 테스트뿐이라 외부 사용자가 없었고, 외부 배포는 지금 시작한다. 최종 수정 줄에 9/14 이력을 덧붙였다.

### 아직 안 된 것

[9/9 인계 문서](beta-2026-09-09/handoff.md)의 체크리스트가 대부분 그대로다. 특히 이것이 남아 있다.

- **앱 안에서 개인정보 처리방침을 열 수 있는 링크가 없다.** `frontend/src`에 관련 문자열이 없다
