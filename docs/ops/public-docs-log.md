# 공개 안내 문서 변경 이력

2026-10-13 사용자가 최종 검토한 개인정보 처리방침을 읽어 현재 본문 사본에 동기화했다. 공개 주소에서 비로그인 본문과 문의·변경 이력 링크를 확인했다. 이번 검토에서 공개 본문을 수정하지 않았으며, 10/12 보관본도 그대로 유지했다. 새 빌드의 백업 제외 보완에 맞춘 안내 갱신은 [최종 심사 검토](app-store-final-review-2026-10-13.md)에 후속 작업으로 남긴다.

노션에 올려 둔 **사용자용 안내**를 고칠 때마다 여기 남긴다. 무엇을 왜 고쳤는지와 그때의 앱 범위를 함께 적는다.

**왜 이 문서가 필요한가.** 앱 기능이 바뀌면 공개 안내도 따라가야 하는데, **고쳤다는 사실이 레포 밖에만 있으면 다음 사람이 모른다.** 2026-09-14에 실제로 그 일이 났다(아래 참고).

## 공개 페이지

| 페이지 | 주소 |
|---|---|
| 안내 허브 | https://phs00.notion.site/runary |
| 개인정보 처리방침 | **https://phs00.notion.site/privacy** (App Store Connect 제출용) |
| 자주 묻는 질문 | 허브에서 이동 |
| 공지사항 | 허브에서 이동 |
| 개인정보 처리방침 변경 이력 | https://phs00.notion.site/p/3f740e8014f9813b980ecca4650b3456?pvs=24 |

**제출용 주소는 로그인 없이 열려야 한다.** 만든 사람은 로그인돼 있어서 잘 보이지만 심사자는 못 볼 수 있다. 고칠 때마다 시크릿 창에서 확인한다.

## 2026-10-12: 정식 제출 준비와 공개 개정 이력 정리

### 문장 끝 줄바꿈과 작성 규약 보완

사용자가 ‘적용됩니다.’ 뒤에서 줄을 나누는 예를 들어, 문단 간격만으로는 수정이 충분하지 않다고 지적했다. 현재 방침과 10월 12일 보관본, FAQ, 공지, 안내 허브에서 하나의 설명이 끝나고 조건이나 예외를 안내하는 지점을 검토했다. 같은 문단에서 줄만 바꿀 곳에는 `<br>`을 넣었다. 마침표마다 일괄 적용하지 않았으며, 줄바꿈 표기를 제외한 내용과 하위 문서 참조가 그대로인지 대조했다.

앞으로의 문서 작성 기준은 [문서 작성 규약](../../.claude/conventions/writing.md)에 추가했다. 사실 대조, 문장 교정, 의미에 따른 줄바꿈, 실제 게시 화면 확인을 작성 완료 전에 수행한다. 공개 방침 개정 절차는 이 규약을 참조한다. AGENTS.md에 규약을 복사하지 않았다.

공개 방침에서 ‘적용됩니다.’ 다음 줄이 ‘별도로’로 시작하는 것을 확인했다. 기본 데스크톱 너비와 375px 브라우저 너비로 확인했으며, 실제 아이폰 Safari 실행 검증은 이번 문체 수정에서 수행하지 않았다. 문서 정합성과 공백 검사도 통과했다. 내용은 그대로이며 앱 소스나 TestFlight 설정은 변경하지 않았다.

사용자 요청으로 개인정보 처리방침, 자주 묻는 질문, 안내 허브와 공지사항을 고쳤다. 일반 배포 앱을 기준으로 하트 샘플, 사진과 영상 배경, 결과물 저장과 삭제, 외부 서비스 통신을 안내한다. 샘플은 해당 기능이 표시되는 버전에만 적용된다고 적어 기존 공개 베타와 구분했다. 내부 측정 테스트 빌드를 일반 앱의 기능으로 안내하지 않는다.

현재 방침의 페이지 ID와 공개 주소는 유지했다. 시행일은 2026-10-12, 문서 버전은 2026.10.12다. 베타 시기의 긴 변경 기록은 현재 본문 하단에서 옮겼지만 삭제하지 않았다. 2026-10-03 전체 본문과 당시 이력을 별도 보관본에 남겼다. 새 방침의 전체 사본도 보관했다. 개정 요약과 ‘이전 문서 안내’는 모두 최근 날짜부터 나열한다.

Expo 업데이트 요청의 무작위 설치 식별자와 접속 정보, 오류 진단 정보를 확인해 안내에 포함했다. 실제 기록의 장소 이름 조회, Instagram 공유, Notion 공개 문서 접속, TestFlight와 문의 처리도 구분했다. 보관 영상의 삭제 시도와 정리에 실패한 파일, 배경 사본이 남을 수 있는 조건을 유지했다. 서비스 이용약관 초안은 비공개로 남겼으며 이번 공개 문서에 연결하지 않았다.

사용자가 문체를 지적해 중간점으로 이어진 나열, 과한 강조와 문장마다 끊는 구성을 다듬었다. 저장소의 문서 작성 규약과 규약이 참고한 im-not-ai 공개 지침을 읽었다. 로컬 설치본은 찾지 못했으며 플러그인이나 자동 진단 프로그램을 실행한 것은 아니다. 개인정보 처리 항목과 삭제 예외, 권한 거부 안내는 원문과 대조했다.

### TestFlight와 심사

이 작업에서 TestFlight 바이너리, 공개 그룹과 초대 링크, App Store Connect 제출 설정은 변경하지 않았다. 기존 처리방침 링크를 여는 사용자는 새 본문을 보게 된다. 정책 문서 수정은 앱의 새 빌드 업로드나 심사 요청과 별개이며, Apple의 추가 확인 여부나 승인 결과를 보장하지 않는다. App Store Connect의 개인정보 공개 항목은 이번 작업에서 변경하거나 검증하지 않았다.

문체 수정 뒤 사용자가 줄바꿈을 다시 지적했다. Notion 도구가 일반 빈 줄을 제거하는 것을 확인하고, 주제가 바뀌는 문단과 질문 사이에 실제 빈 블록을 넣었다. 긴 설명의 문단을 나눴으며 정보 항목과 조건은 그대로 유지했다. 10월 12일 보관본에도 같은 문단 구성을 반영했다.

로그인하지 않은 브라우저에서 현재 방침과 FAQ, 공지, 변경 이력, 두 보관본을 열었다. 변경 이력의 두 하위 문서가 최신순으로 보이고, 이전 베타 이력도 남아 있는 것을 확인했다. 도구에서 허브의 네 하위 문서와 문의 링크가 유지되는 것을 확인했다. 최종 방침은 공개 화면의 문단 구분과 간격을 캡처로 확인했다. 일반 빈 줄만 적용한 첫 확인에서는 간격이 유지되지 않아 큰 항목과 FAQ 질문 사이에 빈 블록을 명시했다. 각 문장마다 빈 블록을 두지 않는다.

저장소 문서 정합성과 공백 검사는 통과했다. 앱 소스를 바꾸지 않아 이번 문서 작업에서는 타입 검사나 앱 테스트를 반복하지 않았다.

## 2026-10-03: 갤러리 영상 배경 반영

**고친 것**: 개인정보 처리방침, 자주 묻는 질문

### 왜

[PR #73](https://github.com/everyware-ie/run-mechuri/pull/73)으로 **갤러리에서 고른 영상을 배경으로 쓸 수 있게 됐다.** 두 문서는 "사진"만 말하고 있었다. 처리방침 7항은 처리 범위가 달라지면 적용 전에 고친다고 약속한다.

빌드 26은 내부 테스터에게만 나갔고 공개 링크는 아직 25다. **공개 링크를 바꾸기 전에 고쳤다.** 시행일(9월 10일)은 지난번처럼 그대로 두고 이력에 남겼다.

### 무엇을 고쳤나

**개인정보 처리방침**

| | |
|---|---|
| 적용 범위 | "사용자 사진" → **"사용자의 사진·영상"** |
| 1항 | 소제목을 **"사진·영상과 카메라"**로. 갤러리에서 고른 영상도 고른 것만 전달된다고 적었다 |
| 1항 | **영상은 결과물에 쓰는 앞부분만 소리를 뺀 채 보관한다**는 문장 추가 |
| 2항 | 보관 표의 "배경으로 쓴 사진"을 **사진·영상**으로. 영상은 첫 장면 이미지도 함께 보관한다 |
| 3항 | 인스타 공유 배경이 **고른 영상의 첫 장면**일 수 있다. 결과물에 배경 사진이나 영상이 들어간다 |
| 4항 | **보관함에서 지워도 배경 사진·영상의 편집용 사본은 남는다**는 문장 추가(아래) |
| 5항 | 카메라를 거부해도 갤러리의 **사진·영상**은 쓸 수 있다 |

**자주 묻는 질문**

- "내 사진이나 카메라로 배경을…" → **"내 사진·영상이나 카메라로…"**로 넓히고, 영상은 앞부분만 쓰며 소리를 넣지 않는다고 적었다
- 갤러리에서 **사진이나 영상을** 고를 때 앨범 접근 권한을 요청하지 않는다
- 보관함 삭제 답에 편집용 사본이 남는다는 문장 추가

### 사진 때부터 빠져 있던 것

**보관함에서 항목을 지워도 배경 사진 사본은 원래 지워지지 않았다.** `deleteResult`는 목록에서 항목만 빼고 `backgrounds/`의 파일은 그대로 둔다. 9/14 반영 때 이 사실이 안내에 빠졌다. 영상은 용량이 커서 더 드러날 수 있어 이번에 함께 적었다.

**나중에 보관함 삭제 때 사본도 지우도록 코드를 고치면 이 문장을 다시 뺀다.** 같은 사본을 이어서 만들기 초안이 쓰고 있을 수 있어서 바로 지우면 안 된다.

### 확인

두 페이지를 다시 읽어 바뀐 문장을 모두 확인했다. 처리방침 공개 주소가 로그인 없이 열리는 것도 확인했다.

## 2026-09-20: 공개 허브 URL 변경

사용자가 노션 메인페이지의 공개 URL 끝부분을 runary로 변경했다. 공개 주소는 https://phs00.notion.site/runary 이며, 로그인 요청 없이 Runary 페이지와 처리방침·공지사항·FAQ 링크가 열리는 것을 확인했다. 현재 주소 표, 제품명 변경 이력의 링크, 최초 베타 인계 문서의 허브 링크를 갱신했다.

앱 소스에는 메인페이지 주소를 직접 참조하는 곳이 없다. 앱의 개인정보 처리방침 링크는 기존 https://phs00.notion.site/privacy 를 사용하며, 새 허브에서도 동일한 처리방침 주소를 안내한다. 노션 페이지 ID와 하위 문서 주소는 유지된다.

## 2026-09-20: 공개 노션 제품명을 Runary로 변경

사용자가 노션도 Runary로 모두 맞추도록 요청했다. 공개 허브와 하위 문서 3개를 확인하고 다음 항목을 바꿨다.

| 페이지 | 변경 |
|---|---|
| [공개 안내 허브](https://phs00.notion.site/runary) | 제목과 하단 사용자 안내의 제품명을 Runary로 변경 |
| [개인정보 처리방침](https://phs00.notion.site/privacy) | 도입부 제품명을 Runary로 변경하고 9월 20일 이름 변경 이력 추가 |
| [자주 묻는 질문](https://app.notion.com/p/3d540e8014f981f488f8c83c128657dd) | 건강 권한 안내 2곳의 앱 이름과 수정일 갱신 |
| [공지사항](https://app.notion.com/p/3d540e8014f981678c85debcf1a24d55) | 옛 제품명이 없는 것을 확인. 본문 변경 없음 |

팀 메추리·문의 주소·공개 URL·페이지 ID는 유지했다. 개인정보 처리 내용과 시행일은 바꾸지 않았다. 워크스페이스 검색에 나온 과거 회의의 이름 후보·발언과 다른 프로젝트는 현재 사용자 안내가 아니므로 유지했다.

수정 후 네 페이지를 다시 읽어 본문에 옛 제품명이 남지 않았고, 허브의 하위 페이지 3개가 유지되는 것을 확인했다. 앱 코드 배포와 무관하게 노션 페이지에 반영했다.

## 2026-09-20: 앱 안 처리방침 연결

첫 실행 안내와 홈 목록 하단에 https://phs00.notion.site/privacy 를 여는 링크를 추가했다. 공개 브라우저에서 로그인 요청 없이 본문이 열리는 것을 확인했다. 앱에서 브라우저 열기 요청이 실패하면 다시 시도할 수 있다. 아직 TestFlight에 배포하지 않았다.

앱 링크 추가 직후에는 공개 노션에 옛 이름이 남아 있었다. 이후 같은 날 사용자 요청으로 아래와 같이 제품명도 변경했다.

## 2026-09-14 — 갤러리 사진과 카메라 촬영 반영

**고친 것**: 개인정보 처리방침, 자주 묻는 질문

### 왜

**공개 안내가 앱과 어긋나 있었다.** 두 문서 모두 "이 버전에는 갤러리 사진 선택과 카메라 촬영 기능이 없으며 이를 위한 권한을 요청하지 않는다"고 적혀 있었는데, **앱은 2026-09-11(PR #50)부터 둘 다 갖고 있다.** 빌드 14부터 나갔고 지금 TestFlight의 18번에도 있다.

심사자는 바이너리가 요구하는 권한과 처리방침을 대조한다. **앱은 카메라 권한을 요청하는데 처리방침은 요청하지 않는다고 말하는 상태였다.**

### 어쩌다 이렇게 됐나

| 날짜 | |
|---|---|
| 9/9 | **최초 제출 빌드는 기본 배경만 제공하기로 정했다.** 그 전제로 안내를 썼다([인계 문서](beta-2026-09-09/handoff.md)) |
| 9/9 | 그 결정과 체크리스트를 담은 PR #47이 **draft로 남아 머지되지 않았다** |
| 9/11 | PR #50으로 사진 배경과 카메라가 들어갔다 |
| 9/14 | 어긋남을 발견하고 고쳤다. PR #47도 함께 머지했다 |

**결정이 레포에 없으면 아무도 추적하지 못한다.** 이번에는 카톡이 아니라 머지 안 된 브랜치였다.

### 무엇을 고쳤나

**개인정보 처리방침**

| | |
|---|---|
| 적용 범위 | "기본 배경으로 만드는 최초 베타" → **"기본 배경과 사용자 사진으로 만드는 베타"** |
| §1 | "사진 앱에 결과물 저장" 절을 **"사진과 카메라"**로 교체. 고르기·찍기·저장 셋을 표로 나눴다 |
| §1 | **편집용 사진 사본을 앱에 보관한다**는 사실을 새로 적었다. 9/11에 들어간 동작인데 안내에 없었다 |
| §2 | 보관 표에 "배경으로 쓴 사진" 줄 추가 |
| §3 | 인스타 공유 배경이 기본 이미지이거나 **사용자가 고른 사진**일 수 있다고 고쳤다 |
| §5 | 권한 표에 **카메라** 줄 추가 |

**자주 묻는 질문**

- "내 사진이나 카메라로 배경을 만들 수 있나요" → **된다**로 교체
- "사진 권한은 왜 필요한가요" → **"사진이나 카메라 권한은 왜 필요한가요"**로 넓히고, 갤러리에서 고를 때는 앨범 접근 권한을 요청하지 않는다는 점을 밝혔다

### 시행일

**2026년 9월 10일을 그대로 두었다.** 사진 기능이 9/11에 들어갔지만 그때까지 내부 테스트뿐이라 외부 사용자가 없었고, 외부 배포는 지금 시작한다. 최종 수정 줄에 9/14 이력을 덧붙였다.

### 아직 안 된 것

[9/9 인계 문서](beta-2026-09-09/handoff.md)의 체크리스트가 대부분 그대로다. 특히 이것이 남아 있다.

- **앱 안에서 개인정보 처리방침을 열 수 있는 링크가 없다.** `frontend/src`에 관련 문자열이 없다
