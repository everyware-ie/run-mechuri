# 갤러리 사진 선택·카메라 추가 후속 계획

작성: 2026-09-09 / phs00 요청, Codex 작성  
상태: 후속 작업 계획. 공개 정책에 아직 적용하지 않은 내부 문서.  
목표: 2026-09-22 출시 범위에 사진 선택·촬영을 포함하되, 구현과 검증 완료 시점에 맞춰 적용한다.

[최초 베타 인계 문서](./handoff.md)와 [현재 정책 스냅샷](./privacy-current.md)을 먼저 읽는다.

## 유지할 결정

최초 베타는 기본 배경만 지원한다. 사진 선택과 카메라 촬영은 이후 빌드에서 도입한다. 배경 동영상은 이번 사진 기능 범위에 포함하지 않는다. 승인된 [배경 선택 FRD](https://github.com/everyware-ie/run-mechuri/blob/335d0de2b8b519d20fb06b6dd3e73289b998e570/docs/specs/frd/background-selection.md)와 [9월 8일 회의](https://github.com/everyware-ie/run-mechuri/pull/46)를 구현 출발점으로 삼는다.

미래 기능을 현재 처리 항목처럼 공표하지 않는다. 확장에 대비하는 일은 실제 선택·촬영·공유·삭제 방식을 정리하고 구현 버전과 정책 버전을 함께 관리하는 것으로 진행한다.

## 구현 전에 확정할 데이터 흐름

### 현재 공유 코드에서 먼저 볼 부분

[InstagramStoryShareModule.swift](https://github.com/everyware-ie/run-mechuri/blob/335d0de2b8b519d20fb06b6dd3e73289b998e570/frontend/modules/instagram-story-share/ios/InstagramStoryShareModule.swift)의 `shareToStory(videoPath, backgroundImagePath)`는 동영상뿐 아니라 배경 파일의 바이트도 `backgroundImage`로 전달한다.

현재는 기본 이미지라 개인 사진이 나가지 않는다. 이후 이 인자에 사용자의 사진 경로를 그대로 넣으면 **완성 영상 외에 선택·촬영 이미지도 공유 앱에 전달될 수 있다.** 이미지가 전달되면 메타데이터도 별도로 검증해야 한다.

공유용으로 가공한 이미지가 필요한지, 이미지 전달을 없앨 수 있는지 실제 호환성을 확인한 뒤 결정한다. 정책에 '완성 동영상만 공유한다'고 먼저 쓰지 않는다. 공유 화면과 보관함 재공유 양쪽을 함께 검사한다.

### 현재 삭제 코드에서 먼저 볼 부분

[results-store.ts](https://github.com/everyware-ie/run-mechuri/blob/335d0de2b8b519d20fb06b6dd3e73289b998e570/frontend/src/lib/results-store.ts)의 `deleteResult`는 AsyncStorage 항목만 제거한다. [렌더러](https://github.com/everyware-ie/run-mechuri/blob/335d0de2b8b519d20fb06b6dd3e73289b998e570/frontend/modules/route-renderer/ios/RouteRendererModule.swift)는 mp4를 임시 폴더에 생성한다.

사진 파일을 추가하기 전에 결과물 삭제 시 해당 영상과 더 이상 참조되지 않는 배경 파일을 실제로 지우는 구조를 정한다. 여러 결과물/초안이 같은 파일을 참조하면 다른 결과물이 깨지지 않아야 한다. 앱 설치 해제 외에도 사용자가 복사된 기록을 지울 수 있는 범위를 명확히 한다. 파일 삭제가 구현되고 검증되기 전에는 정책의 즉시·완전 삭제 표현을 확대하지 않는다.

## 작업 순서와 문서 갱신 시점

1. **범위 고정:** 사진 선택·촬영 FRD와 구현 노트를 확인한다. 기존 승인 범위를 바꾸면 관련 FRD·PRD·결정 이력도 팀 절차에 따라 갱신한다.
2. **구현:** 이미지 선택/촬영, 파일 보관/정리, 공유 payload, iOS 권한 문구를 함께 구현한다.
3. **검증:** 허용·거절·취소·제한 접근·설정 변경, 앱 재실행, 원본 삭제, 다시 편집, 두 결과물의 배경 공유, 저장/공유 실패를 실제 기기에서 확인한다.
4. **문서 작성:** 확인된 데이터 흐름으로 처리방침 개정본을 작성한다. 선택한 사진만 접근한다는 표현과 원본·영상의 공유 범위는 확인한 사실에 한해 사용한다.
5. **배포 정보 일치:** 새 빌드의 버전/번호/SHA, 권한 문구, 정책·FAQ·서비스 소개, App Store Connect 개인정보 응답과 스크린샷을 함께 검토한다.
6. **적용 전 안내:** 이전 정책을 날짜별로 보관하고, 변경 내용·적용 버전·시행일을 공지한다. 필요한 권한/동의는 기능 이용 전에 받는다. 22일 목표가 바뀌면 실제 도입일로 조정한다.
7. **배포 후 확인:** 실제 배포 빌드의 사진/카메라와 공유·삭제 동작, 정책 URL을 재확인하고 아래 표에 근거를 남긴다.

신규 기능의 심사가 끝나기 전에 원격 업데이트로 기능을 켜는 방식으로 제출 빌드와 실사용 동작이 달라지지 않도록 배포 담당자가 채널과 runtime을 관리한다.

## 실제 구현 확인 후 사용할 정책 문구의 틀

아래는 **검증 전 초안**이다. 대괄호를 채우지 않은 채 공개하지 않는다.

> 사용자가 배경 사진을 고르면 [실제 선택 방식]으로 전달된 사진을 [목적]에 사용합니다. 사용자가 촬영을 시작하면 카메라 권한을 요청하며, 거절해도 기본 배경 기능은 사용할 수 있습니다. 선택·촬영 사진은 [보관 위치·기간]에 보관하고 [삭제 동작]에 따라 삭제합니다. 사진의 [메타데이터 처리]는 다음과 같습니다. 사용자가 공유하면 [실제로 전달되는 동영상·이미지 및 포함 정보]를 [공유 대상]에 전달합니다.

FAQ에는 사진 선택/촬영 방법, 권한 거절 시 기본 배경 이용, 원본 삭제 시 편집 가능 여부, 사진·결과물 삭제 범위를 추가한다. 처리방침의 관련 항목은 1항(처리 정보), 2항(보관), 3항(외부 전달), 4항(보관·삭제), 5항(권한), 7항(변경 안내)이다.
