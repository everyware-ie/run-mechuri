# 자체 측정 내부 검증 계획

근거: [내부 측정 PRD](../specs/prd/internal-run-tracking.md) · [내부 측정 FRD](../specs/frd/internal-run-tracking.md). 2026-10-05 FRD 확인 후 첫 기능 코드와 자동 검사를 구현했다. 컴파일·계산 검증과 실기기 운동 검증은 구분한다.

## 1. 내부 테스트 경로

개발 앱 또는 팀 내부 TestFlight 앱의 홈·첫 실행 안내 → `러닝 시작` (팀 테스트 표시) → 측정 시작 → 일시정지·재개 또는 종료 → 측정 기록 상세. 이전 측정은 러닝 화면의 `최근 러닝`을 펼쳐 확인한다. 상세의 메모·팀 테스트 진단도 필요할 때 펼친다. 앱을 덮어 설치하면 유지하고 삭제·재설치하면 사라지는 기기 내 보관이다.

## 3. 평소 러닝에서 단독 측정과 선택적인 비교

2026-10-05 사용자는 팀원이 각자 평소 운동 앱과 Runary를 함께 켜고 운동할 것이며 정해진 환경을 체계적으로 맞추기 어렵다고 알렸다. 이후 사용자는 다른 운동 앱 없이 Runary만으로 심박 측정이 가능해야 한다고 명확히 했다. 워치 연동 기능은 검증 대상이지만 모든 팀원·모든 기록에 워치 착용이나 심박 수집을 요구하지 않는다. 워치 없이 아이폰으로 측정·저장하는 흐름도 검증한다. 워치를 사용할 때 단독 심박 기능을 확인하고, 다른 아이폰 앱과의 거리·시간 비교는 선택할 수 있다. 특별한 코스를 뛰거나 A~G의 모든 조건을 수행하는 것을 팀원의 기본 과제로 두지 않는다.

1. 아이폰 단독 사용은 워치 없이 Runary 내부 측정을 시작한다. 워치를 사용한다면 기존 워치 운동을 종료한 상태에서 시작한다. Runary 워치 앱이 열려 자체 운동으로 심박을 수집하는지 확인한다. 비교하려면 다른 앱은 아이폰에서 실행하되 다른 워치 운동을 중복 시작하지 않는다.
2. 평소대로 뛰고 앱 전환·잠금·횡단보도 대기를 자연스럽게 사용한다.
3. 종료하면 Runary가 경로·거리·시간·정확도·공백·걸음·센서 지연·배터리를 자동 보관한다.
4. 가능하면 비교 앱 이름·거리·시간과 `문제 없음 / 끊김 / 거리 이상 / 기타`만 남긴다. 메모하지 않아도 측정은 저장된다.

사용자는 `진단 요약 복사`와 구현 후 내부 TestFlight 사용 방향을 채택했다([FRD](../specs/frd/internal-run-tracking.md) §9 사용자 선택과 확정한 기준). 진단 복사는 구현했고 내부 배포는 아직 진행하지 않았다. 상세에서 빌드·거리·시간·센서 지연·오류·배터리 등의 집계를 복사해 팀에 전달하는 흐름을 확인한다. 원본 좌표·장소·개별 심박·고유 기기 ID가 복사되거나 자동 전송되지 않아야 한다.

기존 워치 운동의 심박을 아이폰 HealthKit에서 읽는 방식은 선택적인 별도 비교 실험이다. 이 모드에서는 Runary 자체 워치 운동을 시작하지 않는다. 실험 결과를 Runary 단독 심박 측정의 성공으로 기록하지 않는다. 사용자에게 Nike의 동작 방식을 추측해 재현 성공을 약속하지 않는다. 심박의 측정 시각과 수신 시각 차이를 자동으로 남긴다.

다른 앱의 자동 일시정지 여부, 아이폰·워치 중 어느 GPS를 쓰는지, 시작·종료 시각의 차이를 고려한다. 두 앱의 거리·시간이 다르다는 것만으로 Runary 오류라고 단정하지 않는다. 병행 사용의 배터리 감소에는 두 앱과 워치 통신의 영향이 섞인다. Runary 단독 소모로 보고하지 않는다.

Runary만으로 심박을 측정하는 테스트를 첫 내부 버전의 완료 조건으로 둔다. Apple Watch는 운동 세션 하나만 실행하므로 기존 워치 운동과 중복 시작하지 않는다. [Apple 운동 세션 안내](https://developer.apple.com/documentation/healthkit/hkworkoutsession).

사용자는 아이폰에서 Nike를 실행하고 워치에서 심박을 확인하며, 워치에 잘 나타나지 않는 연결 실패를 겪었다고 알렸다. Runary 워치 단계에서는 아이폰에서 시작 후 워치 화면이 열리는지, 열리지 않을 때 안내·재시도가 가능한지 확인한다. 연결 성공과 최신 심박 수신은 다른 검사다. 아이폰의 병행 심박 읽기 성공만으로 워치 화면·연결 검증까지 통과 처리하지 않는다.

팀용 TestFlight 설치 확인에는 개발 서버 없이 실행, 동봉된 워치 앱 설치·시작, 내부 그룹 배정과 공개 진입 차단을 포함한다. 기존 초안·결과물 보관의 회귀도 확인한다. 설치 후 책상에서 기본 동작을 확인한 다음 팀의 실제 러닝으로 GPS 정확도·잠금·배터리를 검증한다. 배포 전에 야외 검증까지 끝났다고 기록하지 않는다.

## 4. 문제 발생 시에만 추가로 확인한다

아래 조건은 기본 사용을 강제하는 체크리스트가 아니다. 발견한 문제의 원인을 좁히거나 출시 전 남은 위험을 확인할 때 개발 담당자가 요청할 항목이다. 강제 종료 테스트는 평소의 소중한 운동 기록 대신 짧은 별도 기록으로 수행한다. 차량 이동은 러닝 정확도 테스트로 사용하지 않는다.

| # | 조건 | 절차 | 확인할 것 |
|---|---|---|---|
| A | 전면 | 앱 화면을 열고 알려진 야외 코스 1km 이상 이동 | 거리, 경로 모양, 정확도, 좌표 공백 |
| B | 다른 앱 | 시작 후 다른 앱으로 전환해 10분 이상 이동, 복귀 후 종료 | 백그라운드 위치 수신과 기록 유지 |
| C | 잠금 | 시작 후 측면 버튼으로 잠그고 10분 이상 이동 | 잠금 구간 좌표·시간·거리 유지 |
| D | 일시정지 | 일시정지한 채 다른 곳으로 이동, 재개 후 이동 | 정지 구간 미집계·직선 연결 없음 |
| E | 강제 종료 | 짧게 측정 후 앱 전환 화면에서 종료, 이동 후 재실행 | 중단 안내, 저장된 경로 복구, 종료 중 이동 미집계 |
| F | 복구 후 재개 | E의 기록을 이어서 측정해 종료 | 새 구간, 앞 기록 유지, 중복 거리 없음 |
| G | 배터리 | 충전 없이 30~60분 잠금 측정 | 잔량 변화·충전 여부·위치 정확도·공백 |

OS가 메모리 부족으로 종료하는 상황과 전원 재시작은 별도 후속 검증이다. 강제 종료 테스트가 둘까지 검증한 것은 아니다.

## 5. 초기 판정 기준 제안

아래 값은 검토·조정할 내부 기준이다. 아직 실측에 근거한 제품 보장이 아니다.

- 평소 운동의 두 앱 비교로 이상 구간을 먼저 찾는다. 정밀 검증이 필요하면 알려진 개방된 야외 코스에서 3회 이상 측정하고 거리 오차 5% 이내를 초기 목표로 본다. 기본 내부 테스트의 필수 조건이 아니다. 비교 앱의 값도 진실로 단정하지 않는다.
- 30초 무수신만으로 실패 판정하거나 경로를 분리하지 않는다. 횡단보도 정지·거리 필터·배치 전달·실제 이동 누락을 구분한다. 누락이 확인된 구간과 불확실한 거리를 숨기면 실패다.
- 중단 복구는 마지막 저장 확정 시점까지의 채택 좌표·거리·시간과 일치해야 한다. 강제 종료 중 누락을 숨기거나 직선으로 채우면 실패다.
- 배터리는 병행 사용에서 먼저 경향만 본다. 문제가 보이면 충전·디버거 없이 같은 기기·유사 코스·시간·화면 사용으로 Runary 단독과 기존 앱 단독을 비교한다. 30분에 5%p 이하라는 초기 목표는 검증 전 참고값이다. 병행 사용·충전 중 결과로 단독 소모를 통과 판정하지 않는다.
- 다른 운동 앱을 실행하지 않고 Runary 자체 워치 운동에서 심박을 수집·표시·보관해야 한다. 워치 미착용·연동 미사용·심박 권한 미허용·미수신에서도 아이폰으로 시작·종료·저장할 수 있고 심박은 미측정이어야 한다. 심박이 없는 기록도 정상 기록으로 보관하며 값을 0으로 채우지 않는다.
- 심박은 값이 있다는 것보다 새 값이 운동 중 지속적으로 들어오는지 확인한다. 오래된 값·전면 복귀 후 몰린 값만 보이면 실시간 심박 기능을 통과 처리하지 않는다. 심박 유지에 활용할 수 있는 지연 한도는 실제 수신 분포를 보고 확정한다.

- 전체 경로와 공백: 실제 기록을 저장하지 않는 개발 전용 합성 화면에서 떨어진 두 구간의 모든 꼭지점·출발·종료가 지도 안에 보였고, 구간 사이 직선은 없었다. 확인 후 임시 화면을 제거했다. 야외 이동 실측과 구분한다.

배경 파일 검사는 실제 아이폰의 파일 시스템에서도 수행했다. 앱 기본 이미지의 동시 복사·원본과 복사본의 해시 일치·정상 파일 재사용·빈 파일 다시 준비·존재하지 않는 원본의 복사 실패 후 미완성 파일 정리를 확인했다. 검사 전용 이름의 파일만 만들고 정리했으며 초안·보관함·사용자 사진은 바꾸지 않았다. 임시 검사 화면은 확인 후 제거했다. 공간 부족 중 일부 복사는 모의 검사로 확인했으며 아이폰 저장 공간을 실제로 가득 채우지 않았다. 이전 버전이 남긴 비어 있지 않은 손상 파일을 모두 찾아 복구하는 기능은 아니다.

존재하지 않는 검사 전용 기록 주소도 실제 아이폰에서 열어 조회 실패·재시도 안내를 확인했다. 앞서 보던 완료 기록의 내용·지도·삭제 버튼이 나타나지 않았고 재시도 후에도 같은 안내를 유지했다. 이 검사로 기록을 만들거나 삭제하지 않았다. 정상 완료 기록은 별도로 지도·1분 26초·0.01km 표시를 다시 확인했다.

종료 저장 회귀 검사는 Mac의 임시 저장소에만 실패를 주입했다. 확정 로그의 완료 복구와 종료 시각 보존을 확인한 것이며, 아이폰 저장 공간 부족 상태에서 네이티브 타이머의 자동 재시도까지 실측한 것은 아니다.

종료 저장 수정 뒤 아이폰·워치 전체 Debug 재컴파일을 통과하고 기존 아이폰 개발 프로파일로 QA 복사본을 다시 덮어 설치했다. 미러링에서 최신 앱이 8081 서버로 열리고 홈의 결과물 22개·이어 만들기 초안이 유지되는 것을 확인했다. 앱 삭제·재가입·기록 초기화는 하지 않았다. 워치 앱은 QA 복사본에서만 제외했으며 워치 실기기 검증은 여전히 남아 있다.
