# Runary 1차 App Store 심사 준비

확인일: 2026-10-12. 지응이 정리한 [제출 체크리스트](https://app.notion.com/p/phs00/appstore-submission-checklist-3f240e8014f980cdbb5ffe7035f9cfc1?source=copy_link)를 코드, 배포 기록, App Store Connect와 대조했다. 최초 조회 결과와 이후 준비 작업을 함께 기록한다. 정식 심사 요청과 외부 공개 설정은 변경하지 않았다.

## 10월 12일 후속 작업

하트 샘플 체험을 구현하고, 개인정보 처리방침과 FAQ, 공지, 안내 허브를 정식 제출 준비 범위로 정리했다. 현재 방침 주소는 유지했으며 로그인 없이 본문을 확인했다. 이전 본문은 날짜별 변경 이력에 보관한다. 아래의 최초 조회 결과와 당시 남은 항목은 이 후속 결과와 구분해서 읽는다.

사용자는 이 소스로 정식 심사 준비용 일반 빌드를 TestFlight에 등록하고 팀 공유 메시지를 작성하도록 요청했다. 소스 `29caba1770f066ae778f2493e439fe7251a818a0`의 깨끗한 배포 사본에서 `production` 빌드 `1.0.0(37)`을 만들었다. 측정 기능이 꺼져 있고 워치 앱이 없는 것, 하트 샘플 포함과 서명을 바이너리에서 확인했다. Apple 사전 검증도 오류 없이 통과했다. 업로드와 TestFlight 처리 결과는 [배포 기록](build-and-dev-commands.md)에 남긴다.

`1.0.0(37)`을 업로드하고 Apple의 `VALID / IN_BETA_TESTING` 상태를 확인했다. 등록된 내부 테스터는 TestFlight에서 업데이트할 수 있다.

App Store 정식 심사 요청, 외부 공개 링크 변경, 스토어 자료와 App Privacy 설문 검토는 별도 후속 작업이다. 실제 영상 저장을 포함한 팀의 최종 사용 확인과 스토어 자료 검토는 이 빌드로 진행한다.

## 이번에 제출할 범위

[10/6 결정](../decisions/2026-10-06-second-sprint-app-store.md)에 따르면 1차는 **측정 기능을 제외한 버전**으로 10/13까지 준비한다. 건강 앱의 러닝 기록을 불러와 경로 애니메이션을 편집하고 영상으로 저장·공유하는 기능이 대상이다. 측정 기능 포함 제출은 11/3~11/10으로 나눴다.

최근 TestFlight 36번은 측정 기능과 워치 진단이 켜진 내부 테스트 빌드다. 그대로 1차 정식 심사에 선택하면 위 결정과 맞지 않는다. 기존 일반 배포 빌드 30번을 다시 검증해 선택하거나, 현재 코드에서 `production` 프로필로 측정 기능을 제외한 빌드를 만들어야 한다. 최신 빌드를 반드시 제출할 필요는 없다.

### 10/12 후속 정리: 담당과 빌드 준비 순서

사용자는 아래 작업 목록의 4번 스토어 자료를 지민이 준비하고 있을 것으로 보고, 현수는 1~3번을 우선 준비하겠다고 했다. 지민의 실제 준비 상태는 아직 확인하지 않았으므로 담당이 확정됐다고 기록하지 않는다.

**샘플 기능을 추가하기로 하면 기존 빌드 재사용 대신 새 빌드가 필요하다.** 1번의 제출 빌드 최종 확정은 2번 재현 방법과 3번 개인정보 검토 뒤에 한다. 진행 순서는 다음과 같다.

1. 측정 기능 제외 범위를 유지하고 샘플 기록의 진입·사용 범위를 정한다.
2. 샘플 기능을 추가한다면 PRD/FRD 확인 후 구현하고, 실제 데이터 처리에 맞춰 개인정보 자료를 검토한다.
3. 새 `production` 빌드를 만들고 App Store Connect에 업로드해 TestFlight에서 검증한다.
4. 검증한 같은 빌드를 정식 심사에 선택한다. 지민에게는 이 빌드를 기준으로 스크린샷·소개를 맞추도록 전달할 자료를 준비한다.

빌드 번호는 새 업로드를 식별하도록 증가시킨다. 앱 버전 `1.0.0`을 올려야 하는지는 별개이며, App Store Connect의 제출 버전 표기와 맞춰야 한다. TestFlight 검증은 팀의 사전 확인 단계로 권장하는 것으로, 정식 제출 전에 반드시 별도의 외부 베타 심사를 거쳐야 한다는 뜻은 아니다. [Apple 빌드 업로드 안내](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds/), [심사 빌드 선택 안내](https://developer.apple.com/help/app-store-connect/manage-builds/choose-a-build-to-submit)

샘플 구현의 제안 범위는 다음과 같다. 이후 사용자가 정식 앱 포함 여부를 확인하고 하트 경로를 선택해 구현 범위를 확정했다. 세부 기준은 [승인된 샘플 FRD](../specs/frd/sample-record-experience.md)를 따른다.

- 일반 사용자도 찾을 수 있는 ‘샘플 기록으로 만들어 보기’ 진입을 제공한다.
- 건강 권한을 허용하지 않아도 가상의 기록으로 실제 편집·영상 저장까지 진행한다.
- 샘플임을 표시하고 건강 앱에 기록을 쓰거나 사용자의 실제 러닝 기록에 섞지 않는다.
- 기존 편집·영상 생성 기능을 사용하며, 샘플 때문에 위치 이름 조회나 다른 외부 요청이 발생하는지도 확인한다.

기존 미리보기만으로 이 흐름이 구현됐다고 설명하지 않는다. Apple은 데모 모드를 제공할 경우 데모 데이터로 실제 기능을 보여 주도록 안내한다. [완전한 심사를 위한 정보 제공](https://developer.apple.com/help/app-review/before-submitting-for-review/complete-review)

### 심사 재현 경로

최초 확인 때 첫 화면에 샘플 경로 애니메이션은 있었지만, 그 샘플을 선택해 실제 편집·영상 생성으로 이어지는 경로는 없었다. 실제 러닝 기록이 없는 심사 기기에서는 핵심 기능 확인이 어려울 수 있다. 로그인은 없으므로 데모 계정을 만드는 작업은 필요하지 않다.

이후 [하트 샘플 결정](../decisions/2026-10-12-heart-sample-experience.md)과 PRD/FRD에 샘플 체험 범위를 정리했다. 사용자는 로컬 미러링 확인을 먼저 요청했으며 TF 업로드는 그 뒤에 진행한다. 실제 검증 전 심사 메모에 완성된 데모 모드가 있다고 쓰지 않는다. Apple은 심사자가 앱 기능에 충분히 접근할 수 있고 필요한 설명·자료를 제공하도록 요구한다. [App Review Guidelines: Before You Submit](https://developer.apple.com/app-store/review/guidelines/)

### 개인정보에서 주의할 부분

현재 앱에는 로그인과 자체 서버 업로드 기능이 없지만, 이것만으로 ‘데이터 수집 없음’을 선택할 수는 없다. `expo-updates`가 설정되어 있고, Expo의 현재 배포 안내는 이를 사용하는 앱에 App Privacy의 Crash Data 신고를 안내한다. 실제 제출 빌드의 SDK와 전송 동작을 확인해 설문에 반영한다. Apple은 기기 밖으로 전송되어 개발자나 제3자가 일정 기간 접근하는 데이터를 수집 범위로 설명한다. [Expo App Store 배포 안내](https://docs.expo.dev/distribution/app-stores/), [Apple App Privacy](https://developer.apple.com/app-store/app-privacy-details/)

앱 내 개인정보 링크는 첫 화면과 홈에 있으며 주소는 `https://phs00.notion.site/privacy`다. 최초 조회 때는 적용 범위가 베타 버전으로 적혀 있었고, HTTP 200 응답만으로 본문 공개 여부를 확인하지 못했다. 이후 사용자 요청으로 일반 배포 앱과 샘플의 적용 범위, 외부 서비스 통신, 보관과 삭제 조건을 반영했다. 현재 공개 주소에서 로그인 없이 본문이 표시되는 것도 확인했다. 변경 전후 본문과 검증은 [공개 문서 기록](public-docs-log.md)에 남겼다.

36번 내부 앱에는 개인정보 매니페스트 파일들이 있다. 이것은 일반 제출 빌드의 모든 SDK 요구사항 충족을 보장하지 않는다. 최종 바이너리의 매니페스트·Required Reason API·대상 SDK를 다시 확인한다. 오픈소스 라이선스 고지와 이미지·폰트 사용 권리는 별도로 점검한다. [Apple 타사 SDK 요구사항](https://developer.apple.com/support/third-party-SDK-requirements/)

### 스토어 자료와 계정 설정

- 스크린샷은 기록 선택, 경로 편집, 완성 영상 등 실제 사용 장면으로 준비한다. 허구의 샘플 기록을 사용하고 개인 주거지 경로나 건강 정보를 그대로 노출하지 않는다. 기본 작업 크기는 세로 `1320×2868`로 잡을 수 있다. Apple은 JPEG/JPG/PNG 1~10장을 허용하며 투명 배경은 허용하지 않는다. 확인한 36번 바이너리는 iPhone 기기군만 포함한다. 최종 제출 빌드의 기기군을 기준으로 필요한 화면 크기를 확정하고, iPad의 iPhone 호환 실행도 확인한다. [Apple 스크린샷 규격](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications), [Expo 배포 안내](https://docs.expo.dev/distribution/app-stores/)
- 심사 메모에는 실제 데이터 불러오기 조건, 건강 권한 안내, 샘플 경로가 있다면 진입 방법, 영상 저장·공유 확인 방법을 적는다. 제출에서 제외한 측정·워치 실험은 소개와 스크린샷에 넣지 않는다. [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)
- 계정 소유자에게 한국 연락 정보와 계약 상태를 확인한다. 개인 개발자에게는 한국 배포 시 연락 이메일이 요구된다. 사업자 정보는 계정 유형·유료 계약 여부에 따라 달라지므로 임의로 입력하지 않는다. [한국 규정 준수 정보](https://developer.apple.com/help/app-store-connect/manage-compliance-information/manage-korea-compliance-information)
- 현재 설정의 `ITSAppUsesNonExemptEncryption`은 `false`다. 제출 빌드의 실제 암호화 사용과 일치하는지 확인한다. 단순히 설정값이 있다는 이유로 수출 규정 확인이 끝났다고 처리하지 않는다. [수출 규정 준수 안내](https://developer.apple.com/help/app-store-connect/manage-app-information/overview-of-export-compliance)
- 현재 로그인 기능이 없으므로 계정 삭제와 소셜 로그인에 대응하는 Apple 로그인 추가는 이번 제출의 작업으로 잡지 않는다. 실제 기능이 바뀌면 다시 검토한다. [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)
