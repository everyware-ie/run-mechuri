# 10월 13일 제출용 일반 빌드

회의 중 사용자가 최종 리뷰 보완과 공개 Notion 도메인 변경을 반영한 새 빌드를 만들고, 검증 후 TestFlight에 바로 등록하도록 요청했다. [작성 중인 회의록](https://app.notion.com/p/3f840e8014f98005bce2ccb8fd60ac5e)의 2026-10-13 20:30 KST까지 작성된 내용을 참고한다. 작성 중 문서의 나머지 안건을 확정 결정으로 취급하지 않는다.

이번 일반 빌드는 앱 보관 영상의 백업 제외, 샘플과 실제 기록의 동시 선택 방지, 앱 내 개인정보 링크의 새 도메인을 포함한다. 측정·워치 기능을 제외한 `production` 프로필을 유지한다. 스토어 등록 자료는 회의에서 지민이 담당하고 있으며 이 작업에서 별도로 덮어쓰지 않는다.

## CI 실패 확인

PR #110의 최종 커밋 CI는 통과했지만, [머지 후 main 실행](https://github.com/everyware-ie/run-mechuri/actions/runs/38387187461)은 기록 상세 화면의 첫 테스트가 5초 제한을 넘겨 실패했다. 타입·린트와 나머지 321개 테스트는 통과했다. 화면 초기화 시간이 필요한 해당 테스트만 15초로 명시하고, 테스트마다 비동기 모의 함수의 구현과 대기열을 초기화한다. 대기 중 이전 기록을 보여주지 않는 검증은 유지한다. 검증 결과는 확인 후 아래에 추가한다.

## 빌드 전 검증

`TZ=UTC`와 병렬 워커 2개로 CI와 같은 Jest 검사를 실행해 43개 묶음·322개가 통과했다. 타입 검사와 문서·diff 공백 검사가 통과했고 린트는 오류 0개·기존 경고 30개다. 앞선 최종 리뷰의 일반 iOS 빌드와 백업 제외 검증은 그대로이며, 이번 제품 변경은 공개 URL이다.

## 제출 기록

### 회의 중 아이콘 교체 요청

38번을 업로드한 뒤 사용자가 제공한 `r-mark 4.png`로 앱 아이콘을 교체하도록 요청했다. 원본 그대로 복사했고 실제 투명 픽셀이 없는 것을 확인했다. 기존 iOS 아이콘 생성의 1024×1024 변환과 알파 제거를 사용한다. 새 아이콘을 포함한 다음 빌드를 최종 후보로 준비하며, 38번은 이번 아이콘 이전 빌드로 구분한다.

38번의 클라우드 생성은 20:38:30 → 20:45:26 KST로 6분 56초가 걸렸다. 검증·Apple 업로드·처리와 시뮬레이터 연결 시간은 이 생성 시간과 구분한다. 시뮬레이터용 일반 Release 빌드·iPad 설치·앱 프로세스 실행은 성공했으나 화면 연결이 지연되어 샘플 생성·기기 저장·복구의 실제 확인을 완료하지 못했다.

새 아이콘 빌드는 `1.0.0(39)`이며 [EAS 빌드](https://expo.dev/accounts/team-mechuri/projects/mechuri/builds/37019a4c-ab91-4b1d-a8d5-591a934bb09f), 소스 `fbb07ad7c5fa6bb76d75e04d10a7cccc49f459ff`다. 38번 소스와 제품 파일을 비교하면 아이콘 PNG만 다르다. 같은 Expo 생성 도구로 1024×1024·RGB·불투명 출력을 만들고 원본 형태가 유지된 것을 확인했다. 최종 IPA와 Apple 결과는 빌드 완료 뒤 기록한다.

38번은 Apple 사전 검증·업로드를 통과하고 `VALID / IN_BETA_TESTING`으로 처리됐다. 임시 제출 키 파일은 사용 후 제거했다. 새 도메인·백업 제외 코드·하트 샘플·일반 빌드 플래그·워치 제외·배경 processing 모드·서명·개인정보 매니페스트를 확인했다. IPA SHA-256은 `9b924dc91988b6b03543b05fd4496d57aef15eb2562486cb11c0a4572f7f60e8`이며 Apple Delivery UUID는 `323268fb-d00c-4929-8ad9-4e953e602002`다. 39번이 최종 아이콘 후보이므로 38번과 구분한다.

21:03 KST 조회에서는 제출 버전이 `1.0.0`으로 바뀌고 38번이 선택되어 있었다. 한국어 스크린샷 5장·지원 URL·심사 연락처가 등록됐다. 심사 메모와 개인정보 URL은 당시 입력 전이었다. [심사 메모 초안](app-store-review-notes.md)을 준비했다. 최종 빌드 등록 뒤 39번으로 교체해야 한다.

39번 빌드는 21:02:06 → 21:09:38 KST로 7분 32초에 생성됐다. 대기 중 사용자에게 38번의 샘플 영상 생성 → 사진 앱 저장 → 앱 재실행 후 다시 편집을 확인해 달라고 요청했고, 사용자가 `확인했고 정상 동작`이라고 답했다. 38번과 39번의 기능 소스는 같고 아이콘만 다르므로 이 사용자 확인을 기능 QA 근거로 남긴다. 39번의 직접 실기기 설치나 iPad 조작 전체를 확인했다고 바꾸어 기록하지 않는다.

39번 IPA에서 새 도메인과 백업 제외 코드, 일반 빌드·워치 제외·개인정보 매니페스트·서명을 확인했다. 실제 배포 아이콘도 확인했으며 Assets.car의 1024×1024 렌디션은 불투명이다. Apple 사전 검증·업로드가 오류 없이 통과했고 21:19 KST 업로드 완료 뒤 자동 처리를 기다린다. 임시 제출 키 파일은 제거했다. Delivery UUID는 `6c17a0da-7bee-4967-a6d0-c81bd9d08abf`, IPA SHA-256은 `79c7dbef89f887fd68b768f98f1c1802965015a748a23859c0c7391118ffe70f`다.

21:26 KST에 39번의 `VALID / IN_BETA_TESTING`과 미만료 상태를 확인했다. [팀 공유 문구](testflight-39-team-message.md)는 작성만 했다. 공개 테스트 그룹·링크와 정식 심사 요청은 변경하지 않았다. 사용자가 제출 화면에서 저작권 입력을 문의해 Apple의 ‘취득 연도 + 실제 저작권자’ 기준과 팀 권리 합의가 있을 경우 `2026 팀 메추리` 예시, 저작권 기호 자동 추가를 안내했다. 저작권 소유 관계를 임의로 확정하거나 입력하지 않았다.

공개 방침은 원문을 유지한 채 갱신됐고 새 공개 주소에서 2026.10.13 버전과 38번부터의 백업 제외 문구를 확인했다. 데스크톱에서는 실제 문단 표시를 확인했다. 데스크톱 사용자 에이전트의 375px 너비 확인은 Notion의 여백·스크롤 영향으로 실제 모바일 사용성을 확정하지 못했으므로 아이폰 화면 확인과 구분한다.

EAS 일반 빌드 `1.0.0(38)`을 소스 `2eda0635db3001bdb96a076b5aff2657dae24518`에서 시작했다. [진행 링크](https://expo.dev/accounts/team-mechuri/projects/mechuri/builds/3e8481ac-0e46-4dae-bc35-f9465cff45e9)는 `production` 프로필·채널과 STORE 배포다. 사용자 회의 안건과 개인 launch 파일은 빌드 소스에서 제외했다. 기존 인증서와 App Store 프로파일을 재사용했다.

공개 방침을 2026.10.13으로 갱신해 초안·결과물 정보와 38번부터의 보관 영상 백업 제외를 설명했다. FAQ·공지와 전체 보관본을 함께 반영했고 변경 이력·이전 문서 목록은 10/13 → 10/12 → 10/3 순서다. 사진 앱 및 외부 공유와 이전 백업은 별도 관리 대상으로 유지한다.

회의 중 20:38 KST 재조회에서 한국어 소개와 새 지원 URL의 등록을 확인했다. 당시 정식 버전은 아직 `1.0`이고 스크린샷·개인정보 URL·심사 메모와 연락처 일부가 등록 전이었다. 사용자가 지민이와 실시간으로 등록 중인 상태이므로 이 시점의 미등록 항목을 최종 결과로 단정하지 않는다.

소스 커밋·빌드 번호·바이너리 확인·Apple 처리 결과는 완료 후 [배포 기록](build-and-dev-commands.md)에 남긴다. TestFlight 업로드와 정식 심사 요청을 구분한다. App Privacy와 스토어 자료, 실기기·iPad 최종 확인은 수행한 범위만 완료로 기록한다.
