# 정식 심사 최종 검토

2026-10-13 기준으로 현재 작업 브랜치와 TestFlight `1.0.0(37)`, 공개 문서, App Store Connect 등록 상태를 대조했다. 사용자는 발견한 문제를 수정하고 검증 후 PR 생성·머지를 요청했다. 이 검토와 저장소 머지는 정식 심사 제출을 대신하지 않는다.

## 발견한 문제와 수정

| 항목 | 판단과 조치 |
|---|---|
| 앱 보관 영상의 기기 백업 | `Documents/clips`에 백업 제외 속성이 없었다. 경로·심박 등 건강 정보가 들어갈 수 있으므로 기존 디렉터리와 새 출력 준비에 제외 속성을 적용했다. 원본 파일은 그대로 보관한다. |
| 내부 워치 권한 안내 | 워치 건강 저장소 직접 읽기를 추가한 뒤에도 ‘워치 건강 권한 불필요’라는 안내가 남아 있었다. 아이폰과 워치의 읽기 권한을 각각 확인하도록 수정했다. 일반 제출 앱에는 이 화면이 없다. |
| 샘플과 실제 기록의 동시 선택 | 실제 좌표 조회 중 샘플을 막는 기존 처리만으로 반대 순서와 화면 갱신 전 연속 탭을 막지 못했다. 양쪽에 동일한 선택 잠금을 적용하고 실제 화면 회귀 검사로 확인했다. |

건강 기록과 트랙을 저장하는 AsyncStorage 2.2.0은 iOS에서 기본적으로 백업에서 제외한다. 설치된 SDK 소스와 37번 Info.plist에 포함 허용 설정이 없는 것을 대조했다. 새 영상 디렉터리 처리의 기준은 [Apple 심사 지침 5.1.3(ii)](https://developer.apple.com/app-store/review/guidelines/#health-and-health-research)다. 임시 캐시로 옮기거나 영상 출력을 축소하지 않았다.

이 네이티브 보완은 **이미 등록한 37번에 포함되지 않는다.** 37번은 비교와 팀 사용 확인용으로 유지한다. 정식 심사에는 이번 수정으로 새 일반 빌드를 만들고 바이너리·실기기 확인을 마친 뒤 선택한다. 정확한 37번 소스 태그 `runary-appstore-1.0.0-37`은 바꾸지 않는다.

## 공개 문서와 앱 기능

로그인 없는 브라우저에서 현재 개인정보 처리방침의 전체 본문과 문의, 변경 이력 링크가 표시되는 것을 확인했다. 운영 주체, 처리 항목, 외부 통신, 삭제·보관, 권한 철회와 문의 방법을 실제 코드와 대조했다. 하트 샘플은 건강 데이터 쓰기나 장소 조회를 하지 않으며 실제 기록과 구분한다. 일반 빌드에 측정·워치 앱이 없다는 설명도 37번 바이너리와 일치한다.

사용자가 최종 검토한 공개 방침의 10/13 편집 내용은 [현재 본문 사본](public-docs-2026-10-12/privacy-current.md)에 동기화했다. 원래 10/12 보관본은 당시 본문을 보존한다. 이번 검토에서 공개 Notion 본문을 다시 수정하지 않았다. 새로운 백업 제외 동작의 공개 안내는 새 빌드 적용 범위와 함께 갱신해야 한다.

서비스 이용약관 초안은 앱에 연결하지 않았으며 현재 무료·비로그인 앱에 유료 구독 약관을 추가하지 않았다. 문서 안에서 공유 대상을 설명하는 `Instagram` 표기는 [Meta 공식 브랜드 지침](https://www.meta.com/brand/resources/instagram/instagram-brand/)과 대조했으며 제휴·후원을 주장하지 않는다.

## 지민이 준비한 스토어 자료

[PR #109](https://github.com/everyware-ie/run-mechuri/pull/109)에 한국어 문구와 스크린샷 5장이 준비되어 있다. 이번 변경에 자료를 중복으로 넣거나 그 PR을 함께 머지하지 않는다. 해당 PR의 문구에는 아래 수정이 필요하다.

- ‘어디에도 보내지 않아요’는 실제 장소 이름 조회와 사용자가 선택한 Instagram 공유를 설명하지 못한다. ‘러닝 기록과 완성 영상을 운영팀 서버에 업로드하지 않습니다’로 범위를 정확히 표현한다.
- ‘모두 내가 실제로 달린 데이터’와 실제 건강 기록만 필수라는 안내에는 하트 샘플 체험의 예외를 반영한다.
- 지원 URL은 `https://phs00.notion.site/runary`, 개인정보 URL은 기존 `https://phs00.notion.site/privacy`를 사용할 수 있다. 실제 등록할 때 공개 접근을 다시 확인한다.
- 첫 이미지의 ‘사진으로 남겨요’와 영상 제작 기능의 불일치는 지민이 PR에도 후속 수정으로 기록되어 있다. 제출 전에 같은 빌드의 화면과 문구를 맞춘다.

심사 자료가 실제 기능과 같아야 하는 근거는 [Apple 심사 지침 2.3](https://developer.apple.com/app-store/review/guidelines/#accurate-metadata)다. 이 검토에서는 지민이 스크린샷 5장의 모든 픽셀과 사용 권리를 확인하지 않았다.

## App Store Connect 재조회

2026-10-13 19:40 KST의 읽기 전용 API 조회 결과다.

| 항목 | 현재 상태 |
|---|---|
| 정식 버전 | `1.0`, `PREPARE_FOR_SUBMISSION` |
| 선택한 빌드 | 없음 |

자료를 작성한 것과 App Store Connect에 등록한 것은 구분한다. 현재 상태로 정식 심사를 바로 제출할 수는 없다. 새 빌드 선택, 버전 표기 정합성, 지민이 자료 입력, URL과 연락처, 샘플 진입을 설명하는 심사 메모가 필요하다. 실제 심사 요청과 자동 출시 설정은 변경하지 않았다.

App Privacy·연령 등급·계약·배포 국가와 한국 연락 정보는 이번 API 조회로 완료 여부를 확인하지 못했다. Chrome의 등록 화면 조회가 연결 시간 초과로 끝나 해당 화면의 설문은 미확인이다. 특히 `expo-updates`가 포함되어 있으므로 ‘데이터 수집 없음’을 자동 선택하면 안 된다. [Expo 공식 제출 안내](https://docs.expo.dev/distribution/app-stores/#app-privacy-questions)는 Crash Data 신고를 안내하며, 실제 응답은 [Apple 데이터 수집 정의](https://developer.apple.com/app-store/app-privacy-details/)와 SDK 동작에 맞춰 확인한다.
