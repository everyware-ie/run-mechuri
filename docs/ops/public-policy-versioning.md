# 공개 개인정보 처리방침 개정 방법

현재 방침은 [기존 공개 주소](https://phs00.notion.site/privacy)에서 계속 제공한다. 이 주소는 앱과 App Store Connect에서 사용하므로 개정할 때 페이지를 새로 만들거나 주소를 바꾸지 않는다. 이전 본문은 [변경 이력](https://phs00.notion.site/p/3f740e8014f9813b980ecca4650b3456?pvs=24)에 날짜별로 보관한다.

## 개정할 때

1. 현재 공개 본문을 읽고 저장소에도 변경 전 사본을 남긴다. 적용 중인 앱 버전의 권한, 저장과 삭제 동작, 외부 서비스 통신을 코드와 대조한다.
2. 기존 버전의 보관본이 없다면 전체 본문을 변경 이력의 하위 페이지로 보관한다. 제목에는 날짜와 당시 버전을 적고, 현재 방침으로 돌아가는 링크를 넣는다. 확정한 과거 보관본은 새 내용으로 덮어쓰지 않는다.
3. 시행일과 달라지는 내용을 정한 뒤 현재 방침을 수정한다. 새 기능이 아직 배포되지 않았다면 어느 버전부터 적용되는지 구분한다. 문서 공지를 개인정보 처리 동의로 간주하지 않는다.
4. 확정한 새 방침의 전체 사본도 날짜별 개정본으로 보관한다. 변경 요약과 보관본 링크를 개정 이력 맨 위에 추가한다. **이전 문서 안내의 하위 페이지도 최근 개정본부터 나열한다.** 도구로 새 페이지를 만들면 맨 아래에 붙을 수 있으므로 두 목록의 순서를 함께 확인한다. 기존 하위 페이지를 삭제하거나 링크만 다른 곳으로 옮기지 않는다.
5. 자주 묻는 질문과 공지사항을 함께 고친다. 중요한 변경은 적용 전에 별도 공지로 안내하고 필요한 권한 요청과 동의 절차를 준비한다. 고정된 공지 기간이나 묵시적 동의를 임의로 약속하지 않는다.
6. 로그인하지 않은 브라우저에서 현재 방침, 변경 이력, 각 보관본을 열어 본문과 링크를 확인한다. Notion의 공개 반영이 늦거나 일부만 보이면 새로고침 후 실제 표시 내용을 확인한다.
7. 변경 전후 사본과 확인 결과를 [공개 문서 변경 기록](public-docs-log.md)에 남긴다. 앱의 개인정보 공개 항목도 실제 기능과 외부 서비스 처리에 맞는지 확인한다. 정책 수정과 앱 바이너리 제출은 별도 작업으로 기록한다.

Notion의 내부 페이지 기록은 복구에 사용한다. 사용자가 이전 방침을 읽는 공개 보관본을 대신하지 않는다.

## 문체를 다듬을 때

사실과 수치, 날짜, 서비스 이름, 정보 항목, 처리 목적, 삭제 조건과 예외를 먼저 고정한다. 이 내용은 문체를 다듬는 과정에서 빼거나 단정적으로 바꾸지 않는다. 예를 들어 ‘삭제를 시도합니다’를 ‘삭제합니다’로 바꾸면 안 된다.

문장과 문단의 줄바꿈, 작성 완료 전 검토는 [문서 작성 규약의 해당 절](../../.claude/conventions/writing.md#5-문장과-문단의-줄바꿈을-검토한다)을 따른다. 문서별로 별도 기준을 만들지 않는다.

Notion 도구는 일반 빈 줄을 제거한다. 같은 문단에서 줄만 바꿀 때는 `<br>`을 사용하고, 문단 사이의 빈 줄에는 독립된 `<empty-block/>`을 사용한다. 수정 뒤에는 게시 화면의 표시도 확인한다. 이전 글이 섞여 보이면 도구의 성공 응답만으로 완료하지 않는다. 하위 페이지가 있는 문서는 모든 `<page>` 참조를 유지한 상태에서 문제를 해결한다.

저장소의 [문서 작성 규약](../../.claude/conventions/writing.md)과 그 규약이 참고한 [im-not-ai의 윤문 지침](https://github.com/epoko77-ai/im-not-ai/blob/main/skills/humanize-korean/references/rewriting-playbook.md)을 참고한다. 2026-10-12 작업에서는 공개 지침을 읽고 수동으로 대조했으며, 플러그인 설치나 자동 진단 프로그램을 실행하지 않았다.

## 참고한 공개 문서 구조

[케어챗 개인정보 처리방침](https://karechatprivacy.oopy.io/)은 이전 방침을 별도 목록에서 볼 수 있게 한다. [설탭 개정 공지](https://seoltabappnotice.oopy.io/3ad853a5-11dd-80e8-b906-fee7418dad82)는 적용일과 변경 내용을 안내한다. 두 사례의 문서 구조를 참고했으며, 다른 서비스의 처리 항목이나 동의 조건을 Runary에 복사하지 않았다.

[Notion 공개 페이지 안내](https://www.notion.com/ko/help/public-pages-and-web-publishing)에 따라 공개 페이지 수정은 사이트 내용에도 반영된다. 기존 주소를 유지하고, 실제 공개 화면을 확인한다. 앱 심사에서는 [Apple 개인정보 지침](https://developer.apple.com/app-store/review/guidelines/#privacy)에 맞게 접근 가능한 방침과 실제 정보 처리가 일치해야 한다.
