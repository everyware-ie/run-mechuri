# App Privacy 적용 전 대조

현재 심사 대기 중인 1.0.0(39)의 App Privacy 답변은 변경하지 않았습니다. 이 문서는 측정 기능을 포함한 다음 버전을 제출할 때 사용할 대조표입니다.

권한을 요청하는 것과 Apple이 정의하는 데이터 ‘수집’은 다릅니다. 기기 밖으로 전달해 실시간 요청 처리에 필요한 기간보다 오래 접근할 수 있게 보관하는지 확인해야 합니다. 기기 안에서만 처리하는 데이터는 해당 정의의 수집이 아닙니다. [Apple App Privacy 기준](https://developer.apple.com/app-store/app-privacy-details/)

| 정보 | 실제 처리 | 제출 전 판단 |
|---|---|---|
| 직접 측정한 위치·경로 | 아이폰에 보관. 워치 단독 GPS 수집 없음 | 기기 보관 자체를 운영팀 서버 수집으로 표시하지 않음. Apple 지도·장소 조회는 별도로 대조 |
| 심박·건강·동작 정보 | 건강 읽기, 워치에서 아이폰으로 전달, 기기 원본 보관과 선택적 건강 운동 저장 | 개발자 서버 전송 없음. 기존 심박 사본 생성 없이 운동에 연결하는 동작과 목적 설명 일치 확인 |
| 지도·장소 이름 | 표시할 지도 영역과 실제 경로 중간 좌표를 Apple 서비스에서 사용 | Apple 프레임워크 처리와 개발자가 별도로 수집하는 범위를 구분. 개정 방침에 외부 통신 설명 |
| 사진·영상과 문구 | 기기에 편집 사본 보관. 공유 선택 시 Instagram에 전달 | 자동 업로드로 설명하지 않음. 이용자가 선택한 전달과 보관·삭제 조건 확인 |
| 업데이트 식별자·접속·오류 정보 | Expo 업데이트 서비스 통신 | 설치 SDK와 Expo의 실제 보관·접근 기준을 확인한 뒤 식별자·진단 등의 공개 항목 확정 |
| 공개 문서 접속 | Notion 웹페이지 통신 | 앱 안 웹페이지에서 발생하는 제3자 처리도 포함해 공개 항목 대조 |
| 문의와 테스트 피드백 | 이용자가 직접 보낸 내용과 첨부 자료, TestFlight 제공 정보 | 선택적 공개 예외가 적용되는지 확인. 문의 자료를 모두 자동 수집한다고 설명하지 않음 |

Expo와 Notion 등 제3자 처리가 있으므로 ‘자체 서버가 없음’만으로 앱 전체를 ‘데이터 수집 안 함’이라고 확정하지 않습니다. 공개 항목을 바꾸기 전에는 현재 App Store Connect 답변, 설치 SDK와 제공자 정책을 함께 대조해야 합니다.

## 권한 설명과 저장

측정 빌드에는 위치, 동작 및 피트니스, 건강 읽기와 운동·경로·심박 연결을 위한 쓰기 목적 설명이 들어갑니다. 건강 저장과 워치 운동 연동은 각각 선택 기능입니다. 건강 저장을 거부해도 Runary 원본은 남습니다.

측정 원본과 건강 저장 상태, 워치 전달 대기 자료의 백업 제외를 코드에서 확인했습니다. 이번 변경으로 새 광고·분석 SDK를 추가하지 않았습니다. 실제 제출 IPA의 권한 키, 개인정보 매니페스트와 확장 구성을 업로드 전에 다시 확인합니다.

## 공개 적용 때 함께 확인할 것

- 적용 버전과 시행일을 정한 개인정보 처리방침, FAQ와 변경 공지.
- 실제 바이너리의 건강 쓰기와 배경 위치 수집 설명.
- SDK와 웹페이지를 포함한 App Privacy 답변.
- 측정 화면과 워치 앱에 맞는 스크린샷·설명·심사 메모.
- 기존 심사 대기 제출을 유지할지, 결과를 기다린 뒤 새 버전을 제출할지 결정.

이 표는 입력 준비 자료이며 App Privacy 설문을 이미 수정하거나 법적 검토를 마쳤다는 기록이 아닙니다.
