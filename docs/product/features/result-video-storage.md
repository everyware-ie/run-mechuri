# 완성 영상의 기기 내 보관

- 근거: [홈과 보관함 FRD](../../specs/frd/home-and-library.md) §2-2 결과물에서 할 수 있는 것, §2-3 무엇이 남나 (`approved`), [PRD](../../specs/prd/running-drawing-mvp.md) §6 내보낸 다음.
- 착수 확인: 사용자가 요청한 후속 안정성 점검 범위에서 기존 영상 보관 기준을 맞춘다. 새 제품 정책은 만들지 않는다.

새 결과물 생성 QA에서 Swift가 MP4를 `temporaryDirectory`에 만들고 보관함은 그 절대 경로만 저장하는 것을 확인했다. 목록과 썸네일은 남아도 임시 파일이 없어지면 재공유할 영상이 사라질 수 있다. 완성된 결과물 파일을 보관한다는 FRD와 어긋난다.

새 영상은 앱의 `Documents/clips/`에 직접 생성한다. 완성 후 별도 복사를 하지 않아 영상 규격과 인코딩 과정은 유지한다. 앱 업데이트로 컨테이너 경로가 달라져도 보관 폴더 안의 파일명으로 현재 경로를 찾는다. 사용자가 결과물을 삭제하면 목록 저장에 성공한 뒤 해당 결과물의 앱 소유 영상만 정리한다. 목록 저장 실패·다른 결과물의 같은 파일 참조·보관 폴더 밖 파일은 삭제하지 않는다.

기존 임시 영상은 자동 이동하거나 삭제하지 않는다. 이미 사라진 파일은 복구할 수 없으며 당시 편집값으로 다시 만들 수 있다. 새 보관 영상은 임시 공간보다 디스크를 오래 사용하므로 삭제 시 파일 정리가 함께 필요하다. 검증 결과는 완료 후 QA 기록에 남긴다.


## 보관 위치 근거

[Apple 파일 시스템 안내](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/FileSystemOverview/FileSystemOverview.html)는 사용자 생성물을 Documents에 두고, tmp는 앱 실행 사이의 보존을 보장하지 않는다고 설명한다. Documents는 시스템 백업 대상이며 큰 영상은 저장 공간과 백업량을 늘릴 수 있다. 이번 수정은 앱 내 보관이며 별도 서버 동기화를 추가하지 않는다.

## 검사 범위

자동 검사에서 새 보관 경로의 컨테이너 복원, 옛 임시 경로 유지, 삭제 시 소유 파일만 정리, 목록 저장 실패 시 보존, 다른 결과물의 같은 파일 참조 보존, 파일 정리 실패 후 다음 저장을 확인했다. 전체 33개 묶음 274개 테스트·타입 검사 통과, 린트 오류 0개(기존 경고 30개). 실제 삭제·저장 공간 부족·강제 종료는 사용자 데이터에 수행하지 않는다.

렌더링 실패·취소 때의 미완성 파일 제거는 기존 Swift 처리를 유지한다. 인코딩 완료 후 앱 강제 종료 등으로 보관함 저장 자체가 끝나지 못한 파일은 남을 수 있다. 실제 보관함 참조를 확인한 뒤 정리하는 후속 점검 항목이며, 완료 영상의 자동 삭제로 해결하지 않는다.


iPhone 11 Pro·iOS 26.6.2 Debug 빌드에서 같은 초안으로 다시 생성한 영상이 `Documents/clips/`에 만들어지고 보관함에 추가되는 것을 확인했다. 보관 위치 변경 전후 영상은 각각 1080×1920·30fps·12초·360프레임이며, 전체 디코딩 픽셀 차이는 0이었다. 기존 영상 19건과 색상/보관 경로 확인 영상 2건을 보존했다. 이후 앱을 홈 화면으로 내리고 같은 초안의 영상을 추가 생성했다. 새 보관 폴더에 완성 파일이 남았고 1080×1920·30fps·12초·360프레임 전체 디코딩을 통과했다. 이 검증은 앱 백그라운드 전환이며 미러링 종료 후 실제 전원 버튼 잠금을 새로 수행한 것은 아니다. 별도 속도 비교는 수행하지 않았다.
