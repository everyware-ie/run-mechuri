# 편집 핀치와 숨기기 안전성 검증

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §4-2 제스처, §7-2 끌어서 숨기기와 지우기 (`approved`)
- 관련 구현: [스토리형 편집 1단계](story-editor-stage1.md)
- 착수 확인: 2026-10-04 사용자가 후속 안정성 작업을 이어 진행하도록 요청했다. 기존의 두 손가락 크기 조절 중 숨기기 방지 기준을 검증한다. TestFlight 배포는 보류한다.

## 확인 범위

두 손가락으로 크기를 조절하다 한 손가락을 먼저 떼도, 같은 조작에서는 러닝 데이터를 숨기거나 문구를 지우지 않아야 한다. 모든 손가락을 뗀 뒤 새로 한 손가락 끌기를 시작하면 숨기기·지우기는 다시 동작한다. 시스템이 제스처를 중단하면 숨기거나 지우지 않는다.

## 발견한 오류

두 손가락인 동안만 숨기기 영역을 비활성화한다. 한 손가락을 먼저 떼고 아래 영역으로 움직이면 영역이 다시 켜지고, 마지막 손가락을 떼면 숨기거나 지운다. 종료 시점에 핀치를 했는지 확인하는 값이 있어도 숨기기 판정에는 적용하지 않는다.

## 수정과 검증

`EditDropGesture`가 조작 시작부터 종료까지 두 손가락 사용 여부를 기억한다. 크기 조절 뒤 한 손가락만 남아도 숨기기 영역이 켜지지 않으며, 영역 진동도 다시 발생하지 않는다. 위치·크기 저장 경로는 유지한다. 조작을 끝내면 상태를 비워 다음 한 손가락 끌기는 정상적으로 숨기거나 지운다. 시스템 중단은 숨기기 없이 기존 위치·크기 저장 경로로 마친다.

- 기존의 현재 손가락 수만 보는 판정을 분리해 테스트하면 핀치 후 한 손가락이 남는 회귀 사례 4개가 실패했다. 수정 후 통과한다.
- 회귀 검사 9개: 한 손가락 진입·이탈, 1·2·3개 손가락으로 시작한 뒤 핀치와 한 손가락 전환, 첫 이동 이벤트 전에 손가락이 줄어든 경우, 영역 위에서 핀치 시작, 시스템 중단, 다음 새 끌기에서 다시 적용.
- 전체 Jest 122개, 타입 검사 통과. 전체 린트 오류 0개, 기존 경고 32개. 문서 정합성 검사 통과.
- 네이티브 코드·패키지·렌더링 규격은 바꾸지 않았다. 앱 설치와 TestFlight 배포는 하지 않았다.

제품 정책과 새 용어를 바꾸지 않으므로 FRD·PRD·결정문은 개정하지 않는다.

## 남은 실기기 확인

러닝 데이터와 문구를 각각 두 손가락으로 키운 뒤 한 손가락을 먼저 떼고 아래 영역으로 움직여 놓는다. 숨김·삭제·영역 진동 없이 위치와 크기가 유지되는지 본다. 이어서 새 한 손가락 끌기로 숨기거나 지우고 되돌리기가 복원하는지 확인한다. 이번 자동 검사는 조작 상태 전환의 판정이며 실제 터치·진동·화면 모양은 확인하지 않았다.
