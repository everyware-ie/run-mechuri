# 원라인 러닝 데이터의 기본 너비 보정

근거: [경로 렌더링 FRD](../../specs/frd/route-rendering.md) §7-5 배치, [결과물 편집 FRD](../../specs/frd/result-editing.md) §7 러닝 데이터와 문구.

## 착수 확인 (2026-09-20)

사용자가 첫 편집에서 원라인 프리셋을 선택하면 거리와 장소가 미리보기 양옆에서 잘리는 화면을 제보했다. 원라인은 장소를 포함한 여섯 항목을 한 줄로 이어 붙이면서 너비 제한 없이 고정 글자 크기로 그렸다. 미리보기와 Swift 저장 영상 모두 같은 구조였다.

## 수정

원라인의 기본 통계 글자 크기를 완성 값 문자열의 예상 너비에 맞춰 줄인다. 최초 보정 후 글자가 너무 작다는 사용자 QA에 따라 좌우 여백을 캔버스 기준 86.4px에서 43.2px(각 4%)으로 줄인다. 원라인만 JetBrains Mono의 고정폭 숫자·영문·구분 기호에 0.62em을 적용한다. 번들 TTF에서 확인한 해당 글자 폭은 0.6em이며 작은 여유를 더했다. 한글 등 대체 서체 문자는 기존 1.05em 여유를 유지한다. 구간 페이스는 두 자리 분을 확보한다. 현재 재생 숫자를 기준으로 매번 축소하지 않아 재생 중 크기가 흔들리지 않는다. 항목 순서·내용은 유지하고, 사용자가 직접 지정한 크기 배율과 이동은 별도로 적용한다.

미리보기·썸네일 공통 배치 함수와 Swift 렌더러에 같은 계산을 적용한다. FRD §7-5 배치에 원라인의 기본 너비 규칙을 보완한다. 저장 영상의 원라인 제목 크기도 미리보기와 같은 22 기준으로 맞춘다. 기존 코드에는 Swift 분기만 26이 남아 있었다.

## 어긋남 기록

원라인의 장소 추가 후 전체 통계 줄이 기본 너비를 넘는 경우를 처리하지 않았다. 사용자 QA에 따라 기존 가로 통계 축소 규칙을 원라인에도 적용한다. 제품 정의와 항목 정책은 바꾸지 않는다.

## 검증

- TypeScript와 Swift iPhone Debug 빌드 통과. 전체 린트는 기존 오류 19개·경고 5개와 동일하다.
- 기존 미리보기·선택 박스 회귀 검사 통과. 원라인은 켜진 항목의 63개 조합, 한글 장소명 두 종류, 일반 기록과 100km·11시간 기록, 재생 진행률 5단계에서 기본 너비 제한과 글자 크기 고정을 확인했다. 항목을 모두 끄고 문구만 둔 경우, 사용자 이동·크기 배율 유지도 확인했다.
- 자동 검사는 배치 계산 검사이며 실제 글꼴의 화면·영상 픽셀 검증은 아니다. 개발용 앱에서 원라인 첫 선택, 긴 장소명, 항목 끄기/켜기, 저장 영상의 너비를 사용자 QA로 확인한다.
- 2026-09-20 개발 아이폰에 새 네이티브 앱 설치를 완료했다. 앞서 자동 승인 검토 서비스의 사용량 제한으로 막혔던 설치를 사용자 요청으로 다시 실행해 성공했다. JS 미리보기는 로컬 서버에서 제공한다. 후속 글자 크기 조정도 타입·관련 린트·회귀 검사와 Swift Debug 빌드 후 개발 아이폰에 설치했다. 저장 영상의 실기기 QA와 TestFlight 배포는 대기다.
