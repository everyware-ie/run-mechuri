# 배경 파일 저장 실패 QA

- 근거: [배경 선택 FRD](../../specs/frd/background-selection.md) §4-1 편집용 사진 보관·§5-5 편집용 영상 보관·§7 실패 (`approved`)
- 착수 확인: 2026-10-05 사용자가 잔여 주간 한도 약 70%까지 QA와 수정을 요청했다. 기존 사진·영상의 저장과 실패 후 재시도 규칙을 확인한다. 새 제품 정책이나 배포 작업은 포함하지 않는다.

## 재현한 문제

파일 복사 API가 일부 바이트를 쓴 뒤 실패하는 상황을 모의 파일 시스템으로 재현했다. 다음 선택은 파일이 존재한다는 이유만으로 미완성 배경을 재사용했고 복사를 재시도하지 않았다. 정상 배경이 아닌데 완료 경로가 반환되므로 이후 미리보기·인코딩에서 실패할 수 있다. 실제 아이폰 저장 공간을 가득 채워 재현한 결과는 아니다.

## 수정 방향

새 복사는 별도 임시 파일에 수행하고 성공 후 확정 파일명으로 옮긴다. 실패한 임시 파일은 정리하고 원래 배경·원본 소재는 보존한다. 이미 정상 보관된 파일은 재사용하며, 비어 있는 파일을 정상 완료로 취급하지 않는다. 같은 대상 파일의 동시 요청은 하나의 준비를 기다린다. 기존 확정 경로와 초안·결과물의 참조 형식은 바꾸지 않는다.

검증 결과는 [내부 측정 안정성 QA](../../ops/internal-run-tracking-qa.md#10-2026-10-05-안정성-qa)에 별도 배경 회귀 검사로 남긴다. 워치·야외 실측의 결과와 섞지 않는다.

저장 단위 검사 8개를 통과했다. 실제 아이폰에서도 복사본과 원본의 해시 일치·동시 요청·완성 파일 재사용·빈 파일 재준비·잘못된 원본의 실패 정리를 확인했다. 검사 파일과 임시 화면은 제거했으며 기존 초안·결과물의 배경은 변경하지 않았다. 이전에 생긴 비어 있지 않은 손상 파일 전체를 검사·복구하는 기능은 포함하지 않는다. 복사 중 프로세스가 종료되면 임시 파일이 남을 수 있지만 완료 경로로 반환하거나 재사용하지 않는다.
