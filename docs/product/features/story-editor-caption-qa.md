# 스토리형 편집 문구 검증

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §7 러닝 데이터와 문구, [경로 렌더링 FRD](../../specs/frd/route-rendering.md) §7-6 한 줄 문구 (`approved`)
- 선행 구현: [스토리형 편집 1단계](story-editor-stage1.md), PR #78
- 범위 확인: 2026-10-04 사용자가 최근 작업을 파악하고 다음 작업을 진행하도록 요청했다. 배포는 보류하고 남은 검증·수정만 진행하기로 확인했다.

## 이번에 확인하는 것

미리보기와 결과 영상이 같은 문구 줄·좌표·크기를 사용하는지 확인한다. 옛 결과물을 다시 편집할 때 문구가 사라지지 않는지도 확인한다. 2단계 기능과 TestFlight 배포는 이번 범위에 없다.

## 발견한 오류

- 새 문구가 러닝 데이터의 옛 표시 모드(`after`, `hidden`)를 따라 늦게 나타나거나 숨는다. 문구는 표시 모드 없이 클립 내내 보여야 한다. 미리보기와 Swift 결과 영상에서 함께 고친다.
- 옛 저장분의 문구 위치를 찾을 때 표시 모드가 `hidden`이면 배치 결과가 비어 문구를 지운다. 재편집 전환에서는 완성 상태의 배치를 이용해 내용과 위치를 보존한다. 보관함에서 옛 저장분을 그리는 규칙은 유지한다.

둘 다 승인된 FRD와 구현이 어긋난 것이며 제품 정책을 바꾸지 않는다. PRD와 결정문을 확인했고 개정할 내용은 없다.

## 검증 결과

- 오류를 먼저 테스트로 재현했다. 수정 전에는 재생 중 표시·숨김 모드 이관·문구 독립성 검증 10개가 실패했다.
- 수정 후 문구 회귀 테스트 20개 통과: 세 표시 모드의 시작·중간·완성 시점, 옛 프리셋 7종의 내용·자리·크기 보존, 중복 전환 방지, 원본 불변, 여러 문구와 빈 줄, 전환 전 옛 표시 규칙 유지.
- 전체 Jest 104개, 타입 검사 통과. 전체 린트 오류 0개, 기존 경고 32개. 변경 파일 린트는 오류·경고가 없다.
- iOS Release `RouteRenderer` 타깃 빌드 통과. 실제 iOS SDK와 ExpoModulesCore를 연결해 수정한 Swift를 컴파일했다. 앱 전체 빌드나 설치는 하지 않았다.
- 소스에서 미리보기와 Swift의 기본 문구 크기(64px), 줄 높이(크기의 1.3배), 가운데 정렬과 기준선 계산을 대조했다. 공유 화면은 미리보기와 같은 `freeCaptionLines`로 줄을 나눠 Swift에 전달한다.

## 남은 실기기 확인

자동 배치 검사와 Swift 컴파일은 글자·그림자의 실제 픽셀 비교를 대신하지 않는다. 아래는 아직 확인하지 않았다.

1. 문구 두 개를 넣고 크기를 다르게 지정한다. 한 문구에는 직접 줄바꿈과 자동 줄바꿈을 함께 사용한다. 저장 영상과 미리보기의 자리·크기·줄바꿈을 비교한다.
2. 문구가 있는 옛 결과물을 다시 편집한다. 내용과 위치를 확인하고 러닝 데이터를 숨겨도 문구가 남는지 본다.
3. 반복 재생 중 이동·핀치·슬라이더를 여러 번 조작한다. 시트 높이와 안내가 방해되지 않는지 함께 본다.

재생 버튼 유지 여부, 시트 높이, 제스처 안내 자리, 앱 재진입 시 되돌리기 기록 보존은 [결과물 편집 FRD](../../specs/frd/result-editing.md) §10 남은 확인 항목으로 유지한다. 실기기 결과나 사용자 결정 없이 확정하지 않는다.

TestFlight 배포는 2026-10-04 사용자 답변에 따라 보류한다. 2단계는 [1단계 인계 노트](story-editor-stage1.md)의 순서대로 이후 진행한다.
