# 하트 샘플 기록 체험

- FRD: [샘플 기록 체험](../../specs/frd/sample-record-experience.md)
- PRD: [샘플 기록으로 Runary 체험하기](../../specs/prd/sample-record-experience.md)
- 구현 상태: 로컬 개발 앱 실행 완료, 사용자 QA 대기
- 착수 확인: 2026-10-12 FRD 제시 후 사용자가 후보 미리보기를 요청했다. 정식 앱에도 샘플을 포함하는 범위를 설명한 뒤 사용자가 하트를 선택하고 로컬 미러링 확인을 요청했다. 기존 `phs00/feature/app-store-sample` 브랜치에서 진행한다.
- 참조 시점: 2026-10-12, 수정 전 소스 HEAD `8e083a5`. 같은 작업의 승인된 샘플 FRD를 기준으로 한다.

## 구현 노트

하트 데이터 생성은 건강 앱 모듈에서 분리한다. 기존 생성 상태와 편집·저장 경로를 사용하며, 식별자로 샘플 표시와 장소 조회 제외를 처리한다. 초안과 결과물은 기존에 저장하는 기록·트랙을 그대로 사용한다.

`sample-run.ts`가 후보 미리보기와 같은 하트 좌표를 생성한다. `SampleRunEntry`는 첫 화면과 기록 선택의 진입을 담당한다. 홈에서는 `새로 만들기`로 기록 선택에 들어간다. 생성 상태에서 샘플 장소를 채우고, 편집에서 외부 역지오코딩을 건너뛰며, 홈·결과물 상세에서 샘플을 표시한다. 실제 기록 좌표를 조회하는 동안 샘플을 잠가 두 흐름의 상태 변경이 겹치지 않게 했다.

일반 제출 설정으로 로컬 서버를 실행한다. 네이티브 앱이 내부 측정 개발 앱인 경우에도 JS 측정 진입을 비활성화했는지 확인하며, 이것을 최종 일반 배포 바이너리 검증과 혼동하지 않는다.

## 검증

타입·문서 검사와 샘플 좌표·진입·실패 재시도·중복 탭·다른 기록과의 동시 선택 방지·권한·초안·결과물 회귀 41개가 통과했다. 린트는 오류 0개·기존 경고 30개다. 실제 영상 생성·기기 저장·초안 복구의 확인 결과는 수행한 범위만 남긴다. 사용자 로컬 확인 전 TF에 업로드하지 않는다.

일반 설정으로 iOS 프로젝트를 재생성했으며 측정 플래그 `false`, 워치 대상 없음, 백그라운드는 영상 생성용 `processing`만 남는 것을 확인했다. 유효한 기존 `Mechuri App Dev` 프로파일과 개발 인증서를 명시해 로컬 Debug 빌드를 진행한다. 새 인증서 생성이나 기기 등록은 하지 않았다. 생성 iOS 프로젝트의 Debug 서명 설정은 Git에 포함하지 않는다.

후속 Debug 빌드가 성공했고 깊은 서명 검증을 통과했다. 기존 앱 위에 `1.0.0(1)` 개발 앱을 설치하고 `192.168.0.7:8081`의 Metro에 연결했다. 미러링에서 홈의 샘플 버튼과 하트 트랙·샘플 코스가 보이는 배경 선택을 확인했다. 첫 설치·권한 거부 기기에서의 실측, 실제 영상 생성·기기 저장·재실행 복구는 아직 사용자 확인 전이다. 기존 앱을 삭제하지 않았으며 기존 보관함 21개와 초안 표시가 유지됨을 확인했다.

## 심사 버전 보관

사용자가 향후 반려 대응을 위해 별도 브랜치 보관을 요청했다. 로컬 검증 소스를 커밋하고 `phs00/feature/app-store-v1` 브랜치로 보관한다. TF 업로드 시 빌드 번호와 정확한 소스 커밋을 [배포 기록](../../ops/build-and-dev-commands.md)에 함께 남긴다. 후속 개발 이후 심사 수정을 할 때 이 브랜치의 제출 커밋을 기준으로 시작한다.

샘플 구현 소스 커밋은 `e790bc97907a5b1c474415f355569ccadca0dbb5`다. 이번 보관은 로컬 Git이며 원격 푸시·PR·TF 업로드·정식 심사 제출은 실행하지 않았다.

## 2026-10-12 로컬 QA UI 보완

사용자가 안내 문구는 `만들어요.` 뒤에 줄바꿈하고, 샘플 버튼은 실제 기록 UI와 비슷하게 표시하도록 요청했다. 샘플을 실제 목록과 같은 배경·테두리·썸네일 자리·제목·메타정보의 카드로 바꿨다. 왼쪽에는 하트 아이콘을 쓰며 기존 시작·중복 탭·실패 처리 동작을 유지한다. 생성 중 안내는 문장 사이에 명시적 줄바꿈을 추가했다.

타입·문서 검사와 샘플 진입·기존 권한 회귀 6개가 통과했다. 린트는 오류 0개·기존 경고 30개다. 미러링의 실제 기록 목록에서 새 카드와 메타정보의 표시를 확인했다. 생성 안내의 두 문장 분리는 소스에서 확인했으며 이번 보완 확인을 위해 새 인코딩을 시작하지는 않았다.

추가로 사용자가 대시보드의 샘플 퀵 링크를 제거하고 `새로 만들기 → 기록 선택 → 샘플 선택`으로 정리하도록 요청했다. 홈의 직접 진입을 제거했으며 첫 실행 안내와 기록 선택의 샘플 카드는 유지한다. PRD·FRD·홈 규칙을 같은 범위로 갱신했다.

이 동선 보완의 타입·문서 검사는 통과했고 린트는 오류 0개·기존 경고 30개다. 소스에서 홈의 직접 진입 제거와 첫 실행·기록 선택의 카드 유지를 확인했다. 미러링은 사용자가 확인 중인 배경 선택 화면을 유지했으며 홈 복귀와 새로 만들기 동선의 추가 실기기 조작은 하지 않았다.
