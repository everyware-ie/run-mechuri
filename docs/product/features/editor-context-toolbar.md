# 편집 도구의 상단 선택 영역

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §1 화면 구조·§3 프리셋 선택·§5 다듬기 세기 (`approved`).
- 착수 확인: 2026-10-04 사용자가 경로 프리셋 상단 배치와 ROUTE B 아이콘 교체 제안을 승인하고 구현을 요청했다. 앞서 확인한 편집 FRD의 배치 개정이며, 기능과 편집값 유지 규칙은 같다.
- 이슈: [#101](https://github.com/everyware-ie/run-mechuri/issues/101)
- 상태: 구현·핵심 실기기 QA 완료. 손그림 획 편집과 [PR #100](https://github.com/everyware-ie/run-mechuri/pull/100)에 묶는다.

손그림에서 확인한 상단 선택·하단 세부 조절 구성을 경로 도구에 적용한다. 경로 도구를 열었을 때만 상단에 되돌리기·기본/불빛/구간·완료를 보여 준다. 아래 시트에는 다듬기/선 스타일 탭과 초기화를 둔다. 다른 도구를 열거나 시트를 닫으면 평소 도구가 돌아온다. 러닝 데이터와 문구의 상단 배치는 이번에 적용하지 않는다.

경로 도구 아이콘은 `point.bottomleft.forward.to.point.topright.scurvepath`로 바꾼다. 프리셋의 짧은 화면 이름과 전체 접근성 이름을 구분하고, 선택 상태를 표시한다. 위치·크기·회전·색·두께와 저장·되돌리기는 기존 처리 함수를 그대로 사용한다. 새 네이티브 의존성을 추가하지 않는다.

## 검증

타입 검사, 전체 테스트 31개 묶음·246개, 린트 오류 0개(기존 경고 32개)를 확인했다. iPhone 11 Pro 개발 앱에서 ROUTE B 아이콘, 상단 프리셋 세 개, 선택 강조, 아래 다듬기/선 스타일 탭과 색·두께를 확인했다. 선 스타일 탭에서 프리셋을 바꿔도 탭·민트색·두께 117%·경로 선택 영역이 유지됐고, 상단 되돌리기로 프리셋이 복구됐다. 상단 완료로 시트를 닫으면 평소 도구가 돌아왔다. QA에서 바꾼 프리셋은 되돌리기로 원래 값에 복원했다.

문서 검사와 diff 공백 검사도 통과했다. 네이티브 변경이 없어 재빌드하지 않고 실행 중인 개발 앱에서 확인했다. 다른 기기 크기·큰 글자 설정은 실기기 미검증이며, 새 영상 생성과 TestFlight 배포는 이번 범위가 아니다.

## 어긋남 기록

기존 FRD가 경로 프리셋을 아래 시트에 두도록 정한 부분은 사용자 승인으로 상단 배치로 개정한다. PRD의 기능 범위는 같고, 결정문에는 배치 개정을 덧붙인다. 새 용어는 없다.
