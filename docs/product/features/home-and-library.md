`frontend/src/app/index.tsx`를 홈 화면으로 구현. §1-1 화면 구성 순서(이어서 만들기 → 새로 만들기 → 결과물 목록 → 쇼케이스) 그대로.

- **결과물 목록**: `frontend/src/lib/results-store.ts`(AsyncStorage)에서 읽음. §2-1 정렬(러닝한 날 최신순), 썸네일(`route-thumbnail.tsx`, 완성 순간 정지 이미지) 반영. 2열 그리드
- **결과물에서 할 수 있는 것**(§2-2): `frontend/src/app/result/[id].tsx`에서 보기, 공유, 다시 편집, 같은 기록으로 새로 만들기, 삭제를 제공한다. 보기는 아래 재생 누락 보완을 따른다. 공유는 만들어 둔 mp4를 재인코딩 없이 인스타그램 스토리로 넘긴다. 자세한 구현은 [내보내기·공유·저장 노트](export-and-share.md)에 있다.
- **이어서 만들기**(§3): `frontend/src/lib/draft-store.ts` — 단일 슬롯(§3-1 "맨 위에 하나"). edit.tsx 진입·프리셋·변형값 변경마다 저장, share.tsx 완성 시 삭제
- **쇼케이스**(§4): FRD가 명시적으로 "여유 시"(§4-3)라 계속 미착수

**§2-3 저장 데이터**: `SavedResult`에 트랙 좌표·프리셋·변형값·배경 참조를 전부 담음 — 원본 HealthKit 기록이 지워져도 다시 편집·재생성이 되게 하는 게 목적.

**아직 안 한 것**: 복귀 위치(§5, 30분 기준 포그라운드 복귀 분기에는 별도 상태 추적 필요).

### 상세 화면의 재생 누락 보완 (2026-10-19)

사용자가 대시보드에서 이전 결과물을 열면 상세 화면에 재생 버튼이 없어 영상을 볼 수 없다고 제보했다. [FRD §2-2 결과물에서 할 수 있는 것](../../specs/frd/home-and-library.md#2-2-결과물에서-할-수-있는-것)의 기존 보기 기능을 구현한다. 현재 자체 기록 편집 브랜치의 QA 보완으로 함께 진행한다.

사용자는 전체 화면 확대 대신 썸네일을 조금 넓혀 그 자리에서 재생하기를 요청했다. 미리보기는 기존 270pt에서 최대 300pt 정사각형으로 넓히되 작은 화면에서는 가용 너비에 맞춘다. 정지 상태의 경로 중심 구도를 유지하고 재생을 누르면 같은 자리의 `expo-video` 플레이어로 전환한다. 저장된 `outputPath`의 9:16 영상을 잘림 없이 보여주며 공유·저장·다시 편집 버튼을 계속 사용할 수 있다.

사용자는 기본 영상 컨트롤이 경로 그림을 가린다고 피드백했다. 네이티브 컨트롤과 영상 위 터치를 끄고 미리보기 아래에 진행률·시간과 전용 아이콘 버튼을 둔다. `playingChange`로 재생·일시정지 아이콘을 맞추고 `timeUpdate`를 0.25초 간격으로 받아 진행률을 표시한다. 처음부터 버튼은 0초로 이동해 재생하고 정지는 플레이어를 해제해 썸네일로 돌아간다. 화면을 떠나거나 앱이 비활성화되면 재생을 멈춘다. 영상이 없거나 읽기에 실패하면 안내하고 편집 사본은 유지한다. 재생을 위해 다시 생성하거나 사진 앱 권한을 요청하지 않는다.

후속 요청으로 재생바의 탭·드래그 탐색을 추가했다. 공통 `Slider`의 `tapToSeek`는 영상 재생바에서만 켜며, 기존 편집용 슬라이더는 누른 위치로 뛰지 않는 동작을 유지한다. 손잡이와 트랙 자식 뷰는 터치를 받지 않아 탭 위치를 재생바 전체 기준으로 읽는다. 탐색 시작 때 재생 여부를 기억하고 잠시 멈췄다가 종료 때 같은 상태로 되돌린다. 도중 앱이 비활성화되면 재개 예약을 취소한다.

타입 검사, Jest 48개 묶음 350개, 문서와 diff 검사를 통과했다. 린트는 오류 0개와 기존 경고 30개다. 새 검사에서는 실제 보관 경로 전달, 비율 유지, 정지와 자원 해제, 중복 탭, 파일 누락·조회 실패 후 재시도, 화면 이탈 뒤 늦은 응답 차단, 앱 비활성화 때 정지와 재생 오류 안내를 확인했다. 전용 재생·일시정지·처음부터 버튼, 영상 종료 후 재생, 탐색 전후 재생 상태 유지와 기존 편집용 슬라이더의 동작도 검사했다.

iPhone 11 Pro에서 이전 5.34km 결과물을 같은 썸네일 자리에서 재생했다. 전용 버튼으로 일시정지한 뒤 재생바를 탭해 3초로 이동하고 손잡이를 드래그해 9초로 옮겼으며 해당 장면에서 정지 상태를 유지했다. 처음부터 버튼으로 0초에서 다시 재생하고 네모 버튼으로 썸네일에 돌아오는 것을 확인했다. 기본 컨트롤이 영상 위에 뜨지 않았고 공유·저장·다시 편집은 스크롤 안에 유지됐다.

파일 누락과 읽기 실패, 자원 해제와 탐색 중 앱 전환은 자동 검사로 확인했으며 사용자 파일을 삭제하지 않았다. 작은 화면과 앱 전환의 실기기 재검증은 하지 않았다. 기존 설치 앱에 JavaScript를 반영했으며 네이티브 재빌드와 TF 업로드는 하지 않았다.

### 홈 목록에서는 러닝 데이터를 안 그린다 (2026-09-02, 아래 2026-09-11 변경으로 대체)

`RouteThumbnail`(route-thumbnail.tsx)은 `run`/`stampConfig`를 넘기면 사용자가 고른 러닝 데이터 프리셋을 원래 크기·자리 그대로 그린다. 홈 화면의 `heroCard`(이어서 만들기 아래 큰 카드)·`gridThumb`(MY RUNARY 그리드 칸)는 각각 `heroOverlay`(거리+날짜)·`gridLabel`(거리만) — 이 화면 전용으로 항상 같은 자리·같은 스타일로 보여주는 고정 표시를 이미 갖고 있는데, 여기에 `run`/`stampConfig`까지 넘기니 **두 표시가 겹쳐 보였다**(실기기 피드백: "위에껀 km+날짜인데 밑에껀 작은 글씨로 km만 남아있다" — 실은 고정 표시 위에 프리셋별로 다르게 배치되는 러닝 데이터가 겹쳐 그려진 것). 홈 목록의 두 `RouteThumbnail` 호출 모두 `run`/`stampConfig`를 안 넘기도록 고쳤다 — 경로 선만 그려지고, 거리·날짜는 이 화면 전용 고정 표시로만 보인다. `share.tsx`(완성! 화면)·`result/[id].tsx`(보관함 상세)는 거리·날짜 텍스트가 카드 밖 별도 자리에 있어(겹치지 않음) 그대로 둠 — 러닝 데이터를 실제로 보여줘야 하는 화면이기도 하고. 러닝 데이터 텍스트 자체의 효과(외곽선·그림자)는 `docs/product/features/result-editing.md` "러닝 데이터 텍스트 효과를 프리셋군별로 분리" 참고.

### "다시 편집"이 배경 파일을 못 찾을 때 미리 안내 (2026-09-03)

배경 이미지 경로가 더는 유효하지 않은 옛 결과물(원인은 `docs/product/features/background-selection.md` "다시 편집이 결과물을 못 만들던 문제" 참고)을 "다시 편집"하면, `result/[id].tsx`가 진입 전에 배경 파일 존재 여부를 먼저 확인한다. 없으면 편집을 다 끝낸 뒤(공유 화면)에야 실패로 알게 되는 대신, 시작 전에 안내하고 배경만 다시 고르게 한다 — 프리셋·변형·다듬기·러닝 데이터 등 나머지 편집값은 그대로 유지한 채 `background-selection`으로 보낸다.

**"이어서 만들기"(§3)도 같은 문제가 있었다** — TestFlight로 실기기 재확인: "업데이트한 뒤 이어서 만들기가 안 되는 것 같다." `draft-store.ts`의 초안도 `SavedResult`와 똑같이 `backgroundImagePath`를 절대경로 문자열로 저장해 둔 채라, 앱 업데이트(테스트플라이트·앱스토어는 데이터를 지우지 않고 덮어써서 설치된다 — 지우고 재설치하는 것과 다르다) 사이에 초안을 남겨 놨으면 똑같이 깨질 수 있었다. `index.tsx`의 `handleResumeDraft`에도 같은 사전 확인·안내를 추가했다.

### 경로·러닝 데이터 중심 썸네일 (2026-09-11)

사용자 요청으로 홈 큰 카드와 그리드에 저장된 배경 및 러닝 데이터를 함께 표시한다.
경로 그림의 이동·확대·회전을 적용한 경계와 러닝 데이터 경계를 합쳐 정사각형으로 맞춘다.
고정 거리·날짜 표시는 그림 밖으로 옮겨 기존의 러닝 데이터 겹침을 방지한다.
구현 세부와 검증은 [러닝 데이터 심박 단위와 결과물 썸네일](stamp-units-and-result-thumbnails.md)에 기록한다.
