# 스토리형 편집 2단계

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §6-2 선 색과 두께, §7-3 폰트와 글자 색, §9 우선순위 (`approved`)
- 렌더링: [경로 렌더링 FRD](../../specs/frd/route-rendering.md) §7 러닝 데이터와 문구
- 제품 근거: [러닝 드로잉 MVP PRD](../../specs/prd/running-drawing-mvp.md) §7 결과물의 형태
- 확인: 2026-10-04 사용자가 1단계 내부 TestFlight 배포 후 다음 2차 진행을 요청했다. 위 FRD 범위를 안내하고 착수한다.
- 상태: 구현·핵심 실기기 검증 완료. 2026-10-04 TestFlight `1.0.0(29)` 내부 배포 완료 ([배포 기록](../../ops/build-and-dev-commands.md#2026-10-04-편집-2단계구간-점등-배포-10029)).

## 이번 작업

경로 시트에 그림·스타일 탭을 두고, 스타일 탭에서 색과 두께를 고른다. 러닝 데이터 시트의 스타일 탭에서 폰트와 글자 색을 고른다. 고른 폰트·글자 색은 문구에도 적용한다. 시트 안에서 바로 바뀌며 별도 적용 버튼은 없다.

| 선택 | 구현값 |
|---|---|
| 선 색 | 기존 따뜻한 흰색 `#FFF3EC`, 오렌지 `#FF985C`, 민트 `#8EF0CE`, 하늘 `#8ECFFF`, 분홍 `#FFADD5`, 보라 `#C5AEFF` |
| 선 두께 | 기존 프리셋 두께의 50~200%, 기본 100%. 위치·크기 초기화와 별개로 유지 |
| 폰트 | 프리셋 기본, Pretendard, Noto Sans KR. 이미 앱에 포함된 한글 지원 글꼴을 사용하며 중간·굵은 굵기를 유지 |
| 글자 색 | 프리셋 기본, 흰색, 검정. 검정은 밝은 그림자·카드로 읽히게 함 |

범위와 색은 FRD가 구현 노트에서 정하도록 남긴 값이다. 실기기 확인 후 필요한 조정을 이 작업에 함께 기록한다. 폰트 기본은 러닝 데이터의 각 프리셋 글꼴과 자유 문구의 Noto Sans KR을 그대로 사용한다.

## 연결 방식

선 스타일은 위치·회전·크기와 분리한 선택값으로 저장한다. 글자 스타일은 `StampConfig`의 선택값이다. 값이 없는 옛 저장물은 기존 모습 그대로 그린다. 프리셋 교체와 위치·크기 초기화는 스타일을 지우지 않는다.

미리보기·썸네일·문구 입력·네이티브 영상의 색과 폰트를 연결하고, 초안·결과물·다시 편집·되돌리기에 포함한다. 두께 슬라이더는 손을 뗄 때 한 단계로 확정하며 재생을 다시 시작하지 않는다. 기존 UI 스레드 애니메이션을 유지한다.

### 실기기 QA (2026-10-04)

사용자가 연결한 iPhone 11 Pro(iOS 26.6.2)의 개발용 앱에서 확인했다. 구현·QA 수정·문서는 2단계 PR 하나로 묶는다.

| 확인 | 결과 |
|---|---|
| 시트 높이 | 그림·스타일 전환에 따라 필요한 높이만 사용. 색 6개·두께 슬라이더, 폰트 3개·글자 색 3개가 기본 글자 크기에서 세로 스크롤 없이 표시 |
| 선 색·두께 | 민트 선택, 50%와 200% 적용, 조작 후 되돌리기로 이전 두께 복원. 색은 유지 |
| 경로 그림 프리셋 | 불빛 러너·구간 점등 전환 후 민트·200% 유지 |
| 러닝 데이터 프리셋·초기화 | 원라인·글래스 전환 후 폰트·글자 색 유지. 위치·크기 초기화도 스타일을 지우지 않음. Noto 원라인 기본 너비는 캔버스 안에 표시 |
| 폰트·글자 색 | Pretendard·검정, Noto Sans KR·흰색이 러닝 데이터와 두 줄 한글 문구에 즉시 반영. 검정 글래스는 밝은 카드, 흰색은 어두운 카드로 전환 |
| 문구 입력 화면 | 기존 두 줄 한글 문구를 탭해 입력 화면에서도 선택 폰트·색을 확인. 이번 QA에서 새 한글 입력을 다시 요청하지 않았으며, 일반 입력·줄바꿈은 1단계 사용자 확인을 이어 사용 |
| 저장·재진입 | 초안에서 나갔다 다시 열기, 앱 종료·재실행 후 이어서 만들기, 보관함 상세·다시 편집에서 선택값·문구 복원 |
| 실제 영상 | Pretendard·검정·민트 200% 구간 점등 영상에서 작은 날짜·라벨·문구까지 미리보기와 육안 비교. Noto Sans KR·흰색·원라인도 같은 한글 문구와 너비를 확인. 두 최종 영상 모두 1080×1920·30fps·12초·360프레임 전체 디코딩 성공 |

**QA에서 수정:** 검정 글자를 Swift에서 흰색 외곽선과 함께 그리면 선이 글자 안쪽을 덮어 날짜·작은 라벨이 흰색처럼 보였다. 미리보기와 영상에서 외곽선을 빼고 반대 색의 옅은 그림자를 유지했다. 수정 전·후 영상을 같은 설정으로 생성해 마지막 프레임을 비교했다. 색·폰트·위치와 영상 규격은 유지한다.

개발 중 Fast Refresh로 상태가 초기화된 구간은 저장 결과물에서 다시 불러왔다. 소스 변경 없이 앱을 완전히 재시작한 별도 검증에서는 스타일·두 줄 문구가 유지됐다. 재시작 중 미러링의 검은 화면은 홈에서 앱을 직접 열어 해소했다. 개발 도구의 재연결을 저장 검증 통과로 대신하지 않았다.

**남은 범위:** 다른 아이폰 화면 크기·큰 글자 설정, 모든 사진 배경 조합과 실제 인스타그램 공유·복귀는 배포 전 통합 확인에서 본다. 이번 단계의 핵심 QA와 구분한다. 영상 생성 때 iOS의 백그라운드 작업 안내 배너 글자가 어두워 보이는 기존 현상은 [QA 기록](../../ops/qa-log.md)에 후속 항목으로 남긴다.

QA 직전 사용자 초안과 기존 결과물 13개를 로컬에 백업했다. 검증용 결과물 3개를 별도로 남겼고, 종료 후 작업 직전 초안을 복원했다. 복원 파일은 백업과 바이트가 같고 기존 13개 결과물의 편집값도 유지된다. 앱 업데이트로 바뀐 컨테이너 경로와 기본 선 스타일 호환 값만 저장소가 갱신했다. 사용자 원본을 옛 세션 백업으로 덮지 않는다.

## 어긋남 기록

경로 렌더링 FRD §7-6 한 줄 문구에 남아 있던 Pretendard 제안은 실제 1단계 배포본의 Noto Sans KR 기본값과 달랐다. 원문의 작업 시 재검토 조건과 2단계 폰트 선택 규칙에 맞춰 FRD를 동기화했다. PRD의 기능 범위와 결정문의 단계 구분은 바뀌지 않는다.
