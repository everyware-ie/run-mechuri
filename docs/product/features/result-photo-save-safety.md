# 결과물 사진 앱 저장 안정성

- FRD: [내보내기·공유·저장](../../specs/frd/export-and-share.md) §4 기기에 저장 / [공통 규칙](../../specs/frd/common-rules.md) §3 실패
- PRD: [러닝 경로 그림 MVP](../../specs/prd/running-drawing-mvp.md) §5 MVP 범위, §6 내보낸 다음
- 구현 상태: 구현 완료, 실기기 확인 대기 (2026-10-04)

## 착수 근거

사용자가 승인한 안정성 후속 검증으로 진행한다. 공유 화면과 보관함 상세의 사진 앱 저장에서 권한 요청이 예외 처리 밖에 있고, 연속 탭을 막는 처리가 없다. 권한 요청 오류를 사용자에게 알리고, 진행 중 저장 요청을 한 번만 실행한다. 권한은 기존 사진 쓰기 전용 요청을 유지한다.

## 구현과 검증

`frontend/src/hooks/use-save-to-photos.ts`를 공유 화면과 보관함 상세에서 사용한다. 모듈 로딩부터 사진 쓰기 권한 요청과 실제 저장까지 같은 예외 처리 안에 둔다. 실패하면 저장 버튼으로 다시 시도하라는 안내를 보여주며 결과물은 보관함에 그대로 남는다.

진행 중 요청은 ref로 즉시 막는다. React가 버튼을 비활성화하기 전 빠르게 연속으로 누른 경우에도 권한 요청과 파일 저장을 중복 실행하지 않는다. 끝난 뒤 사용자가 다시 저장하는 동작은 허용한다. 버튼은 저장 중 흐리게 표시하고 접근성의 사용 불가·작업 중 상태를 제공한다. 화면이 사라져도 이미 시작한 사진 앱 저장은 계속하고, 사라진 화면의 UI 갱신은 하지 않는다.

기존 동적 모듈 로딩, 사진 쓰기 전용 권한 요청(`true`), SDK 57의 `legacy` 저장 진입점은 유지했다. 인코딩 규격이나 생성 속도에는 영향이 없다.

- 네이티브 경계를 대역으로 둔 React 검사 9개 통과: 영상 없음, React 갱신 전 연속 탭, 권한 대기·파일 저장 중 재탭, 권한 거부 후 재시도, 모듈 로딩·권한 요청·저장 오류 후 재시도, 화면 종료 후 성공·실패.
- 전체 테스트 155개(17개 묶음), TypeScript 검사 통과. 린트 오류 0개, 기존 경고 32개.
- 코드에서 발견한 오류 경계를 보완한 것이다. 실제 iOS에서 권한 오류나 중복 저장을 재현했다는 뜻은 아니다. Jest는 로더 대역을 사용하며 실제 Expo 동적 모듈 로딩을 실행하지 않는다.
- 실제 사진 앱 저장, 권한 창, 버튼 모양·VoiceOver는 실기기 확인이 필요하다. 공유 화면과 보관함 상세 각각에서 저장 연속 탭, 권한 거부·허용 후 재시도, 성공한 저장 한 건을 확인한다. TestFlight 배포는 보류한다.

## 어긋남 기록

제품 정책 변경은 없다. 기존 실패 안내와 재시도 원칙에 맞추는 수정이다.
