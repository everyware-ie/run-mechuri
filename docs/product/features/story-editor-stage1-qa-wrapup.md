# 스토리형 편집 1단계 묶음 QA

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §2 미리보기·§4 편집 대상과 조작·§7 러닝 데이터와 문구·§9 우선순위, [홈과 보관함 FRD](../../specs/frd/home-and-library.md) §3 만들다 만 것 (`approved`)
- 사용자 확인: 2026-10-04 배포는 나중에 한꺼번에 진행하고, 핵심 QA를 한 번에 마무리한 뒤 2단계에 착수하도록 요청했다.
- 환경: iPhone 11 Pro, 개발용 Runary, 원본 프로젝트의 Metro 8081. 기존 초안과 보관함을 먼저 백업했다.

## 묶음 확인

**1단계 핵심 QA 완료(2026-10-04).** 이전에 통과한 자동 검사·실기기·영상 검증을 합치고 남았던 입력과 실제 조작을 확인했다. 아래 배포 전 통합 확인은 별도로 남으며, 다음 작업은 2단계다.

| 항목 | 근거와 상태 |
|---|---|
| 자동 검사 | [문구 초안 보존](caption-draft-preservation.md)의 전체 테스트 190개·타입·린트·문서 검사 통과 |
| 사진·옛 문구 재편집, 러닝 데이터 숨김·되돌리기, 위치 보존 | [실기기 QA](story-editor-device-qa.md)에서 확인 |
| 경로·러닝 데이터 시트와 반복 재생 중 조작 | 같은 실기기 QA에서 기본 글자 크기로 확인. 정량적인 FPS 측정은 아님 |
| 생성 영상·공유 카드·기기 저장 | 같은 실기기 QA에서 1080×1920·30fps·12초·360프레임 끝까지 디코딩, 문구 배치 육안 비교, 생성 중·완성 카드와 저장 완료 안내 확인 |
| 완료 전 문구 저장 | 이번 확인에서 문구 완료를 누르기 전에 실제 저장 파일에 새 문구와 크기 0.74가 포함됨 |
| 앱 종료·재실행 | 저장을 확인한 뒤 앱 프로세스를 종료·재실행. 홈에서 해당 초안의 이어서 만들기를 확인. 편집 화면에서 완료 전 문구의 내용·크기가 복원된 것을 육안 확인 |
| 일반 한글·줄바꿈·문구 크기·재진입 | 사용자가 입력·줄바꿈·크기 변경·다시 열기 모두 정상이라고 확인. 실제 초안 파일에서도 `오늘도 잘 달렸다\n기분 좋은 하루`와 크기 1.36 확인. 자동 줄바꿈·3줄 제한은 기존 회귀 검사로 확인 |
| 두 손가락 핀치·회전, 숨기기 진동·되돌리기 | 사용자가 직접 조작한 2·3번 항목은 정상이라고 확인. 자동 입력이나 자체 진동 측정 결과로 해석하지 않음 |

## 이번에 보완한 오류

문구 크기 슬라이더는 크기 변경만 전달하고 조작 시작·종료를 미리보기의 일시 정지에 연결하지 않았다. 경로·러닝 데이터 슬라이더와 달리 잡고 있어도 재생이 계속되는 구조였다. FRD §2-1 재생에 맞춰 시작 시 멈추고 손을 떼면 이어 가며, 문구 입력 화면이 닫히면 조작 중 상태를 정리한다.

수정 전 연결·종료 정리 React 검사 2개가 실패했고 수정 후 통과했다. 전체 테스트 21개 묶음·192개 항목과 타입 검사 통과, 린트 오류 0개(기존 경고 32개). 문서 검사도 통과했다. React 검토에서는 조작 이벤트에서 상태를 바꾸고, 종료 정리는 안정적인 상태 setter를 의존성으로 두는 것을 확인했다. 글자 레이아웃·입력 제한·출력 규격은 바꾸지 않았다.

### 추가한 문구를 탭해도 수정 화면이 열리지 않는다

사용자 직접 QA에서 발견했고 미러링에서도 재현했다. 터치 처리기는 첫 렌더에서 만든 함수를 계속 호출하지만, `useCaptionEditing`의 수정 시작 함수는 그때의 문구 목록을 읽고 있었다. 나중에 추가한 문구는 찾지 못하고, 기존 문구도 수정·핀치 전의 내용과 크기를 읽을 수 있었다.

현재 문구 설정과 확정 함수를 참조값으로 두고 레이아웃 효과에서 갱신한다. 처음 만든 터치 처리기도 최신값으로 문구를 열며, 완료 시에는 현재 위치·다른 문구·장소를 보존한다. 렌더 중 참조값을 덮지 않고 저장용 초안 합성 규칙도 유지한다.

수정 전 새 문구 재진입·기존 문구 최신값·오래된 완료 함수 검사 3개가 실패했고 수정 후 통과했다. 전체 테스트 21개 묶음·195개 항목과 타입 검사 통과, 린트 오류 0개(기존 경고 32개). 앱을 재실행한 뒤 사용자가 만들고 옮긴 문구를 탭해 입력창·왼쪽 크기 슬라이더가 열리고 내용·크기를 유지하는 것을 실제 기기에서 확인했다. 일반 한글·줄바꿈·크기 변경 후 재진입도 사용자가 모두 정상이라고 확인했다. 실제 저장 파일에 두 줄 한글과 크기 1.36이 남았고, 기존 결과물 목록 파일은 변경 전과 바이트 단위로 같았다.

## 이번 조작의 범위

자동 키 입력으로 들어간 테스트 원문은 `QA draftBef\nore Done`이다. 미러링의 줄바꿈 위치 전달 제약이 있어 일반 키보드 입력의 정확성 검증으로 사용하지 않는다. 완료를 누르기 전 슬라이더로 크기를 1에서 0.74로 바꾼 뒤 실제 초안 파일에서 내용·크기를 읽었다. 원래 초안을 백업했고 기존 결과물 13개를 유지한다. 후속 사용자 QA는 원래 1.95km 기록에서 진행했으므로 그 편집값을 예전 백업으로 덮어쓰지 않는다. 변경 전·후 초안을 따로 보존한다.

## 2단계 착수와 배포 전 확인

핵심 QA 완료로 2단계에 착수할 수 있다. 확인하지 않은 배포 전 항목까지 통과한 것은 아니다. TestFlight를 단계 사이에 먼저 배포하는 조건은 사용자 후속 요청에 따라 [결정문 개정](../../decisions/2026-10-04-story-style-editor.md#2026-10-04-단계별-qa와-묶음-배포)과 FRD에 반영했다.

큰 글자·다른 기기, 실제 인스타그램 공유·복귀, Release 빌드의 통합 확인은 배포 전에 진행한다. 새 기능 범위로 확장하거나 이 항목을 자동 검사 통과와 같은 의미로 쓰지 않는다. 재생 버튼·시트 높이·안내 자리·재진입 후 되돌리기 기록은 FRD의 정책 미결과 구분해 관리한다.
