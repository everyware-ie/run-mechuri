## 정한 것

| | |
|---|---|
| 도구 | **배경, 경로, 러닝 데이터, 문구 넷만.** 그리기와 내 스타일은 3단계에서 만들 때 버튼도 같이 넣는다. 눌러도 아무것도 안 되는 버튼을 미리 두지 않는다 |
| 문구 입력 | 문구 시트 안의 입력창. 키보드가 올라온다. 화면 전체를 쓰는 입력은 나중에 다듬을 거리 |
| 크기 슬라이더 | **1/3배~3배, 기본 크기가 가운데.** 눈금을 곱셈 비율로 둬서 키우는 쪽과 줄이는 쪽이 같은 길이다. **누르기만 해서는 바뀌지 않고 끈 거리만큼만 바뀐다.** 러닝 데이터·문구는 핀치도 같은 범위다. 경로 그림은 FRD가 상한을 두지 않아(§4-4) 핀치로는 더 키울 수 있다. 2026-10-04 실기기 확인에서 "가운데를 눌렀는데 갑자기 엄청 커진다"는 지적을 받고 바꿨다. 처음에는 누른 자리로 값이 뛰고 100%가 아래쪽 20% 지점에 있었다 |
| 숨기기 자리 | 러닝 데이터를 끌기 시작하면 화면 아래 가운데에 동그라미가 나온다. 시트가 열려 있으면 시트 위에 놓는다 |
| 끄는 동안 | 도구 버튼과 ✕·↶를 숨긴다. 결과물만 보이게 한다 |
| 배경 시트 | 기본 배경은 누르면 바로 바뀐다. 갤러리·사진 찍기는 배경 선택 화면으로 가서 고르는 창을 바로 연다(`pick` 파라미터) |
| 되돌리기 | 초안이 바뀔 때마다 바뀌기 전 모습을 쌓는다(`lib/edit-history.ts`, 최대 60단계). 문구 시트를 연 동안의 글자 입력은 한 단계로 묶는다. 장소 이름 채우기는 쌓지 않는다. 앱을 나갔다 오면 기록은 없다 |
| 재생 | `LOOP_PREVIEW = true`. 평소 반복 재생, 손대는 동안 멈춘다. 실기기에서 느리면 false로 두고 재생 버튼을 되살린다 |

## 설계

### 문구를 러닝 데이터에서 떼는 방법

**문구는 러닝 데이터 프리셋 여섯 개의 배치 계산 안에 들어 있다.** 프리셋마다 문구 자리가 다르고, 글래스는 카드 안에, 코너는 위쪽 머리글에 둔다. 미리보기(`stampLayoutDescriptors`)와 결과 영상(Swift `drawStamps`)이 같은 계산을 따로 갖고 있다.

그래서 배치 계산은 고치지 않고 **두 번 돌린다.**

| 계산 | 위치·크기 | 쓰는 것 |
|---|---|---|
| 러닝 데이터 | `position`, `scale` | 문구를 뺀 나머지 |
| 문구 | `captionOffset`, `captionScale` | 문구만 |

**문구가 러닝 데이터와 붙어 있을 때**(두 위치와 크기가 같을 때)는 지금처럼 한 번에 계산한다. 글래스 카드 안의 문구처럼 지금 모습 그대로다. 둘 중 하나를 옮기거나 키우면 떨어진 것으로 보고, 러닝 데이터는 문구 자리를 비우지 않고 다시 배치한다. 글래스 카드가 문구 줄만큼 줄어드는 식이다.

**옛 저장분은 문구 위치·크기가 없다.** 읽을 때 러닝 데이터의 위치·크기를 그대로 쓴다. 그래서 지금까지 만든 결과물을 다시 편집해도 문구가 제자리에 있다.

**숨김은 러닝 데이터만 숨긴다.** 문구는 남는다. 붙어 있을 때 숨기면 문구는 원래 자리에 그대로 있다.

## 확인할 위험

- 문구를 떼면 러닝 데이터가 다시 배치되면서 손을 뗀 순간 한 번 움직인다(글래스, 코너, 스탯바). 실기기에서 거슬리는지 본다
- 네이티브가 바뀌므로 개발용 앱을 다시 설치해야 한다
- 반복 재생 중 조작이 느려지는지(FRD §2 미리보기)
