## 정한 것

|---|---|
| 도구 | **배경, 경로, 러닝 데이터, 문구 넷만.** 문구는 시트가 아니라 화면에서 바로 쓰는 버튼이다. 그리기와 내 스타일은 3단계에서 만들 때 버튼도 같이 넣는다. 눌러도 아무것도 안 되는 버튼을 미리 두지 않는다 |
| 문구 입력 | **화면에서 바로 쓴다**(`components/caption-editor.tsx`). 가운데에서 결과물과 같은 글꼴·크기로 쓴다. 화면은 어둡게 하지 않는다(처음엔 어둡게 했는데 필요 없다는 의견). 왼쪽 슬라이더로 크기를 바꾼다. 완료나 빈 곳을 누르면 끝나고, 새 문구는 화면 가운데에 놓인다. 처음에는 문구 시트의 입력창이었는데 "인스타에선 그냥 화면에 바로 들어간다"는 지적을 받고 바꿨다 |
| 크기 슬라이더 | **1/3배~3배, 기본 크기가 가운데.** 눈금을 곱셈 비율로 둬서 키우는 쪽과 줄이는 쪽이 같은 길이다. **누르기만 해서는 바뀌지 않고 끈 거리만큼만 바뀐다.** 러닝 데이터·문구는 핀치도 같은 범위다. 경로 그림은 FRD가 상한을 두지 않아(§4-4) 핀치로는 더 키울 수 있다. 2026-10-04 실기기 확인에서 "가운데를 눌렀는데 갑자기 엄청 커진다"는 지적을 받고 바꿨다. 처음에는 누른 자리로 값이 뛰고 100%가 아래쪽 20% 지점에 있었다 |
| 숨기기 자리 | **결과물 밖, 맨 아래 띠 가운데.** 끄는 동안 완료 버튼 자리에 동그라미가 나온다. 손가락이 띠 안으로 들어가고 가로로 가운데에서 72pt 안이면 놓았을 때 숨긴다(문구는 지운다). 끄는 동안 시트는 아래로 치우고, 들어가는 순간 진동(expo-haptics)한다. 숨기거나 지우면 3.5초 동안 "되돌리기" 안내를 띄운다. 처음에는 결과물 안(시트 위)에 나와 실수로 숨기기 쉬웠다 |
| 문구 입력 칸 | **글자 크기는 가장 큰 크기(3배)로 고정하고, 보이는 크기는 칸 전체를 줄여서(transform) 맞춘다.** 칸 너비는 거꾸로 넓혀 줄바꿈이 결과물과 같은 자리에서 일어나게 한다. React Native의 iOS 입력 칸은 한국어 키보드를 쓰는 동안 글자 크기 변경을 이미 쓴 글자에 다시 적용하지 않는다(`RCTTextInputComponentView.mm` `_textOf:equals:`가 `ko-KR`이면 글자만 비교). 그래서 크기 슬라이더를 움직이면 칸만 커지고 글자는 그대로라 "위치만 움직이다가 손을 떼면 크기가 바뀐다"는 현상이 났다. 줄이기만 하므로 글자가 흐려지지 않는다 |
| 시트 닫기 | 완료를 누르거나 아래로 끌어 내린다. 시트 높이의 35%(최대 120pt)보다 많이 내리거나 빠르게 밀면 닫히고, 아니면 제자리로 돌아간다. 세로로 끈 거리가 가로의 1.5배를 넘을 때만 시트가 가져가서 가로 스크롤(배경 목록)과 겹치지 않는다. 슬라이더는 잡은 응답을 놓지 않아 시트가 끌리지 않는다 |
| 끄는 동안 | 도구 버튼과 ✕·↶를 숨긴다. 결과물만 보이게 한다 |
| 배경 시트 | 기본 배경은 누르면 바로 바뀐다. 갤러리·사진 찍기는 배경 선택 화면으로 가서 고르는 창을 바로 연다(`pick` 파라미터) |
| 되돌리기 | 초안이 바뀔 때마다 바뀌기 전 모습을 쌓는다(`lib/edit-history.ts`, 최대 60단계). 문구 시트를 연 동안의 글자 입력은 한 단계로 묶는다. 장소 이름 채우기는 쌓지 않는다. 앱을 나갔다 오면 기록은 없다 |
| 다듬기 슬라이더 | 손잡이는 끄는 동안 슬라이더가 바로 그린다. 다듬기 계산은 화면 프레임당 한 번이라 손잡이가 그걸 기다리면 늦게 따라온다. 누르기만 해서는 바뀌지 않는다(iOS 기본 슬라이더와 같다). 잡고 있는 동안 미리보기를 멈춘다(FRD §2-1). 2026-10-04 실기기에서 "원하는 대로 정확히 움직이지 않는다"는 지적을 받고 바꿨다 |
| 재생 | `LOOP_PREVIEW = true`. 평소 반복 재생, 손대는 동안 멈춘다. 실기기에서 느리면 false로 두고 재생 버튼을 되살린다 |

## 설계

### 문구

**문구는 인스타처럼 화면에 바로 쓰는 글자이고 여러 개다.** 러닝 데이터 프리셋과 상관없다. `StampConfig.captions`에 `{ id, text, offset, scale }`을 넣은 순서대로 담는다. 나중에 넣은 것이 위에 그려지고 먼저 잡힌다. 자리는 화면 가운데로부터의 오프셋(캔버스 px), 크기는 기본 크기(64px)에 곱하는 배율이다. 가운데 정렬이고 줄바꿈 폭은 좌우 여백(캔버스 8%) 안이다.

**러닝 데이터 프리셋 배치는 문구 없이 돌린다.** 프리셋 여섯 개의 배치 계산 안에는 문구 자리가 섞여 있다(글래스는 카드 안, 코너는 왼쪽 위). 그 계산에 빈 문구를 넣어 돌리면 문구 자리를 비우지 않고 배치된다. 미리보기(`stampLayoutDescriptors`)와 결과 영상(Swift `drawStamps`)이 같은 규칙이다.

**끄는 문구 하나만 자기 레이어로 옮긴다.** 문구는 여러 개라 문구마다 SharedValue를 둘 수 없다. 가만히 있는 문구는 저장된 자리에 그리고, 끄는 문구는 끄기 시작할 때 따로 떼어 SharedValue로 옮긴다. 손을 떼면 자리를 저장하고 다시 합친다.

**옛 저장분은 `captions`가 없다.** 문구 하나가 프리셋 안에 있던 모습 그대로 그린다. 보관함 썸네일이 바뀌지 않게 하려는 것이다. 편집 화면에 들어오면 `migrateLegacyCaption`이 프리셋이 놓았던 문구의 자리와 크기를 계산해 그 근처의 문구 하나로 바꾼다. 글꼴만 문구 글꼴(굵은 한글)로 바뀐다.

> 같은 날 세 번 바뀌었다. ① 옮기기·크기만 따로 하고 처음 자리·글꼴은 프리셋을 따름 → ② 프리셋과 상관없는 문구 하나(`captionOffset`, `captionScale`) → ③ 화면에 바로 쓰는 여러 개(`captions`). ②의 형식은 개발용 앱에만 저장됐고 읽을 때 ③으로 바꾼다(`captionItems`).

**숨김은 러닝 데이터만 숨긴다.** 문구는 남는다. 문구는 같은 자리(휴지통)에 놓으면 지운다.

## 코드 검토에서 고친 것 (2026-10-04)

실기기에서 나온 문제(크기 슬라이더, 탭 동작, 다듬기 슬라이더)와 같은 종류를 찾으려고 브랜치 전체를 다시 읽었다.

| | 고친 것 |
|---|---|
| 크기 슬라이더가 늦게 따라온다 | 끄는 동안 손잡이를 슬라이더가 바로 그린다. 편집 화면은 경로 그림이면 SharedValue만 바꾼다. 핀치로 범위 밖까지 키운 뒤 잡아도 튀지 않게 잡은 순간의 값에서 곱셈으로 이어 간다 |
| 원라인 문구 줄 간격 | 위 "어긋남 기록" |
| 되돌리기로 장소가 사라진다 | 장소 이름은 늦게 채워져 첫 단계에 없다. 되돌려도 지금 장소 이름을 남긴다 |
| 첫 되돌리기가 아무것도 안 바꾼다 | 옛 저장분에 문구 자리를 채우는 일을 들어올 때 초안에 바로 반영하고 단계로 쌓지 않는다 |
| 슬라이더를 잡다 뒤로 가기가 된다 | 화면 왼쪽 끝에서 밀면 뒤로 가기라 슬라이더를 안쪽으로 옮겼다 |
| 문구를 탭해도 키보드가 안 올라온다 | 문구 시트가 열린 채 키보드만 내렸으면 다시 올린다 |
| 크기를 바꾸려다 숨겨진다 | 두 손가락이 되면 숨기기 자리 위였더라도 숨기지 않는다 |

## 확인할 위험

- 자유 문구가 화면 가운데에서 시작해 경로 그림과 겹친다. 인스타와 같은 동작이지만 실기기에서 어색한지 본다
- 네이티브가 바뀌므로 개발용 앱을 다시 설치해야 한다
- 반복 재생 중 조작이 느려지는지(FRD §2 미리보기)

## 어긋남 기록

- **원라인 문구 크기 (2026-10-04 코드 검토).** 9/16에 원라인 문구를 26→22로 줄일 때 미리보기·결과 영상은 바꿨는데 줄바꿈 계산(`caption-layout.ts`)만 26으로 남아 있었다. 두 줄 이상이면 미리보기의 줄 간격이 결과 영상보다 넓고 줄도 일찍 바뀌었다. 22로 맞추고 테스트를 더했다. FRD와는 상관없는 구현끼리의 어긋남이다
- **문구 하나, 시트 입력 (2026-10-04).** FRD에 "문구는 하나만 둔다"(시안의 "1개만")와 시트 입력으로 정했는데, 실기기에서 인스타처럼 화면에 바로 쓰고 여러 개를 넣고 끌어서 지우자는 요청을 받았다. FRD §7·§7-2·§4-1과 경로 렌더링 §7-6, 결정문에 개정을 덧붙였다
- **선택과 끌기 (2026-10-04).** "러닝 데이터를 선택했는데 경로가 움직인다". 탭으로 선택되게 바꾼 뒤에도 끌기는 손가락이 닿은 곳만 봐서, 글자 사이를 짚으면 경로가 움직였다. 규칙 두 개(손댄 것을 만진다, 탭하면 선택한다)를 따로 바꾸면서 둘의 관계를 놓쳤다. 글자를 직접 짚지 않은 끌기는 선택된 대상을 움직이게 하고, **조작 규칙을 `lib/edit-gesture.ts`의 순수 함수로 떼어 조합별 테스트(10개)를 붙였다.** 조작 규칙을 바꾸면 이 테스트부터 고친다
- **경로 그림 탭 (2026-10-04).** 탭하면 아무 일이 없었는데 "경로는 선택이 안 된다"는 지적을 받았다. 경로 그림 영역(점선 상자, `computeRouteLocalBounds`)을 지금 위치·회전·크기로 되돌려 판정하고, 안이면 경로 시트를 연다. 끌기는 그대로 글자가 아닌 곳 어디서나 경로 그림을 움직인다
- **러닝 데이터 탭 (2026-10-04).** 결정문 7번대로 탭하면 다음 프리셋으로 넘어가게 만들었는데, 실기기에서 "선택이 아니라 다른 프리셋으로 바뀐다"는 지적을 받았다. 탭하면 러닝 데이터 시트를 열어 선택하도록 바꾸고, FRD §4-1·§7과 결정문에 개정을 덧붙였다.
