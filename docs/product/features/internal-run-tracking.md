# 자체 러닝 측정 내부 구현

근거: [PRD](../../specs/prd/internal-run-tracking.md) · [FRD](../../specs/frd/internal-run-tracking.md).

## 착수 확인

2026-10-05 사용자가 지표 추천·실패 복구와 FRD를 확인하고 “바로 구현 진행”을 요청했다. 위치·시간·거리·페이스·동작 센서, 선택적 워치 심박·화면·제어, 내부 보관·복구·진단 요약, 권한 안내 화면을 구현한다. 심박 없는 기록도 시작·저장한다. TestFlight는 구현과 기본 검증 후 팀 내부용으로 배포하는 계획이다.

## 구조와 기술 선택

- 아이폰: Expo 로컬 Swift 모듈의 단일 네이티브 측정 상태. Core Location·Core Motion 수집과 저장은 JS 화면 수명과 분리한다.
- 기록: 별도 내부 저장소. 원본 이벤트 로그와 원자적 요약, 잠금 후 파일 접근·백업 제외. 기존 초안·결과물과 섞지 않는다.
- 워치: SwiftUI 동봉 앱의 HealthKit 운동 세션과 심박 원본 보관. WatchConnectivity로 같은 기록 ID의 상태·심박을 연결한다. 건강 앱에는 별도 완성 운동을 저장하지 않아 비교 앱과 중복 저장하지 않는다.
- 빌드: `RUNARY_INTERNAL_TRACKING=1`일 때만 네이티브 내부 플래그·위치 background mode·워치 타깃을 추가한다. JS 진입 차단과 네이티브 API 차단을 함께 적용한다.

## 어긋남 기록

워치의 안전한 세션 시작 확인과 전면 GPS 준비 후 재개 조건을 FRD에 함께 구체화했다. 미검증 사항을 성공으로 기록하지 않는다.

## 검증

기능 코드와 자동 검사를 구현했다. 자동 검사·빌드와 실기기·야외 실측을 구분해 [QA 계획](../../ops/internal-run-tracking-qa.md)에 남긴다.

홈·첫 실행 안내에서 진입한다. 내부 기록은 `Documents/InternalRuns/<UUID>/events.jsonl`에 보관하고 기존 결과물·초안을 바꾸지 않는다. 좌표와 심박의 샘플 시각을 수신 시각과 분리한다. GPS 원본의 거절 사유는 재생 시 같은 계산으로 산출한다. 정상 대기 중 제외한 좌표는 수신 신선도에서 지우지 않는다. 계산 기준 `internal-v1`, GPS 준비·확보 시각, 배터리·충전·저전력 모드를 진단에 포함한다.

저장 확정은 이벤트 배치 끝의 checkpoint를 파일에 동기화한 시점이다. 요약 파일이 실패해도 확정 로그로 복구한다. 재실행 때 최근 미완료 기록에 자동 연결하고 아이폰 수집은 중단 상태로 둔다. 손상된 꼬리는 확정 로그 이후 부분만 잘라 복구하고 원본 전체가 손상되면 보존한다. 저장 재시도 때문에 종료 시각이 늘어나지 않게 종료 요청 시각을 고정한다.

워치 심박은 기기에 먼저 보관하고 아이폰 저장 성공을 확인한 자료만 전달 완료로 처리한다. 백그라운드 전송은 제한된 배치이며 실시간 전달을 보장하지 않는다. 아이폰 지표가 10초 넘게 갱신되지 않으면 워치에 지연을 표시하고 시간도 계속 추정하지 않는다. 살아 있는 워치가 모은 실제 심박은 GPS 중단 시간·거리와 분리해 병합한다. 일시정지·종료 제어에는 같은 기록 ID를 확인하며 워치 종료도 확인 동작을 둔다.

## 첫 구현의 동작 상세

워치에서 새 운동 세션을 만들기 전에 사용자가 시작을 확인한다. 아이폰에서 워치 앱을 여는 것만으로 기존 워치 운동을 종료시키지 않는다. 워치 재개도 아이폰 전면의 GPS 준비 완료를 요구한다. 항상 위치 권한을 요청하지 않는 FRD와 같은 조건이다. 건강 앱에는 `finishWorkout`으로 별도 완성 운동을 저장하지 않는다.

미지원·미수신 지표는 표시를 비워 두고 GPS 측정은 유지한다. HealthKit의 읽기 권한 거부를 데이터 부재로 단정하지 않는다. 앱 권한 화면은 홈·측정과 기존 건강 접근·카메라·사진 저장 실패 안내에서 연결되며 OS에서 돌아오면 상태를 재조회한다. 원본 GPS·심박 배열은 진단 복사에서 제외한다. 진단 버전은 Expo 매니페스트 대신 네이티브 앱의 Info.plist에서 읽어 개발 런처에서도 실제 설치 버전을 표시한다. 기록 삭제 시 아이폰은 삭제 표식을 보관해 늦은 심박 전송으로 기록이 되살아나지 않게 하고 워치에도 삭제를 전달한다. 워치가 오프라인이면 다음 연결에 적용하며 동봉 실기기에서 확인해야 한다. 사용자 메모는 직접 입력한 내용이므로 복사 전에 개인정보를 넣지 않도록 주의한다.

## 자동 검증 명령

```bash
sh frontend/scripts/check-run-tracking.sh

cd frontend
node_modules/.bin/jest --runInBand src/lib/tracking-display.test.ts
node_modules/.bin/tsc --noEmit
node_modules/.bin/eslint src/ modules/
```

Swift 검사는 합성 좌표로 계산·정지·신선도·심박 중복·저장 복구·쓰기 실패를 확인한다. 빌드 설정 검사는 공개 빌드의 위치 백그라운드 모드·워치 타깃 제외와 내부 타깃 생성·중복 생성 방지를 확인한다. 이 자동 검사를 실제 야외 GPS·워치 심박·잠금·배터리의 합격 근거로 사용하지 않는다.

## 설치·배포 조건

지원 하한은 iOS 16.4, watchOS 10.0이다. Mac에 watchOS 26.5 구성요소를 설치해 워치 앱 전체 컴파일을 확인했다. 기존 아이폰 개발 프로파일은 사용 가능하지만 새 `com.mechuri.runmechuri.watch`용 개발 프로파일은 없다. 사용자가 Xcode에 로그인했으나 해당 팀의 Certificates, Identifiers & Profiles 접근은 허용되지 않아 새 프로파일을 만들 수 없다. 팀 관리자 조치와 워치 서명·실기기 검증은 별도 완료가 필요하다. 실제 상태는 [QA 기록](../../ops/internal-run-tracking-qa.md)에서 확인한다.

내부 TestFlight용 프로필은 `internal-tracking`이며 `RUNARY_INTERNAL_TRACKING=1`을 사용한다. EAS가 워치 자격 증명을 준비하도록 app extension 선언을 추가했다([Expo CNG 타깃 안내](https://docs.expo.dev/build-reference/app-extensions/)). 실제 배포 전 IPA의 아이폰·워치 버전/빌드 번호 일치, 워치 서명과 설치, 내부 테스터 배정 여부를 확인한다. 자동 제출·공개 그룹 배포는 하지 않았다.

## 러닝 화면 개선 (2026-10-05)

사용자가 서버 실행과 서비스 환경에 맞춘 UI 개선을 요청했다. [FRD](../../specs/frd/internal-run-tracking.md) §1-1 실제 러닝을 위한 화면 구성을 먼저 보완했다. 준비·측정·완료를 구분하고 네 지표와 하단 고정 제어를 중심으로 정리한다. 기록 목록·메모·진단은 접힘 영역에 둔다. 네이티브 계산·권한·복구·수집 조건과 내부 빌드 제한은 유지한다.

화면 개선 검증에서 전체 Jest 34개 묶음·277개, TypeScript와 문서 검사를 통과했다. ESLint는 오류 0개·기존 경고 30개다. iPhone 11 Pro에서 준비·시작·일시정지·종료 저장을 확인했다. 실내 13초·0.00km QA 기록을 보관했으며 실제 센서 정확도 검증으로 해석하지 않는다. 새 화면의 재개는 실내 GPS 재확보가 30초 안에 완료되지 않아 확인하지 못했다. 이전 구현의 재개 확인과 구분한다.

최신 8081 연결 후 완료 요약과 작은 위치 없음 안내, 최근 기록 펼치기·열기, 접힌 메모·진단과 메모 입력 영역 펼치기를 실기기에서 확인했다. 개발 연결은 앱에 등록된 `exp+mechuri` 스킴을 사용한다. 다른 화면 크기·큰 글자와 야외 실측·워치 검증은 별도다.

## 러닝 지도 착수 (2026-10-05)

사용자가 지도 보완안을 확인하고 지도 추가 작업을 요청했다. PRD §2 범위와 FRD §1-2 러닝 지도를 먼저 개정했다. 준비·측정·완료/이전 기록의 Apple 지도, 현재 위치 따라가기·탐색·복귀, 구간별 경로 표시를 구현한다. 지도는 기존 GPS 수집을 재사용하고 화면용 읽기 API를 추가한다. 권한별 이동 개선과 워치 기본 연결 변경은 이번 지도 작업과 구분한다.

지도 패키지는 Expo 57이 안내하는 react-native-maps를 사용한다. 실제 좌표 원본과 거리 계산은 유지하며 지도 배경의 Apple 네트워크 요청을 기기 내 기록 보관과 구분해 안내한다. 새 네이티브 의존성과 브릿지 때문에 개발 앱 재빌드가 필요하다. 기존 워치 동봉 서명 제한과 야외 실측 미완료를 이번 지도 구현으로 완료 처리하지 않는다.


### 지도 코드와 자동 검사

- `run-map.tsx`: Apple 지도, 현재 위치와 출발·종료 표시, 따라가기와 수동 탐색·복귀. 완료 기록은 전체 경로를 맞추며 좌표가 없으면 작은 안내로 표시한다. 화면 이탈·백그라운드에서는 지도 뷰를 내려 수집 엔진과 분리한다.
- `TrackingManager.mapSnapshot`: 기존 채택 좌표를 한 번에 최대 512개씩 읽는다. 매초 파일을 재생하지 않으며 엔진이 교체되면 버전을 바꿔 같은 기록을 복구해도 오래된 좌표에 이어 붙이지 않는다. JS는 기존 전면 상태 조회에서 한 차례 최대 8쪽을 읽고 남은 좌표는 다음 조회에서 읽는다.
- `tracking-map.ts`: 새 좌표 합치기·구간 분리·지도 표시 간소화. 각 구간의 처음·끝과 굽은 점을 남기는 2m 기준이며 저장 원본·거리·페이스 계산에는 적용하지 않는다.

지도 신규 Jest 7개를 포함한 전체 35개 묶음·284개, Swift 엔진·확정 로그 합성 검사 29개, 공개/내부 설정 검사, 타입·문서 검사를 통과했다. 린트는 오류 0개·기존 경고 30개다. react-native-maps 1.27.2 연결 후 아이폰·워치 동봉 무서명 Debug 빌드와 iOS JS export를 통과했다. 실기기 결과는 [지도 검증](../../ops/internal-run-tracking-qa.md#9-2026-10-05-러닝-지도-검증)에 별도로 남긴다.


실기기에서 준비 위치·지도 이동·따라가기 해제·현재 위치 복귀, 네 지표와 하단 제어, 일시정지·종료 저장·기록 재진입을 확인했다. GPS 준비값이 오래되거나 측정 첫 좌표가 늦어도 같은 상태의 마지막 실제 위치를 유지하고 지연을 표시한다. 다른 기록·복구에 과거 위치를 이어 붙이지 않는다. 완료된 짧은 경로는 도로가 보이는 최소 범위를 적용해 과확대를 막는다. 합성 지도는 두 구간의 전체 맞춤과 단절을 화면으로 확인한 뒤 임시 화면을 제거했으며 실제 기록으로 저장하지 않았다. 상세 결과와 실측 한계는 QA 문서에 모았다.

## 안정성 QA 착수와 첫 수정 (2026-10-05)

사용자가 남은 주간 한도가 약 70%가 될 때까지 QA와 수정을 요청했다. 승인된 FRD §3-1 지표 계산 추천안·§5-1 실패와 복구 추천안·§8-3 워치가 열리지 않거나 연결이 끊어질 때를 기준으로 상태·실패 흐름을 확인한다. 기능 공개와 TestFlight 배포를 뜻하지 않는다.

워치 심박 과거 배치의 저장 성공과 현재 운동 세션 상태를 분리했다. 직접 받은 최신 응답만 연결 상태를 바꾸고, 시작 확인 대기·일시정지·종료를 구분한다. 이전 연결 요청의 늦은 실패가 새로운 연결을 덮지 않도록 기록·요청 식별자를 확인한다. 워치에서 아이폰 지표가 오래되면 페이스·케이던스를 현재값으로 유지하지 않으며, 이전 운동 세션/수집기의 늦은 콜백은 새 세션을 바꾸지 않는다.

GPS 준비와 실제 시작에 같은 좌표·시각·정확도 검사 함수를 사용한다. 미래 시각은 기존 센서 필터와 같은 최대 2초 오차 범위만 허용한다. 지도 현재 위치 점의 중앙을 좌표에 맞추고 신선도가 바뀌면 표시도 갱신한다. 원본 경로·거리 계산은 바꾸지 않는다.

권한 조회는 개별 제공자의 실패를 분리한다. 카메라 확인 실패가 위치·동작·사진 상태를 가리지 않으며 실패한 항목은 `확인 실패`로 남긴다. 화면 이탈·백그라운드·새 조회 뒤의 오래된 응답은 무시하고 다시 확인할 수 있다. 새 권한 요청이나 OS 설정 변경을 자동 수행하지 않는다.

첫 수정의 Swift 합성 검사 38개, Jest 36개 묶음 287개, TypeScript·공개/내부 설정 검사와 아이폰·워치 무서명 Debug 빌드를 통과했다. 실기기 재설치와 후속 QA 결과는 [안정성 QA](../../ops/internal-run-tracking-qa.md#10-2026-10-05-안정성-qa)에 이어 기록한다.

후속 QA에서 홈의 측정 상태를 전면에서 주기적으로 확인하고, 권한 설정 이동 실패에는 직접 찾을 수 있는 경로를 제공했다. 기록 상세는 현재 기록 ID에 해당하는 자료만 표시하며 조회 실패 시 원본을 보존하고 다시 불러온다. 전환 전의 늦은 응답이 새 기록을 덮지 않는다. 측정 화면도 백그라운드 전환 전 시작한 조회의 늦은 응답을 무시하며, 조회 복구 시 조회 오류만 지우고 사용자 동작의 오류는 유지한다.

종료 저장의 자동 재시도가 성공하면 종료 처리까지 이어가도록 보완했다. 확정 로그의 두 종료 경계에서 쓰기 실패·복구 후 완료 상태·원래 종료 시각 보존을 임시 저장소로 확인했다. 아이폰 공간 부족 상황의 타이머 실측은 별도다. 최종 Jest 39개 묶음 299개·Swift 44개·타입·설정·iOS export와 아이폰·워치 전체 재컴파일을 통과했고 아이폰 업데이트 설치와 완료 기록 재진입을 확인했다. 워치 동봉 설치와 야외 실측은 완료되지 않았다.

## PR 정리와 TestFlight 인계 (2026-10-05)

사용자가 지금까지의 작업을 PR로 정리하고 머지하도록 요청했으며 TestFlight 제출은 Claude에서 진행한다고 밝혔다. 이번 Git 작업은 제출·테스터 배정을 수행하지 않는다.

- 자체 측정을 포함하려면 `frontend/eas.json`의 `internal-tracking` 프로필로 빌드한다. `RUNARY_INTERNAL_TRACKING=1`이 적용되어 워치 타깃·위치 백그라운드 설정·내부 진입이 포함된다. 일반 `production` 프로필에는 자체 측정 진입이 없다.
- 워치 개발 프로파일과 실기기 설치는 완료되지 않았다. 배포 담당자는 워치 배포 서명과 아이폰·워치 버전/빌드 번호 일치, 동봉 설치와 심박 전달을 확인한다. 로컬 아이폰 전용 QA 복사본은 TestFlight 배포물로 사용하지 않는다.
- 내부 측정 빌드는 팀 내부 테스터에게만 배정한다. 공개 링크·일반 외부 그룹에는 배정하지 않는다. 야외 GPS·잠금 수신·배터리는 내부 운동 테스트에서 확인할 남은 항목이다.
- 검증 결과와 미실시 항목은 [QA 기록](../../ops/internal-run-tracking-qa.md)에 있다. 설정 자동 이동 실패의 원인은 미확인이며 현재는 직접 이동할 수 있는 안내를 제공한다.
