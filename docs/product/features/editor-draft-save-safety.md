# 편집 초안 저장과 이어서 만들기 검증

- 근거: [홈과 보관함 FRD](../../specs/frd/home-and-library.md) §3 만들다 만 것 / [결과물 편집 FRD](../../specs/frd/result-editing.md) §1 화면 구조 (`approved`)
- 관련 구현: [스토리형 편집 1단계](story-editor-stage1.md)
- 착수 확인: 2026-10-04 사용자가 후속 안정성 검증·수정을 이어 진행하도록 요청했다. 마지막 편집값을 남기고 완성된 작업이 초안으로 다시 나타나지 않게 한다. TestFlight 배포는 보류한다.

## 확인 범위

편집 화면이 공유 화면 뒤 스택에 남아 있을 때 자동 저장을 중단한다. 나가기 직전 최신 편집값은 명시적으로 저장한다. 저장·읽기·완료 후 삭제가 겹치면 호출 순서대로 처리하고, 앞선 저장 실패가 이후 작업을 막지 않도록 한다.

## 발견한 구조

자동 저장은 화면의 포커스를 보지 않는다. 공유 화면에서 완료 후 초안을 지워도, 뒤에 남은 편집 화면의 값이 갱신되면 다시 저장할 수 있다. 나가기는 React 상태 갱신 뒤 자동 저장에 의존한다. 저장·읽기·삭제 사이에는 앱 계층의 대기와 순서 보장이 없다.

## 수정과 검증

`useDraftAutosave`가 포커스를 확인해 보이는 편집 화면에서만 자동 저장한다. 공유를 취소하고 돌아오면 저장을 다시 시작한다. 나가기·완료 시 `commitAll`은 프레임에 대기하던 편집값까지 반영한 최신 참조값을 직접 저장 요청한다. React 갱신이나 화면 전환 뒤의 효과 실행에만 의존하지 않는다.

`draft-store`의 저장·읽기·삭제를 하나의 대기열에서 호출 순서대로 처리한다. 홈의 읽기는 앞선 저장을 기다리고, 완료 후 삭제도 앞선 저장 뒤에 적용된다. 요청할 때 직렬화하므로 대기 중 객체가 바뀌어도 요청 당시의 편집값을 저장한다. 실패는 해당 호출자에게 반환하되 이후 저장·삭제는 계속한다. 자동 저장의 실패는 처리되지 않은 Promise 오류로 남기지 않고 경고 로그에 남긴다. 기기의 저장 공간 부족 자체를 해결하거나 저장 성공을 보장하는 변경은 아니다.

- 지연된 저장소를 모의 처리한 기존 `draft-store` 검사 3개와 포커스를 보지 않는 기존 자동 저장 방식을 분리한 React 검사 2개가 실패했다. 수정 후 통과한다. 실제 iOS 저장소의 완료 순서가 뒤집힌 것을 관측한 결과는 아니다.
- 저장소 검사 7개: 저장 순서·읽기 대기·완료 후 삭제·삭제 뒤 새 작업·실패 뒤 다음 작업·옛 사진 경로와 기본값·요청 당시 객체 보존.
- React 검사 5개: 활성 화면 저장·숨은 화면 갱신 무시·편집 복귀·재료 없는 상태와 실패 처리·포커스 전환 직전 명시적 저장.
- 전체 Jest 146개, 타입 검사 통과. 전체 린트 오류 0개, 기존 경고 32개. 문서 정합성 검사 통과.
- 저장 키·파일 형식·옛 저장분 호환은 유지한다. 네이티브 코드와 패키지는 바꾸지 않았다. 앱 설치와 TestFlight 배포는 하지 않았다.

기존 저장 정책을 맞추는 안정성 수정이다. 제품 정책과 새 용어가 바뀌지 않아 FRD·PRD·결정문을 개정하지 않는다. 앱 재진입 시 되돌리기 기록 보존은 FRD의 미결 항목으로 남긴다.

## 남은 실기기 확인

위치·크기·문구를 바꾸고 바로 나간 뒤 이어서 만든다. 마지막 편집값이 남는지 확인한다. 결과물을 완성한 뒤 홈에 해당 작업의 이어서 만들기가 다시 나타나지 않는지, 생성 취소 후 돌아와 편집하고 나가면 다시 이어서 만들 수 있는지 본다. 이번 검사는 React 갱신과 지연 저장소 모의 검사이며 실제 iOS 저장·앱 재실행·영상 생성 흐름은 확인하지 않았다.
