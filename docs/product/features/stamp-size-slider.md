# 러닝 데이터 크기 슬라이더

근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §4-2 제스처, §7 러닝 데이터와 문구.

## 착수 확인 (2026-09-20)

사용자가 직선·코너 다듬기처럼 편집 모달에서 러닝 데이터 크기를 슬라이더로 조절하도록 요청했다. 기존 핀치 크기 조절을 유지하고 같은 값을 조절하는 보조 입력을 추가한다. FRD의 '슬라이더를 쓰지 않는다' 설명은 경로 그림의 위치·크기·회전 조작에 한정하고 러닝 데이터 크기는 예외로 보완한다. PRD의 편집 기능 범위는 바뀌지 않는다.

## 동작

러닝 데이터의 프리셋·항목·문구 탭에 공통으로 '크기' 슬라이더와 현재 백분율을 보여준다. 기존 핀치 범위인 50~300%를 사용하고 1% 단위로 조절한다. 100%는 프리셋 기본 크기다. 핀치로 조절한 값과 슬라이더 값이 서로 반영되며 초기화 시 100%로 돌아온다. 위치·표시 항목·문구·프리셋은 크기 조절로 바꾸지 않는다.

직선·코너와 같은 슬라이더 컴포넌트·36pt 행을 재사용하고 기존 패널 높이 상한을 유지한다. 드래그 중 미리보기를 갱신하되 저장은 손을 뗄 때 확정한다. 완료 버튼은 대기 중인 갱신을 반영한다.

## 어긋남 기록

이번 요청으로 러닝 데이터 크기에 제스처 외의 조절 경로가 추가됐다. FRD를 함께 보완한다. 저장 데이터 구조와 네이티브 출력 설정은 기존 scale을 그대로 쓴다.

## 검증

- TypeScript와 기존 미리보기·원라인·선택 박스 회귀 검사 통과. 전체 린트는 기존 오류 19개·경고 5개와 동일하다.
- 공용 슬라이더의 기존 0~100과 새 50~300 범위, 눌렀다가 즉시 손을 떼는 동작, 눌러 이동하는 동작, 범위 끝 제한, 제스처 중단 시 확정, 외부 값 변경 및 최신 콜백 사용을 검사했다.
- 크기 갱신은 기존 프레임 단위 갱신 함수를 재사용하고, 드래그 완료 시 마지막 입력값을 저장한다. 공용 슬라이더는 리렌더를 기다리지 않고 마지막 터치 값을 보관하므로 짧게 누른 값도 이전 값으로 저장되지 않는다.
- 실제 아이폰의 슬라이더 사용감·핀치 후 동기화·초기화·패널 높이는 사용자 QA로 확인한다. TS 변경이라 네이티브 재설치 없이 로컬 개발 서버에서 확인할 수 있다. TestFlight 배포는 별도다.
