# 앱 보관 영상의 백업 제외

근거: [홈과 보관함 FRD](../../specs/frd/home-and-library.md) §2-3 무엇이 남나, [MVP PRD](../../specs/prd/running-drawing-mvp.md) §6 MVP에서는 기기에만 저장한다.

## 착수와 수정

2026-10-13 사용자가 정식 심사 위험 검토와 문제 수정 후 PR 생성·머지를 요청했다. 앱 보관 영상에는 경로와 건강 지표가 들어갈 수 있지만 `Documents/clips`에 백업 제외 속성이 없었다. [Apple 심사 지침 5.1.3(ii)](https://developer.apple.com/app-store/review/guidelines/#health-and-health-research)에 맞춰 기존 기기 내 보관을 보완한다. FRD와 PRD도 같은 변경에서 정리한다.

`LocalClipStorage`가 영구 보관 디렉터리에 `isExcludedFromBackup`을 적용한다. 렌더러 생성 때 기존 디렉터리에 적용하고, 새 인코딩 전에 다시 확인한다. 새 출력 준비에서 속성 적용이 실패하면 렌더링을 진행하지 않는다. 기존 영상은 옮기거나 지우지 않는다. 초기 적용 실패는 개인 경로 없이 로그로 알린다.

건강 기록과 트랙이 들어가는 초안·결과물 정보는 AsyncStorage 2.2.0의 iOS 기본 동작으로 이미 백업에서 제외된다. 설치된 `RNCAsyncStorage.mm`의 기본값과 37번의 Info.plist에 포함 허용 설정이 없는 것을 대조했다.

## 검증과 배포 범위

실제 파일 시스템에서 새 디렉터리·기존 디렉터리의 제외 속성, 파일 보존, 반복 적용, 저장 경로 오류를 검사한다. iOS 네이티브 빌드와 기존 타입·린트·문서 검사도 수행하며 결과는 [최종 심사 검토](../../ops/app-store-final-review-2026-10-13.md)에 남긴다.

이 수정은 이미 업로드한 `1.0.0(37)`에 포함되지 않는다. 네이티브 변경이므로 정식 제출 전 새 일반 빌드를 만들고 바이너리와 실기기에서 확인해야 한다. 37번의 소스 태그는 그대로 보존한다. iCloud 백업 자체를 실행한 검증이나 기존 백업의 원격 삭제를 수행하지 않았다.
