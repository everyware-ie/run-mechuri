# 손그림 획 선택과 편집

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §4-1 손댄 것을 만진다·§11 손그림 (`approved`), [경로 렌더링 FRD](../../specs/frd/route-rendering.md) §8-1 손그림 합성.
- 착수 확인: 2026-10-04 사용자가 획 하나씩 선택하는 추천안의 FRD 내용을 확인하고 구현을 요청했다.
- 이슈: [#99](https://github.com/everyware-ie/run-mechuri/issues/99)
- 상태: 구현·자동 검사·핵심 실기기 QA 완료.

기존에는 그리기 화면에서 새 선을 더하거나 지우는 것만 가능했다. 편집 화면에서 손그림 획을 직접 누르면 선택하고, 위치·크기·붓·색·굵기를 바꾸는 시트를 연다. 선택은 실제 선과의 거리를 검사하며 문구·러닝 데이터가 우선한다. 여러 획을 그룹으로 묶는 기능은 이번 범위가 아니다.

기존 점 배열을 보존하고 획의 이동·크기 값을 따로 저장한다. 미리보기의 제스처는 SharedValue로 표시하고 손을 놓을 때 한 번 저장한다. 썸네일·지우개·영상도 같은 변환을 사용한다. 옛 저장분은 이동 0·크기 1로 읽는다. 새로 그리는 세션의 되돌리기와 편집 화면의 획 편집 되돌리기는 구분한다.

## 검증

타입·문서 검사와 iOS Debug 빌드를 통과했다. 전체 테스트 31개 묶음 246개를 통과했고 린트 오류 0개·기존 경고 32개다. 실제 편집 컴포넌트의 터치 콜백으로 선택·드래그·핀치 후 한 손가락 먼저 떼기·손을 놓은 좌표 저장을 검사했다. 초안·보관함의 이동·크기 값 왕복 저장, 변환된 획 지우기, 빈 사각형 오선택 방지, 선택한 획의 속성 변경과 편집 되돌리기를 확인했다.

실기기 iPhone 11 Pro 개발 앱에서 기존 획 선택·펜→네온·색 변경과 상단 붓 전환 후 되돌리기를 확인했다. 사용자가 이동·핀치·크기 슬라이더를 직접 확인하고 정상이라고 답했다. 앱 다시 열기 후 이동·크기·붓이 남는 것도 확인했다. 사용자 의견에 따라 붓을 상단으로 옮기고 아래 시트에는 색·굵기·삭제만 남겼다. 색 팔레트가 가는 줄로 표시되던 실기기 문제는 고정된 원형 버튼 너비로 수정했다.

현재 초안을 임시 폴더에 백업했고 기존 보관함 19건은 유지했다. 사용자가 이번 QA에서 바꾼 위치·크기를 포함한 최신 초안을 남겼다. 이 작업에서 새 영상을 생성하지는 않았으므로 새 변환 영상의 실제 픽셀 비교는 미검증이다. Swift 합성 코드는 빌드로 확인했다. 다른 기기 크기·실제 사진/영상 배경 조합은 실기기 미검증이며 TestFlight에는 배포하지 않았다.

## 표시와 저장

이동·크기는 기존 점 배열을 기준으로 한 `offset`·`scale`이다. 미리보기는 선택 획의 Group 변환을 SharedValue로 갱신하고 저장된 획은 같은 변환으로 그린다. Swift는 같은 획 중심을 기준으로 투명 손그림 이미지에 변환을 적용한 뒤 기존 프레임 합성에 재사용한다. 썸네일 범위와 획 지우기는 변환 후 점을 사용한다. 붓 굵기는 원래 4~48px이고 크기는 1/3~3배다. 획 전체를 키우면 굵기도 같이 커지고, 굵기 조절은 기본 굵기만 바꾼다. 화면 밖 이동은 점을 하나씩 잘라 모양을 변형하지 않고 획 전체의 이동량을 제한해 최소 일부를 남긴다.

## 어긋남 기록

FRD의 기존 이동·확대 제외 제한은 사용자 승인으로 §11-1 획 선택과 수정으로 개정했다. 결정문에 후속 개정을 추가하고 PRD·경로 렌더링의 합성 규칙을 같은 작업에서 갱신했다. 새 용어는 만들지 않았다.
