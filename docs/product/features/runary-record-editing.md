# Runary 자체 기록 편집 연결

## 착수 근거

[FRD](../../specs/frd/runary-record-editing.md)와 [내부 측정 PRD](../../specs/prd/internal-run-tracking.md)를 따른다. 2026-10-19 사용자가 실제 5km 이상 측정한 기록을 편집에 연결하도록 요청했고, 제시한 FRD를 확인한 뒤 `이 범위로 구현 진행`을 선택했다. 기존 측정·잠금화면 커밋을 보존한 `codex/feature/runary-record-editing` 브랜치에서 구현한다.

## 구현 방향

기존 네이티브 측정 저장소의 요약과 선택한 경로를 읽어 기존 RunRecord·Track으로 변환한다. 건강 앱과 자체 기록의 조회·실패 상태를 분리하고 화면에서는 날짜순으로 합친다. 자체 기록 ID와 출처를 보관하며 원본을 수정하지 않는다.

좌표에 선택적 구간 번호를 추가해 기존 자료와 호환한다. 미리보기·투영·다듬기·진행률과 네이티브 영상 렌더러가 구간 경계를 보존하도록 맞춘다. 내부 네이티브 기능 여부를 확인해 구간 렌더링을 지원하지 않는 이전 앱에는 새 선택 진입을 노출하지 않는다.

## 검증 결과

2026-10-19 타입 검사, Jest 45개 묶음 337개, 측정·저장 Swift 133개, Live Activity 30개, 구간 처리 Swift 6개와 영상 보관 경로 검사를 통과했다. 일반·내부 설정과 타깃 생성, 문서·diff 검사도 통과했다. 린트는 오류 0개와 기존 경고 30개다. 새 구간 Swift 파일을 CocoaPods에 반영한 뒤 아이폰·워치·Live Activity 확장 전체 iphoneos Debug 빌드와 깊은 서명 검증을 통과했다. 기존 개발 프로파일을 재사용했다.

검사에서 건강 앱 조회·권한 응답 지연 중 자체 기록 선택, 한 출처의 실패, 진행·경로 없는 기록 제외, 선택 중 삭제와 재시도, 연속 탭 차단을 확인했다. 구간 사이 거리 제외와 다듬기·경로 명령·진행률 보존, 없는 지표의 null 보관, 출처·좌표 구간 사본과 업데이트 후 영상 경로 복원을 확인했다.

기존 수동 보조 검사인 `check-preview-work.cjs`는 현재 컴포넌트의 필수 `lineStyle`을 주지 않는 오래된 스텁 때문에 통과하지 못했다. 임시로 스텁을 맞춰 보니 옛 문구·위치 래퍼 가정도 남아 있어 이 작업에서는 변경하지 않았다. 현행 Jest와 구간 계산 검사는 통과했으며, 보조 스크립트의 갱신은 별도 정리 사항이다. 네이티브 FPS나 모든 프리셋의 시각 비교가 끝났다는 근거로 쓰지 않는다.

## 실기기 확인

내부 개발 앱 `1.0.0(1)`을 iPhone 11 Pro에 업데이트 설치했다. 10월 14일 완료 기록 `3A617A3D-7540-40D4-9CF3-534D415BAEA7`은 5,412.68m, 2,291.85초, 채택 좌표 1,187개, 한 구간이었다. 저장 요약을 읽어 확인했으며 원본 파일은 수정하지 않았다. 사용자가 실외 수집을 확인한 사실과 이번 편집 연결 검증을 구분한다.

미러링에서 `Runary · 5.41km · 38:12 · 7'03"/km · 165bpm` 기록이 건강 앱 기록과 날짜순으로 표시되는 것을 확인했다. 선택 후 배경·편집에 실제 경로와 지표가 전달됐고 12초 1080×1920 영상 생성이 완료됐다. 사진 저장 버튼의 `기기에 저장했어요` 응답, 보관함 26개(기존 25개와 이번 결과물 한 개), 결과물 상세의 다시 편집까지 확인했다. 영상과 편집 사본은 남겨 뒀고 Instagram 공유는 실행하지 않았다. 현재 미러링은 해당 자체 기록의 재편집 화면이다.

여러 구간의 실기기 영상·모든 프리셋 비교, 원본을 실제 삭제한 뒤 재편집은 이번 QA에 포함하지 않았다. 구간 보존과 사본 독립성은 자동 검사로 확인했고 사용자 원본을 삭제하지 않았다. TestFlight 업로드와 공개 배포는 수행하지 않았다.

## 검토 중 보완

읽기 실패한 행이 비활성화돼 재시도할 수 없던 기존 목록 동작을 함께 고쳤다. 출처 이름이 붙은 파일도 업데이트 후 다시 열고 정리할 수 있도록 기존 콜론 파일명 호환을 유지하고, 새 영상 파일명에는 안전한 문자만 사용한다. 논리 기록 ID와 출처는 사본에 그대로 남긴다.

### 뒤로가기 오류 제보

2026-10-19 사용자가 왼쪽 위 뒤로가기에서 오류가 난다고 제보했다. 개발 로그에 이전 화면 없이 `GO_BACK`을 호출한 오류가 남아 있었다. [공통 규칙 FRD §5 화면 이동](../../specs/frd/common-rules.md#5-화면-이동)에 따른 기존 이동을 복구한다. 이전 화면이 있으면 돌아가고, 직접 진입해 이전 화면이 없으면 홈으로 이동한다. 배경 선택의 작업 취소와 사진 선택 취소는 먼저 처리하고 초안은 유지한다.

타입 검사, Jest 46개 묶음 341개, 문서 검사와 diff 검사를 통과했다. 린트는 오류 0개와 기존 경고 30개다. 헤더 검사에서 이전 화면 유무, 화면별 취소 처리 우선, 홈의 화살표 숨김을 확인했다. 아이폰에서 기존 오류 안내를 확인한 뒤 개발 코드를 새로 불러와 같은 기록 목록의 뒤로가기로 홈에 복귀했다. 홈에서 새로 만들기로 목록을 다시 열고 돌아오는 경로도 확인했다. 보관함 26개와 5.41km 이어서 만들기가 유지됐다. 이번 수정은 JavaScript에만 해당해 네이티브 재빌드나 TF 업로드는 하지 않았다.
