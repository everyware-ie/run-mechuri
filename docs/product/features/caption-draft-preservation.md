# 쓰는 중인 문구의 초안 보존

- 근거: [홈과 보관함 FRD](../../specs/frd/home-and-library.md) §3 만들다 만 것 / [결과물 편집 FRD](../../specs/frd/result-editing.md) §7 러닝 데이터와 문구·§4-3 되돌리기와 초기화 (`approved`)
- 선행 확인: [실기기 QA](story-editor-device-qa.md), [편집 초안 저장](editor-draft-save-safety.md)
- 착수 확인: 2026-10-04 사용자가 남은 안정성 작업을 이어 진행하도록 요청했다. TestFlight 배포는 보류한다.

## 확인할 문제

문구 입력 내용과 크기는 편집 화면의 별도 상태에 있고 완료를 누를 때 초안에 합쳐진다. 자동 저장은 합치기 전의 초안만 읽어서, 쓰는 도중 앱이 종료되면 새 내용과 크기가 남지 않을 수 있다. 마지막 입력과 완료가 같은 React 갱신에 묶이거나 완료가 연속 호출되는 경우도 확인한다.

## 수정 범위

쓰는 중인 문구를 저장용 초안에만 합친다. 화면의 확정된 편집값과 되돌리기 기록은 완료 시 한 번 바꾼다. 기존 문구의 위치와 다른 문구를 유지하고, 새 문구는 가운데에 둔다. 빈 문구는 저장하지 않는다. 파일 형식·저장 키·3줄 입력 제한·출력 규격·배포 정책은 바꾸지 않는다.

FRD·PRD와 결정문의 기존 초안 보관·문구 편집 정책을 맞추는 수정이다. 새 정책이나 용어는 추가하지 않는다.

## 검증 결과

기존 입력·완료 방식을 훅으로 분리해 저장 훅과 연결했을 때 7개 검사 중 5개가 실패했다. 완료 전 내용·크기가 저장에서 빠졌고, 마지막 입력과 완료를 같은 React 갱신으로 호출하면 이전값을 읽었다. 실제 아이폰 강제 종료로 오류를 관측한 결과는 아니다.

`useCaptionEditing`은 입력 중 내용과 크기를 저장용 설정에 합친다. 확정값은 바꾸지 않아 입력마다 되돌리기 단계가 생기지 않는다. 최신 입력을 참조값에도 바로 남기고, 완료 시 참조를 먼저 비워 중복 확정을 막는다. 편집 화면을 나가는 `commitAll`도 남은 문구를 먼저 확정한다.

- 문구 검사 8개: 새 문구·크기 자동 저장, 기존 위치·다른 문구·늦은 장소 채우기 보존, 빈 문구 제외, 마지막 입력과 완료의 동시 호출·연속 완료, 3줄 제한, 확대 후 원문 보존, 숨은 화면의 저장 중단, 실제 되돌리기 훅과 연결한 한 단계 복구.
- 전체 테스트 20개 묶음·189개 항목과 TypeScript 검사 통과. 린트 오류 0개, 기존 경고 32개. 문서와 공백 검사 통과.
- 새 네이티브 코드와 패키지가 없어 개발 앱 재설치는 필요 없다. iOS 빌드·재설치·실기기 강제 종료 검증과 TestFlight 배포는 이번에 하지 않았다.

## 남은 실기기 확인

완료 전 문구를 입력하고 크기를 바꾼 뒤 잠시 다른 앱으로 이동한다. 앱을 다시 실행해 이어서 만들기에서 내용·크기·기존 위치가 남는지 확인한다. 일반 한글 입력·물리적인 핀치와 진동은 [실기기 QA](story-editor-device-qa.md)의 남은 항목으로 유지한다.

자동 저장은 비동기다. 저장 공간 부족과 앱이 마지막 입력 직후 강제로 종료되는 경우의 저장 완료를 보장하는 변경은 아니다. 재진입 후 되돌리기 기록의 보존 정책도 바꾸지 않는다.
