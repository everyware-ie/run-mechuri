# 경로의 자유 색상 선택

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §6-2 선 색과 두께 (`approved`), [PRD](../../specs/prd/running-drawing-mvp.md) §10 로드맵의 색 선택.
- 착수 확인: 2026-10-04 사용자가 기본 6색과 더 많은 색, iOS 상세 선택, 미리보기·완료·취소·한 단계 되돌리기, 저장·썸네일·영상 반영 추천안을 승인했다.
- 추적: [#103](https://github.com/everyware-ie/run-mechuri/issues/103).
- 상태: 구현·핵심 검증 완료. 개발 앱에 반영했으며 TestFlight 배포는 진행하지 않았다.

기본 팔레트 끝에 무지개색 버튼을 두고 직접 고른 색도 버튼 안에 표시한다. 상세 선택은 UIKit 색상 선택기를 기존 네이티브 모듈의 뷰로 연결한다. 별도 네이티브 의존성은 추가하지 않는다. 격자·스펙트럼·슬라이더는 시스템 UI를 사용하고, 완료·취소는 앱 시트에서 처리한다. 투명도와 HDR 노출은 사용하지 않고 색은 sRGB 6자리 HEX로 보관한다.

기존 색 ID를 그대로 읽으면서 유효한 HEX도 허용한다. 동일한 팔레트색은 기존 ID로 정규화한다. 상세 선택 중에는 미리보기만 갱신하고 완료 시 한 단계로 확정한다. 취소·배경 터치·시스템 뒤로 가기·화면 이탈은 시작 전 색으로 복원한다. 내 스타일·초안·보관함은 공통 정규화를 사용하고 Swift도 임의 HEX를 검증해 사용한다. 불빛 러너 마감의 색 판정도 팔레트 목록 의존을 제거한다.

## 출처

- [Apple UIColorPickerViewController](https://developer.apple.com/documentation/uikit/uicolorpickerviewcontroller): 시스템 색상 선택 UI와 투명도 제어.
- [Expo SDK 57 네이티브 UI](https://docs.expo.dev/versions/v57.0.0/sdk/ui/swift-ui/colorpicker/): 시스템 선택기의 색상 전달 형식 참고.

## 검증

- 타입 검사 통과. 전체 테스트 32개 묶음 258개 통과. 린트 오류 0개·기존 경고 30개. 문서·diff 검사 통과.
- iOS Debug 빌드와 iPhone 11 Pro 덮어 설치 성공. 기존 결과물 19건을 유지했다.
- 실기기에서 6색과 상세 선택 버튼의 한 줄 배치, 시스템 격자, 후보 변경과 취소 시 보라색 복원을 확인했다. 초기 뷰 생성 이벤트가 검정색 후보로 전달되는 문제를 수정하고, 하단 최근 색 버튼이 잘리지 않도록 높이를 조정했다. 재설치 후 초기 색·격자·하단 버튼 표시를 확인했다.
- 후속 미러링 화면에서 직접 고른 색이 선택 버튼과 불빛 러너의 밝은 중심·주변 빛에 반영되는 것을 확인했다. 사용자가 직접 조작을 시작한 뒤에는 화면 조작을 중단하고 현재 선택을 보존했다.
- 실제 편집 화면을 렌더링하는 회귀 검사에서 후보는 이력을 만들지 않고 취소 시 복원되며, 완료한 색만 한 번 되돌리는 것을 확인했다. 기존 두께와 손그림을 유지한다. 별도 검사에서는 늦게 도착한 이벤트·화면 닫힘의 중복 저장을 막고 초안·내 스타일의 HEX 저장·적용을 확인했다.
- 다른 화면 크기·큰 글자·시스템 스펙트럼/슬라이더/스포이트 조작과 새 영상의 최종 픽셀은 실기기 미검증이다. 영상은 같은 HEX 전달과 Swift 색 파싱을 연결하고 빌드를 통과했지만, 이번 검증에서 새 결과물은 생성하지 않았다.

선택창은 시스템 UI를 사용하는 하단 시트라 경로 위치에 따라 미리보기 일부를 가릴 수 있다. 편집한 경로 배치는 임의로 바꾸지 않는다. 작은 화면에서의 선택창 공간 조정은 실제 사용자 확인 후 검토한다.
