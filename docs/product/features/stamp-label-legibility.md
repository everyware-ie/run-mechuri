# 러닝 데이터 라벨 가독성

- FRD: [경로 렌더링](../../specs/frd/route-rendering.md) §7-4-1 읽히는 것이 먼저다
- 근거 QA: [QA 기록](../../ops/qa-log.md) "러닝 데이터의 라벨 글씨가 흐리다"(2026-09-29), "라벨 글씨 가독성은 아직이다"(2026-10-06)
- 구현 상태: **보류.** 2026-10-22에 한 번 시도했고 사용자가 폰에서 보고 이전이 더 낫다고 해서 되돌렸다(아래 "시도한 것"). 코드는 main과 같다

## 무엇을 고치나

러닝 데이터에서 값(시간, 페이스 등)은 읽히는데 값 위의 라벨(TIME, PACE, 날짜)이 흐려서 밝은 배경에서 잘 안 보인다. 2026-09-30 확인에서 원인은 라벨만 투명도 50%인 크림색이라는 것이다. 값은 불투명하다.

[FRD §7-4-1](../../specs/frd/route-rendering.md)이 "바탕이 무엇이든 읽혀야 한다"를 기준으로 두고 있다. 이 기준은 그대로 따른다. 구체적인 색과 두께는 FRD가 "실기기에서 보며 정한다"고 했으므로 이 노트에 정한 값과 확인 결과를 남긴다.

**예쁜 것을 희생하지 않는다.** 러닝 데이터는 결과물의 얼굴이라 예쁜 것도 매우 중요하다(사용자, 2026-10-22). 문제는 예쁨이 아니라 라벨이 안 보인다는 것이다. 값은 크고 밝게, 라벨은 작고 옅게 두는 위계는 디자인이므로 지킨다. 라벨을 값과 똑같이 만들어 해결하지 않고, 위계가 보이는 범위에서 대비만 올린다. 고친 모양이 예쁜지는 사용자가 폰에서 보고 판단한다.

FRD 7-4-1의 "예쁜 것보다 읽히는 것이 먼저다"라는 표현은 사용자의 관점과 다르다. 이 문장은 9/16 회의 결정에서 온 것이라 개인이 문서에서 고치지 않는다. 문구를 바꿀지는 팀에 올려서 정한다. 이 작업의 구현은 어느 쪽이든 같다.

## 고칠 곳

편집 화면과 저장되는 영상이 같은 모양으로 그려져야 한다. 둘을 함께 고친다.

| | 파일 | 무엇 |
|---|---|---|
| 편집 화면 | `frontend/src/components/route-preview.tsx` | `muted`인 글씨의 투명도(`fillOpacity .5`) |
| 저장한 영상 | `frontend/modules/route-renderer/ios/RouteRendererModule.swift` | `mutedColor`(투명도 0.5)와 글씨에 거는 그림자 |

## 방법(잠정)

- 라벨 투명도를 50%에서 올린다. 값과 같아질 때까지 올리지 않고 위계가 남는 수준에서 멈춘다
- 글씨 뒤 그림자를 보강한다. 밝은 배경에서는 어두운 그림자가, 어두운 배경에서는 지금 모양이 유지되는지 본다
- 편집 화면과 저장 영상에 같은 값을 쓴다
- 값은 폰에서 후보를 나란히 놓고 정한다

## 확인할 것

0. 고친 모양이 예쁜지(사용자 판단). 고치기 전과 나란히 본다
1. 흰 사진 한 장에서 편집 화면과 저장한 영상의 라벨을 나란히 본다. 영상의 라벨이 편집 화면보다 더 흐린지(QA 기록의 `[확인 필요]`)
2. 새 기본 배경 6장(특히 하늘이 밝은 `bg-3-track`, `bg-2-coast-road`)에서 라벨이 읽히는지
3. 글자 색을 흰색과 검정으로 바꿔도 읽히는지(FRD §7-4-1이 어느 색이든 또렷함 기준이 그대로라고 한다)

## 시도한 것

**2026-10-22, 라벨 투명도 0.5 → 0.78, 라벨 그림자 0.55 → 0.8.** 편집 화면(`route-preview.tsx`)과 저장 영상(`RouteRendererModule.swift`)에 같은 값을 넣었다. 사용자가 폰에서 보고 **이전 모양이 더 낫다**고 해서 같은 날 되돌렸다. 커밋 이력에 시도와 되돌림이 그대로 남아 있다.

- 이 방식(투명도와 그림자를 균일하게 올리기)은 예쁨을 해친다고 판단됐다. 같은 방식으로 값만 바꾸는 시도는 반복하지 않는다
- 라벨이 안 보인다는 문제 자체는 남아 있다. 어떤 배경·프리셋에서 어느 정도로 안 보이는지 스크린샷으로 확인한 뒤, 다른 방법을 찾는다. 예를 들면 배경이 밝을 때만 라벨 대비를 올리는 방식이다
- 사용자가 어떤 점이 더 낫다고 느꼈는지는 확인하지 못했다. 다음 시도 전에 물어본다
