# 러닝 데이터 라벨 가독성

- FRD: [경로 렌더링](../../specs/frd/route-rendering.md) §7-4-1 읽히는 것이 먼저다
- 근거 QA: [QA 기록](../../ops/qa-log.md) "러닝 데이터의 라벨 글씨가 흐리다"(2026-09-29), "라벨 글씨 가독성은 아직이다"(2026-10-06)
- 구현 상태: **구현했다. 값은 폰에서 보며 조정하는 중이다**(2026-10-22). 1차 값(0.78)은 사용자가 폰에서 보고 "훨씬 잘 보인다, 조금 더 보여도 된다"고 해서 2차 값(0.9)으로 올렸다

## 무엇을 고치나

러닝 데이터에서 값(시간, 페이스 등)은 읽히는데 값 위의 라벨(TIME, PACE, 날짜)이 흐려서 밝은 배경에서 잘 안 보인다. 2026-09-30 확인에서 원인은 라벨만 투명도 50%인 크림색이라는 것이다. 값은 불투명하다.

[FRD §7-4-1](../../specs/frd/route-rendering.md)이 "바탕이 무엇이든 읽혀야 한다"를 기준으로 두고 있다. 이 기준은 그대로 따른다. 구체적인 색과 두께는 FRD가 "실기기에서 보며 정한다"고 했으므로 이 노트에 정한 값과 확인 결과를 남긴다.

**예쁜 것을 희생하지 않는다.** 러닝 데이터는 결과물의 얼굴이라 예쁜 것도 매우 중요하다(사용자, 2026-10-22). 문제는 예쁨이 아니라 라벨이 안 보인다는 것이다. 값은 크고 밝게, 라벨은 작고 옅게 두는 위계는 디자인이므로 지킨다. 고친 모양이 예쁜지는 사용자가 폰에서 보고 판단한다.

FRD 7-4-1의 "예쁜 것보다 읽히는 것이 먼저다"라는 표현은 사용자의 관점과 다르다. 이 문장은 9/16 회의 결정에서 온 것이라 개인이 문서에서 고치지 않는다. 문구를 바꿀지는 팀에 올려서 정한다. 이 작업의 구현은 어느 쪽이든 같다.

## 고칠 곳

편집 화면과 저장되는 영상이 같은 모양으로 그려져야 한다. 둘을 함께 고친다.

| | 파일 | 무엇 |
|---|---|---|
| 편집 화면 | `frontend/src/components/route-preview.tsx` | `STAMP_MUTED_ALPHA`, `STAMP_MUTED_SHADOW_ALPHA` |
| 저장한 영상 | `frontend/modules/route-renderer/ios/RouteRendererModule.swift` | `stampMutedAlpha`, `stampMutedShadowAlpha` |

## 값의 이력

| | 라벨 글씨 투명도 | 라벨 그림자(옅은 그림자 레이아웃) | 결과 |
|---|---|---|---|
| 원래 | 0.5 | 0.55 | 밝은 배경에서 사라졌다 |
| 1차 | 0.78 | 0.8 | 사용자 확인: **훨씬 잘 보인다.** 조금 더 보여도 된다 |
| 2차 | **0.9** | **0.9** | 확인 대기 |

- 값 글씨, 값 그림자, 문구는 바꾸지 않았다. 라벨만 바뀐다
- `row` 레이아웃은 그림자가 원래 불투명한 흰색이라 라벨 그림자는 그대로 두고 글씨 투명도만 올랐다
- 두 군데의 값은 같아야 한다. 값을 바꿀 때는 TS와 Swift를 함께 고친다
- **0.9보다 더 올리면 값과 라벨의 위계가 거의 사라진다.** 그래도 부족하면 투명도가 아니라 다른 방법을 쓴다. 후보: 라벨 글씨를 한 단계 굵게, 배경이 밝을 때만 그림자를 더 진하게, 글자 색을 값과 살짝 다르게

## 한 번 되돌렸다 다시 적용했다

1차 값을 적용한 직후 사용자가 "이전이 더 나은 것 같다"고 해서 되돌렸다(2026-10-22). 같은 날 다시 보고 "훨씬 잘 보인다, 수정한 쪽이 낫다"고 판단해 되살렸다. 커밋 이력에 적용, 되돌림, 재적용이 모두 남아 있다. 처음 판단은 이전 값이 눈에 익어서였을 수 있으니, 폰에서 오래 본 뒤 정하는 것이 좋다.

## 확인할 것

0. 고친 모양이 예쁜지(사용자 판단). 고치기 전과 나란히 본다
1. 흰 사진 한 장에서 편집 화면과 저장한 영상의 라벨을 나란히 본다. 영상의 라벨이 편집 화면보다 더 흐린지(QA 기록의 `[확인 필요]`)
2. 새 기본 배경 6장(특히 하늘이 밝은 `bg-3-track`, `bg-2-coast-road`)에서 라벨이 읽히는지
3. 글자 색을 흰색과 검정으로 바꿔도 읽히는지(FRD §7-4-1이 어느 색이든 또렷함 기준이 그대로라고 한다)
4. 코너 외의 프리셋(스탯바, 레일, 스택, 원라인, 글래스)에서도 라벨이 같은 정도로 보이는지
