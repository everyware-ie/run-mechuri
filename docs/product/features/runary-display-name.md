# 앱 표시 이름을 Runary로 반영

근거: [제품명 결정](../../decisions/2026-09-16-product-name-runary.md), [홈과 보관함 FRD](../../specs/frd/home-and-library.md) §1-1 화면 구성, [러닝 기록 선택 FRD](../../specs/frd/run-record-selection.md) §3 권한.

## 착수 확인 (2026-09-20)

사용자가 처리방침 링크 구현 다음에 앱 표시 이름·홈 제목·시작 버튼의 제품명 반영을 이어서 진행하도록 요청했다.

## 구현

앱 표시 이름과 홈 제목, 완성 화면의 브랜드 문구는 `Runary`로 표시한다. 첫 실행 버튼은 `러너리 시작하기`, 건강 데이터 권한 설명의 앱 이름은 `러너리`로 바꾼다. Expo 설정과 현재 로컬 iOS 개발 프로젝트의 표시 이름을 맞춘다.

기존 결정에 따라 번들 ID, Expo 프로젝트·업데이트 주소·URL 스킴, 보관함 저장 키는 유지한다. 기존 앱의 이름을 바꾸는 작업이므로 앱이나 보관함을 새로 만들지 않는다. 과거 회의·QA 인용과 디자인 파일 이름, 팀 메추리 이름도 그대로다.

## 어긋남 기록

PRD에는 빌드에 옛 이름이 남아 있다고 기록되어 있었다. 로컬 반영과 TestFlight 배포 상태를 구분해 갱신했다. 공개 노션은 앱 코드 변경만으로 바뀌지 않아 후속 사용자 요청으로 2026-09-20 허브·처리방침·FAQ의 이름을 Runary로 변경했다. [공개 문서 변경 이력](../../ops/public-docs-log.md)에 범위와 검증을 기록했다. 스토어·SNS 표시는 이번 작업에 포함하지 않았다.

## 검증

타입·문서 검사와 iOS Debug 빌드를 통과했다. 변경 화면의 린트가 통과했고 전체 린트는 기존 오류 16개·경고 5개로 동일하다. 빌드된 Info.plist에서 표시 이름 Runary, 기존 번들 ID com.mechuri.runmechuri, 러너리 건강 권한 문구를 확인하고 개발 아이폰에 설치했다. 이후 PR #63을 머지해 TestFlight `1.0.0(23)` 내부 배포를 완료했다. production IPA의 표시 이름·번들 ID·JS 번들·서명을 확인했고 Apple의 `VALID` / `IN_BETA_TESTING` 상태를 확인했다. 외부 공개는 팀원 또는 후속 작업으로 남겼다. [배포 기록](../../ops/build-and-dev-commands.md)에 제출 결과와 인계 절차가 있다.
