# 배경 선택 전체 미리보기

- FRD: [배경 선택](../../specs/frd/background-selection.md) (`approved`, §2 기본 이미지·§4 사진 처리)
- 구현 상태: 구현 완료 (로컬)

## 확인한 범위 (2026-09-10)

사용자가 배경 선택 화면의 상단 미리보기를 9:16으로 줄여 가운데 배치하는 방식을 적용하고 실기기에서 확인하기로 했다.
현재 기본 이미지 3장은 1080×1920이므로 미리보기 틀도 같은 비율로 맞추면 배경과 경로의 전체 구도를 함께 보여줄 수 있다.
이미지는 기존처럼 틀을 채우며, 결과물의 크롭 정책과 저장 규격은 바꾸지 않는다.

## 구현

- 2026-09-11부터 고정 높이·화면 비율 상한 대신, 하단 선택 도구를 제외한 가용 영역을 `onLayout`으로 측정한다.
- 가용 높이와 가용 폭의 16/9 중 작은 값을 높이로 쓰고, 가로 폭은 높이의 9/16으로 계산한다. 좁은 화면에서도 전체 구도를 유지한다.
- 기본 소재 목록과 사진 조정 도구를 번갈아 표시해 미리보기 공간을 확보한다. 자세한 동선은 [사진 배경 구현 노트](photo-backgrounds.md)에 기록한다.
- 배경과 `RoutePreview`에 같은 크기를 전달하고 가운데 정렬한다.
- 번들 이미지는 원본 크기를 기본 스타일로 가지므로 `absoluteFill`만으로는 부족하다. 이미지의 `width`·`height`를 각각 `100%`로 지정해 카드 크기로 덮어쓴다. 그렇지 않으면 9:16 틀 안에서도 원본 윗부분만 보인다.
- 안내 라벨과 실제 기본 이미지 제공 상태에 맞지 않는 설명을 갱신한다.

## 관련 구현

- 홈 썸네일은 후속 [드로잉·각인 중심 썸네일](stamp-units-and-result-thumbnails.md)에서 배경과 전체 결과물을 함께 맞추는 방식으로 변경했다.
- 편집 화면의 시트 겹침은 후속 [편집 도구와 전체 미리보기](editor-docked-preview.md)에서 개선했다. 남은 공간에 9:16 전체를 맞추고 도구를 접으면 확대한다.

## 검증

- 타입 검사, 해당 화면 린트, 문서 검사와 `git diff --check` 통과.
- 기본 배경 3장의 실제 크기(1080×1920)를 확인했고, 320×568부터 430×932 및 가로 화면에서 미리보기의 9:16 비율과 가로 폭 상한을 확인했다.
- 최초 비율 변경 뒤에도 원본 크기의 번들 이미지가 카드에서 잘리는 문제가 남아 있었다. 사용자 피드백 후 이미지 크기를 100%로 명시해 수정했다.
- 수정 후 타입 검사·해당 화면 린트 통과. 실기기에서 아침의 어두운 하단, 정오의 밝은 하단, 저녁의 주황색 하단까지 작은 선택 이미지와 같은 전체 그라데이션으로 표시되는 것을 확인했다.
- 실기기의 최종 배치와 크기 만족도는 사용자 확인을 기다린다.
