# 보관함과 러닝 하단 탭

- FRD: [보관함과 러닝 하단 탭](../../specs/frd/home-running-tabs.md)
- 상태: 구현과 로컬 QA 완료, TestFlight 준비

## 사용자 선택

2026-11-03 결과물 목록 끝까지 내려야 러닝을 시작할 수 있는 문제를 제보했다. 비교 시안의 보관함·러닝 탭 구성을 선택했고, 아이콘은 편집의 경로 도구와 같은 모양으로 정했다.

`CLAUDE.md`, 문서·Git 규약, 용어집과 `frontend/AGENTS.md`를 읽었다. 사용자에게 FRD 2~4절의 화면과 전환 범위를 제시했고 같은 날 구현 진행 승인을 받았다. Expo 57의 버전별 Router·Symbols 문서와 탭 가이드도 읽었다.

## 구현과 코드 리뷰

편집의 경로 도구는 `frontend/src/app/edit.tsx`의 `point.bottomleft.forward.to.point.topright.scurvepath`를 사용한다. 탭에서도 같은 심벌을 재사용해 추후 한쪽만 달라지지 않도록 한다.

기존 홈과 러닝 화면을 `(home)` 그룹으로 옮기고 Expo Router의 지연 로딩 탭으로 연결했다. `/`와 `/internal-run` 주소는 유지하며 편집·상세·공유는 바깥 Stack에 남겼다. 하단 탭은 보관함과 준비 화면에서 표시하고 실제 측정 중에는 숨긴다.

홈의 `InternalRunEntry` footer는 탭으로 대체하고 앱 권한·개인정보 링크를 남겼다. 편집과 러닝 탭은 `ROUTE_SYMBOL`을 공유한다. 기존 기록·초안 저장소와 측정 네이티브 모듈은 변경하지 않았다.

코드 리뷰에서 탭의 이전 조회가 측정 화면의 새 상태를 덮어쓰는 경로를 차단했다. 탭이 배경에 있을 때 처음 안내로 이동시키지 않도록 홈의 첫 확인도 전면 상태에 맞췄다. 보관함은 상태만 읽으며 준비·시작 API를 호출하지 않는다.

첫 안내에는 ‘달리기를 새로 기록하지 않는다’는 이전 문구가 남아 있어 측정 빌드에서만 실제 기능에 맞게 고쳤다. 처음 안내에서 러닝을 고르면 안내를 마친 것으로 기록하고 화면을 교체한다. 보관함 복귀 시 같은 안내를 반복하지 않으며, 저장 실패와 연속 탭도 검사한다.

화면 전환은 같은 러닝과 기존 주소를 유지해야 한다. 탭 왕복과 종료·재개, 워치·실시간 현황 진입을 함께 확인하며, 앱 코드 착수 전 Expo 57의 해당 버전 문서를 읽는다.

## 검증

전체 Jest 53개 묶음 391개, 타입·린트·문서·빌드 구성 검사를 통과했다. 린트는 오류 0개와 기존 경고 30개다. iOS 배포용 JavaScript의 Hermes 번들 생성도 통과했다.

개발 앱 48번과 새 JavaScript를 연결한 미러링에서 탭 표시, 준비 화면 전환과 보관함의 스크롤 위치 유지를 확인했다. 측정 중 보관함으로 나가면 탭에 측정 상태가 표시됐고, 러닝 탭으로 돌아와도 같은 기록의 시간이 이어졌다. 측정 화면에서는 탭이 숨겨졌으며 일시정지·종료 뒤 0.00km, 1:39의 기록 저장 완료와 준비 화면 복귀를 확인했다. 워치 연동과 건강 자동 저장은 기존 꺼짐 상태를 유지했다.

이번 QA는 실내 화면 전환과 저장을 확인한 것이다. 야외 거리와 워치 세션의 기존 실기기 검증을 유지하며, 새 TestFlight 앱 설치 결과로 간주하지 않는다. 첫 안내 완료 표시는 자동 검사로 확인했고 사용자의 기존 데이터를 지우는 새 설치 검사는 하지 않았다.

TestFlight 등록 결과는 [빌드·개발 기록](../../ops/build-and-dev-commands.md)에 따로 남긴다. 현재 심사 중인 이전 빌드와 공개 문서는 이 UI 변경으로 수정하지 않는다.
