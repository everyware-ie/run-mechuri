# 편집 되돌리기 안정성 검증

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §4-3 되돌리기와 초기화, §1 화면 구조 (`approved`)
- 관련 구현: [스토리형 편집 1단계](story-editor-stage1.md)
- 착수 확인: 2026-10-04 사용자가 후속 안정성 검증·수정을 계속 진행하도록 요청했다. TestFlight 배포 보류를 유지한다.

## 확인 범위

실제 편집 한 번이 되돌리기 한 단계가 되는지 확인한다. 같은 프리셋 재선택, 바꾸지 않은 문구 입력 완료, 기본값에서 초기화처럼 결과가 같은 조작은 편집 이력을 차지하지 않아야 한다. 자동으로 채운 장소 이름은 사용자의 편집이 아니며, 사용자 편집과 동시에 채워져도 그 편집의 되돌리기를 막지 않아야 한다.

## 발견한 오류와 수정

- 초안 객체가 바뀌기만 하면 값을 비교하지 않고 이전 모습을 쌓는다. 실제로 바뀐 편집값만 비교해 기록한다.
- 장소 이름을 채울 때 다음 이력 기록을 무조건 생략하는 플래그를 켠다. 사용자 편집과 같은 렌더에 반영되면 사용자 편집도 함께 빠진다. 자동 장소 정보는 값 비교에서 제외하고 사용자 편집은 그대로 기록한다.

FRD와 PRD의 기존 되돌리기 기준을 맞추는 수정이다. 제품 정책과 새 용어는 바꾸지 않는다. 앱 재진입 후 기록 보존은 FRD의 미결 항목으로 유지한다.

## 검증

- 기존처럼 값 비교 없이 기록하는 동작으로 실제 React 갱신 테스트를 실행하면, 같은 값의 조작 후에도 단계가 추가되어 실패했다. 수정본에서는 통과한다.
- 값 판정 테스트: 같은 값·객체 키 순서·옛 저장분의 기본 크기, 자동 장소 정보, 장소 정보와 편집의 동시 변경, 문구·숨김·표시 항목·위치·크기·다듬기·프리셋, 배경 구도와 사진·영상 소재 변경.
- React 갱신 테스트: 같은 값의 조작 후 한 번 되돌리기, 자동 장소 채우기 이후 편집, 자동 채우기와 이동의 동시 반영, 옛 문구 전환 뒤 문구 삭제와 배경 변경의 기록 순서.
- 전체 Jest 113개, 타입 검사 통과. 전체 린트 오류 0개, 기존 경고 32개. 문서 정합성 검사 통과.
- Swift와 네이티브 패키지는 바꾸지 않았다. 앱 재설치와 TestFlight 배포는 하지 않았다.

## 남은 실기기 확인

같은 프리셋을 다시 고르거나 문구를 바꾸지 않고 완료한 뒤, 되돌리기가 마지막 실제 편집을 되돌리는지 확인한다. 장소가 늦게 표시되는 기록에서도 이동·프리셋 선택을 되돌릴 수 있는지 본다. 이번에는 실제 터치·화면 모양·영상 픽셀 비교를 수행하지 않았다.

[문구 검증 노트](story-editor-caption-qa.md)의 미리보기·저장 영상 비교와 반복 재생 중 조작감 확인도 아직 남아 있다.

## 2026-10-05 후속: 빠른 연속 되돌리기

사용자가 승인한 후속 안정성 점검에서 같은 React 갱신 안에 되돌리기를 두 번 누르는 경우를 검사했다. 크기를 100% → 120% → 150%로 바꾸고 두 번 되돌리면 이력은 두 개 사라지지만 화면은 120%까지만 돌아갔다. 버튼 콜백이 같은 마지막 스냅샷을 두 번 읽는 것이 원인이다. 손그림 화면에서도 두 획을 그린 뒤 빠르게 되돌리면 마지막 한 획이 남았다.

이력의 현재 배열을 ref에 보관하고, 이벤트가 올 때 이전 스냅샷을 꺼내는 것과 이력을 줄이는 것을 함께 처리한다. 다음 React 갱신을 기다리지 않아도 다음 이벤트는 다음 단계를 복원한다. 최근 60단계, 장소 자동 채움, 같은 값의 조작 제외, 그리기 세션을 전체 편집의 한 단계로 묶는 기존 정책은 유지한다. FRD §4-3 되돌리기와 초기화와 §11 손그림에 맞추는 오류 수정이며 제품 정책은 바꾸지 않는다.

수정 전 실제 편집 화면과 손그림 컴포넌트 검사에서 두 오류를 재현했다. 수정 후 빠른 여러 번 탭, 이력 소진 뒤 추가 탭, 되돌리기 이후 새 편집을 검사해 통과했다. 앱 전환으로 진행 중 획을 마친 뒤 완료를 눌러도 동일한 획이 중복 저장되지 않았다. 전체 테스트 33개 묶음 266개·타입 검사 통과, 린트 오류 0개(기존 경고 30개). 실기기에서는 색상 확정 후 한 단계 되돌리기와 다른 편집값 유지를 확인했으며, 빠른 연속 탭은 이벤트 순서를 제어하는 실제 컴포넌트 회귀 검사로 검증했다.
