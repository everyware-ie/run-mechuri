# 러닝 잠금화면 현황 구현

## 근거와 착수 확인

[잠금화면 FRD](../../specs/frd/run-live-activity.md)와 [PRD](../../specs/prd/run-live-activity.md)를 따른다. 2026-10-19 대화에서 사용자가 거리 중심의 아이콘 제어 시안을 확인하고 “네 다음 구현작업 진행해 주세요”라고 요청했다. 이후 사용자가 잠금화면에서 즉시 재개하도록 요청해 FRD와 기존 측정 문서에 반영했다. 앱 내 재개와 최초 시작의 GPS 준비는 유지하고, 잠금화면 재개는 새 구간과 재개 이후 GPS만 사용한다.

## 구조

기존 TrackingManager가 원본 측정과 저장을 맡고 ActivityKit 연결부에 표시용 요약만 전달한다. SwiftUI 위젯 확장은 같은 기록의 요약을 표시하고 App Intent로 기존 제어를 호출한다. 경로 원본과 센서 수집은 확장에 넣지 않는다. 일반 빌드에는 위젯 확장을 추가하지 않는다.

종료 확인에는 기록 ID와 상태 변경 세대를 함께 사용한다. 앱이나 워치에서 상태를 바꾸면 이전 확인 요청은 무효다. 앱 진입 링크는 현재 기록이나 해당 완료 기록으로 연결하며 새 러닝을 시작하지 않는다.

## 검증

2026-10-19에 다음을 확인했다.

| 검사 | 결과 |
|---|---|
| 순수 Swift | 기존 엔진·저장 123개, Live Activity 제어·심박 만료·재개 GPS 구간 30개 통과 |
| 앱 테스트 | Jest 44개 묶음 325개 통과 |
| 앱 검사 | 타입 통과. 린트 오류 0개, 기존 경고 30개. 변경한 화면의 경고는 없음 |
| 빌드 설정 | 일반 설정에서 확장·표시 플래그 제외. 내부 설정에서 워치·위젯 타깃 생성과 재실행 시 중복 방지 통과 |
| 네이티브 빌드 | Xcode iOS 26.5 시뮬레이터 SDK, Debug 무서명 아이폰·워치·위젯 전체 빌드 통과 |
| 화면 | 실제 SwiftUI 카드로 320·360·430pt의 측정·일시정지·종료 확인·긴 값·지연·심박 미수신을 렌더링. 기본 글자에서 모두 높이 160pt. 320pt 큰 글자의 긴 거리·시간에서도 단위 표시 확인 |

화면 검증에는 시뮬레이터의 별도 시안 앱과 가상 값을 사용했다. 실제 ActivityKit 잠금화면이나 사용자 러닝 데이터의 검증으로 세지 않는다. 최초 전체 빌드에서 워치 아이콘 원본 1000px 복사로 실패해 생성 시 1024px로 변환하도록 고쳤다. Expo가 생성하는 내부 import와 App Intent의 import 접근 수준 충돌도 맞췄다.

실기기 잠금 상태에서의 일시정지·즉시 재개·새 GPS 수신, OS 인증, 워치 제어, 저장 실패 복구와 사용자 카드 삭제는 남아 있다. 배터리 사용량과 Dynamic Island 세부 시각 확인도 별도 검증한다. iOS 16.4·17의 실행 검증은 해당 런타임에서 남아 있으며 현재 SDK의 최소 지원 버전 컴파일과 구분한다.

## 어긋남 기록

처음 제안한 앱 진입 후 GPS 준비 방식은 사용자가 즉시 재개를 요청해 변경했다. 같은 브랜치에서 잠금화면 FRD와 기존 측정 FRD에 새 구간·위치 권한 기준을 반영한 뒤 구현했다.
