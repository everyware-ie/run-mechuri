# 스토리형 편집 실기기 검증

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §2 미리보기·§7 러닝 데이터와 문구, [경로 렌더링 FRD](../../specs/frd/route-rendering.md) §7-6 한 줄 문구 (`approved`)
- 선행 검증: [문구 코드 검증](story-editor-caption-qa.md), [스토리형 편집 1단계](story-editor-stage1.md)
- 범위 확인: 2026-10-04 사용자가 다음 작업인 실기기 QA를 진행하도록 요청했다. TestFlight 배포와 2단계 구현은 보류한다.

## 환경과 준비

iPhone 11 Pro에서 개발용 앱과 Mac의 아이폰 미러링으로 확인한다. JS는 main `bf1b6a9`와 연결한 Metro 8081을 사용한다. 현재 초안과 보관함 저장 정보를 먼저 Mac에 백업했다. 기존 결과물을 삭제하거나 덮어쓰지 않는다.

수정된 문구 렌더러와 Expo Haptics를 포함한 iOS Debug 앱 전체 빌드가 성공했다. 기존 앱을 삭제하지 않고 업데이트 설치했으며, 설치 경로 변경과 새 앱 실행을 별도로 확인했다. 카드 수정은 이 버전을 바탕으로 원본 프로젝트의 작업 브랜치와 Metro에서 확인한다.

## 확인한 동작

| 항목 | 실기기에서 본 결과 |
|---|---|
| 옛 결과물 다시 편집 | 사진 배경과 코너 프리셋의 문구가 불러와진다. 문구는 원래 왼쪽 위 자리 근처에 유지된다 |
| 러닝 데이터 숨기기 | 러닝 데이터를 화면 아래로 끌면 숫자만 숨는다. 옛 문구를 전환한 자유 문구는 남는다 |
| 숨기기 되돌리기 | 되돌리기 한 번으로 러닝 데이터가 원래 위치·크기로 돌아온다 |
| 문구 이동과 재진입 | 여러 줄 문구를 캔버스 아래쪽으로 옮겼다. 앱 재실행 후에도 문구 두 개의 내용·위치·서로 다른 크기가 유지된다 |
| 반복 재생 중 조작 | 직선·코너 다듬기와 경로 크기를 연속 조작하고 크기를 되돌렸다. 조작 후 재생이 이어진다. 조작 지연을 측정한 것은 아니다 |
| 경로 시트 | 기본 글자 크기에서 세 프리셋·직선·코너 슬라이더·초기화·완료·조작 안내가 스크롤 없이 표시된다 |
| 러닝 데이터 시트 | 기본 글자 크기에서 여섯 프리셋과 항목 탭·초기화·완료·조작 안내를 스크롤 없이 볼 수 있다. 시트 위의 미리보기가 계속 재생된다 |

이 결과는 한 기기의 육안 확인이다. 큰 글자 설정과 다른 화면 크기를 검증한 것은 아니다.

## 생성 중 카드에서 발견한 오류

위·아래에 문구를 둔 QA 입력에서 내보내기 카드가 두 문구를 보여 주지 않았다. `share.tsx`의 생성 중·완성 카드가 `RouteThumbnail`의 기본값인 가운데 크롭을 사용한다. 홈과 보관함 상세는 이미 `framing="content"`로 경로 그림·러닝 데이터·문구 전체를 담는다.

[홈과 보관함 FRD](../../specs/frd/home-and-library.md) §2-1 목록에 보여줄 것과 [내보내기 FRD](../../specs/frd/export-and-share.md) §1 흐름을 기준으로 공유 카드도 같은 구도를 사용한다. 카드는 화면 표시이며 저장 영상·편집 좌표·출력 규격은 바꾸지 않는다. 기존 썸네일의 프레이밍·배경 합성 컴포넌트를 재사용한다. 수정 후 기본 경로로 다시 생성했을 때 진행 중·완성 카드에 위·아래 두 문구가 모두 표시되는 것을 확인했다. PRD의 공유·보관 정책이나 결정문을 바꾸는 작업은 아니다.

## 실제 생성 영상

설치한 앱에서 사진 배경·문구 두 개·불빛 러너 입력으로 영상을 만들었다. 하나는 기존 한글 문구를 옮겨온 것이고 배율은 약 0.54, 다른 하나는 자동 조작으로 입력한 자모 문구이며 배율은 1이다. 여러 줄 문구에는 직접 줄바꿈과 자동 줄바꿈이 함께 있다.

아이폰의 mp4를 Mac으로 복사해 AVFoundation으로 검사했다. **1080×1920·30fps·12초·360프레임**이며 끝까지 디코딩됐다. 시작·6초·11초 프레임을 추출했다. 시작·완성 프레임과 편집 화면을 육안 비교했을 때 두 문구의 위치·크기·세 줄 나눔이 맞고, 문구는 영상 시작부터 보인다. 픽셀이 완전히 같다는 검사는 아니다.

첫 생성 후 보관함이 11개에서 12개가 되었고 초안 저장 키가 지워졌다. 앱을 다시 실행해 QA 결과물을 열었을 때 사진과 문구 두 개가 유지된다. 카드 수정 검증용으로 기본 경로 영상을 한 번 더 생성해 총 13개가 되었다. 기존 11개 결과물의 내용은 유지되며 앱 업데이트에 따라 사진 경로만 새 컨테이너로 정규화됐다.

검증이 끝난 뒤 원래 1.95km·2026-10-02 초안만 복원했다. 원본 백업과 초안 파일의 바이트가 일치하고 보관함 파일은 복원 직전과 동일하다. 홈에서도 원래 초안의 ‘이어서 만들기’와 보관함 13개를 확인했다.

## 사진 앱 저장과 개발 환경

보관함 상세에서 저장 버튼을 눌렀고, 원본 프로젝트의 Metro에서 ‘기기에 저장했어요’ 안내가 표시됐다. 저장 API 완료를 확인한 것이며 사진 앱에서 다시 재생한 검사는 아니다.

처음 워크트리에서는 외부 `node_modules` 연결 때문에 `expo-media-library` 동적 가져오기 경로를 찾지 못했다. 원본 프로젝트 서버로 전환하니 같은 영상의 저장이 성공했다. 이 개발 환경 문제를 제품의 저장 기능 오류로 집계하지 않는다.

## 검사 결과

전체 iOS Debug 빌드, TypeScript 검사, 테스트 19개 묶음·181개 항목, 문서 검사와 공백 검사가 통과했다. 린트 오류는 없고 기존 경고 32개가 남아 있다. Debug 생성 시간을 Release 성능 측정으로 사용하지 않는다.

## 남은 확인

- 일반 한글 키보드로 입력한 여러 줄 문구와 문구 크기 슬라이더를 추가 확인한다.
- 물리적인 두 손가락 핀치와 진동은 미러링의 마우스 조작으로 확인할 수 없다.
- 실제 인스타그램 공유·복귀는 확인하지 않는다.

미러링 자동 키 입력은 한글을 자모로 나누어 전달했고 붙여넣기도 반영되지 않았다. 이를 앱의 한글 입력 오류로 판정하지 않는다. 일반 한글 입력은 사용자에게 직접 입력을 요청한 상태이며 이번 자동 조작 결과로 완료 처리하지 않는다.

재생 버튼 유지, 시트 높이·제스처 안내, 재진입 후 되돌리기 기록 정책은 [결과물 편집 FRD](../../specs/frd/result-editing.md) §10 남은 확인 항목으로 유지한다. 한 기기의 관찰만으로 정책을 확정하지 않는다.
