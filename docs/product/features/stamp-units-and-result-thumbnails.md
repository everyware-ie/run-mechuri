# 각인 심박 단위와 결과물 썸네일

- FRD: [경로 렌더링 §7 각인](../../specs/frd/route-rendering.md), [홈과 보관함 §2 결과물](../../specs/frd/home-and-library.md) (`approved`)
- 구현 상태: 구현 완료 (로컬, 화면 확인은 사용자 진행)
- 확인: 2026-09-11 사용자가 심박 단위 중복 제거와 드로잉·각인 전체 중심 정사각형 썸네일을 요청했다.

## 구현 범위

- 심박은 단위를 한 번만 표시한다. 별도 BPM/AVG BPM 라벨이 있으면 값은 숫자만, 라벨이 없으면 값에 bpm을 붙인다. JS 미리보기와 Swift 영상 렌더러에 같은 규칙을 적용한다.
- 홈의 큰 카드·2열 그리드와 결과물 상세 페이지는 배경·경로·각인을 함께 표시한다. 경로의 편집 변형과 각인 경계를 합쳐 정사각형 표시 영역을 계산한다.
- 배경도 같은 좌표계로 표시하고, 원본 배경 밖의 여백은 같은 좌표에서 가장자리 색을 연장하고 흐리게 표시한다. 배경 파일이 없으면 기본 배경을 사용한다.
- 목록용 거리·날짜는 그림 밖으로 옮겨 각인을 가리지 않는다. 카드 크기는 실제 가용 폭에 맞춘다.
- 저장된 결과물의 배경 참조를 사용한다. 갤러리 가져오기는 이후 [사진 배경](photo-backgrounds.md)에서 구현했다.
- 사용자 요청에 따라 화면 육안 확인은 사용자가 진행하고, 타입·문서·좌표 계산과 단위 회귀만 간단히 검증한다.

## 결과물 상세의 썸네일 통일 (2026-09-11)

- 결과물 상세의 `RouteThumbnail`에도 홈과 동일하게 `framing="content"`와 저장된 `backgroundImagePath`를 전달한다. 상세에 남아 있던 중앙 크롭·배경 미표시를 수정했다.
- 공통 프레이밍 함수를 그대로 재사용하므로 표시 크기가 달라도 동일한 결과물의 구도가 유지된다. 저장된 편집값이나 영상 파일은 변경하지 않는다.

## 썸네일 여백의 회색 띠 수정 (2026-09-11)

- 기존 여백 레이어는 정사각형에 별도로 `cover`한 이미지에 불투명도 0.5를 적용했다. 원본 배경과 좌표·밝기가 달라 카드 바탕색이 섞인 띠와 경계가 생겼다.
- `ThumbnailBackground`에서 Skia `ImageShader`의 `clamp` 타일 모드로 원본 배경의 가장자리 색을 연장한다. 같은 좌표계에서 흐림을 적용한 여백 위에 선명한 원본을 표시하며, 두 레이어는 같은 디코딩 이미지를 사용한다.
- 홈·결과물 상세에 공통 적용한다. 프레이밍, 경로·각인의 위치와 저장된 결과물은 바꾸지 않는다. 배경 경로 복원과 파일이 없을 때의 기본 배경 대체를 유지한다.

## 검증

- TypeScript 및 변경한 홈·썸네일·순수 함수 파일의 ESLint 통과.
- 7개 각인 배치에서 심박 단위 1회, 심박 없을 때 단위 미표시를 확인했다.
- 21가지 배치·변형 조합에서 경로와 각인이 정사각형 안에 들어오는지, 빈 내용의 기본 구도를 확인했다.
- Swift 변경을 포함한 iOS 개발 빌드 성공. 기존에 만든 영상 파일은 재생성하지 않으며, 새로 만드는 영상부터 수정이 반영된다.
- 각인 경계는 기존 레이아웃 계산을 재사용하되 한글과 넓은 영문을 고려해 여유 있게 추정한다. 카드의 여백과 글자 크기는 실기기에서 사용자가 판단한다.

## 스탯바 통계 겹침 수정 (2026-09-11)

실기기에서 `7.01km / 49:40 / 7′05″/km / 154`의 페이스와 심박이 겹쳤다.
직접 원인은 해상도 자체보다 거리·시간·페이스·심박 칸을 고정 가중치로 나눠 긴 문자열을 고려하지 않은 것이었다.

- `stamp-columns.ts`에서 문자 종류와 글자 크기를 고려한 보수적인 폭을 계산한다. 최소 간격을 먼저 확보하고 부족한 경우 통계 값과 라벨을 같은 비율로 축소한다.
- 폭은 완성 시점 거리·시간으로 계산하므로 카운트업 중에도 칸 위치와 크기가 유지된다. 꺼진 항목이나 없는 심박은 공간을 차지하지 않는다.
- JS 미리보기·썸네일과 Swift 최종 렌더러에 같은 계산을 적용한다. 각인 프리셋 서체와 한 줄 스탯바 형태는 유지한다.
- 제보된 값이 기존 페이스 칸을 넘는 것을 확인했고, 일반·긴 기록·심박 없음과 3개 크기 배율에서 새 칸이 겹치지 않고 주어진 너비에 들어오는지 확인했다.
- 구체 배치 규칙을 [경로 렌더링 FRD §7-5 배치](../../specs/frd/route-rendering.md)에 반영했다. 기존 완성 영상은 자동으로 다시 만들지 않는다.

## 간결·글래스 추가 겹침 수정 (2026-09-11)

각인을 편집하지 않고 교체해도 간결의 `신대방동`과 심박이 겹치고 글래스 오른쪽이 잘린다는 사용자 제보에 따른 수정이다.

- 간결과 스택 보조 통계의 한글 폭 과소 추정을 공통 문자 폭 계산으로 교체하고, 완성 값 기준으로 한 줄의 너비를 제한한다. 짧은 줄은 기존처럼 모아서 배치한다.
- 글래스는 카드 너비를 캔버스 좌우 여백 안으로 고정하고, 내부 통계 칸과 글자만 가용 폭에 맞춘다. 패널을 넓혀 겹침을 피하던 기존 구현을 대체한다.
- 미리보기와 Swift 영상 출력에 함께 적용한다. 실제 화면 판단은 사용자에게 맡기고 좌표·타입·네이티브 빌드를 검증한다.
- 검증: 간결·스택·글래스·스탯바의 216개 배치 조합(크기 3종, 장소명 3종, 심박 유무, 카운트업 3시점)에서 추정 글자 경계의 간격·가용 폭·카운트업 중 위치 유지를 확인했다. 글래스 기본 위치 카드의 좌우 경계와 기존 썸네일 21개 변형 검사도 통과했다. 실제 서체를 렌더링한 육안 검사는 사용자 확인 대상이다.
- TypeScript·문서 정합성·iOS 개발 빌드 통과. `route-preview.tsx`의 기존 Reanimated 관련 ESLint `immutability` 오류 2건은 별도이며 이번 각인 변경 위치에는 새 오류가 없다.
