# GPS 구간 페이스 각인

- 근거: [경로 렌더링 FRD §7-3 값의 움직임](../../specs/frd/route-rendering.md), [결과물 편집 FRD §2 미리보기](../../specs/frd/result-editing.md) (`approved`)
- 확인: 2026-09-13 사용자가 GPS 좌표·시각으로 구간 페이스를 추정하고 완성 시 평균으로 고정하는 방식을 선택했다. 평균을 향해 단순히 숫자를 올리는 연출은 선택하지 않았다.

## 구현

`frontend/src/lib/pace-timeline.ts`에서 원본 GPS 누적 거리를 기준으로 주변 100m 창의 이동 시간을 계산한다. 구간 거리가 30m 미만이거나, 15초 초과/역행/누락 시각, 12m/s 초과 점프가 창에 포함되면 평균값으로 보완한다. 추정 페이스가 1km당 1시간을 초과하는 등 이동 근거가 약한 경우도 평균값을 쓴다. 좌표 자체는 삭제하거나 수정하지 않는다.

9초 × 30fps의 270구간(완성 포함 271개)을 한 번 계산하고 5개 표본 이동평균으로 숫자 떨림을 줄인다. 끝 15개 프레임(0.5초)은 smoothstep으로 최종 평균에 합류한다. 시각이 없는 옛 기록·유효 구간이 없는 기록은 빈 표본 배열을 반환하고 기존 평균값을 표시한다. 별도 네트워크 요청·권한·HealthKit 데이터 조회는 추가하지 않는다.

- 미리보기: `RoutePreview`에서 좌표/평균 변경 때만 memo 계산한다. `StampPreviewLayer`는 이미 확보한 30fps 진행률로 표본을 읽는다. 지도 다듬기와 별개이므로 다듬기 강도 때문에 페이스가 변하지 않는다.
- 저장 영상: `share.tsx`에서 같은 함수를 호출해 `paceSamples`를 네이티브에 전달한다. Swift `paceAtProgress`가 같은 선형 보간을 쓰고 완성 구간은 `averagePaceSecPerKm`로 고정한다. 표본이 없는 호출은 평균값을 유지해 호환된다. 새 옵션을 소비하려면 개발 앱 네이티브 재빌드가 필요하다.
- 배치: TS/Swift 모두 페이스 칸에 최소 두 자리 분 단위 공간을 예약한다. 카운트업 중 레이아웃은 고정하고, 작은 텍스트 뷰포트에도 좌우 글자 여유를 둔다. 정적 썸네일에는 최종 평균 페이스가 표시된다.
- 한계: GPS 기반 구간 추정치로서 워치가 별도로 계산한 순간 페이스와 완전히 같지는 않다. 원본 경로 누적 거리 비율을 쓰므로 강한 경로 다듬기 후 화면상 선 끝의 정확한 GPS 지점과 차이가 날 수 있다. 화면 시간·거리는 전체 기록 카운트업이며 이 두 숫자의 비율로 구간 페이스를 만들지 않는다.

## 검증

- 합성 GPS: 빠른/느린 구간 차이, 타임스탬프 누락·역행·큰 공백, 잘못된 좌표의 안전한 평균값 보완, 완성 후 최종 평균 고정.
- 기존 회귀: 각인 30fps 샘플, 고정 텍스트 memo/뷰포트, Canvas memo, 화면·앱·제스처 정지와 복귀.
- 실제 개발 앱에서 표본 271개가 생성되고 구간 값이 변하며 마지막 표본과 기록 평균이 일치함을 확인했다. 원본 좌표는 로그에 출력하지 않았다.
- iPhone 11 Pro 동일 기록 코너에서 2회: 평균 UI 프레임 간격 16.64 / 16.61ms, 최대 29.24 / 16.61ms, 34ms 및 100ms 초과 지연 0회. 특정 기기/기록의 진단값이며 모든 기록과 릴리스 성능을 보장하는 수치는 아니다.
- TypeScript·변경 파일 ESLint·회귀 검사·아이폰 Debug 네이티브 빌드 통과. 저장 영상의 실제 육안 비교는 사용자 확인 범위다.
