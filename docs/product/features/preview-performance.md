# 미리보기 경로 재생 성능 조사와 개선

- 근거: [결과물 편집 FRD §2 미리보기](../../specs/frd/result-editing.md), [경로 렌더링 FRD §3-4 신호가 끊긴 구간·§5 애니메이션](../../specs/frd/route-rendering.md) (`approved`)
- 확인: 2026-09-13 사용자가 기록 선택 이후 최종 생성 전 미리보기의 끊김을 조사하고 개선하도록 요청했다. 개발용 앱과 TestFlight 양쪽에서 처음부터 관찰했고, 선이 비는 것이 아니라 **선 끝이 잠깐 멈췄다가 다시 움직이는 현상**이라고 답했다.
- 상태: Canvas 분리·비활성 화면 정지 및 각인 처리 최적화 로컬 적용. 이후 30fps 카운트업을 위해 실시간 각인은 텍스트별 SVG와 네이티브 합성 그림자로 분리했다(아래 후속 기록). iPhone 11 Pro 개발 빌드에서 전후 UI 프레임 간격을 비교했다. TestFlight와 모든 기록·프리셋의 검증을 완료한 것은 아니다.

## 팀 공유: 원인과 최종 해결

**재현된 큰 멈춤은 각인 숫자를 바꿀 때 발생한 SVG 그림자 처리 비용이었다.** GPS 시간 공백 때문에 재생 시계가 멈추는 코드는 없었다. GPS 겹침이 정지처럼 보이는 경우와 실제 프레임 지연은 구분해야 한다.

- 변경 전에는 9초 그리기 중 숫자를 12번 갱신할 때마다 100ms 초과 지연이 12번 발생했고, 최대 약 233ms였다. SVG 텍스트마다 전체 화면 크기의 이미지·필터 처리를 반복하고 있었다.
- 최종 구현은 경로 Canvas를 별도 memo 경계로 분리하고, 숨겨진 화면의 시계를 멈춘다. 각인은 텍스트별 고정 크기 SVG로 나누고 정적 라벨/카드 갱신을 건너뛴다. 실시간 그림자는 iOS 합성 레이어에서 처리해 CPU SVG 필터 반복을 제거했다.
- 숫자만 자주 바꾸면 성능이 악화된다. 중간 실험에서는 30fps 숫자 갱신 시 평균 프레임 간격이 25.28ms로 늘었다. 위 구조를 함께 적용한 뒤 코너에서 평균 약 16.7ms, 34ms 초과 지연 0회를 확인했다. 간결·글래스도 별도 확인했다(아래 표본 수·조건 참고).
- 거리·시간은 저장 영상과 같은 30fps 카운트업이다. 이후 추가한 [GPS 구간 페이스](pace-timeline.md)도 한 번 계산한 표본을 읽으므로 프레임마다 GPS를 다시 순회하지 않는다. 완성 시 평균 페이스로 고정한다.
- GPS 경로·폰트·좌표 배치는 유지하지만 SVG Gaussian 그림자와 네이티브 레이어 그림자가 픽셀 단위로 같지는 않다. 이 수치는 iPhone 11 Pro 개발 앱의 UI 콜백 간격이며 모든 기기에서의 60fps 보장은 아니다.

재확인할 때는 동일 기록의 배경 선택 화면에서 조작 없이 2회 이상 재생하고 개발 콘솔의 `[preview-performance]` 집계를 비교한다. 기록/각인/드로잉 프리셋·앱 빌드·측정 횟수를 함께 남긴다. `frontend/scripts/check-preview-work.cjs`는 로직 회귀 검사이며 실기기 성능 측정을 대신하지 않는다.

## 코드로 확인한 작업과 개선 범위

1. 각인 숫자를 갱신하는 `RoutePreview`의 state 변경마다 Skia `Canvas`의 새 children이 만들어졌다. 설치된 Skia의 `Canvas.tsx`는 children 변경 시 `root.render`를 실행한다. 기존 memo는 Canvas 아래 프리셋 레이어에만 있어 Canvas 자체의 갱신을 차단하지 못했다. Canvas와 경로 레이어를 하나의 memo 경계로 분리한다.
2. 스택에 남아 있는 이전 화면의 미리보기에는 화면 포커스에 따른 재생 중단이 없었다. 공통 미리보기에서 화면 포커스·앱 활성 상태를 확인하고 숨겨진 동안 프레임 콜백을 중단한다. 사용자의 재생/정지 설정과 조작값은 유지한다.
3. GPS 좌표 제거·보간 변경, 프리셋 모양·글로우 축소, 숫자 갱신 주기 축소는 이번 조치에 포함하지 않는다. 먼저 불필요한 재생·캔버스 갱신을 제거해 비교한다.

## 1차 적용 후 재현 및 실기기 진단 (2026-09-13)

사용자는 8081 개발용 앱에서도 선 끝이 잠깐 멈추는 현상이 남는다고 확인했다. 따라서 1차 조치를 원인 해결로 보지 않는다.

- 개발 서버 연결 목록만으로 앱 종류를 판단하지 않는다. 아이폰 설치 정보에서 개발 빌드임을 확인했고, 재연결 후 디버거에서 진단 코드가 실행 번들에 포함됐는지도 확인했다.
- 현재 편집 중인 로컬 기록을 임시 파일로 읽었다. 원본 2,949점, 현재 다듬기 결과 452점이며 5초 초과 시간 공백 4곳과 20m 초과 점 간 이동 4곳이 있었다. 최대 시간 간격 13초, 최대 점 간 이동 약 44.4m였다. 원본 좌표는 저장소나 외부 서비스에 업로드하지 않았다.
- 선 길이 기준으로 이동한 머리점이 이전 선의 반폭(4.5 캔버스 px) 안에 드는 구간이 많았다. 이는 겹쳐 그리기로 인한 정지 착시 후보이며, 실제 프레임 멈춤을 배제하는 증거는 아니다.
- 모든 프리셋의 시계를 공통화해 동일한 방법으로 측정한다. 개발 모드에서만 그리기 1회당 평균/최대 프레임 간격·34/100ms 초과 횟수·최대 지연 시점(진행률)을 출력한다. GPS 좌표·건강 값은 로그에 포함하지 않는다. GPU 표시 시간을 직접 측정하는 도구는 아니다.

## 각인 필터 병목 확인과 2차 개선

실행 번들에 함수가 존재하는 것만으로 현재 마운트된 화면에 적용됐다고 보지 않는다. 실제 훅 상태에서 측정 카운터가 없음을 확인해 새로고침했고, 사용자가 같은 기록의 배경 선택 화면을 다시 연 뒤 측정했다.

- **변경 전**(1차 개선 포함): 9초 그리기마다 100ms 초과 프레임 간격 12회. 반복 측정의 평균 약 21.8~21.9ms, 최대 약 233~234ms. 각인 숫자 갱신 12회와 주기가 일치했다.
- 설치된 `react-native-svg`의 iOS `RNSVGRenderable.mm` / `Filters/RNSVGFilter.mm`는 각 필터 대상마다 전체 SVG 뷰 크기의 중간 이미지와 마스크를 생성한다. 화면 전체 크기의 SVG에서 각 텍스트에 필터를 별도로 적용하고 있었다.
- **개선**: 그림자 대상을 한 그룹에 묶어 필터 적용을 한 번으로 줄였다. 미리보기 SVG는 완성 시점 각인 경계에 충분한 상하 여유를 더한 세로 영역만 사용한다. `viewBox`와 위치를 함께 보정해 화면상 좌표·크기·드래그는 유지한다. 가로 폭은 유지해 문자 폭 추정으로 옆이 잘리지 않도록 한다. 폰트·숫자 갱신·블러 강도·GPS 좌표는 바꾸지 않는다.
- **변경 후**, 같은 화면에 수정이 반영된 연속 3회: 평균 16.90 / 16.93 / 16.99ms, 최대 모두 49.93ms, 34ms 초과 2 / 2 / 3회, 100ms 초과 모두 0회. 각인 필터 비용이 이 기록에서 큰 지연을 만든다는 근거다. 작은 지연은 남아 있으며 모든 프리셋에서 완전한 60fps를 보장하는 결과는 아니다.
- 개발 모드 진단은 재생 1회당 집계만 출력한다. 진단 자체 및 디버거의 영향이 있을 수 있고 GPU 실제 표시 시간·릴리스 성능을 대신하지 않는다. GPS 겹침에 따른 시각적 정체 가능성은 별도로 남는다.

후속 확인: 같은 기록의 주관적인 끊김 감소, 큰 문구·각인 이동/확대에서 잘림 여부, 각인 영역이 세로로 넓은 프리셋과 불빛 러너의 잔여 지연. 아직 TestFlight에는 이 변경을 배포하지 않았다.

## 영상과 같은 미리보기 숫자 갱신 (2026-09-13)

사용자가 2차 개선의 체감을 확인한 뒤 미리보기 거리 카운트업도 다운로드 영상처럼 부드럽게 하되 부작용을 확인해 달라고 요청했다. [결과물 편집 FRD §2 미리보기](../../specs/frd/result-editing.md)에 갱신 기준을 보완했다.

### 비교와 구현

- 기존 미리보기는 9초 동안 12회(0.75초 간격), 최종 Swift 영상은 30fps로 숫자를 갱신했다.
- 기존 SVG 구조에서 270회로 갱신만 늘린 실험은 코너 프리셋 평균 25.28ms, 34ms 초과 지연 79회로 악화됐다. 이 구조를 최종안으로 채택하지 않았다.
- 텍스트마다 작은 고정 SVG 뷰로 분리해도 CPU SVG 그림자 필터가 남아 평균 약 21.8~22.0ms였다.
- 최종안은 **텍스트별 고정 SVG + memo + iOS 네이티브 합성 그림자**다. 폰트·색·좌표·단위 크기는 공통 `stampLayoutDescriptors` / `StampTextsSvg`를 재사용한다. 그림자는 SVG Gaussian 필터에서 네이티브 레이어 그림자로 바뀌므로 픽셀 단위로 동일한 효과를 보장하지는 않는다. 프리셋별 어두운 그림자/따뜻한 글로우와 외곽선을 유지한다.
- 완성 값으로 뷰포트를 고정하고 여유를 둬 숫자가 바뀔 때 뷰 크기가 흔들리지 않게 한다. 변하지 않은 날짜·장소·라벨과 카드 배경은 memo로 갱신을 건너뛴다. 이동은 기존 Animated.View에서 계속 수행한다. 선택 박스는 별도 SVG로 둔다.
- UI 경로 진행률에서 30fps 영상과 같은 270단계 값을 샘플링한다. 경로는 계속 UI 스레드의 매 프레임 값을 쓴다. 최종 썸네일 SVG와 Swift 저장 영상의 렌더링은 유지한다.

### 검증

- iPhone 11 Pro 개발 빌드, 동일 기록의 코너: 평균 프레임 간격 16.67 / 16.66ms, 최대 30.30 / 33.36ms, 34ms 및 100ms 초과 지연 모두 0회(연속 2회). 기기·기록·프리셋에 한정한 UI 콜백 측정이며 GPU 실제 표시 시간이나 릴리스 결과를 보장하지 않는다.
