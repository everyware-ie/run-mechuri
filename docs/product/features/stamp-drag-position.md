# 러닝 데이터 이동 후 튐 제거

근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §4-2 제스처.

## 착수 확인 (2026-09-20)

사용자가 아이폰 미러링으로 러닝 데이터를 이동하면 놓은 지점을 지나쳤다가 돌아오는 현상을 제보하고 관성 없이 멈추도록 요청했다.

## 원인과 수정

기존에는 드래그 이동량을 별도 화면 오프셋으로 적용했다. 손을 떼면 저장 위치를 바꾼 뒤 두 프레임 후에 오프셋을 지웠다. 그 사이 새 위치와 이동량이 중복 적용되었다. 관성 애니메이션이 원인은 아니다.

미리보기 러닝 데이터는 원점 기준으로 배치하고, 이동은 캔버스 좌표의 공유 위치 값만 사용한다. 드래그·핀치 중 이 값을 직접 갱신하고 손을 뗄 때 같은 값을 저장한다. 위치 반영 대상을 교체하거나 지연된 오프셋 초기화를 하지 않는다. 선택 점선도 같은 이동을 사용한다. 초기화·저장·재진입의 위치와 프리셋 배치는 유지한다.

## 어긋남 기록

프레임 지연으로 이전 튐을 피하던 처리에서 반대 방향의 튐이 생겼다. FRD에 손을 뗀 위치에서 추가 이동 없이 멈추는 기준을 명시한다.

## 검증

타입·미리보기 회귀 검사 통과. 공유 위치를 바꾼 뒤 저장 위치를 반영해도 화면 이동량이 같고, 연속 드래그와 편집 외 미리보기가 유지됨을 확인했다. 전체 린트는 기존 19개 오류 중 이전 Animated 참조 관련 3개가 사라져 16개 오류·5개 경고가 남았다. 신규 오류는 없다. 개발 앱을 새로고침해 기존 제스처 콜백도 교체했다. 실제 미러링 드래그 사용감은 사용자 QA로 확인한다.
