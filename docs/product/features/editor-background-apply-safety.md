# 편집 배경 변경과 화면 전환 검증

- 근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §1 화면 구조, §4-3 되돌리기와 초기화 / [배경 선택 FRD](../../specs/frd/background-selection.md) §0-1 다음 단계로 이동 (`approved`)
- 관련 구현: [스토리형 편집 1단계](story-editor-stage1.md)
- 착수 확인: 2026-10-04 사용자가 후속 안정성 검증·수정을 이어 진행하도록 요청했다. 마지막 편집값으로 결과물을 만들고, 화면 전환 뒤 이전 작업이 새 배경을 덮지 않게 한다. TestFlight 배포는 보류한다.

## 확인 범위

기본 배경 파일 준비가 늦게 끝날 때 갤러리·카메라 이동, 나가기, 되돌리기와 충돌하는지 확인한다. 배경 적용 중 완료를 눌러 이전 배경으로 영상을 만들기 시작하지 않아야 한다. 실패하면 현재 배경을 유지하고 다시 고를 수 있어야 한다.

## 발견한 오류

파일 준비를 기다린 뒤 화면과 선택이 여전히 유효한지 확인하지 않고 배경을 반영한다. 갤러리·카메라·나가기·되돌리기는 파일 준비 중에도 가능하며, 완료도 막지 않는다. 빠른 연속 탭은 React 상태 반영 전에 여러 작업을 시작할 수 있다.

## 수정과 검증

`useBackgroundApply`가 작업 번호와 즉시 반영되는 대기 상태를 관리한다. 같은 화면 갱신 안의 연속 탭은 한 작업만 시작한다. 갤러리·카메라 이동, 나가기, 되돌리기와 편집 화면의 포커스 해제는 이전 작업의 반영을 취소한다. 취소된 작업의 늦은 성공·실패는 새 배경, 새 작업의 대기 상태, 오류 안내를 바꾸지 않는다. 화면이 사라져도 같다.

배경 준비 중 완료 버튼은 비활성화되고 "배경 적용 중"으로 표시된다. 버튼 상태가 화면에 반영되기 전에도 완료 처리에서 대기 여부를 확인한다. 현재 작업이 실패하면 기존 배경은 유지하고 오류를 알린 뒤 다시 고를 수 있다.

**파일 준비 자체를 중단하는 것은 아니다.** 취소한 기본 배경은 파일로 준비될 수 있지만 편집에 적용되지 않는다. 같은 배경의 준비가 아직 끝나지 않았으면 다음 선택도 그 작업을 함께 기다린다(`persistDefaultBackground`). 동일한 파일을 동시에 복사하지 않고, 성공·실패 후에는 작업 기록을 비워 재선택·재시도가 가능하다. 완성된 기본 파일을 다시 쓰는 기존 보관 방식은 유지한다.

- 기존의 상태 기반 중복 방지와 무조건 반영하는 비동기 흐름을 React 훅으로 분리해 검사하면 회귀 사례 7개가 실패했다. 수정 후 통과한다.
- React 검사 8개: 화면 갱신 전 연속 탭·완료 대기 판정, 취소 후 성공·실패, 취소 후 새 작업을 진행할 때 옛 작업의 성공·실패, 현재 실패 후 재시도, 화면 제거 후 성공·실패.
- 실제 파일 준비 함수도 같은 배경의 동시 요청에서 중복 준비를 재현했다(네이티브 파일·에셋 API는 모의 처리). 파일 검사 4개: 같은 배경 공유, 다른 배경 독립 준비, 실패 후 재시도, 이미 보관한 파일 재사용.
- 전체 Jest 134개, 타입 검사 통과. 전체 린트 오류 0개, 기존 경고 32개. 문서 정합성 검사 통과.
- 네이티브 코드·패키지·영상 규격은 바꾸지 않았다. 앱 설치와 TestFlight 배포는 하지 않았다.

기존 FRD의 최종 편집값과 화면 전환 기준에 맞추는 수정이다. 제품 정책과 새 용어를 바꾸지 않으므로 FRD·PRD·결정문은 개정하지 않는다.

## 남은 실기기 확인

기본 배경을 고른 직후 갤러리·카메라로 이동하거나 나간다. 돌아오거나 새 사진을 적용해도 이전 기본 배경으로 바뀌지 않는지 확인한다. 파일 준비 중 완료 버튼의 안내와 비활성 상태를 확인하고, 적용이 끝난 뒤 결과 영상에 선택한 배경이 사용되는지 본다. 이번 검사는 비동기 처리 순서와 코드 연결이며 실제 iOS 파일 복사·화면 전환·버튼 모양·영상은 확인하지 않았다.
