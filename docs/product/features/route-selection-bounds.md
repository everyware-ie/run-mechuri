# 경로 그림 선택 박스의 위치 불일치 수정

근거: [결과물 편집 FRD](../../specs/frd/result-editing.md) §4-1 편집 대상 고르기, §4-2 제스처.

## 착수 확인 (2026-09-20)

사용자가 TestFlight QA 화면에서 경로 그림을 위로 옮겼는데 점선 박스는 아래에 남아 있는 현상을 제보했다. 기존 FRD의 선택 영역 표시를 올바르게 구현하는 오류 수정이다. 이동·확대·회전 중과 손을 뗀 뒤에 선택 박스가 경로 그림과 같은 변형을 따르도록 한다.

## 원인과 수정 방향

경로는 Skia Group의 SharedValue 변형을 사용하지만 박스는 별도 SVG AnimatedG에 transform 문자열을 전달했다. 설치된 react-native-svg의 G는 JS에서 문자열을 네이티브 matrix로 변환한다. UI 스레드의 직접 속성 갱신은 이 JS 변환 경로와 다르므로 문자열 전달만으로 같은 동작을 보장할 수 없다.

박스를 경로와 같은 Skia Group 안에 둔다. 위치·크기·회전·미리보기 축소 비율을 따로 계산하지 않고 부모 변형을 그대로 상속한다. 주황색 점선과 둥근 모서리는 유지한다. 박스의 원래 영역은 메모해 러닝 데이터 숫자가 갱신될 때 경로 캔버스가 다시 구성되지 않게 한다.

## 어긋남 기록

FRD 정책 변경은 없다. 이전 구현 노트의 '같은 SharedValue를 읽으면 SVG 박스도 함께 움직인다'는 설명만으로는 네이티브 속성 변환까지 보장되지 않았고, 이번 사용자 QA에서 위치 불일치가 확인됐다.

## 검증

- TypeScript 검사 통과. 변경 컴포넌트 lint 오류·경고 없음. 전체 `src/ modules/` lint는 수정 전후 동일하게 기존 오류 19개, 경고 5개가 남아 있다.
- 기존 미리보기 회귀 검사 통과. 선택 박스에도 검사 범위를 추가했다. 경로와 박스가 같은 변형 그룹에 있는지, React 리렌더 없이 SharedValue를 변경해도 이동·축소/확대·회전·초기화가 반영되는지, contain/cover/cover-safe에서 맞는지 확인한다.
- 경로 선택 중에도 러닝 데이터 숫자 갱신 12회 동안 Canvas props 참조가 유지되며, 선택을 해제하면 박스가 사라지는지 확인했다.
- 자동 검사는 렌더 트리와 좌표 계산의 회귀 검사다. 네이티브 화면 재현은 아직 하지 않았다. 실기기 이동 중·손을 뗀 뒤·확대·회전·초기화·편집 패널 접기/펼치기는 사용자 QA로 확인한다. 이번 변경은 TS만 수정하므로 개발 앱에서는 Metro 새로고침으로 확인할 수 있고, TestFlight에는 후속 배포가 필요하다.
