# 갤러리·촬영 사진 배경

- FRD: [배경 선택 §3 사용자 소재·§4 사진 처리·§6 대기·§7 실패](../../specs/frd/background-selection.md), [공통 규칙](../../specs/frd/common-rules.md) (`approved`)
- 구현 상태: 구현 완료 (로컬, 실기기 사용자 확인 예정)
- 확인: 2026-09-11 사용자가 이번 빌드에 갤러리 사진과 직접 촬영 사진을 구현하도록 요청했다.

## 구현 방향

- 사진만 단일 선택하는 시스템 갤러리를 사용한다. 갤러리 전체 읽기 권한은 요청하지 않는다.
- 카메라 버튼을 눌렀을 때만 카메라 권한을 요청한다. 촬영 확인에서 다시 찍기·사진 앱에 저장하기·이 사진으로 진행하기를 제공한다.
- 배경 선택 화면의 9:16 틀에서 사진을 빈틈없이 채우고, 두 손가락 확대·축소와 이동으로 구도를 조정한다. 드로잉은 고정해 합성 결과를 보며 조정한다.
- 확정한 영역을 1080×1920 JPEG로 만들어 기존 편집·영상 렌더러·썸네일에 같은 배경을 넘긴다. 기본 이미지 3장은 기존 전체 미리보기를 유지한다.
- 사진 선택·권한·처리 실패나 취소는 앞선 선택과 드로잉 편집값을 유지한다.
- 사용자 확인: 편집용 사진과 구도 조정값을 앱에 보관한다. 시스템 선택창의 다운로드 안내와 앱의 작업 안내·취소를 이번 MVP에 사용한다.

## 코드와 보관 방식

- `background-selection.tsx`: 사진 전용 PHPicker(`allowsEditing: false`), 카메라 권한 요청과 촬영 확인, 이전 선택 복원. 기본 이미지·갤러리·촬영 버튼은 같은 화면에 둔다.
- `photo-background-preview.tsx` / `photo-crop.ts`: 화면 스레드에서 팬·핀치를 처리한다. 빈틈없는 최소 배율부터 6배까지 확대하며, 사진 밖으로 이동하지 않게 제한한다. 구도 초기화 버튼을 제공한다.
- `photo-processing.ts`: 방향을 반영한 JPEG를 편집용으로 준비한다(긴 변 최대 4096px). 확정한 영역을 1080×1920으로 만들어 기존 영상 렌더러에 전달한다.
- `background-storage.ts`: `Documents/backgrounds/` 안의 편집용 사진과 확정 배경을 보관한다. `backgroundPhoto`에 원본 영역과 확대·이동값을 함께 저장하고, 초안·보관함·다시 편집에서 복원한다. 앱 업데이트로 컨테이너 UUID가 달라져도 현재 Documents 경로로 해석한다.
- 촬영 확인에서 사진 앱에 저장하는 대상은 자르기 전 촬영 사진이다. 별도의 사진 쓰기 권한은 그 버튼을 누를 때 요청하며 거부해도 배경으로 진행할 수 있다.
- `use-background-task.ts`: 0.3초 이후 안내(최소 0.5초 유지), 2초 이후 취소. 취소·화면 이탈 이후 완료된 결과를 무시하고 이 작업에서 만든 미사용 파일을 정리한다. 이미 시작한 이미지 디코딩 자체를 중단하는 기능은 라이브러리가 제공하지 않아 결과 적용을 취소하는 방식이다.
- 네이티브 의존성: Expo 57용 `expo-image-picker`, `expo-image-manipulator`. 카메라 및 사진 추가 문구를 반영하며 마이크·갤러리 전체 읽기 권한을 새로 요청하지 않는다.

## 검증

- TypeScript, 사진 기능 관련 파일 ESLint, 문서 정합성 검사 통과.
- 가로·세로·9:16·저해상도 사진의 20가지 확대/이동 경계에서 사진 밖으로 벗어나지 않는지와 9:16 자르기 범위를 확인했다.
- 새 네이티브 모듈 및 권한 문구를 포함한 iOS 개발 빌드 성공.
- 갤러리 실제 선택·촬영·권한 거부·저장·구도 조정의 육안 확인은 사용자 요청에 따라 실기기에서 사용자가 진행한다.

## 후속 UX 개선 — 정확한 다운로드 진행률

- [ ] iCloud 원본 내려받기의 수치 진행률과 실제 다운로드 취소를 제공하는 네이티브 경로를 검토한다. 갤러리 전체 읽기 권한 없이 선택한 사진만 가져오는 현재 경험을 유지하는 것이 조건이다.
- [ ] 느린 네트워크·오프라인·iCloud 원본만 있는 사진에서 진행률, 취소, 재시도와 이전 선택 보존을 함께 검증한다.

**미룬 이유 (2026-09-11 사용자 판단):** 정확한 진행률이 실제 사용자 경험에는 더 좋다고 보지만, 현재 MVP 단계와 작업 공수를 고려해 시스템 다운로드 안내를 사용한다. 필요 없어서 제외한 기능이 아니라 후속 개선 대상으로 남긴다.

## 사진 선택 후 Render Error 수정 (2026-09-11)

실기기에서 사진 선택 후 `GestureDetector must be used as a descendant of GestureHandlerRootView` 오류가 발생했다.
사진 선택 자체가 아니라 사진 미리보기를 마운트할 때 필요한 상위 제스처 루트가 앱에 없었던 것이 원인이다.
`_layout.tsx`의 내비게이션 전체를 `GestureHandlerRootView`로 감싸 사진 이동·확대가 동작할 수 있게 수정했다.
사진 불러오기·처리 실패의 실제 오류 메시지도 개발 로그에 남겨, 반복해서 진행되지 않는 경우의 원인을 구분할 수 있게 했다.
정책 변경은 없으므로 FRD 대신 이 구현·오류 기록에 반영한다. 사진 재선택과 이동·확대의 실기기 재확인은 사용자가 진행한다.

## 사진 도구와 중앙 로딩 안내 (2026-09-11)

- 사용자 요청으로 촬영 사진의 네 가지 도구를 한 줄로 정리했다. 후속 피드백에서 보조 도구가 너무 큰 영역을 차지한다는 의견을 반영해, 작은 SF Symbols 아이콘 옆에 초기화·선택 취소·다시 찍기·사진 저장을 둔다. 저장 중·저장 완료를 같은 자리에서 표시한다.
- 바깥 카드의 배경·테두리·패딩을 없애고 기본 도구 높이를 약 82px에서 44px로 줄였다. 터치 영역은 최소 높이 44px를 유지하며, 조작 안내도 한 줄로 줄였다. 로딩 안내는 승인된 중앙 카드 방식을 유지한다.
- 기존 서비스의 어두운 카드, Pretendard 서체, 주황색 강조색을 사용한다. 각 도구는 아이콘보다 넓은 터치 영역과 구체적인 접근성 이름을 갖는다.
- 불러오기 안내는 화면 전체를 어둡게 덮고 중앙 카드에 스피너·작업 문구를 표시한다. 0.3초 지연·최소 0.5초 표시·2초 후 취소 규칙은 유지한다.
- 시스템 사진 선택창과 네이티브 모달이 동시에 열리는 충돌을 피하도록, 앱 화면 위의 오버레이로 구현했다. 시스템 선택창이 열려 있으면 그 화면이 우선하고, 닫히면 중앙 로딩이 보인다. 로딩 중에는 아래 화면의 터치 및 접근성 탐색을 막는다.
- 요구사항은 [배경 선택 FRD §3 사용자 소재 고르기·§6 불러오기와 대기](../../specs/frd/background-selection.md)에 함께 반영했다.

## 미리보기 공간과 소재 선택 전환 (2026-09-11)

- 미리보기 높이를 화면의 46%·최대 420px로 제한하던 방식을 제거했다. 하단 도구를 제외한 실제 가용 영역을 측정하고 9:16 전체 구도가 가장 크게 들어오도록 맞춘다.
- 기본 이미지·갤러리·촬영 목록은 화면 아래에 배치한다. 사진을 선택하면 이 목록을 숨기고 작은 사진 도구와 진행 버튼만 표시한다.
- 선택 취소 시 새 사진 후보를 버리고 앞선 배경으로 돌아간다. 사진 도구를 숨기고 소재 목록을 다시 보여준다. 저장된 사진을 다시 편집하는 경우에도 선택 취소로 소재 목록을 열 수 있다.
- 사진 미리보기를 감싸던 전체 화면 스크롤을 제거해, 사진 이동 제스처와 세로 스크롤이 경쟁하지 않도록 했다. 중앙 로딩 표시는 유지한다.
- TypeScript·해당 화면 ESLint·문서 검사 통과. 실제 표시 크기와 전환 느낌은 사용자가 실기기에서 확인한다.
