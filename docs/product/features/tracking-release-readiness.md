# 측정 기능 정식 출시 전 검토

2026-10-25 사용자는 제작 흐름을 먼저 검증한 뒤, 자체 측정과 워치 심박 전달 및 측정 화면 복귀를 중점적으로 확인하도록 요청했다. 이번 스프린트 목표는 안정적인 측정 기능의 정식 출시다.

현재 승인된 [내부 측정 PRD](../../specs/prd/internal-run-tracking.md)와 [FRD](../../specs/frd/internal-run-tracking.md)를 기준으로 검토했다. 이 문서는 구현 승인이나 출시 완료 기록이 아니다. 기존 5.41km 실기기 러닝과 심박 연동 확인은 유효한 근거로 유지한다.

## 출시 전에 해결해야 하는 차이

| 항목 | 현재 코드 | 출시 전 필요한 작업 |
|---|---|---|
| Runary 단독 연속 심박 | `WatchHealthReader`는 건강 저장소를 읽는다. `RunaryWatchApp`은 운동 세션을 생성하지 않는다. | 일반 러닝과 워치 운동 세션의 시작·일시정지·재개·종료를 연결하고 연속 심박을 검증한다. 권한 거부와 워치 미착용에서도 아이폰 기록은 유지해야 한다. |
| 손목을 들었을 때 측정 화면 복귀 | 워치의 활성 상태에서 3초마다 아이폰 상태를 요청한다. 운동 처리 백그라운드 모드는 생성되지 않는다. | 실제 워치에서 앱 목록으로 이동 → 손목 내리기 → 다시 들기 순서로 검증한다. 세션 실행이나 시계 위 아이콘만으로 통과 처리하지 않는다. |
| 워치 시작·재개 | `continueWatchRequest()`는 아이폰 활성화와 GPS 준비를 기다린다. 아이폰의 즉시 시작·재개와 다르다. | 아이폰이 잠긴 경우의 시작 범위, 준비 대기와 실패 안내를 먼저 확정한다. 중복 요청과 연결 단절 후 같은 러닝 복원을 검증한다. |
| 정식 배포 | `RUNARY_INTERNAL_TRACKING=1`일 때만 워치와 잠금화면 확장 및 측정 권한 구성이 포함된다. | 공개 범위를 PRD·FRD에 반영하고 일반 빌드 설정, 개인정보 안내, 스토어 권한 설명을 함께 검토한다. 플래그만 켜서 배포하지 않는다. |

운동 세션은 예전 3분 실험에만 있었고 제품 코드에는 합쳐지지 않았다. [심박 구현 노트](health-heart-permissions.md)의 당시 배포 결정과 현재 소스를 함께 확인했다.

Apple은 운동 세션 중 높은 빈도의 심박 샘플 생성과 백그라운드 실행을 설명한다. 운동 처리 모드와 실제 세션 수명 관리가 필요하다. [Running workout sessions](https://developer.apple.com/documentation/healthkit/running-workout-sessions)

백그라운드 세션 문서는 손목을 들었을 때 앱 표시와, 크라운으로 시계 화면에 나갔을 때 세션 아이콘 표시를 구분한다. 원하는 앱 목록 이후 자동 복귀는 설치된 OS와 설정에서 직접 검증해야 한다. [Enabling Background Sessions](https://developer.apple.com/documentation/watchkit/enabling-background-sessions)

워치는 운동 세션 하나만 실행한다. 다른 운동이 시작되면 기존 세션이 종료될 수 있으므로, 기존의 다른 운동 앱과 병행하는 정책을 그대로 유지하면서 자체 운동 세션까지 보장할 수는 없다. [HKWorkoutSession](https://developer.apple.com/documentation/healthkit/hkworkoutsession)

## 다음 구현안

일반 러닝에 워치 운동 세션을 연결하되 아이폰 GPS를 기록의 기준으로 유지하는 안을 권장한다. 워치 연결 실패가 아이폰 러닝 실패로 이어지면 안 된다.

세션은 같은 러닝 식별자에 연결하고 재연결 때 중복 생성하지 않는다. 종료 확인, 늦은 메시지, 앱 재실행 복구를 포함한다. 다른 워치 운동과 충돌하면 아이폰 기록을 보존하고 워치 연결 상태를 명확히 표시한다. 다른 운동을 몰래 다시 종료시키는 재시도는 하지 않는다.

건강 앱에 운동 기록을 저장할지와 다른 운동 앱 병행 정책은 승인된 FRD와 달라지는 부분이다. 구체적인 정책을 FRD와 PRD에 반영하고 확인받은 뒤 구현한다. 사용자에게 반복 장거리 테스트를 요청하기보다 새로 달라지는 워치 동작을 짧게 검증한다.

## 이번 검증

- 전체 Jest 51개 묶음 375개 통과.
- Swift 측정·저장·워치 자료 처리 133개와 잠금화면 36개 통과. 실제 워치 센서와 화면 복귀를 대체하는 검사는 아니다.
- 타입 검사 통과. 린트 오류 0개, 기존 경고 30개.
- 공개·내부 빌드 설정 및 워치·잠금화면 타깃 생성 검사 통과. 현재 내부 제한이 의도대로 유지됨을 확인한 것이다.
- iPhone 11 Pro에서 하트 샘플 선택 → 갤러리 열기·취소 → 트랙 배경 선택 → 불빛 프리셋 편집 → 12초 영상 생성 → 사진 앱 저장 → 보관함 재생 → 다시 편집을 통과했다. 다시 편집한 기록·경로·배경·프리셋·배치·다듬기·러닝 데이터가 저장 결과물과 일치했다.
- 기존 결과물 26개는 유지됐고 QA 샘플 한 개를 추가했다. 앱 재설치에 따른 파일 경로 보정과 빈 손그림 배열 정규화 외에 기존 결과물 내용은 같았다. 원래 편집 초안은 사전 백업으로 복원했으며 내 스타일도 보존했다.
- Xcode 기기 목록에서 Apple Watch SE는 `unavailable`이었다. 이번 검토에서 실제 워치 화면 복귀를 새로 확인했다고 보고하지 않는다.

이 검토 후 사용자의 요청으로 현재 구현을 TestFlight 43번에 제출했다. [배포 기록](../../ops/build-and-dev-commands.md)에 Apple 내부 테스트 가능 상태를 확인한 결과를 남겼다. PR #125는 사용자 승인 후 main에 머지됐다.

## 2026-10-26 후속 착수

사용자가 짧은 야외 테스트에서 측정이 잘 되는 것 같다고 알렸다. 워치 연동 완성 → 화면 복귀 검증 → 정식 출시 준비 순서에 동의했다.

[워치 연동 PRD](../../specs/prd/watch-workout-integration.md)와 [FRD 검토안](../../specs/frd/watch-workout-integration.md)을 준비했다. 이번 순서 승인은 상세 정책 확정과 구분한다. 시안을 확인받은 뒤 기존 정책 개정과 제품 구현에 착수한다.

## 2026-10-26 승인 후 구현

위 현황은 TestFlight 43번과 구현 착수 전 기준이다. 이후 사용자가 자체 워치 운동 세션과 건강 저장까지 승인해 [구현 노트](watch-workout-integration.md)에 작업을 진행한다. 아이폰 단독 완료 기록도 건강 저장 대상이며 저장된 심박 읽기에는 운동 세션이 필수가 아니다. 실기기 화면 복귀와 피트니스 표시를 확인하기 전에는 정식 출시 준비 완료로 표시하지 않는다.
